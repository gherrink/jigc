# symbol-mention sweep — prose blast radius on a symbol removal/rename

**Status: parked 2026-07-12.** From the RC implementation-half trial, probe 2 ([trial-record](../completions/artifacts/RC-adoption/impl-rc5/trial-record.md) → Probe 2). Indexed from [VISION.md](../VISION.md) → Open questions. **Extended 2026-09-28** with the path-mention case (below), from M54's restructure — keyed to **M56**.

## The gap

The anchor gate catches the *structured* half of a symbol's blast radius (`cites-code`/`implemented-by` anchors) and blocked the trial's refactor correctly. The *prose* half — seven managed docs whose paragraphs mentioned `AuditService` or asserted "the gate is dead" — was invisible: the agent found them by hand-grepping in three rounds of guessed patterns. "Green validate, lying prose" is the false-safety failure mode, and it lands on exactly the tasks the anchor gate already flags.

> The cheap fix is a symbol-mention sweep. When a task removes or renames a file or symbol, grep the managed corpus for the old name and emit advisory findings: "6 managed docs mention AuditService in prose — review." It doesn't need to understand the prose; it just needs to point.

## The shape

Detect-and-route, never rewrite (the determinism boundary holds: pointing is structural, judging materiality is the agent's). Trigger condition is already known deterministically — a task whose diff deletes/renames a file or an anchored symbol (the same signal `doc-code.symbol-exists` consumes). Sweep = substring/word match of the old name across managed-doc prose; emit one **advisory** finding per mentioning doc, route "review whether this prose still holds." Kinship: the in-prose `mention-resolves` check (M33) is the managed-mention sibling; this sweeps *unstructured* mentions, keyed off a task's code delta rather than the store.

Also the honest-cost framing from the trial, worth carrying wherever this lands: docs that describe code in the present tense make every fix a documentation project — that's the deal, and the sweep is what makes the deal payable.

## The path-mention case (added 2026-09-28, M54's Settle)

**The same class, one noun over: a *path* that moves under prose that cites it.** A symbol rename strands the paragraphs that name the symbol; a file or directory move strands the paragraphs that name the path — as a markdown link, or as a backticked path a reader will type. Nothing structural breaks, `jigc validate` stays green, and the prose now sends its reader to a file that is not there.

**The evidence is this repository's own restructure.** M54 moved both packs (~~`crates/cli/pack/`~~ and the root ~~`packs/methodology/`~~ → `crates/cli/packs/{dev,methodology}/`), the two installed guides into the crate, and the probe's sources out of ~~`crates/cli/probes/doc-code/`~~. The Settle's census counted **~25 live-doc citations** of paths that move, **one of them a real link** ([methodology-docs.md](../design/methodology-docs.md):19, into ~~`crates/cli/pack/workflows/`~~). A re-grep at the write (2026-09-28, the two pack roots plus the probe directory, over live `.md` files with the dated records excluded) counts **43 lines across 22 files**, two of them followable links (that one, and [validation.md](../design/validation.md):300 into the probe's source) — the two numbers are different census definitions, recorded side by side rather than reconciled. M54 answers it **for this repository** with a gate test that every relative link and backticked repo path in an enumerated list of live docs resolves ([DECISIONS.md](../DECISIONS.md) → *M54 settled*, S15). That is a repo test, not a product capability.

**What jigc already covers, and where it stops.** Structured references survive a move by construction: `ref-resolves` over the edge index, `jigc rename`'s lockstep repointing of every structured referrer, `mention-resolves` for in-prose managed mentions, and `doc-code`'s `code-anchor` fields, which name the file they anchor. **None of them reads a path written in free prose.** So the product question is this idea's, widened: when a task's diff moves or deletes a path, does jigc point at the managed docs whose prose cites it — the same detect-and-route advisory the symbol sweep would emit, keyed off the task's rename/delete set instead of its symbol set? The shapes and the determinism boundary above carry over unchanged; the one new consideration is that a path is **cheaper to match** than a symbol (it is a literal string with a known root), so this half may be the sweep's cheapest first slice.

**Trigger: M56 — the port is the test.** Porting this repository onto jigc puts this repository's path-citing prose under management; whatever of it M54's repo test does not cover, and the port finds stranded, is reported through the findings channel M55 ships, and that residue is the measurement this idea is decided on ([decisions-pending.md](../implementation/decisions-pending.md) → *The road to 1.0.0 and the port* → M56).
