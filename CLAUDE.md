**Throwaway repos: never `rm -rf` a path built from variables.** Agents that drive the binary (validators, auditors, e2e) build scratch repos under the session scratchpad and reach for `rm -rf $V/$D` to reset them. **That command is refused before it runs** — the harness scans the command *text*, cannot prove `$V` and `$D` are non-empty, and escalates it as a possible `rm -rf /`; the refusal is about the **shape**, so no allowlist suppresses it and every retry re-prompts. In a delegated run this **parks the agent** on a prompt nobody is watching. **Use `dev/jigc-rig <state>`** — it mints its root with `mktemp -d`, so there is nothing to remove and the shape never appears. Failing that, a fresh directory instead of a cleared one — `W=$(mktemp -d "$SCRATCH/probe.XXXXXX")` — or, when a fixed path is genuinely needed, empty it without `rm`: `mkdir -p "$D" && find "$D" -mindepth 1 -delete`. `set -u` and `: "${V:?}"` do **not** help: the check is static on the text, never on runtime behaviour. Quote every path expansion regardless. **Two more rig-side traps, each hit twice in one session (M53, 2026-09):** (1) **this harness's `grep` is a shell function over `ugrep --ignore-files`, which honours `.gitignore` — and `.jigc/` is gitignored whole**, so `grep -rl <marker> .` under a working area says *not found* whether or not the bytes exist; every loss claim under `.jigc/` uses `command grep` with a **before-control that finds the plant** (the M52 review's A3-2 evidence had the bad shape; its verdict stood, re-proved). (2) **`rig=$(dev/jigc-rig … 2>&1)` corrupts `$REPO`** — stderr folds into the captured assignments, the two-step `eval` half-applies, `$REPO` comes out empty or wrong, and the probe's next `git -C "$REPO" commit` lands in **this** repository (twice: `f00800f9` and a `chore: deep dir`, both reset before any push). ## How we work together

Two operating modes, each with its own loop:

- **Design decisions & docs** → the [design workflow](implementation/design-workflow.md) (discuss → converge → write; default output is discussion).
- **Code** → the [dev workflow](implementation/dev-workflow.md) (test-first: scope → red → green → refactor → gate → commit).

The conventions below apply across both.

**Branches** (since 2026-10-01 — [DECISIONS.md](DECISIONS.md) → *the branching switch*). **This is the branch model's one home**; the lifecycle an increment walks is [increment-workflow.md](implementation/increment-workflow.md) → Branches, and `main`'s ruleset is [release.md](implementation/release.md) → The main branch.

| Branch | What it carries | Who makes it |
|---|---|---|
| `main` | the trunk — changes **only through a pull request the human merges**, never a direct push | nobody pushes it |
| `milestone/<slug>/main` | one milestone, forked from `main`; the planning commits land here, and it reaches `main` as one PR after the completion audit | planning, or the `milestone-build` harness's first step |
| `milestone/<slug>/<increment-slug>` | one increment, forked from its milestone branch, merged back `--no-ff` once validated, then deleted — **local only**, never pushed | the `milestone-build` harness |
| `fix/<slug>` | a fix outside a milestone | anyone |
| `work/<slug>` | any other change outside a milestone (tooling, docs, a switch like this one) | anyone |
| `release-plz-*` | the release PR | release-plz only, never by hand |

`<slug>` is jigc's slug grammar — lowercase `a-z0-9` words joined by single `-` — and the milestone's is chosen at planning and recorded in its roadmap decomposition (M55 → `findings-channel`); increment order is the roadmap's, never the name's. **No other prefix exists** — the commit type lives in the conventional commit, so there is no `feat/` or `docs/` — and CI's `hygiene` job refuses any other name ([`dev/branch-name`](dev/branch-name)) on every push and on every pull request **but one from a fork**, whose branch is its contributor's to name — the fork's pull request gets every other check unchanged, the denylist skipping with its notice because a fork receives no secrets ([DECISIONS.md](DECISIONS.md) → *Pull requests from forks are exempt from the branch-name check*). **Every new branch starts from the current remote `main`** — `git fetch origin`, then branch from `origin/main`; a local `main` that has diverged from it halts to the human, never reset ([dev-workflow.md](implementation/dev-workflow.md) → Starting a branch from `main`). **Pushes:** a branch is pushed **by name** (`git push origin <branch>`) — the harness pushes the milestone branch after every landed increment, and a `fix/`/`work/` branch is pushed at the end of its work unit; **before any pull request to `main`, `origin/main` is merged into the branch** — a merge commit, never a rebase; a conflict confined to the append-only logs resolved by `dev/merge-logs`, any other one halted to the human; then the gate, the push, the PR ([dev-workflow.md](implementation/dev-workflow.md) → Before a pull request to `main`). **While a pull request that touches the shared logs (`DECISIONS.md`, `implementation/project-history.md`) is open, the orchestrator starts no second branch that touches them** — two branches appending to one singleton log collide (PR #6 against PR #5, 2026-10-02). Agents never push or merge `main`, never force-push any branch, never merge a PR, never push a tag ([release.md](implementation/release.md) → What agents may not do). **Releases:** a merged milestone PR updates the release PR, and **the release PR is the release boundary** — the human merges it when the planned set is in ([release.md](implementation/release.md) → The release PR).

Shared content earns its own part-doc (the document model, applied to us).

`team-ready-state` (M39) reads after `design-altitude-doctypes` — it adds the methodology pack's fifth work-doc doctype (`milestone-record`, graduating in-flight milestone state out of the gitignored `.jigc/` workbench into a committed record under the **`.jigc`-is-the-workbench, the repo is the record** principle), extending `methodology-docs`' work-doc surface and revising `storage`' source-of-truth model (the milestone record joins the `.md` set; the `.jigc/milestones` JSON demotes to a rebuildable cache), so both must be in hand; `findings-channel` (M55) reads after `team-ready-state` — it adds the methodology pack's two findings doctypes (`jigc-feedback`, `inconsistency`, one doc per finding) filed and triaged through code-less workflows over a doc-only finalize step, extending the same work-doc surface plus the `finalize` and `doc-read-surface` contracts it revises, so all three must be in hand; `measurement` (M17) reads **last of all** — it designs the proof-in-the-wild (the dogfood protocol, the three measured facts, the A/B control), consuming every prior surface plus the composed packs, and is the spine's final word. Read `DECISIONS.md` alongside for the *why*.
- **No number prefixes** on part-docs (descriptive names only) — principle #2; we don't grow our own `01-`/`02.5-` disease.
- **Flag the unsettled.** Mark illustrative notation as illustrative; list open questions explicitly rather than implying resolution.
- **What the "Notation is illustrative" header disclaims.** A `design/` part-doc opening with that header disclaims its **notation** — YAML sketches, render and error-text examples, shape and syntax illustrations are non-normative, and the doc it names as owning the format is the source of truth for those. It disclaims nothing else: a rule, contract or invariant stated in the doc's prose is **citable** exactly as in an undisclaimered doc. Every doc carrying the header links here; none of them restates this.
- **Decisions log.** Record every decision in `DECISIONS.md` (dated, ≤1 line of why) as it's made — the *when & why*, not the architecture (`VISION.md` + this file hold current truth). A decision you *defer to a future milestone* (rather than make) goes in [implementation/decisions-pending.md](implementation/decisions-pending.md) → *Before planning*, keyed to its **trigger milestone**, in the same motion as the deferral — so milestone planning resurfaces it. `DECISIONS.md` = what was *decided*; `decisions-pending.md` = what is *owed and when it's due*. A deferral left only in prose has no trigger and will be forgotten. And the third home in the same family: a milestone's **fold-back** — the `**M<nn> — …**` span a close increment writes when the wave lands — appends to [implementation/project-history.md](implementation/project-history.md), where `crates/cli/tests/foldback_truth.rs` and `crates/cli/tests/count_fences.rs` read it; `## Project state` above carries current truth and a pointer, and never a milestone claim again.
- **Public hygiene.** This repository is public, and so is every commit it has carried. No credential (even a revoked one), internal hostname, employer/client/internal project name, private ticket key, or other person's name or email in any file or commit message; trials and evals run on synthetic or public corpora, and a real-work trial commits only aggregated, anonymized findings; a raw transcript is committed only when a test or tool reads it as a named fixture. The rules, the fixed anonymization vocabulary (`acme`, `project-alpha`…, `TKT-<n>`) and the guard — gitleaks plus a private denylist, hard in CI, advisory in `dev/gate` — live in [implementation/public-hygiene.md](implementation/public-hygiene.md).
- **Trivial lane.** Small clarifications skip the loop — don't ceremony-tax a typo — but never the gate: no commit is gate-exempt by its path ([dev-workflow.md](implementation/dev-workflow.md) → Gate).

## What this project is

A **context compiler for coding agents**. A deterministic CLI assembles exactly the instructions and document slices an agent needs for a specific task, just-in-time, and is the sole channel through which the agent reads and writes managed project documents (specs, ADRs, PRDs, commit messages, architecture docs). It replaces static rules files (`CLAUDE.md`, Cursor rules), GSD-style skeleton generation, and Spec-Kit-style workflows.

## The one load-bearing idea

**Take every *structural* operation away from the LLM and give it to the CLI. Leave the LLM only the prose.** Every architectural decision descends from this. The determinism boundary is a hard contract — the canonical table lives in [VISION.md](VISION.md#the-determinism-boundary) (CLI owns: which docs exist, structure, ordering, cross-references, workflow composition + placeholder resolution, placement of every write, validation results; LLM owns: the prose inside slots). "Reproducible" applies to **structure**, never to LLM prose. Do not chase reproducibility of content.

## Architectural invariants (do not violate without revising VISION.md)

- **The CLI core makes no LLM calls.** Composition is deterministic: same *resolved cascade* in → same workflow out. (The *coding agent* may use the CLI to draft a merge proposal — that is the agent acting, not the CLI.)
- **The LLM writes only through the CLI.** It hands content for a *named slot*; the CLI owns placement, cross-ref wiring, versioning, and commit. The LLM places nothing, so it can misplace nothing. *Honest boundary:* this is **adapter-enforced, not sandboxed** — frictionless `jigc` access + bootstrap *advertise+demonstrate* make the CLI the path of least resistance, but an agent that ignores the adapter can still edit files directly. The bet is on ergonomics, not prevention; see [VISION.md](VISION.md) principle #3 and [design/assistant-adapter.md](design/assistant-adapter.md).
- **Stable opaque IDs, never positions — identity changes only through one atomic CLI op.** Managed-artifact IDs (docs, sections, steps, slots, items) and work-unit IDs (tasks; planned: milestones, increments — `milestone > increment > task`) are stable under **reorder** and **ordinary retitle-without-reslug**; ordering lives in a separate ordered list. No renumbering; cross-references point at IDs and survive reorder. A doc-level **identity change** (re-slug) is allowed **only** through the atomic **`jigc rename`** op (M35) — never an untracked move — which repoints every structured referrer in lockstep, so *reference-integrity* survives even though *identity-stability* does not ([VISION.md](VISION.md) → Stable IDs; [storage.md](design/storage.md) → Identity; [write-commands.md](design/write-commands.md) → `jigc rename`).
- **Engine vs CLI vs domain pack are separate** — the canonical statement lives in [VISION.md](VISION.md) → "What it is" / "Design principles." Working implication for this repo: the engine ships **empty by invariant**; pack content + adapter profiles ride in `cli` per [implementation/module-layout.md](implementation/module-layout.md).
- **Config cascades: project > team > pack-default.** (`team` = a cross-project layer, not per-developer.) All customization is a recorded **delta** against a known base version (never an untracked fork), so upgrades re-apply deltas and report clean/conflict/orphaned.
- **Slots vs placeholders are opposites and must stay syntactically distinct.** *Slots* (`<<slot>>`) are LLM-filled on the write path. *Placeholders* (`{{…}}`) are CLI-filled on the read path (command refs, data values, includes).
- **Storage is plain, human-readable, diff-friendly files.** Humans review and edit through git regardless of the CLI; out-of-band edits are **detected and routed** — conformant non-conflicts absorbed, conflicts blocked and routed to a human, never silently merged or forbidden (see [design/reconciliation.md](design/reconciliation.md)).
- **Writes are transactional.** Integrity holds at a `finalize`/commit boundary, not on every write (else bootstrapping deadlocks).
- **Frozen-v1 doctype schemas are version-gated.** The six dev-pack doctypes (`commit`/`adr`/`spec`/`prd`/`arch-doc`/`changelog`) + the schema-definition format are **frozen v1** ([implementation/doctype-map.md](implementation/doctype-map.md) → The v1 freeze). **The v1 baseline crystallizes across the M33+M34 pair** ([DECISIONS.md](DECISIONS.md) → 2026-06-24 M33+M34 paired): M33 froze an interim shape and M34 *completes* v1 by injecting the engine `schema-version` stamp — so the five persisted hashes evolving under **version 1** during M34 is the sanctioned baseline establishment (the stamp's own v0→v1 corpus migration ships alongside it), **not** an un-versioned change. The version-gate binds **after** the v1 baseline is crystallized: from then on, no schema-*shape* change to a frozen doctype ships without bumping its manifest `schema-version` **and** shipping a versioned M34 corpus migration. The engine pack-load assertion recomputes each doctype's `schema-hash` against `crates/cli/packs/dev/config/schema-manifest.yaml` and **blocks loudly** on an un-migrated change (the intrinsic-floor-assertion sibling, not the report-only `validate` sweep). **The gate binds at every layer that can change a schema (M49):** a project-layer whole-file shadow at `.jigc/config/schemas/<ty>.yaml` is hashed **as resolved**, so the layer that outranks every pack cannot reshape a frozen doctype either — until M49 it could, and the corpus it made non-conformant still validated clean at exit 0 while `doc schema` reported the frozen version for an unfrozen shape. The documented shadow capability survives unchanged: M47's presentation projection erases `description:`/`usage:`/slot `hint:`, so a prose reword still shadows cleanly ([design/overrides.md](design/overrides.md) → Authored metadata on a definition resolves by whole-file shadow). Originally scoped to the frozen-v1 dev set; **since M40 the methodology pack is version-gated the same way under its own `schema-manifest.yaml`** — the recorded adoption trigger fired at the RC adoption trial: ten schemas listed, the nine persisted doctypes stamp-injected at schema-version 1, the manifest resolved per-origin-pack ([design/corpus-migration.md](design/corpus-migration.md) → The freeze-exempt sibling, the M40 revision). **Location is a gated change-kind (M38):** a frozen doctype's `location`/`placement` is inside its `schema-hash`, so a *home* change is version-gated exactly like a shape change — `changelog`'s move to root `CHANGELOG.md` bumped it to **schema-version 2** and shipped a location-only corpus migration ([design/storage.md](design/storage.md) → Placement; [DECISIONS.md](DECISIONS.md) → 2026-07-04 M38 planned).
- **Concurrency is one bounded primitive only.** `fan-out`/`join` steps; each sub-agent writes to an isolated working area keyed by task ID; the CLI merges at a join ordered **by task ID, not completion order**. **The isolation is that working area plus the code worktree, never the shared `.jigc/` caches** — a worktree binds to the main checkout's `.jigc`, so all N sub-agents write one `state/file-state.json`, one `index/edges.json` and one milestone `tasks.json`; each carries its own concurrent-writer rule (base-relative merge · lock-only · atomic-but-unmerged) in [design/storage.md](design/storage.md) → Concurrent writers. No DAGs, conditionals, cross-agent messaging, or runtime. Sub-agents coordinate through the CLI (blackboard pattern), never directly — messages carry only `task_id` + status; state is always re-derived from the CLI.

## MVP scope (M1 — shipped; kept as the historical scope record)

> **Status note (2026-07-02):** this section records the *M1* scope calls and their rationale — kept because the reasoning still explains why the core loop is shaped the way it is. Several "not yet" statements below have since shipped: the **router** workflow (M2 flipped `default-workflow`), the full frozen-v1 doctype set (`commit`/`adr`/`spec`/`prd`/`arch-doc`/`changelog`), store-scope validation (M18/M20), fan-out/join (M7/M8/M31), migration (M23/M34), and `jigc rename` (M35). Current truth lives in the [roadmap](implementation/roadmap.md) per milestone; do not read the bullets below as the present surface.

First loop to build end-to-end: **`single task execution`** (discover → compose → execute → validate) — the cheapest proof the core loop beats a plain `CLAUDE.md`. Scope calls (rationale in [DECISIONS.md](DECISIONS.md), 2026-05-25):

- **Spec-less.** The MVP `single-task` does **not** read a SPEC (no `task.spec`, no `spec` schema ships); the "what" comes from the human `intent` + the codebase. The composed workflow *does* embed `{{task.intent}}` (an engine-native `task` data-value root), so real data-value resolution is exercised. Adding spec support later is a trivial pack addition.
- **Front door, no router workflow yet.** `jigc start` is built in all four forms (orient · cascade-default compose · `--workflow X` · `--task <id>` — see [design/write-commands.md](design/write-commands.md) → Task origination). The **router** selection-guidance workflow is **not** built; instead the cascade knob `default-workflow` ships pointing at `single-task` directly (a `creates-task: true` work-workflow), so MVP's `jigc start "<intent>"` mints in one call. Post-MVP, when ≥2 work-workflows exist, the cascade flips `default-workflow` to a router workflow (`creates-task: false`) and the model-free selection path activates without any code change.
- **Two doc types — one transient, one persisted.** The pack ships **`commit`** (sink = the git message, transient) *and* **`adr`** (persisted to `decisions/`; engine-native fields `status`/`date` + prose slots + the optional **`supersedes`** relation, adr→adr). The agent **creates** an ADR in-task via the workflow-gated `create` flow when a decision is warranted (`single-task` ships with `allows-create: [{type: adr, as: decision}]` in its front-matter — the created ADR binds to `task.decision`; see [design/workflow-dialect.md](design/workflow-dialect.md) → On-disk definition format and [design/write-commands.md](design/write-commands.md) → The create-gate). The persisted ADR is what makes the MVP *prove its differentiators*, and the proof is **mandated by one acceptance path** — the **superseding-decision flow** ([design/worked-examples.md](design/worked-examples.md) → Superseding decision): a later task records an ADR that `supersedes` a committed one, so the loop (a) round-trips a committed, human-editable file — parsing/slicing it in-loop over the byte-stable, golden-tested splice path that **retires the #1 risk** ([implementation/parsing.md](implementation/parsing.md) owns byte-stability as a writer property), (b) detects `file ↔ CLI-state` drift + reconciles OOB edits, (c) composes a **context-slice over that persisted ADR** (`{{@task.decision.supersedes#decision}}`), and (d) walks the **edge index** for forward-ref integrity at finalize — passing when the target exists, blocking when it dangles (the **"validate against reality" integration advantage**). `supersedes` is the only logic-free handle from task state to a committed doc in a spec-less MVP, so this single path converts the differentiators from *supported* to *proven*.
- **The deliverable is `engine` + `cli` + a minimal *embedded* dev pack + the Claude Code profile** — not just the engine (which ships empty by invariant). MVP pack: the **`commit`** + **`adr`** doc-types, the **`single-task`** workflow + its steps, and the cascade pack-default config (incl. the `create`-gate entry `{type: adr, as: decision}`). **Zero *pack* probes** — the MVP checks are engine-native.
- **`finalize` is the commit boundary.** It validates, **renders the commit doc into the git commit message** (the commit type's sink is the VCS message, not a repo file), **promotes any created ADR** to `decisions/`, and `git`-commits the task's code changes + promoted docs as one commit. The CLI commits code too (the agent authors it directly; committing is the CLI's job — "CLI orchestrates, git executes").

Validation is in the MVP: the framework + the **two engine-native probes** (`workflow-refs`, `file-state`) **plus the intrinsic `finalize` integrity gate** — which the ADR + `supersedes` now genuinely exercise: **forward-ref resolution over a real edge index** (the integration advantage), required-slot presence, malformed-value rejection. Pack-provided `doc ↔ code` probes come *after* (they need real code anchors); inverse/minimum-cardinality stays advisory at store scope, never a per-task gate.

Implementation foundations live in [implementation/](implementation/) — language/runtime, parsing, module layout, [machine-setup.md](implementation/machine-setup.md) (read once per dev machine), plus [doctype-authoring.md](implementation/doctype-authoring.md) (the registration checklist a new or reshaped doctype is walked through), [pinning.md](implementation/pinning.md) (how a verified fact stays verified: compose goldens · contract property suites · repro blocks · the trial-shaped fixture substrate) and [release.md](implementation/release.md) (how jigc is versioned, packaged, published to crates.io and installed — settled at M54's planning, built by M54).

**Trial tooling is reusable and lives outside any one trial's directory — check it before building anything for a new RC trial.** Four homes, none of them under `completions/artifacts/<trial>/`: [completions/trial-corpus-template/](completions/trial-corpus-template/) instantiates a **foreign, pre-jigc corpus** (9 TS modules · 3 test files · 24 tests · 7 commits · zero managed docs) with `instantiate.sh [--clean-prose]` and gates it with `check-corpus.sh` (7 commits · clean tree · no jigc/adapter residue **including `.git/hooks/pre-commit`** · no remote · clean reflog · suite green); [completions/trial-harness/](completions/trial-harness/) builds and verifies the **isolated container** a blind session runs in (`build-image.sh <sha>` pins the binary by commit and `build-image.sh --registry <version>` installs a published one from crates.io, `verify-image.sh` runs seven checks, `verify-pair.sh` proves two images are different trees, `run-session.sh` drives one session and copies the evidence back out); [completions/workflow-eval/](completions/workflow-eval/) is the older per-workflow agent-run eval; and [completions/trial-driver/](completions/trial-driver/) **drives and scores a session without an operator** (`run.py observe` reads a finished session's §3.3 channels off its own evidence and reproduces the 1.0.0-gate table exactly; `seed`/`fork` record a conversation once and fork it N times from an identical mid-arc position; `plant` fires a plant on a *state* polled from outside the session, which is the step that voided B3a; `gate` refuses a round the isolation record does not cover; `walk.py` drives the operator walk as scripted arms so an unrun arm is **visibly blank**). Its bounds are in its own README — chiefly that a headless result is a fact about the headless channel, and that it does **not** solve mid-turn injection: `-p` has no queued-message channel at all, so the postmortem's answer (plant a state, never schedule a sentence) is unchanged. **This paragraph exists because the corpus template was committed after RC-pre-1.0 precisely so it would be reused, nothing referenced it, and the next session assumed it had been lost and planned to rebuild it.** A tool nothing points at is a tool that gets rebuilt. **The boundary between the three corpus builders, since they are one grep apart:** the trial tooling above builds **foreign, pre-jigc** corpora (zero managed docs — the state an adoption trial adopts *from*); [`dev/jigc-rig`](dev/jigc-rig) builds **adopted** ones for a shell probe; and `crates/cli/tests/support/trial_corpus.rs` is that same adopted builder for the Rust suites. A trial reaching for the rig is asking the wrong question, and a probe reaching for the template is too.

## Non-goals

Not a general-purpose workflow engine (no DAGs/conditionals/runtime), not an auto-doc-writer (detects and routes drift; never auto-authors prose), not one-size-fits-all, **no longer single-domain** (M12/M14: the methodology pack composes with dev — the engine/pack boundary is proven architecture) but **not yet a public pack platform** (a stabilized third-party pack-authoring API is future work, when an external domain earns it), not an LLM wrapper.
