**Build / lint / test:** `cargo build` · `cargo test` · `cargo clippy --all-targets -- -D warnings` · `cargo fmt --check` (the dev-workflow gate — all four must pass before a commit; **measure them unpiped** — `cmd | tail` reports *tail's* exit status, so redirect to a file and capture `$?` directly, per [dev-workflow.md](implementation/dev-workflow.md) → Gate). **Run it with [`dev/gate`](dev/gate)** (`dev/` is this repo's home for agent-facing development tooling) rather than retyping the gate — it runs all five commands **bare** (probe prebuild · fmt · clippy · build · test), captures each exit code directly, prints the aggregate `passed=`/`failed=` totals and the log path, and on failure names the failing **step** *and* the failing **test names**, so the `| tail` reflex has something to reach for instead (a step exiting 127 is reported as **did not run**, naming the missing binary, because that is not a verdict about the code; `--report <log>` re-prints that report over an existing log and runs no cargo, which is how `crates/cli/tests/dev_gate_report.rs` fences it); `--quick` drops the tests for a fast pre-check (never a commit), `--private-target` builds in a private `CARGO_TARGET_DIR` when a concurrent gate holds the shared `target/` lock, and every run opens with `gate: deps <N> entries` for the `debug/deps` it is about to build into — a directory cargo never garbage-collects, which reached 1.8 M entries (26 GB) by 2026-09-14 and cost the gate roughly twice its runtime in Gatekeeper rescans ([dev-workflow.md](implementation/dev-workflow.md) → Gate carries the measurement). `[profile.dev] split-debuginfo = "packed"` stops new litter at the source; **[`dev/clean-litter`](dev/clean-litter)** (`cargo clean` over both target trees, no `rm` anywhere in it) is the reset, run at the [milestone close](implementation/milestone-completion-workflow.md). **Need a jigc repo to poke at, use [`dev/jigc-rig`](dev/jigc-rig)** rather than hand-building one: `rig=$(dev/jigc-rig committed-singletons) || exit; eval "$rig"` builds any of the six named corpus states `crates/cli/tests/support/trial_corpus.rs` declares, plus a rig-only **`bare`** (a git repo with one commit and *no* `jigc setup` — the only state `setup` itself, the adapter install, `ingest` or the leftover classifier can be probed from). **Eval it in two steps, never `eval "$(…)"`** — that form reports the *eval's* status, so a rig that failed to build returns 0 and your probe silently runs against the previous corpus — driving the real binary, never writing into `.jigc/` — and exports `$RIG`/`$REPO`/`$RIG_HOME`/`$JIGC`/`$RIG_TASK`, so a shell probe reaches that fixture builder without writing a `#[test]`, registering it in a group root and running a group target. **It has no teardown and needs none** — every root comes from `mktemp -d`, a path that did not exist a moment ago — which is the answer the `rm -rf $V/$D` rule below has been missing: that shape is refused *before it runs*, so in a delegated run it parks on a prompt nobody is watching. `--pack-from-dev`/`--schema`/`--workflow` manufacture a throwaway pack, `--repin` re-pins a reshaped schema's `schema-hash` until pack-load is clean, `--print-only` emits the construction as a paste-runnable repro; `crates/cli/tests/dev_rig_parity.rs` fences its state set against `State::ALL` (up to `RIG_ONLY_STATES`, each carrying its reason), fences `dev/` against recursive removal of a variable path, and — because the rig *writes* its commands rather than containing them, so a static scan of `dev/` reads the generator and never the generated — drives `--print-only` with adversarial names and scans the **emitted** script. One test: `cargo test -p engine <name>` / `cargo test -p cli <name>`; one integration/acceptance suite: `cargo test -p cli <suite>::` (e.g. `flow37_rename::` — the `crates/cli/tests/flow*.rs` suites drive the built binary through the [worked-examples](design/worked-examples.md) flows in throwaway repos). **Since M47 the ~250 suite files are compiled into twelve `[[test]]` group targets** (`crates/cli/tests/groups/`), not one cargo target each — a macOS Gatekeeper assessment per freshly-linked binary was costing ~44 s × 252 per gate run. `autotests = false`, so **a new suite file must be registered in exactly one group root** (`#[path = "../<name>.rs"] mod <name>;`); `tests/test_target_registration.rs` fences that, and `--test <file>` no longer addresses a suite. Install the release binary: `cargo build --release && install -m755 target/release/jigc ~/.local/bin/jigc`.

**Throwaway repos: never `rm -rf` a path built from variables.** Agents that drive the binary (validators, auditors, e2e) build scratch repos under the session scratchpad and reach for `rm -rf $V/$D` to reset them. **That command is refused before it runs** — the harness scans the command *text*, cannot prove `$V` and `$D` are non-empty, and escalates it as a possible `rm -rf /`; the refusal is about the **shape**, so no allowlist suppresses it and every retry re-prompts. In a delegated run this **parks the agent** on a prompt nobody is watching. **Use `dev/jigc-rig <state>`** — it mints its root with `mktemp -d`, so there is nothing to remove and the shape never appears. Failing that, a fresh directory instead of a cleared one — `W=$(mktemp -d "$SCRATCH/probe.XXXXXX")` — or, when a fixed path is genuinely needed, empty it without `rm`: `mkdir -p "$D" && find "$D" -mindepth 1 -delete`. `set -u` and `: "${V:?}"` do **not** help: the check is static on the text, never on runtime behaviour. Quote every path expansion regardless.

**Quickstart:** [QUICKSTART.md](QUICKSTART.md) walks the core loop on a real machine — install → `jigc setup` → `jigc start "<intent>"` → `jigc task finalize <id>`. **Migrating an existing project (or a corpus across versions):** [MIGRATING.md](MIGRATING.md).

**Code architecture** (canonical detail: [implementation/module-layout.md](implementation/module-layout.md)): `crates/engine` is the deterministic core — schema-driven parse/canonical-write/byte-stable splice (`parse.rs`, `write.rs`), the derived forward-edge index (`index.rs`), validation families (`validate.rs`), file-state reconciliation (`file_state.rs`), and the fan-out join (`milestone.rs`). It ships **empty of content by invariant** and makes no LLM calls. `crates/cli` owns the verb surface (`cli.rs` dispatch → per-verb modules like `start.rs`, `task.rs`, `doc.rs`, `rename.rs`), git integration (shell-out via `task.rs` helpers — never a git library), and embeds the packs at compile time via `include_dir!` — the dev pack from `crates/cli/pack/` (doctype schemas, workflows, cascade config incl. the frozen-v1 `schema-manifest.yaml`), the methodology pack from `packs/methodology/` (repo root), and adapter profiles from `crates/cli/adapters/`. Three cross-cutting gotchas: doc locations resolve through the cascade's `docs-root` knob (never read `schema.location` raw) — **and mind the placement branch (M38): a `placement` doctype has `location: None` and homes at its `placement.file` (repo-root `VISION.md`/`CHANGELOG.md`, or `docs/roadmap.md`), bypassing `docs-root` entirely, so every `schema.location` consumer must also handle the placement case** — and **since M49 that file is not read raw either**: a declared home carrying a leading directory component resolves through the `placement-root` knob (`docs/roadmap.md` → `<placement-root>/roadmap.md`; a root-declared home is never re-rooted), so a census row now states *declared or resolved* as well as *branch or latent* ([design/storage.md](design/storage.md) → Placement) — `jigc validate` (store scope) is report-only/exit-0 for content findings — blocking verdicts live at the task/finalize gate — and **since M40 the methodology pack is manifest-governed too**: `packs/methodology/config/schema-manifest.yaml` freeze-asserts all ten shipped schemas at pack-load (a doctype's governing entry resolves per-origin-pack via `origin_packs`), so a schema-shape **or home** edit to any methodology doctype blocks loudly until its `schema-version` bumps and a corpus migration ships, exactly like the frozen dev pack ([design/corpus-migration.md](design/corpus-migration.md) → The freeze-exempt sibling, the M40 revision).

## How we work together

Two operating modes, each with its own loop:

- **Design decisions & docs** → the [design workflow](implementation/design-workflow.md) (discuss → converge → write; default output is discussion).
- **Code** → the [dev workflow](implementation/dev-workflow.md) (test-first: scope → red → green → refactor → gate → commit).

The conventions below apply across both.

**Conventions:**
- **One file, one purpose — route by home.** Thesis/framing → `VISION.md`; working truth & how-we-work → this file; the *why* of a decision → `DECISIONS.md`; architecture detail → a part-doc in `design/`; a shaped-but-unscheduled idea → one descriptive file in `ideas/`. **Cross-reference, never restate** — if two docs state the same fact, one is wrong. Shared content earns its own part-doc (the document model, applied to us).
- **Parked ideas → `ideas/`.** A direction too detailed for a one-line `DECISIONS.md` entry but too immature for a `design/` part-doc parks as one descriptive file in `ideas/` — indexed from `VISION.md` → Open questions, with a terse `DECISIONS.md` pointer when the direction is locked. Promote into `design/` (and the reading order) when de-parked.
- **Reading order for `design/`.** VISION → `structural-grammar` → `document-type-schema` → `write-commands` → `overrides` → `storage` → `workflow-dialect` → `command-catalog` → `validation` → `reconciliation` → `finalize` → `architecture-documentation` → `introspection` → `doc-read-surface` → `command-output-contract` → `surface-contract` → `bootstrap` → `assistant-adapter` → `project-setup` → `changelog` → `auto-migration` → `corpus-migration` → `worked-examples` → `self-hosting` → `methodology-docs` → `multi-pack` → `design-altitude-doctypes` → `team-ready-state` → `measurement`. The first two are the foundation; `overrides` sits before `storage`/`workflow-dialect` so the cascade vocabulary (`project > team > pack-default`, *delta*, *config family*) is in hand before those docs reach for it; `command-catalog` sits after `workflow-dialect` (whose command-ref placeholders it defines) and before `validation` (whose `workflow-refs.command-ref-resolves` check targets it); `reconciliation` consumes the `file-state` probe from `validation` and is consumed by `finalize`'s preflight, so the trio reads in that order; `architecture-documentation` (the M13 `arch-doc` doctype + its driving workflow) reads after `finalize` (it rides the create→author→code-less-finalize→promote spine) and `validation` (it activates `doc-code` and adds the per-field-type predicate selector); `introspection` (the `describe` read-path surface) reads after the cascade/definition-format/schema/command-catalog it projects; `doc-read-surface` (M39/M40/M42 — the `jigc doc show` committed-doc read surface + its pinned 1.0 `--format json` contract, joined at M40 by `jigc doc schema`, the separately-versioned schema projection, and at M42 by `jigc doc list`, the store-surface index projection) reads right after `introspection`, its sibling read surface (the four sit on one axis: `describe` is a non-contractual menu, `doc show` a contract-pinned content read, `doc schema` a separately-versioned schema read, `doc list` a contract-pinned index read — identity + registration state, `managed` vs `unregistered`), after the address grammar/schema/slice path it consumes; `command-output-contract` (M41 — the pinned `--format json` of composed output, write-acks, and the findings envelope) reads right after `doc-read-surface`, its **write/compose-side** machine-contract sibling (the read side pins content-read-back; this pins what a driver reads back from the *acting* verbs — the task id on compose, the decomposed write-ack target, findings-as-data + the stable `(code, target)` key), after `write-commands`/`workflow-dialect` whose outputs it pins; `surface-contract` (M43 — the three laws every printed surface obeys + their generation-seam fences + the surface style guide for the judgment tier) reads right after `command-output-contract` — it governs the *prose and affordance* tier of the same output surfaces whose machine shapes the two contract docs pin, and its fences reference the finding-key seam and route kinds those docs own; `bootstrap`/`assistant-adapter`/`project-setup` are integration layers (`project-setup` last of the three — it composes the setup *workflows* over the `jigc setup` *install* `assistant-adapter` defines); `changelog` (the post-M21 doctype-expansion track's first member) reads after `project-setup` (it earns from a **Flow-A** authoring workflow that doc frames) and before `worked-examples` (whose flow 24 is its acceptance) — it lifts the multi-level-repetition / optional-slot / doc-level-`set: on-create` engine capabilities that `structural-grammar`/`document-type-schema` flag as opens, plus the multi-word-section-id parser fix; `auto-migration` (M23, the doctype-expansion track's auto-migration milestone G1) reads after `changelog` (its first migration *target*) and `project-setup` (the Flow-2 detect-and-route it adds the *transform* arm to) — it ships the `jigc migrate` verb that rewrites a foreign `CHANGELOG.md` to conformant shape + adopts it under **Framing A** (LLM rewrites prose, CLI strict-parses + places — determinism boundary intact, no CLI fuzzy-mapping); `corpus-migration` (M33/M34, the productive-readiness pair) reads after `auto-migration` (its managed-corpus sibling — foreign *adoption* there, managed v1→v2 *upgrade* here, same determinism boundary) and before `worked-examples` — it declares the schema/format frozen v1 and adds the schema-version stamp + the store-scope conformance detector + the deterministic schema-diff transform that *bound* the freeze's lock-in cost; `team-ready-state` (M39) reads after `design-altitude-doctypes` — it adds the methodology pack's fifth work-doc doctype (`milestone-record`, graduating in-flight milestone state out of the gitignored `.jigc/` workbench into a committed record under the **`.jigc`-is-the-workbench, the repo is the record** principle), extending `methodology-docs`' work-doc surface and revising `storage`' source-of-truth model (the milestone record joins the `.md` set; the `.jigc/milestones` JSON demotes to a rebuildable cache), so both must be in hand; `measurement` (M17) reads **last of all** — it designs the proof-in-the-wild (the dogfood protocol, the three measured facts, the A/B control), consuming every prior surface plus the composed packs, and is the spine's final word. Read `DECISIONS.md` alongside for the *why*.
- **No number prefixes** on part-docs (descriptive names only) — principle #2; we don't grow our own `01-`/`02.5-` disease.
- **Flag the unsettled.** Mark illustrative notation as illustrative; list open questions explicitly rather than implying resolution.
- **What the "Notation is illustrative" header disclaims.** A `design/` part-doc opening with that header disclaims its **notation** — YAML sketches, render and error-text examples, shape and syntax illustrations are non-normative, and the doc it names as owning the format is the source of truth for those. It disclaims nothing else: a rule, contract or invariant stated in the doc's prose is **citable** exactly as in an undisclaimered doc. Every doc carrying the header links here; none of them restates this.
- **Decisions log.** Record every decision in `DECISIONS.md` (dated, ≤1 line of why) as it's made — the *when & why*, not the architecture (`VISION.md` + this file hold current truth). A decision you *defer to a future milestone* (rather than make) goes in [implementation/decisions-pending.md](implementation/decisions-pending.md) → *Before planning*, keyed to its **trigger milestone**, in the same motion as the deferral — so milestone planning resurfaces it. `DECISIONS.md` = what was *decided*; `decisions-pending.md` = what is *owed and when it's due*. A deferral left only in prose has no trigger and will be forgotten.
- **Trivial lane.** Small clarifications skip the loop — don't ceremony-tax a typo.

## What this project is

A **context compiler for coding agents**. A deterministic CLI assembles exactly the instructions and document slices an agent needs for a specific task, just-in-time, and is the sole channel through which the agent reads and writes managed project documents (specs, ADRs, PRDs, commit messages, architecture docs). It replaces static rules files (`CLAUDE.md`, Cursor rules), GSD-style skeleton generation, and Spec-Kit-style workflows.

## The one load-bearing idea

**Take every *structural* operation away from the LLM and give it to the CLI. Leave the LLM only the prose.** Every architectural decision descends from this. The determinism boundary is a hard contract — the canonical table lives in [VISION.md](VISION.md#the-determinism-boundary) (CLI owns: which docs exist, structure, ordering, cross-references, workflow composition + placeholder resolution, placement of every write, validation results; LLM owns: the prose inside slots). "Reproducible" applies to **structure**, never to LLM prose. Do not chase reproducibility of content.

## Architectural invariants (do not violate without revising VISION.md)

- **The CLI core makes no LLM calls.** Composition is deterministic: same *resolved cascade* in → same workflow out. (The *coding agent* may use the CLI to draft a merge proposal — that is the agent acting, not the CLI.)
- **The LLM writes only through the CLI.** It hands content for a *named slot*; the CLI owns placement, cross-ref wiring, versioning, and commit. The LLM places nothing, so it can misplace nothing. *Honest boundary:* this is **adapter-enforced, not sandboxed** — frictionless `jigc` access + bootstrap *advertise+demonstrate* make the CLI the path of least resistance, but an agent that ignores the adapter can still edit files directly. The bet is on ergonomics, not prevention; see [VISION.md](VISION.md) principle #3 and [design/assistant-adapter.md](design/assistant-adapter.md).
- **Stable opaque IDs, never positions — identity changes only through one atomic CLI op.** Managed-artifact IDs (docs, sections, steps, slots, items) and work-unit IDs (tasks; planned: milestones, increments — `milestone > increment > task`) are stable under **reorder** and **ordinary retitle-without-reslug**; ordering lives in a separate ordered list. No renumbering; cross-references point at IDs and survive reorder. A doc-level **identity change** (re-slug) is allowed **only** through the atomic **`jigc rename`** op (M35) — never an untracked move — which repoints every structured referrer in lockstep, so *reference-integrity* survives even though *identity-stability* does not ([VISION.md](VISION.md) → Stable IDs; [storage.md](design/storage.md) → Identity; [write-commands.md](design/write-commands.md) → `jigc rename`).
- **Engine vs CLI vs domain pack are separate** — the canonical statement lives in [VISION.md](VISION.md) → "What it is" / "Design principles." Working implication for this repo: the engine ships **empty by invariant**; pack content + adapter profiles ride in `cli` per [implementation/module-layout.md](implementation/module-layout.md).
- **Config cascades: project > team > pack-default.** (`team` = a cross-project layer, not per-developer.) All customization is a recorded **delta** against a known base version (never an untracked fork), so upgrades re-apply deltas and report clean/conflict/orphaned.
- **Slots vs placeholders are opposites and must stay syntactically distinct.** *Slots* (`<<slot>>`) are LLM-filled on the write path. *Placeholders* (`{{…}}`) are CLI-filled on the read path (command refs, data values, includes).
- **Storage is plain, human-readable, diff-friendly files.** Humans review and edit through git regardless of the CLI; out-of-band edits are **detected and routed** — conformant non-conflicts absorbed, conflicts blocked and routed to a human, never silently merged or forbidden (see [design/reconciliation.md](design/reconciliation.md)).
- **Writes are transactional.** Integrity holds at a `finalize`/commit boundary, not on every write (else bootstrapping deadlocks).
- **Frozen-v1 doctype schemas are version-gated.** The six dev-pack doctypes (`commit`/`adr`/`spec`/`prd`/`arch-doc`/`changelog`) + the schema-definition format are **frozen v1** ([implementation/doctype-map.md](implementation/doctype-map.md) → The v1 freeze). **The v1 baseline crystallizes across the M33+M34 pair** ([DECISIONS.md](DECISIONS.md) → 2026-06-24 M33+M34 paired): M33 froze an interim shape and M34 *completes* v1 by injecting the engine `schema-version` stamp — so the five persisted hashes evolving under **version 1** during M34 is the sanctioned baseline establishment (the stamp's own v0→v1 corpus migration ships alongside it), **not** an un-versioned change. The version-gate binds **after** the v1 baseline is crystallized: from then on, no schema-*shape* change to a frozen doctype ships without bumping its manifest `schema-version` **and** shipping a versioned M34 corpus migration. The engine pack-load assertion recomputes each doctype's `schema-hash` against `crates/cli/pack/config/schema-manifest.yaml` and **blocks loudly** on an un-migrated change (the intrinsic-floor-assertion sibling, not the report-only `validate` sweep). **The gate binds at every layer that can change a schema (M49):** a project-layer whole-file shadow at `.jigc/config/schemas/<ty>.yaml` is hashed **as resolved**, so the layer that outranks every pack cannot reshape a frozen doctype either — until M49 it could, and the corpus it made non-conformant still validated clean at exit 0 while `doc schema` reported the frozen version for an unfrozen shape. The documented shadow capability survives unchanged: M47's presentation projection erases `description:`/`usage:`/slot `hint:`, so a prose reword still shadows cleanly ([design/overrides.md](design/overrides.md) → Authored metadata on a definition resolves by whole-file shadow). Originally scoped to the frozen-v1 dev set; **since M40 the methodology pack is version-gated the same way under its own `schema-manifest.yaml`** — the recorded adoption trigger fired at the RC adoption trial: ten schemas listed, the nine persisted doctypes stamp-injected at schema-version 1, the manifest resolved per-origin-pack ([design/corpus-migration.md](design/corpus-migration.md) → The freeze-exempt sibling, the M40 revision). **Location is a gated change-kind (M38):** a frozen doctype's `location`/`placement` is inside its `schema-hash`, so a *home* change is version-gated exactly like a shape change — `changelog`'s move to root `CHANGELOG.md` bumped it to **schema-version 2** and shipped a location-only corpus migration ([design/storage.md](design/storage.md) → Placement; [DECISIONS.md](DECISIONS.md) → 2026-07-04 M38 planned).
- **Concurrency is one bounded primitive only.** `fan-out`/`join` steps; each sub-agent writes to an isolated working area keyed by task ID; the CLI merges at a join ordered **by task ID, not completion order**. **The isolation is that working area plus the code worktree, never the shared `.jigc/` caches** — a worktree binds to the main checkout's `.jigc`, so all N sub-agents write one `state/file-state.json`, one `index/edges.json` and one milestone `tasks.json`; each carries its own concurrent-writer rule (base-relative merge · lock-only · atomic-but-unmerged) in [design/storage.md](design/storage.md) → Concurrent writers. No DAGs, conditionals, cross-agent messaging, or runtime. Sub-agents coordinate through the CLI (blackboard pattern), never directly — messages carry only `task_id` + status; state is always re-derived from the CLI.

## MVP scope (M1 — shipped; kept as the historical scope record)

> **Status note (2026-07-02):** this section records the *M1* scope calls and their rationale — kept because the reasoning still explains why the core loop is shaped the way it is. Several "not yet" statements below have since shipped: the **router** workflow (M2 flipped `default-workflow`), the full frozen-v1 doctype set (`commit`/`adr`/`spec`/`prd`/`arch-doc`/`changelog`), store-scope validation (M18/M20), fan-out/join (M7/M8/M31), migration (M23/M34), and `jigc rename` (M35). First loop to build end-to-end: **`single task execution`** (discover → compose → execute → validate) — the cheapest proof the core loop beats a plain `CLAUDE.md`. Scope calls (rationale in [DECISIONS.md](DECISIONS.md), 2026-05-25):

- **Spec-less.** The MVP `single-task` does **not** read a SPEC (no `task.spec`, no `spec` schema ships); the "what" comes from the human `intent` + the codebase. The composed workflow *does* embed `{{task.intent}}` (an engine-native `task` data-value root), so real data-value resolution is exercised. Adding spec support later is a trivial pack addition.
- **Front door, no router workflow yet.** `jigc start` is built in all four forms (orient · cascade-default compose · `--workflow X` · `--task <id>` — see [design/write-commands.md](design/write-commands.md) → Task origination). The **router** selection-guidance workflow is **not** built; instead the cascade knob `default-workflow` ships pointing at `single-task` directly (a `creates-task: true` work-workflow), so MVP's `jigc start "<intent>"` mints in one call. Post-MVP, when ≥2 work-workflows exist, the cascade flips `default-workflow` to a router workflow (`creates-task: false`) and the model-free selection path activates without any code change.
- **Two doc types — one transient, one persisted.** The pack ships **`commit`** (sink = the git message, transient) *and* **`adr`** (persisted to `decisions/`; engine-native fields `status`/`date` + prose slots + the optional **`supersedes`** relation, adr→adr). The agent **creates** an ADR in-task via the workflow-gated `create` flow when a decision is warranted (`single-task` ships with `allows-create: [{type: adr, as: decision}]` in its front-matter — the created ADR binds to `task.decision`; see [design/workflow-dialect.md](design/workflow-dialect.md) → On-disk definition format and [design/write-commands.md](design/write-commands.md) → The create-gate). The persisted ADR is what makes the MVP *prove its differentiators*, and the proof is **mandated by one acceptance path** — the **superseding-decision flow** ([design/worked-examples.md](design/worked-examples.md) → Superseding decision): a later task records an ADR that `supersedes` a committed one, so the loop (a) round-trips a committed, human-editable file — parsing/slicing it in-loop over the byte-stable, golden-tested splice path that **retires the #1 risk** ([implementation/parsing.md](implementation/parsing.md) owns byte-stability as a writer property), (b) detects `file ↔ CLI-state` drift + reconciles OOB edits, (c) composes a **context-slice over that persisted ADR** (`{{@task.decision.supersedes#decision}}`), and (d) walks the **edge index** for forward-ref integrity at finalize — passing when the target exists, blocking when it dangles (the **"validate against reality" integration advantage**). `supersedes` is the only logic-free handle from task state to a committed doc in a spec-less MVP, so this single path converts the differentiators from *supported* to *proven*.
- **The deliverable is `engine` + `cli` + a minimal *embedded* dev pack + the Claude Code profile** — not just the engine (which ships empty by invariant). MVP pack: the **`commit`** + **`adr`** doc-types, the **`single-task`** workflow + its steps, and the cascade pack-default config (incl. the `create`-gate entry `{type: adr, as: decision}`). **Zero *pack* probes** — the MVP checks are engine-native.
- **`finalize` is the commit boundary.** It validates, **renders the commit doc into the git commit message** (the commit type's sink is the VCS message, not a repo file), **promotes any created ADR** to `decisions/`, and `git`-commits the task's code changes + promoted docs as one commit. The CLI commits code too (the agent authors it directly; committing is the CLI's job — "CLI orchestrates, git executes").

Validation is in the MVP: the framework + the **two engine-native probes** (`workflow-refs`, `file-state`) **plus the intrinsic `finalize` integrity gate** — which the ADR + `supersedes` now genuinely exercise: **forward-ref resolution over a real edge index** (the integration advantage), required-slot presence, malformed-value rejection. Pack-provided `doc ↔ code` probes come *after* (they need real code anchors); inverse/minimum-cardinality stays advisory at store scope, never a per-task gate.

Implementation foundations live in [implementation/](implementation/) — language/runtime, parsing, module layout, [machine-setup.md](implementation/machine-setup.md) (read once per dev machine), plus [doctype-authoring.md](implementation/doctype-authoring.md) (the registration checklist a new or reshaped doctype is walked through) and [pinning.md](implementation/pinning.md) (how a verified fact stays verified: compose goldens · contract property suites · repro blocks · the trial-shaped fixture substrate).

**Trial tooling is reusable and lives outside any one trial's directory — check it before building anything for a new RC trial.** Four homes, none of them under `completions/artifacts/<trial>/`: [completions/trial-corpus-template/](completions/trial-corpus-template/) instantiates a **foreign, pre-jigc corpus** (9 TS modules · 3 test files · 24 tests · 7 commits · zero managed docs) with `instantiate.sh [--clean-prose]` and gates it with `check-corpus.sh` (7 commits · clean tree · no jigc/adapter residue **including `.git/hooks/pre-commit`** · no remote · clean reflog · suite green); [completions/trial-harness/](completions/trial-harness/) builds and verifies the **isolated container** a blind session runs in (`build-image.sh <sha>` pins the binary by commit, `verify-image.sh` runs seven checks, `verify-pair.sh` proves two images are different trees, `run-session.sh` drives one session and copies the evidence back out); [completions/workflow-eval/](completions/workflow-eval/) is the older per-workflow agent-run eval; and [completions/trial-driver/](completions/trial-driver/) **drives and scores a session without an operator** (`run.py observe` reads a finished session's §3.3 channels off its own evidence and reproduces the 1.0.0-gate table exactly; `seed`/`fork` record a conversation once and fork it N times from an identical mid-arc position; `plant` fires a plant on a *state* polled from outside the session, which is the step that voided B3a; `gate` refuses a round the isolation record does not cover; `walk.py` drives the operator walk as scripted arms so an unrun arm is **visibly blank**). Its bounds are in its own README — chiefly that a headless result is a fact about the headless channel, and that it does **not** solve mid-turn injection: `-p` has no queued-message channel at all, so the postmortem's answer (plant a state, never schedule a sentence) is unchanged. **This paragraph exists because the corpus template was committed after RC-pre-1.0 precisely so it would be reused, nothing referenced it, and the next session assumed it had been lost and planned to rebuild it.** A tool nothing points at is a tool that gets rebuilt. **The boundary between the three corpus builders, since they are one grep apart:** the trial tooling above builds **foreign, pre-jigc** corpora (zero managed docs — the state an adoption trial adopts *from*); [`dev/jigc-rig`](dev/jigc-rig) builds **adopted** ones for a shell probe; and `crates/cli/tests/support/trial_corpus.rs` is that same adopted builder for the Rust suites. A trial reaching for the rig is asking the wrong question, and a probe reaching for the template is too.

## Non-goals

Not a general-purpose workflow engine (no DAGs/conditionals/runtime), not an auto-doc-writer (detects and routes drift; never auto-authors prose), not one-size-fits-all, **no longer single-domain** (M12/M14: the methodology pack composes with dev — the engine/pack boundary is proven architecture) but **not yet a public pack platform** (a stabilized third-party pack-authoring API is future work, when an external domain earns it), not an LLM wrapper.
