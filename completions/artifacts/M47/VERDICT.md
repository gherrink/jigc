## Two plan halts, both correct, both on a false premise in the record

- **Increment 7 — `staged_docs`.** The roadmap pinned `[{id, address}]` on the **1.0-frozen** contract, but the two are the same string in every case: `staged_docs()` reads `<task_dir>/docs/*.md`, whose names are `<type>:<slug>.md`, and stripped of the extension that *is* the address `doc show` takes. The key count had never been adjudicated (Decision 11 pinned `{id, body}`; the review swapped `body` for prose reading as one fact or two). Settled to **one key**, on the sibling projection's own rule: *"both are derivable from `id`, and a contract does not carry the same fact twice."* On a frozen contract the asymmetry is decisive — adding a key later is additive, removing one is breaking. The same halt caught a rider that would have shipped a **pre-commit hook that silently never fires on macOS**: the specified pattern used `\s`, a GNU extension BSD `grep -E` does not honour, and the hook's own acceptance would have used the same pattern.
- **Increment 11 — the one-shot clause.** *"An already-staged doc rejects a second create"* is false — a second `create` acks `(already existed — copied in for update)`. It stood on 14 sites in both packs. Increment 10's T7 carried it as an **unchanged context line in its own diff**. Settled in scope and landed **before** the golden regeneration, per the wave's own ordering rule.
