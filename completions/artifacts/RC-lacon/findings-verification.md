# Part A — the migration half

## A1 — Task-id truncation unpredictable — **CONFIRMED** (deterministic rule, zero user-facing documentation, no non-id selector) (High-friction)

The rule (slug-rule-version 2, M42): `renormalize` (case-fold, transliterate, map ` `/`_`/`/`/`.`→`-`, strip, collapse) → **cap at the first 5 words** (`MAX_WORDS`, `crates/engine/src/slug.rs:72`) → 50-char backstop with word-boundary retreat (`MAX_CHARS`, `slug.rs:82`) → drop edge stopwords `a/an/the/of/to/in/on/at/by/for` (`slug.rs:91`). Both trial examples reproduce arithmetically (`0004: Project > User > Bundled config precedence` = 6 words → drops `precedence`; `link-specs-to-v1-scope-prd` = 6 → drops `prd`). **Live repro sharpened it:** `jigc migrate docs/decisions/use-sqlite-storage.md --as adr` minted `migrate-adr-docs-decisions-use` — the migration id is `migrate-<doctype>-<path-slug>` (`start.rs:200-209`) and the fixed prefix consumes 2 of the 5 words, so the path's discriminating stem is what gets cut; a self-constructed `migrate-adr-use-sqlite-storage` got "no task" — the tester's exact failure, including the ordering-mishap precondition (A7). Mitigations present: `task minted: <id>` opens every work-minting compose (M42, `render.rs:171-186`); `--slug` overrides at mint (A2). **Discoverability: the rule appears on no user-facing surface** — grep of CLI help strings, `QUICKSTART.md`, `MIGRATING.md`, and the AGENT.md bootstrap finds nothing; it lives only in `design/storage.md` and `slug.rs` rustdoc. **No verb accepts a non-id selector** — every task verb takes the verbatim id (`task.rs:70-113`). Papercut found en route: the wrong-id routes diverge — `doc author` routes to `jigc task list`, `task finalize` routes to `jigc start "<intent>"` (the wrong repair for a typo). *Tracked:* [ideas/slug-minting-ergonomics.md](../../../ideas/slug-minting-ergonomics.md); the migrate-prefix word-cap compounding is **new**.

## A2 — "migrate/author have no `--slug`; only post-hoc `rename --slug`" — **PARTIAL: true on the path the tester drove; false as a general claim** (Medium)

**Refuted half:** mint-time `--slug` exists on `jigc start` (`cli.rs:91-97`) and `jigc doc create` (`doc.rs:52-58`) — both M39 — plus `jigc rename --slug` (M35, `cli.rs:233-235`). **Confirmed half:** the migration flow can reach none of them. `jigc migrate` takes only `<path> --as <doctype>` (`cli.rs:175-185`); its mint passes `slug_override: None` (`start.rs:181`). The workflow's prescribed write verb is `doc author`, which has no `--slug` flag (`doc.rs:173-183`) and no payload key (`AuthorPayload` = `title` + `sections` only, `author.rs:57-70`); the templates state "the CLI creates the record at `decisions/<title-slug>`" — the title is the only identity lever surfaced. So for onboarding a repo with cross-referenced filenames, identity preservation genuinely requires post-hoc `rename` (which the tester did ~40 times). *Fix-shaped:* `--slug` on `jigc migrate` (threaded to the doc mint, not the task mint) or a `slug:` payload key on `author`. **New** as a concrete gap.

## A4 — Finalize contract revealed in stages (same-path: clobber → `git rm` → then `--approve`) — **CONFIRMED** (Medium-High on the onboarding path)

The M42 staging contract *is* in the composed output, but the review gate and clobber/retire behavior are not. Two design facts bound the fix: (a) in the *ordinary* off-path case the first finalize's exit-4 message does name the exact command and the retire (`render.rs:1727-1732`), so the gap is same-path-specific; (b) the same-path block is a **declared bound** — `plan_clobber_guard` excludes the in-place rewrite only for **singleton** doctypes (`finalize.rs:357-366`; `auto-migration.md` "bounded to off-canonical foreign paths"), so "ideally `--approve` retires the same-path original itself" is a deliberate-bound revision, not a bug fix. # Part B — the four task sessions

## Routing / start

### B1 — `start "<intent>"` prints a menu, does no routing — **CONFIRMED; the "promise" is real but lives in orientation output, not AGENT.md** (Medium)

Live repro: `jigc start "<decision-shaped intent>"` prints exactly **10** selectable work-workflows and "Pick the workflow whose situation best fits the intent, then re-run with that choice" — the intent string is not consulted. Mechanics: the dev pack's `default-workflow` knob is `router` (`crates/cli/pack/config/knobs.yaml:20-23`); `router.yaml` is `creates-task: false`, composing `present-catalog` + `route-to-workflow`. **Attribution correction:** AGENT.md never says "routes among the workflows" — the wording is bare-`start` orientation's footer: ``Run: `jigc start "<intent>"`   — routes among the workflows above; pick one, then re-run with `--workflow <chosen>` `` (`crates/cli/src/render.rs:111`). The same line says "pick one," so it half-corrects itself, but "routes" as the verb for a step where the CLI does zero selection work oversells — the design's answer is that the *agent* is the router (CLI-makes-no-LLM-calls invariant); an intent-keyword heuristic in the CLI would be a design change. *Tracked:* [ideas/spec-router-matching.md](../../../ideas/spec-router-matching.md) is the buildable residue (surface, don't match).

### B2 — quick-fix composed zero doc context — **CONFIRMED, by design; the framing tension is real** (Medium as onboarding)

`quick-fix.yaml` = `locate` + `implement-quick` + `finalize`, `allows-create: []`; `locate.yaml` embeds only `{{ task.intent }}`; no `{{ @… }}` context slice anywhere in the closure. By design: the workflow's own `usage:` declares "needs nothing preserved beyond the commit itself." The tension is real: `BOOTSTRAP_FRAMING` promises "assembles exactly the workflow steps and doc slices your task needs" — for quick-fix that is vacuously zero slices, which a first-time agent reads as a broken promise. *Fix-shaped:* scope the promise per-tier, or have quick-fix pull the handover/deferral slice.

## Statefulness / resumability

### B3 — `--task <id>` required on every write verb — **REFUTED** (behavior); the default is undiscoverable in flow (papercut)

`--task` is **optional** on every doc write verb: explicit wins; else the single active task; else the write rejects (`crates/cli/src/doc.rs:59-62`; resolution at `doc.rs:2833-2852`). Live: with one active task, `set-field` and `set-slot` both succeeded **without** `--task` and landed in the task working area. With two active tasks: `more than one active task — name one with --task <id>: another-fix, fix-a-flaky-test` — a precise, copyable rejection. Shipped 2026-06-04 (`70611e4`). The kernel of truth: every composed `Run:` line prints `--task <id>` explicitly, so the flow models it as mandatory and the tester never tried omitting it — a discoverability gap, not a missing feature. *Tracked:* [ideas/sticky-task-context.md](../../../ideas/sticky-task-context.md).

### B4 — No way to re-derive "what does finalize still need" / current phase — **PARTIAL: two real affordances missed; the phase-cursor gap is real** (Medium)

Confirmed absent: `task show` / `task status` / `task next` / top-level `status` don't exist (`jigc task --help` lists exactly `list · diff · validate · discard · finalize · bind`); `task list` shows only id + minting workflow + intent. **What the testers missed:** (a) `jigc start --task <id>` "resumes an existing task and re-composes it" (top-level help, live-verified — re-prints the full runbook; this directly answers Task-3's "start re-routes; it doesn't resume" — that claim is **wrong**: bare `start` re-routes, `start --task <id>` resumes); (b) `jigc task validate <id>` re-derives precisely "what finalize still needs" — live on a fresh task it printed the empty-enum + empty-required-slot findings, exit 3. What genuinely doesn't exist: a "you are here" step cursor and any surface *naming* those two verbs as the resume path. *Tracked:* [ideas/state-aware-compose.md](../../../ideas/state-aware-compose.md).

### B5 — Full runbook at t=0, no staged reveal — **CONFIRMED, by declared design; staged reveal is architecturally barred as asked** (design tension, not a defect)

Live: minting quick-fix/dev-task/planning dumps the entire lifecycle including the finalize recipe. By declared invariant the composer is a pure substitution engine — "the binary grows no loop, no progress cursor, no runtime" (`design/workflow-dialect.md:74`); conditional step inclusion is explicitly barred as control flow. The one sanctioned halt mechanism exists and fires: planning composes a structural `Checkpoint: settle` directive mid-body (live-verified) — a phase separator the Task-4 feedback didn't credit; `dev-task` composes no checkpoint, so its runbook is one unbroken block, as reported. A true staged reveal is a design revision, not a fix. *Tracked:* [ideas/state-aware-compose.md](../../../ideas/state-aware-compose.md).

## Read surface

### B6 — No command lists a doc instance's writable addresses — **PARTIAL: the address-listing gap is real; the "raw JSON + Python walker" fallback is obsolete on rc.6** (Medium)

Tested on a real committed roadmap with a repeatable milestone item (the trial's exact truncation reproduced: title "Tier 2 post-v1 rule expansion" → id `tier-2-post-v1-rule`). Three findings: (a) `jigc doc schema roadmap` is **type-level only** — it shows `milestones: repeatable` with each field's owning section, but no instance item ids and no address grammar (nothing states the `#section/<item-id>/<slot>` form). (b) Instance item ids are now **first-class on the read surface**: `doc show roadmap --format json` carries `"id"` inside each item object (M42), and the plain render keeps the `{#…}` anchor — so schema (leaf names) + show (ids) answers the question in two reads, no walker needed; also `add-item` echoes the minted full address at mint. (c) The guessed verbs don't exist (live: `doc slots` → unrecognized subcommand; `doc show --slots` → unexpected argument), and **no** command prints assembled settable addresses one per line — the composition of (a)+(b) into addresses is left to the agent, with the grammar documented only in `doc author --help`/`set-field --help`. *Fix-shaped residual:* an `--addresses` one-per-line projection; plus point the workflow text at `doc schema`.

### B7 — `doc show` reads committed only; `--task` rejected with a misleading tip — **CONFIRMED** (Low-Medium; the bound itself is declared design)

Live rejection, verbatim: `error: unexpected argument '--task' found` / `tip: to pass '--task' as a value, use '-- --task'` — clap's generic tip, actively misleading (implies a positional was intended; teaches nothing about `task diff`). The committed-only bound is declared and documented — `doc show --help` itself says "Reads the committed store — it takes **no** `--task` … read it with `jigc task diff <id>` instead" — but that teaching lives only in help, not at the rejection or as a staged-edits hint on a successful stale read. `task diff <id>` covers the **whole changeset** (no single-address filter), so the "proof one slot" ask has no surface. *Note:* the rc.5 verification adjudicated the committed-only bound by-design (R7) — **three consecutive trials have now demanded a staged read; the record is rebuttable.**

### B8 — `jigc doc --help` verb descriptions are walls — **CONFIRMED** (Low)

Live sample (show): one paragraph, six clauses, an internal design-doc path, ending in the task-diff pointer; `author`'s summary alone is a 10-line block. Root cause is structural: M41/M42 deliberately moved contract detail *into* long help, and clap prints the full first paragraph in the subcommand table. The "lead with the one-line common case" fix is real and cheap. **New.**

## Advisories / gates

### B9 — "no action needed" advisories + a managed path named — **CONFIRMED; the no-op route is a recorded design decision, and the noise concern lands on a deferred item** (Medium as UX)

Reproduced verbatim at finalize. Exactly **five** finding codes ship informational "no action needed" routes: `file-state.baseline-adopt` (`crates/engine/src/file_state.rs:976`), `file-state.un-baselined` (`:682`), `reconciliation.absorb` (`:895`), `doc-code.symlink-anchor`, `doc-code.unsupported-language`. ### B10 — changelog gate fires on docs-only changes — **CONFIRMED, by design, decided four days ago** (works-as-decided; a legitimate revision candidate)

`changelog_gate_advisory` (`crates/cli/src/task.rs:1284-1355`) keys on exactly two facts: the minting workflow grants the `changelog` create-gate and no entry was authored. `#type` is never consulted — deliberately: "whether a change is 'user-facing' is judgment … any gate keys on *gate-granted-and-unused*, never on the CLI adjudicating the diff" (doc comment `:1265-1271`; M42 Settle fork 6, settled 2026-07-13). The route even ends "if it is not user-facing, no action is needed." One honest wrinkle: suppressing on `#type == docs` would read a *field value*, not adjudicate a diff — deterministic, so the boundary argument doesn't strictly bar it; it would however hard-code "docs commits are never user-facing" as CLI policy. A revision engages the fork-6 record, not sidesteps it.

### B11 — Commit-field vocabulary invisible; `refactor` accepted silently — **PARTIAL, mostly REFUTED** (papercut remains)

## Workflow gaps

### B12 — A decision task had no home for the decision — **CONFIRMED for what was surfaced; sharpened: the remedy exists in the pack but is hidden behind a stale flag** (High — the trial's strongest new finding)

All three tester facts verify: methodology `dev-task` has **no** `allows-create` and no decision step; AGENT.md forbids direct managed-doc writes; the menu's only decision-axis text is quick-fix's "records no decision" — a contrast that implies the others do. But the pack **already ships the exact missing workflow**: `decided-task` (scope → implement → gate → **author-decision** → finalize; `allows-create: [{type: decisions-log, as: log}]`; `packs/methodology/workflows/decided-task.yaml`), built 2026-06-13 (`fc1ba3b`) *precisely for this case*, present in the rc.6 binary, live-verified working via `jigc start --workflow decided-task`. It is `selectable: false`, so it appears on **no** surface an agent sees — and the recorded rationale for hiding it was "holds the single-default catalog invariant **until the router-flip is built**."
