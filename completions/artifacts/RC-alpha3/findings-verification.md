# Findings verification — project-alpha-3.0 trial claims vs the rc.8 code (2026-07-22)

**Method:** every claim in [feedback-verbatim.md](feedback-verbatim.md) was adversarially verified against the rc.8 code (HEAD `1ea2ed8`) by four cluster verifiers — write-path/atomicity · finalize/state/output-contract · workflow/composed-surface · anchors/concurrency — each reading the mechanism to file:line and, where practical, **reproducing live** with the installed rc.8 binary in throwaway repos (never the real corpora), plus a fifth historian pass classifying every finding against the full findings history (RC-greenfield · RC-adoption + rerun-rc4 + impl-rc5 + rerun-rc7 · RC-lacon · M39–M44 VERDICTs · DECISIONS.md · decisions-pending.md · all 43 idea files). Verdicts: **CONFIRMED** (mechanism located, repro where run) / **REFUTED** (with evidence) / **PLAUSIBLE** (unverified residue). Classes: **A** regression · **B** incomplete fix (same class, un-swept sibling) · **C** known-deferred (trigger status noted) · **D** known-by-design/previously-refuted · **E** new (with new-environment attribution).

**Bottom line:** ~44 distinct findings (deduped across the 9 sessions). **A: 0** — all three suspected regressions dissolved under verification. **B: ~19** — the dominant class and the real recurrence signature. **C: ~10** — four with triggers that have now fired 3–4 times uncounted. **D: 4** re-reports of declared bounds (each a signal the bound needs *printing*, not just recording). **E: ~11**, of which the three strongest are new-environment — surfaces this trial was the first to *exercise* (active hooks emitting on success · `vendor/` under worktrees · Pest `maps-to-test` · the live fan-out; the corpus itself is a fresh renamed copy of project-alpha-2.0, which always had these properties — prior trials never drove these paths).

## 1. The v1-gating tier (all CONFIRMED, live-reproduced)

### 1.1 Item-slot writes bypass the heading guard entirely — the original corruption bug, open on its original path (Bug A) — **B**, HIGH

The trial's model ("the guard stops at `###`, `####` is missed") is wrong in an important way — the split is **by write path, not by depth**:

- `slot_ceiling_finding` (`crates/engine/src/write.rs:5800-5829`, consts at `:5773-5775`) rejects H2/H3 + Setext — but it is invoked **only** on the section-slot path (`set_slot_validated`, `write.rs:5712-5722`).
- The item-slot path (`apply_slot_target`, `crates/cli/src/doc.rs:826-843` → `set_item_slot`/`set_nested_item_slot`, `write.rs:1426-1504`) has **no ceiling check and no validate-after** — it re-renders and splices unconditionally. Live-verified: `##`, `###`, **and** `####` all write through into a roadmap item slot with `findings: []` exit 0; the doc is then `store.unparseable`; a valid plain-prose retry rejects `write.non-reparseable`; only `task discard` (or hand-editing the staged file) recovers.
- The parser has owned the precise diagnosis since M16: `conformance.item-slot-delimiter-shadowed` (`parse.rs:1090-1146`) names the offending line and says "use `#####`+".
- **Recurrence chain:** the guard shipped at M1 (`81c5d9b`) when ##/### were the only structural depths → **M16** made `####` structural in multi-slot items (`ddd8eb5`) but fenced only the read-time site (`implementation/parsing.md` → "Slot heading-depth ceiling" declares *two* enforcement sites; site 1 was never extended) → **M43** then seam-generated the "headings must sit at `####` or deeper" statement from the same global constants (`b0c8bcf`) and renders it inside the planning workflow — **actively instructing the corrupting depth** exactly where the primary writes are roadmap item slots. The fence propagates the lie consistently: it proves surface==constant, not constant==truth.
- **Fix shape (two layers, both derived):** (a) validate-after (re-parse) on the item-slot write paths exactly as `set_slot_validated` does — the shadow guard's finding becomes an atomic reject with the precise message; (b) the ceiling scan extended to the item path with the reserved set **derived from the write context/schema** (multi-slot item → `####` reserved), and the stated floor parameterized per render context — one shared schema-parameterized source for statement *and* enforcement. The trial's own proposed fix ("widen the guard to ####") is insufficient — the item path bypasses the guard at every depth.

### 1.2 Commit trailers silently dropped — the feature is dead on the entire real write path — **E** (latent since the schema-driven sink), HIGH, law-1

Live repro ×2 (clean-room): `add-item commit:<t>#trailers --title Co-Authored-By` → ok (minted `co-authored` — the M41 edge-stopword drop eats "by", itself a small trap) → `set-field …/value` → ok → validate clean → finalize exit 0 → `git log --format='%B'`: **no trailer**. Mechanism: `trailers` declares `id-from: key` (`crates/cli/pack/schemas/commit.yaml:25-30`), so the writer renders `key` as the item **heading** and the parser symmetrically excludes it from item fields (`parse.rs:1195-1199`); at finalize, `instance_from_source` (`write.rs:2464-2512`) rebuilds items with no `key` field, and `trailer_lines` (`write.rs:2429-2442`) does `item_field(item,"key")?` → `None` → `filter_map` **silently drops every trailer**. No CLI write sequence can produce a trailer in the message. The unit/golden tests pass because they hand-construct instances with explicit `key` fields (`write.rs:9616-9626`) — and `write.rs:8727-8730` records commit as **exempt from the on-disk round-trip fixture suite**, which is exactly the hole. Aggravator: `crates/cli/pack/steps/implement.yaml:24-25` teaches the failing recipe. **Fix shape:** `trailer_lines` takes the key from the item title (id-from semantics: the heading *is* the key), falls back to a `key` field; **commit joins the round-trip suite** with one finalize-path test authoring a trailer through the write verbs.

### 1.3 Dangling file-state entries block every task and survive `git reset --hard` (Bug C) — **B**, HIGH — with the trial's attribution corrected

Live repro: `milestone create` writes+commits the record, then baselines its hash into gitignored `.jigc/state/file-state.json` (`milestone.rs:317-352`, `:426-435`); `git reset --hard` to pre-milestone → file and commit gone, cache entry survives → **every** fresh task blocks on `reconciliation.rename` (weak-signal constructor, `file_state.rs:863-874`), exit 3, until `jigc unmanage` (which the route does name). **Correction:** the trial blamed a discarded/abandoned task — false; a plain task writes no file-state entries before finalize, `run_discard` has nothing to roll back, and no writer is un-paired from a commit — the "writes are transactional" invariant holds in the letter. The actual trigger was the trial's own **git-level history discard** of a commit whose baseline had been recorded. **The real defect:** the gitignored cache's lifetime is decoupled from git history and reconciliation treats the cache as **authoritative over the record** — contradicting the M39 principle (".jigc is a rebuildable cache; the repo is the record"). Blast radius: `advance_file_state` (`task.rs:2237-2271`) records *every* committed file, so any jigc-landed commit later removed by reset/rebase orphans entries. Historian note: same disease as impl-rc5's M4 ("abandoned work leaves lying state that gates future work"), fixed at M42 for the *record* half; the cache half is the un-swept sibling. **Fix shape:** at the reconciliation sweep, a tracked path with no committed file **and** no reachable history downgrades to an advisory with a prune route (or auto-prunes under the rebuildable-cache principle).

## 4. Recurrence diagnosis — why the repeats happen

1. **Fixes scoped to the reported repro; the class boundary is a shape/path axis the fix never sweeps.** The guard covers the original flat-repro's depths while the parser knows `####` is structural in item contexts; the Pest hint fixed prompting for named-symbol languages; ref-edge steps fixed per-field twice, never generalized; the staging contract stated for single-task, not fan-out. M41's audit named this failure ("the un-enumerated sibling… committed in the fix for it") — still the top producer: **seven of this trial's B items are one un-swept axis each.**
2. **Cross-surface contracts verified once, held by nothing.** Address grammar (live-verified rc.5), exit codes (M42), JSON purity (M41) — each observed, never pinned; later waves moved them silently. The commit round-trip exemption is the same hole in fixture form (→ §1.2 lived undetected under 2195/0).
3. **Wave verification replays create-fresh fixtures, not trial-shaped corpus state.** §1.5 exists only on a migrated/committed/edited-from-base path; rc.5's placement false-green was the same lesson one wave earlier.
4. **Fences inherit their constants' blind spots.** Seam generation makes surface-vs-constant drift unrepresentable — and guarantees a context-dependent constant lies *consistently everywhere* (§1.1, the heading floor). Context-dependent rules need the context as a fence input (derive from schema, not consts).
5. **Condition-keyed deferrals accumulate demands nobody counts.** Milestone-keyed deferrals get actioned; condition-keyed ones pile up "trigger-adjacent evidence" with the count restarting in each reader's head — four deferrals at 3–4 demands each (table above). The M42 principle covers code-fact triggers ("should be a test"); *Nth-field-demand* triggers are countable too and nothing counts them.
