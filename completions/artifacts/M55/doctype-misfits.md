# Doctype misfits — the standing register

**What this file is.** The one standing register of what did not fit when this repository's own documents were shaped into jigc's doctypes. The rule it serves is the human's of 2026-10-29: a document this repository writes takes the shape of the jigc doctype that will hold it after the port, written and checked with jigc itself, and every place the shape does not fit is logged here rather than bent by hand ([working-principles.md](../../../implementation/working-principles.md)). The register is not tied to one document: every later piece of document work adds its rows here.

**A row is a finding for the port's triage, never a requirement.** It records what jigc could not say, refused or made awkward, with the command that showed it. Whether jigc changes, the document changes, or the misfit is accepted is decided at the port's triage ([roadmap.md](../../../implementation/roadmap.md) → M56), and the port is a discovery mechanism, never a requirements source.

**How a row reaches the port.** Each row is a seed source of the [seed ledger](seed-ledger.md), under the tag `misfits`: it is re-driven, written as a filing input under `seed-filing/input/jigc-feedback/doctype-misfit-m<n>/`, and filed through the real binary as one `jigc-feedback` doc under `seed/jigc-feedback/`, which its disposition links. New rows are filed in a fan-out of their own, so the docs already filed stay byte for byte. `tooling-tests/seed_ledger.rs` holds each row to exactly one ledger row and to its seed doc.

Columns: **id** (`M<n>`, never reused) · **what** · **evidence** (the document work that met it, and what was driven) · **disposition**.

## The register

| id | what | evidence | disposition |
|---|---|---|---|
| M1 | **A roadmap entry has no place for a step's question, estimate or safe break.** The `roadmap` entry is a title, a `proves` slot and a `decomposition` slot. | M2 | **No doctype holds a builder-level task spec.** A plan's per-task spec — what each task writes, its red-first arms, its done-when, its gates — has no doctype, so it stays a plain record beside the managed roadmap entry, and the table that maps the entry's steps to the spec's tasks is held by hand. | The pre-opening plan's `detail.md`, 2026-10-29: the methodology pack's thirteen schemas read; none takes it. | Open — for the port's triage. Seeded as [jigc-feedback/no-doctype-holds-a-builder.md](seed/jigc-feedback/no-doctype-holds-a-builder.md). |
| M3 | **A roadmap decomposition is one level, and this plan is two.** The plan is steps with tasks under them; the `decomposition` slot holds one level of prose. The recorded trigger for the roadmap's increment tier asks for a second driver that is not this repository's own planning convenience, so this row alone does not fire it. | The pre-opening plan's roadmap entry, 2026-10-29; the trigger at `design/methodology-docs.md` → *The one-level bound (roadmap)*. | Open — for the port's triage; does not fire the increment-tier trigger. | M4 | **A milestone record cannot say a task has not started, or waits for the human.** The task `status` is `active`, `joined` or `discarded`, and `jigc milestone add-task` writes `active` the moment a task is added, so a planned task reads as in progress. An empty value is refused; leaving the leaf out validates clean but is never what the door writes. | The pre-opening plan's `progress.md`, 2026-10-29: 86 `add-task` calls, each task `active`; an empty `status:` refused `schema-conformance.field-value-conformant`; the leaf left out, `jigc validate` reports no conformance finding. | Open — for the port's triage. Seeded as [jigc-feedback/milestone-record-cannot-say.md](seed/jigc-feedback/milestone-record-cannot-say.md). |
| M5 | **A milestone record's workflow can only name a pack workflow.** `jigc milestone add-task --workflow` must name a workflow the loaded packs provide, so who runs a task in this repository — a builder, a main-session edit, a git step, a review, a question to the human — cannot be recorded through the door; written by hand, the same values validate clean. | The pre-opening plan's `progress.md`, 2026-10-29: `add-task … --workflow builder` refused `workflow-refs.unknown-workflow`, nothing minted. | Open — for the port's triage. Seeded as [jigc-feedback/milestone-records-workflow-can.md](seed/jigc-feedback/milestone-records-workflow-can.md). |
| M6 | **A sub-task's id is cut from its intent.** The id is the first few words of the intent, slugged; a plan's own task code becomes the id only when the intent opens with it. The milestone's id and a roadmap entry's id are cut the same way, and lose a title's last words. | The pre-opening plan's `progress.md`, 2026-10-29: `D0 — write down the rulings, …` minted `d0-write-down-the-rulings`; the title *Before the first stabilization run opens* minted `before-the-first-stabilization-run`. | Open — for the port's triage.
