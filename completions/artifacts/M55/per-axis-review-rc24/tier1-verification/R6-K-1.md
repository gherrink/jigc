# (R6, K-1) — independent verification

Subject: *the M55 create-only gate (`new: true`) is check-then-use; a home that becomes occupied in the
window is copied in at exit 0 and the occupant's bytes are lost at `task finalize`.*

Binary: `~/.local/bin/jigc`, `jigc --version` → `jigc 1.0.0-rc.24` (asserted first). Release posture.
Rigs: two `dev/jigc-rig fresh --binary ~/.local/bin/jigc` roots (v1, v2), two-step eval, stdout only,
`[ -n "$REPO" ]` guard, no teardown. Nothing in the working repository was edited or committed.
`CLAUDECODE` was set unless a cell says otherwise.

## Verdict in one paragraph

**The finding reproduces, both halves, and the bytes are unrecoverable. It is not a tier-1 row of its
own.** The gate half is M55's (`doc.rs:title_pre_check` rank 0 probes, `state::create` re-probes ~1 ms
later and copies in). The **loss half is not the gate's**: it is the pre-M55 rule that an *on-disk*
file at a home is treated as *committed* (`state::create` step 4 — copy-in, provenance
`edited-from-base`, which switches `finalize.promote-clobber` off). That same exit-0 loss is reachable
**with no race at all** under every `allows-create` entry that does not carry `new: true`, and the
committing door has its **own** check-then-use window against the same kind of writer that is ~26×
wider than K-1's and predates M55 (driven below, 13 losses in 80). K-1 is therefore the narrowest
member of a standing class, reached only when a non-jigc writer lands a **schema-conformant,
same-slug, untracked** file inside ≈1 ms. My tier: **3 for the gate's contract sentence, 2 where the
breached task parks; tier 1 only on a reading of the predicate that admits a genuine concurrent
non-jigc process as the racer — and on that reading the tier-1 row is the class at `task finalize`,
not this one.**

## 2 · The two halves

**Exit 0.** `doc create` 0, every step line 0, `task validate` 0, `task finalize` 0. No finding,
warning or route names a loss in either format: the only findings are `file-state.staged-copy` and
`file-state.baseline-adopt`, both advisory, both *"no action needed"*. `displaced: []`.

What the surfaces *do* say, exactly:

- `doc create`, text: `inconsistency:race-two (already existed — copied in for update)`; JSON:
  `"existed": true`. So at this door the copy-in **is named in the ack** (as an ack, not a finding).
  A fresh mint prints the bare address / `"existed": false`.
- `doc author`: the breach's ack is **byte-identical to a fresh mint's** in both formats (text: the bare
  address; JSON has no `existed` key, `"copied_in": false`), and the payload's slots are already written
  over the victim's body inside the same call (staged copy: victim marker 0, payload marker 1). This is
  the silent door. It is also standing behaviour: `doc author` over a *committed* doc on `park-idea`
  acks the same way.

**Loss.** Before-control found the marker in two places (the home and the task's staged copy). After
`task finalize`, searched and absent in every one of:

| place | probe | result |
|---|---|---|
| worktree + `.jigc/` + `.git/` | `command grep -rl RACE-VICTIM-MARKER .` in `$REPO` (control: the same grep finds `SEED-MARKER` and `REPORTER-MARKER`) | nothing, exit 1 |
| index | `git status --short` empty; `git ls-files --stage` holds only jigc's blob | absent |
| HEAD and every ref | `git for-each-ref` → one ref, `refs/heads/main`; `git log --all --oneline -S…` | 0 |
| reflog | `git log -g --all --oneline -S…` | 0 |
| object database | every blob of `git cat-file --batch-all-objects` grepped (control: finds the `SEED-MARKER` blob) | none |
| unreachable objects | `git fsck --unreachable --lost-found` | empty |
| stash | `git stash list` | empty |
| jigc's kept-bytes areas | `.jigc/displaced/` does not exist; the task area was removed at finalize | absent |
| the rig root outside the repo | `command grep -rl … "$RIG"` | nothing |

The toggler's park directory is empty (the file was at the home when it stopped). Nothing a user could
recover from. The same was driven end to end at `doc author` → `task finalize` (which the record did
not drive past the create): exit 0, `RACE3-VICTIM-MARKER` 1 → 0, same absences.

**What exactly is lost:** the slots the reporter then writes. Copy-in carries the victim's whole body
into the staged copy; `set-slot #description` (or the `author` payload) replaces the addressed slot;
finalize copies the staged file over the untracked home.

So the loss needs, all at once: a writer **outside jigc** that does not move `HEAD`; a file that is
**schema-conformant for the same doctype**; the **same slug**; **untracked and unstaged**; landing in
the window; and left unedited until finalize.

### The window, measured

One-shot plant: spawn `jigc doc create …`, busy-wait a uniformly random delay, `os.rename` the victim
into the home, classify. `doc create` takes ≈23–24 ms wall here; the check and the use sit at its end.

```text
coarse   N=80,  delay 0–40 ms    → 48 refused · 1 breach · 31 fresh ; transition at ≈23–25 ms after spawn
fine     N=500, delay 18–30 ms   → 213 refused · 41 breach · 246 fresh
         edges pure: delay < 20 ms → 85/85 refused ; delay > 28.5 ms → 60/60 fresh
         window = 12 ms × 41/500 = 0.98 ms   (≈0.7–1.3 ms at 95 %)
aimed    N=40,  delay 22.3–24.3 ms, --slug, human env → 32 breach (≈1.6 ms by the same arithmetic)
```

**≈1 ms** on this host (APFS, release build). The record's *"sub-millisecond"* is slightly low; the
toggler's 19/60 could not measure it (its period is far below the window, so it only shows
p(absent at check) × p(present at use)).

### Is this M55 code at all?

Split, and the split is the answer:

- **The gate (the breach)** is M55's: `e9f7f081`, 2026-10-03 (git blame, a read).
- **The copy-in of an on-disk file as if committed** is `state::create` step 4,
  `committed.is_file()` — `f6a9340a` 2026-06-09 (M16, singleton-gated), made doctype-blind at M43 —
  and **the clobber guard's exemption of `edited-from-base`** is `e1cbe581` 2026-06-17 (M25). Both
  predate M55. Its doc comment says the copy came *"from the committed store"*; the predicate it keys
  on is *a file exists*.
- **The non-`new: true` path has no window because it has no gate**: the same file is copied in every
  time (row above). M55 narrowed a standing exposure on two workflows from *always* to *≈1 ms*.

## 4 · Declared?

**No sentence declares a race bound for the create gate.** What the surfaces state is a universal:

- `design/findings-channel.md` §4: *"the create-gate refuses it **before copy-in**, so nothing is
  staged … so a task whose entry carries `new: true` cannot overwrite an existing doc by either path."*
- `design/write-commands.md` → The create-gate: *"the create is refused **before anything is copied
  in**, so nothing is staged and no role is bound."*
- `jigc doc create --help` / `jigc doc author --help`: *"Under a create-gate entry carrying `new: true`
  there is no create-or-update … refused before anything is copied in (`create.already-exists`)."*
- the step text: *"This task files exactly one NEW record."*

Neighbouring declarations that do **not** cover it:

- `design/worked-examples.md` (flow 52/53 bounds): *"The arms are headless by construction: no genuine
  concurrent process races a restore population. The racer is the design's named one — an
  in-transaction `pre-commit` hook."* — a bound on the **rollback populations**, and the only place the
  design says how the *no byte dies* claim was driven with respect to concurrency.
- `design/storage.md` → Concurrent writers: *"A lost baseline therefore does not degrade the guarantee,
  it switches it off — silently, at exit 0, with both sides' bytes merged into one commit."* — the
  neighbouring, milder cost (a merge), which is `(R3, F7)`'s declaration.
- Create-or-update is declared over a **committed** doc (`findings-channel.md` §4 *"where a committed
  doc already carries X's slug"*; `command-output-contract.md` defines `existed: true` as a committed
  doc at the home). Over a committed doc nothing is lost — git holds the bytes. **No sentence declares
  the copy-in of an untracked file**, which is the half that loses.

## 5 · Tier

**For tier 1.** Both halves are shown and re-shown here: exit 0 at every door including the
committing one, bytes absent from every place listed in §2, no finding names it. The contract is a
universal with no stated bound. Inside the window both guards are off at once — the gate has passed
and the copy-in flips provenance to `edited-from-base`, which is exactly what disarms
`finalize.promote-clobber`. At `doc author` the ack is indistinguishable from a fresh mint. Aimed, it
is not flaky: 32 of 40.

**Against.** (1) The loss is not produced by the gate. The identical exit-0 loss is reachable
sequentially under every entry without the key (32 of the 34 the scope counts), and the record files
that as an observation (O-2), not a finding; a `new: true` breach makes the product behave, for 1 ms,
the way it otherwise always behaves. (2) The only writer that reaches it is outside jigc, must not
move `HEAD`, and must drop a schema-conformant doc of the same type and slug — a free-form note
dead-ends at exit 3 with its bytes intact; a second reporter is refused at exit 3. (3) Miss the window
on either side and a guard answers (`create.already-exists` before, `finalize.promote-clobber` after).
(4) The committing door's own guard has the same shape with a ≈26 ms window, for any file and any
workflow, since M25 (§7) — so a predicate that admits this racer finds its tier-1 row there, on every
candidate the four zero-tier-1 re-reviews passed. (5) At `doc create` the ack says *already existed —
copied in for update* in both formats.

**Where I land: not tier 1 as a row.** Tier 3 for what K-1 itself is — three surfaces state a
universal the binary honours only sequentially — and tier 2 for where it leaves a task in the
jigc-vs-jigc and non-conformant variants (parked, routed at `task discard --force`). The exit-0 loss
is real, and I would not call it negligible on the predicate's letter; but it belongs to the class
*an untracked file at a home is treated as committed, and no door is atomic against a non-jigc
writer*, which is older than M55, wider elsewhere, and should be ruled on **once, as a class**. If the
human rules that a genuine concurrent non-jigc writer is inside the predicate, there is a tier-1 row —
at `task finalize` and at the untracked copy-in — and K-1 is its narrowest member. If not, K-1 is 2/3.
Either way K-1 does not decide the call by itself, and a fix aimed at the gate alone would not remove
the loss.

## 6 · How a real adopter reaches it

Something other than jigc has to create `docs/inconsistencies/<slug>.md` (or
`docs/jigc-feedback/<slug>.md`) — conformant, same slug, untracked — during the last millisecond of a
23 ms `doc create`. Candidates: `git stash pop` / `git checkout <ref> -- <path>` / `git restore
--source` of a finding with that slug; a copy from another clone or worktree; a file-sync client; an
agent that bypasses the CLI and hand-writes a correctly shaped doc. Each is rare by itself, needs the
slug to coincide, and then needs the ≈1 ms. Honest estimate: not reachable in ordinary use; reachable
on purpose in one or two tries (32/40 when aimed). Fan-out reporters do not reach it — each sub-task's
home is in its own worktree — and two plain reporters are refused at the committing door.

## 7 · The code (read-only; nothing edited)

- **Site.** `crates/cli/src/doc.rs:title_pre_check`, rank 0 — `entry.new && state::create_occupied(…)`
  (the check) — against `crates/engine/src/state.rs:create`, step 4 — `committed.is_file()` →
  `copy_in` (the use). Between them: the rest of the pre-check (`create_incumbent`, `held_instance`),
  `is_migration`, the on-create fields, `create_admission`, two `mint_instance` calls. `entry.new` is
  read at exactly one production site (`doc.rs:3425`); **`state::create_gated` takes the gate and
  never consults the key**, so the engine's create under a `new` entry still copies in.
- **Introduced.** The gate: `e9f7f081`, 2026-10-03, M55 Increment 2. The copy-in predicate:
  `f6a9340a`, 2026-06-09. The clobber guard and its `Created`-only hinge: `e1cbe581`, 2026-06-17. The
  pre-check seam itself: `d9cf3e34`, 2026-08-13. (git log -S / blame — read, not driven.)
- **Class — every door sharing the mechanism.**
  1. `doc create` and `doc author` under `new: true` — this finding. The only two production callers
     of `create_gated`.
  2. The same pre-check's rank 3, `write.title-ignored`: `create_incumbent` probes, `create` re-probes
     — a file landing between is copied in with the supplied title silently dropped (read, not driven).
  3. **`task finalize`'s own clobber guard** — `engine/src/finalize.rs:plan_clobber_guard` probes
     `is_file()` at plan time; `cli/src/task.rs:promote` `fs::copy`s later. **Driven here** (rig v2, a
     fresh `created` mint, a victim created with `O_CREAT|O_EXCL` at a random delay after spawning
     `task finalize`): delay 0–160 ms, N=60 → 60 refused `promote-clobber`; delay 140–300 ms, N=80 →
     26 refused · **13 exit 0 with the planted file's bytes gone** · 41 planted-after (`EEXIST`).
     Window ≈ 160 ms × 13/80 ≈ **26 ms**. For all 13: marker in 0 files under `$REPO`, `git log --all
     -g -S` 0, no blob in the object database, fsck and stash empty. Any workflow; the destination is not re-read after the plan (read), so any content;
     pre-M55. Not in the review record.
  4. The untracked-conformant copy-in under an entry without the key (the record's O-2), and the
     no-baseline overwrite `(R3, F7)` — the same *on disk is read as committed / no recorded baseline*
     root, no race needed.
  5. The milestone boundary's promote shares `plan_clobber_guard` (read, not driven).
- **The contract a fix must restore.** *Under a `new: true` entry no path reaches the copy-in* — the
  probe that decides the refusal and the probe that decides copy-in must be one decision, not two. And
  for the class: *bytes git never held at a promote destination are never overwritten at exit 0* —
  refused, or kept somewhere named.
- **Cheap vs robust — a genuine fork.**
  - *Cheap:* make the engine's create honour the entry's key, so the single `is_file()` it already
    performs decides both outcomes. Small, local, pinnable without a race. Restores the M55 sentence;
    a file landing later still meets `promote-clobber`. **Leaves the loss class open** (members 3–5).
  - *Robust:* stop reading *on disk* as *committed* at copy-in and at promote — a baseline or pre-image
    recorded at copy-in, and a promote that refuses or displaces when the destination is not what the
    task last saw. Closes K-1's loss half, O-2, the finalize window and a share of `(R3, F7)` together.
    Costs a change to provenance, the finalize plan and the promote seam, on the candidate the call is
    about to be taken on.
