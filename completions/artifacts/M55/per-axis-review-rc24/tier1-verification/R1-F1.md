# (R1, F1) — independent verification

**Finding as graded:** on an unborn `HEAD`, `jigc setup` overwrites untracked user bytes at a
whole-rewrite install path (`.jigc/AGENT.md`, `.jigc/config/packs.yaml`) at exit 0 with no finding.

**Verdict in one line:** reproduces in full; both halves of the tier-1 predicate are shown; the loss is
**not** declared (the *exemption* is, on a rationale that is false at these paths); **tier 1 on the
predicate's letter**, with a precondition that is narrow and a blast radius that is small. Three facts the
record does not carry are added below (the class is wider than two paths; `packs.yaml` loses comments only;
the precondition is *unborn `HEAD`*, not *zero commits*).

Binary: `~/.local/bin/jigc`, `jigc --version` → `jigc 1.0.0-rc.24` (asserted at the top of every script).
Every cell ran in its own `mktemp -d` repository under a fresh `dev/jigc-rig bare --binary …` root (isolated
`HOME`). Scripts and raw output: `r1f1-A.sh`, `r1f1-V.sh`, `r1f1-V.out`, `r1f1-B.sh`, `r1f1-B.out` beside

## 4. Is it declared?

**The exemption is declared. The loss is not.**

- `design/validation.md`, the `setup.dirty-install-path` row: *"**The exclusion survives on an unborn
  `HEAD`**, where that rationale does reach: there is no `HEAD` for a pre-existing file to differ from and
  `setup` owns minting the repo's first commit, so the green cell is keyed on the repo having **no
  commits** — a stated door rule — rather than on a status flag that also silenced the born case."* The cost
  it prices for an untracked path is the preceding sentence's: *"because `setup` **merges into** the host
  files the adopter's bytes are still there when the commit is made"*. That is the milder, neighbouring
  cost (bytes ride the first commit) and it is true only of the merged-into members.
- The same row names this finding's exact signature as **the loss the guard exists to close**: *"a path
  `setup` rewrites whole reads clean afterwards **because** the adopter's bytes have just been destroyed …
  driven, `.jigc/AGENT.md` prose gone at exit 0 with `git status --short` empty and the bytes in no git
  object, and `.jigc/config/packs.yaml`'s comments dropped the same way"*, and promises *"Forgetting a new
  install path now costs a loud false alarm `--force` clears, never a silent sweep."*
- `DECISIONS.md` (M51 Increment 3 plan), where the exclusion originates: *"excluding `??` is also what makes
  an **unborn HEAD clean by construction** … Nothing is lost in this cell"*. The premise is false at four
  paths.
- `crates/cli/src/setup.rs`, `dirty_against_head`'s doc-comment gives the on-ramp reason only (*"Asking
  here would turn the QUICKSTART on-ramp into a refusal routed at `jigc setup --force`"*).
- Three adopter-facing surfaces state the opposite as a universal, with no unborn carve-out:
  `crates/cli/guides/QUICKSTART.md` → *1. `jigc setup`* (*"staged, unstaged or untracked — it stops … your
  bytes are still exactly where you left them — including at the files jigc regenerates whole
  (`.jigc/AGENT.md`, `.jigc/config/packs.yaml`)"*); `crates/cli/guides/MIGRATING.md` gate 4 (*"asks its own
  install pathspec against `HEAD` **before it writes a byte** … and refuses"*); `jigc setup --help`
  (*"Refuses its own install commit when a path in that footprint carries work no commit has a copy of,
  rather than sweeping it in"*). `design/project-setup.md` → *Idempotency & irreversibility* adds *"an edit
  the user makes after the failure still re-arms `setup.dirty-install-path`"* — false in B arm 2.

No sentence in `design/`, the guides, `--help` or `DECISIONS.md` says that pre-existing bytes at a
whole-rewrite path are destroyed on an unborn `HEAD`.

## 5. Tier — my verdict: **1**

**For tier 1.** Exit 0 with an empty finding list, shown five ways. Bytes found before and in no place
after. `setup` is a commit-on-behalf door and its install commit is what leaves `git status` empty. The
product refuses the identical bytes one commit later (V6), so they are user bytes by its own rule. The
design row cites this very outcome as the defect the M51 audit closed, and three adopter-facing surfaces
promise it cannot happen. The declaration covers the exemption on a premise (*nothing is lost*) that does
not hold here.

**Against tier 1.** The exemption is a written, tested door rule (cell 18 of
`setup_install_pathspec_guard.rs` pins the green cell), so the behaviour is by design at the level of the
check. Every lost path is inside jigc's own `.jigc/` namespace and is a file jigc generates; a human
authoring one before jigc is installed, in a repository with no commit, is close to hypothetical, and the
realistic route needs a failed first run, an unstage and a hand edit of a generated file. At `packs.yaml`
only comments go. At `AGENT.md` human bytes are never durable anyway (V19).

**Why 1.** The predicate has no likelihood term and neither half is missing. The declaration defence fails
on the task's own test: it declares a milder neighbouring cost and its stated premise is false for this
class. What the against-case buys is weight, not a re-tier: this is a low-reach tier 1 with a small blast
radius, and the fix is narrow.

## 6. How a real adopter or agent gets here

- **Hand-authored or copied `.jigc/` before the first commit** (repro A). Someone scaffolds a new project
  from a template directory that carries `.jigc/`, runs `git init`, then `jigc setup`. Plausible as a
  sequence, but the bytes still exist in the template, so nothing unique is lost. Unique human bytes at
  `.jigc/AGENT.md` before jigc has ever run there: very unlikely.
- **Failed first run → unstage → edit → re-run** (repro B). Step one is common: a new machine, container
  or devcontainer with no git identity fails the install commit exactly as shown. The loss then needs both
  an unstage (`git reset` — nothing routes to it; the route says the files are staged for the re-run) and
  an edit to `.jigc/AGENT.md` or a comment in `packs.yaml` before the re-run. Uncommon; an agent "tidying"
  the index is the likeliest actor.
- **Orphan branch with an emptied index** (V17′). Rare.

Overall: **low**. No route was found that an adopter following QUICKSTART reaches without a deliberate
extra act.

## 7. Code (read-only; nothing edited)

- **Site:** `crates/cli/src/setup.rs` : `dirty_against_head` — `is_fresh_repo(jigc_home)` selects
  `--untracked-files=no`, so on an unborn `HEAD` no untracked path can enter the dirty set that
  `InstallSubject::probe` hands the pre-write gate. The writers that then destroy the bytes are
  `adapter::write_bootstrap_file` (unconditional `fs::write`, follows a symlink), the `.gitkeep` and
  version-stamp writers, and `write_compose_marker`'s parse-mutate-serialize.
- **Introduced (read from `git blame` / `git log -L`, not driven on an older binary):** `15b919ca`,
  2026-09-15, *fix(setup): the install-commit guard asks about untracked bytes too* — M51 Increment 3's
  completion-audit fix, which widened the born case and kept `=no` on unborn. Its parent `abfdae2c`
  (2026-09-14) excluded `??` everywhere. **Outside M54, M55 and the co-author trailer.** M54's S22
  (`record_failed_install`) is on repro B's path but is not the cause.
- **Class (same mechanism, same fix):**
  1. the pre-write gate at all four non-preserving members (`AGENT.md`, `.gitkeep`, `version`,
     `packs.yaml` comments);
  2. the symlink variant — a link at a whole-rewrite path destroys its target outside the install set;
  3. `--force` on an unborn `HEAD` — `Consented(∅)`, so `setup.forced-install-path` names nothing;
  4. S22's re-arm on an unborn `HEAD` — `record_failed_install` asks the same function for `before`/`now`,
     so a post-failure edit is never re-armed once unstaged (and a mid-span failure there records and
     stages nothing: V15 left five paths `??`);
  5. the commit-time backstop for the hook member, which asks the same `InstallSubject`;
  6. the declared other face: untracked bytes at a merged-into member ride the first commit under
     `--no-verify` (declared, not a defect, but it moves with the same line).
- **Contract a fix must restore:** on an unborn `HEAD` as on a born one, `jigc setup` does not destroy
  bytes at an install path that no git object holds without either refusing before the first write or
  naming the path — while a fresh `git init` holding ordinary pre-existing files still installs at exit 0.
  The three adopter-facing sentences in §4 then have to be true as written, or carry the carve-out.
- **Fork — genuine:**
  - *Cheap:* keep the unborn exemption for members whose writer preserves bytes and withdraw it for the
    ones that do not. Costs a per-member *preserves / replaces* fact the disposition table does not carry
    today (it has `Refuses` / `ExemptWhenJigcOwned`; `packs.yaml` is classed merged-into in the design row
    yet drops comments), one more place to forget a new member, and it leaves face 6 as declared.
  - *Robust:* ask the untracked question over the install candidates on an unborn `HEAD` too. Closes the
    whole class including face 6 by construction, at the price the door rule was written to avoid: a new
    repository that already holds an untracked `CLAUDE.md`, `.gitignore` or `.claude/settings.json` — a
    common on-ramp state — now refuses and routes to commit, stash or `--force`. That reverses a recorded
    decision and cell 18's assertion.
