## 2 · The two halves

**Exit 0.** `milestone join` exit 0 (text and JSON, `findings: []`, stderr empty); `milestone finalize` exit 0,
stderr empty, the landed envelope says `promoted` for both overwritten paths and `displaced: []`. `jigc validate`
and `jigc start` afterwards name nothing. The only trace on any surface is the join's own
`← suffixed -2 on collision` line (which names the id, never that it is occupied) and the commit's diff stat,
where `stage-2.md` shows as a modification of an existing file.

**Loss — the untracked victim.** `UNTRACKED-NOTE-MARKER`, found before in exactly one place, is afterwards in **none**:

| place | how checked | result |
|---|---|---|
| worktree, `.jigc/` (tasks, milestones, worktrees, state, index, any `displaced/`), `.git/` loose files | `command grep -rl` over `$REPO` (before-control found the plant; "charlie reporter" control still found after) | nothing |
| the whole rig root, `$RIG_HOME` included | `command grep -rl` over `$RIG` | nothing |
| the index | `git grep --cached` | nothing |
| HEAD and every ref | `git grep` over `git for-each-ref` | nothing |
| history | `git log --all -S…` and `git log --all --reflog -S…` | 0 / 0 |
| stash | `git stash list` | 0 entries |
| unreachable objects | `git fsck --unreachable --lost-found` | no object listed |
| **every object in the object database**, reachable or not | `git cat-file --batch-all-objects`, each blob/commit/tag read and grepped (control: finds the committed marker's blob) | 0 objects |
| a displaced/backed-up area | `.jigc/` inventory after: `.gitignore AGENT.md config/ index/ milestones/ state/ tasks/ version worktrees/` — no `displaced/` | none exists |

It is in no object and nowhere under the repository or the rig. **Unrecoverable.**

**The committed victim — not loss on the letter, harm on the predicate.** `EARLIER-FINDING-MARKER` is gone from the
worktree, the index and HEAD, and survives in history only: `git log --all -S` → 2 (the commit that added it and
the finalize commit that removed it), one blob in the object scan; `git show 6f1142f:docs/inconsistencies/stage-2.md`
returns it. So *"bytes absent from every place"* is **false** for this half. What is damaged is the committed
record: the commit jigc made replaces a managed doc **under its own identity** — `inconsistency:stage-2` now
resolves to another reporter's finding, with the title, `kind`, `status` and prose of the newcomer; any structured
referrer of that id now points at different content; the earlier finding is in no live doc and no listing. Nothing
says so: the manifest word is `promoted`, the same word as for a new file. Discoverability of the recovery: a user
must first notice from the diff stat that a "created" doc modified an existing path. That is repository harm through
a committing door, history-recoverable.

## 4 · Is it declared?

No sentence in `design/`, `crates/cli/guides/`, the two doors' `--help`, or `DECISIONS.md` states this behaviour as
intended or as a bound. What is stated says the opposite, or covers a milder neighbour:

- `design/storage.md` → Placement: *"The **no-silent-data-loss guard is inherited, not rebuilt**: the general
  `plan_clobber_guard` already blocks any create-promote whose destination file already exists"* — false at the
  milestone door.
- `design/auto-migration.md` → Honest bounds: the guard exists because a create *"would silently **clobber
  `decisions/<slug>.md` at promote**"* — *"M25's guard fires at **finalize-promote**"*.
- `design/storage.md` → The by-task-id join, rule 4: colliding created instances *"are *distinct docs*, not a
  clash"*; and after the rules: *"`finalize`'s destination-path sort never sees two docs competing for one path"* —
  a claim about the overlay; silent about the store.
- The binary itself (`join.same-doc-clash`, V3): *"the join never silently overwrites a managed doc"*.
- `jigc milestone join --help`: *"disjoint-union their staged docs (collision-suffixing distinct created
  instances) … Commits nothing"* — names the suffixing, not where it may land.
- `design/findings-channel.md` §4: *"`new: true` does not change fan-out join suffixing: two sub-tasks that mint one
  slug in isolation still land `-2` at the join, ordered by task id."* — declares that suffixing continues; a
  landing **beside**, not **on**.
- The neighbouring declared cost — `design/findings-channel.md` §1.5: *"any task can `set-field`/`set-slot`/
  `remove-item` on any committed doc whatever its workflow's `allows-create`"* (parked as

  no caller named, and it says nothing about untracked files.

**Not declared.**

## 5 · Tier

**Tier 1.**

*Strongest case for:* a committing door, exit 0 at both steps, `findings` empty, and bytes that existed before are
in no object and nowhere on disk after (§2; V2, V8 the same). No declaration. The single-task door refuses the
identical state by name (`finalize.promote-clobber`, V1), the design calls that state *"irreversible data loss"*,
and the binary's own join message asserts the invariant that is broken. The committed half is independently harm:
the commit replaces a managed doc under its own id and says `promoted`.

*Strongest case against:* the precondition is a coincidence of two independent facts (§6) — M55's own seed fan-out
landed 92 findings with **zero** suffix events (`completions/artifacts/M55/seed/`: no `-N.md` file); the mechanism
has shipped unchanged since M7 without being met; the committed victim is one `git show` away; the unrecoverable
victim is a file that was never `git add`ed, sitting at a managed home out of band; and a dirty tracked victim is
caught (V4). On likelihood alone this reads like a tier-2-weight row.

*Where I land:* the predicate has no likelihood term, and both of its halves are shown without any contrivance in
the door's argv — no caller addresses either victim, and the door's sibling guards exactly this. The committed half
taken alone would still be tier 1 on the harm disjunct (weaker: recoverable). Tier 1, with low reach — and the row
understates the defect's width (V2), which matters for the fix more than for the grade.

## 6 · How a real adopter or agent reaches it

Two conditions must hold at one `milestone finalize`:

1. **≥2 sub-tasks of one fan-out create a doc of one doctype whose ids slug the same.** Reachable from any sub-task
   workflow whose `allows-create` names a doctype with a directory home: the default fan-out target `sub-task`
   (`adr`), `single-task`, `record-decision`, `implement-from-spec` (`adr`), `plan` (`spec`),
   `architecture-documentation` (`arch-doc`), `park-idea` (`idea`), `do-research`, and M55's `report-inconsistency` /
   `report-jigc-feedback`. Ids are title-minted and **capped at five words** (`slug::MAX_WORDS`), so two titles that
   share their first five words collide, not only identical ones. Under `new: true` and under create-or-update alike
   the bare `<slug>` must be **absent** from the main checkout when the sub-tasks create (else: `create.already-exists`,
   or a copy-in that ends in `join.same-doc-clash`).
2. **`<slug>-2` … `<slug>-N` is already a file at the home** while `<slug>` is not. Ways there: a doc genuinely titled
   `"<T> 2"` (`Stage 2`, `Phase 2`, `HTTP 2`, `Cache 2`) and two reporters filing `"<T>"`; an earlier fan-out landed
   `<slug>` + `<slug>-2` and triage later **retitled the bare one** (`jigc rename`), freeing `<slug>` with `<slug>-2`
   still there; a hand-written `<slug>-2.md`.

Or, without any collision (V2): an untracked file appears at a sub-task doc's home between that sub-task's create
and the finalize.

**Likelihood: low.** Condition 1 did not occur once in the one real fan-out of this workload (92 docs). Condition 2
on top of it is rarer. It is not zero — a recurring review fan-out over one store, with short titles and a triage
step that retitles, walks toward it — and when it happens nothing on any surface says so.

## 7 · Code (read-only)

- **Site.** `crates/engine/src/finalize.rs` : `plan_milestone_finalize` — runs `plan_promotions` and returns; it
  never calls `plan_clobber_guard`, which `plan_finalize` (the single-task planner) calls right after its own
  promote sweep. The suffix that reaches an occupied id is minted in `crates/engine/src/milestone.rs` :
  `fold_areas` → `suffix_resolve` (and again in `materialize` → `resolved_body`) as `slug::suffixed(slug, nth)` —
  `nth` is the position in the colliding group; neither the committed store nor the worktree is consulted. The
  overlay-only guard is `fold_areas`' `claim` closure → `cross_group_collision_finding`.
- **Introduced (git log / blame — read, not driven).** M7, 2026-06-04: `12fd6285` (the suffix), `7a721d80` (the
  cross-group guard), `988d6847` (`materialize`), `e6902cc0` (`plan_milestone_finalize`). The clobber guard arrived
  later — `e1cbe581`, 2026-06-17 (M25) — on the single-task planner only; the milestone planner never received it.
  `git log jigc-v1.0.0-rc.22..HEAD` over both files is empty. **Outside M54, M55 and the co-author trailer.**
- **Class.** (1) every `created` promotion through `milestone finalize`, suffixed or not, both squash modes, every
  doctype with a home — D-1 and V2 are the same missing guard; (2) the join's suffix assigner, which can mint an id
  the store already holds and reports it as a plain suffix; (3) the window between `milestone join` (a preview) and
  `milestone finalize` — any store-aware decision taken at the join must be re-taken at the boundary; (4) the
  staged-index victim (V5), whose index entry is replaced without the pre-finalize entry being reported; (5) not
  driven, same planner: two `created` instances of a **placement/singleton** doctype in one fan-out. The guarded
  doors, for contrast: both create doors, `doc rename` (`write.already-present`), `task finalize`
  (`finalize.promote-clobber`), `relocate` (parks in `.jigc/displaced/`). `(R6, K-1)` is a neighbour, not a member:
  there the guard is skipped by provenance (`edited-from-base`), here it is never called.
- **Contract a fix must restore.** *A `created` doc never promotes over a file already at its destination — at the
  milestone boundary exactly as at the task boundary* — decided at the commit boundary (not only at the join
  preview), over the worktree as well as the committed store, with a blocking, routed finding and nothing committed.
- **Cheap vs robust — a genuine choice.**
  - *Cheap:* run the clobber guard in the milestone planner, keyed on the overlay's `created` provenance. Closes
    D-1, V2, V5, V6, V8 at once. Costs: a coincidental suffix landing becomes a **blocked** fan-out (exit 3) with N
    sub-tasks' work pending, so the finding needs a milestone-arm route that actually runs (the existing
    `clobber_finding` routes name `jigc task finalize` and a per-task re-create); and the materialized `merged/` area
    carries no provenance manifest today, so provenance has to be carried from the overlay.
  - *Robust:* the same boundary guard **plus** a store-aware suffix — the join skips an occupied `<slug>-N` to the
    next free one — so rule 4's promise (*distinct docs, not a clash*) keeps a clean join. Costs: the suffix stops
    being a pure function of the sub-area set (it becomes a function of the store at the base as well), which
    `design/storage.md` rule 4 and `structural-grammar.md` state today and would have to be revised; `fold_areas`
    and `materialize` must agree on the probe; the guard is still required for V2 and for the join→finalize window.
  - A fix that only teaches the suffix to look leaves V2 open.
