# (R3, F7) — independent verification

**Finding as recorded.** Door `task finalize`. With no file-state baseline (a second clone before its
first finalize, or after `jigc unmanage`), an uncommitted out-of-band edit made after a task's first
write to that doc is overwritten by `jigc task finalize` at exit 0.

**Verdict.** Reproduces exactly, on the exact contested shape (a plain second clone, no other act).
Both halves of the tier-1 predicate are shown. The declaration in `design/storage.md` covers the
neighbouring order (a merge), not this one (a loss), and three other contract sentences forbid it.
**Tier 1 stands.** The verifier did not build jigc, did not drive this row and did not reconcile it.

Binary: `~/.local/bin/jigc`, `jigc --version` → `jigc 1.0.0-rc.24` (asserted at the top of every
script; release posture). `git diff --stat jigc-v1.0.0-rc.24 HEAD -- crates` is empty, so every source
read below is a read of the released source. Every rig is a fresh `dev/jigc-rig <state> --binary …`
(two-step eval, stdout only, `[ -n "$REPO" ]` guard), every exit code read bare, every count under
`.jigc/` a `command grep` with a before-control.

Marks: `HL` = *A hand line written out of band VERIFIER-MARK-7731.* (appended under `VISION.md`'s
thesis sentence, in the worktree, never committed) · `TP` = *Which domains earn a pack, and when
TASK-PROSE-4410.* (the task's prose, through `doc set-slot`).

## 2 · The two halves

**Exit 0.** `task validate` 0, `task finalize --dry-run` 0, `task finalize` 0 — text and `--format json`.
No finding is blocking; the only rows at `VISION.md` are `file-state.staged-copy` and
`file-state.baseline-adopt`, both routed *no action needed*; the JSON envelope's `displaced` and
`left_out` are both `[]`. Nothing on any surface says an on-disk edit existed, let alone that it was
replaced. The only inferable hint is the manifest line `promoted VISION.md`.

**Loss.** The before-control finds `HL` once (the worktree file) and nowhere else. After the door it is in
none of: the worktree · the index · `HEAD` · any ref · `git log --all -S` · `git log --reflog -S` ·
`git stash list` · any object in the object database, reachable or not · `git fsck --unreachable
--lost-found` · any file under `.jigc/` (including `state/`, `index/`, `tasks/`; no `displaced/`
exists) · loose text under `.git`. `promote` captures the destination's pre-image only in memory, for a
rollback that a landed commit never runs (`crates/cli/src/task.rs` `promote`), so jigc keeps no displaced
copy of these bytes. **The bytes are unrecoverable from git and from jigc.**

One bounded exception, driven (`clone-hand-staged`): if the hand edit was `git add`-ed before finalize,
the door still exits 0 with no `finalize.carried-staged` and still overwrites worktree and index, but
the staged blob survives as **one unreachable blob** in the object database
(`git fsck --unreachable --lost-found` lists it; it carries the mark). Recoverable by someone who knows
to look, until `git gc` prunes it; no jigc surface points there.

Not driven: an unborn `HEAD` (a managed doc committed at its home presupposes a born one, and a clone
carries only tracked files, so *untracked* does not arise on this shape); the `new: true` create path
(it never copies a committed doc in — the mechanism here is the copy-in, i.e. the non-`new: true`
path, which every row above is); an rc.23-or-older binary. There is no `--force` on `task finalize`
(`--approve`, `--carry-staged`, `--dry-run`, `--format` only); `--carry-staged` is inert here.

**The finding's true boundary.** Baseline absent for the doc × the task has copied the doc in × a
later worktree edit to that doc that is not committed → the edit is destroyed at exit 0, at both
committing doors, for placement and location doctypes alike, in any environment. In a clone the
baseline stays absent through `setup`, `validate`, `start`, `doc show`, every `doc` write,
`task validate` and `finalize --dry-run`; only a landed finalize or `jigc ingest` writes it. So the
window is not "a moment" — it is the **whole of the first task in every clone**.

## 4 · Is it declared?

**No.** What is declared is the neighbouring cost.

- `design/storage.md` → *Concurrent writers*, the paragraph **What none of this buys — and the pair that
  makes the cost observable**: *"A lost baseline therefore does not degrade the guarantee, it switches it
  off — silently, at exit 0, with **both sides' bytes merged into one commit**."* It names the fresh
  clone, `jigc unmanage` and the cache deletion as legitimate origins. The cost it states is a merge:
  both sides survive. Driven (`hand edit before the first write`), that is exactly what the pinned order
  does. The order driven here keeps one side and destroys the other; the paragraph does not say so.
- `DECISIONS.md` → *2026-08-18 — M46 Increment 1 / T4* says the same thing in the same words (*"finalize
  lands at exit 0 with both sides' prose merged into one commit"*).
- `design/reconciliation.md` → *Conflict*, the migration bullet: *"`jigc unmanage <source>` drops the
  stale baseline, and the migration lands its rewrite over it … so a later on-disk edit is replaced
  unreviewed … **Not offered on any other path**."* A declared replacement, scoped by its own words to a
  migration task's own source. It does not cover `single-task` on a clone; it does show the authors
  treat replacement as something that must be declared per path.

Against it, three sentences state the opposite as a contract:

- `design/reconciliation.md` → *The principle*: *"The CLI never forbids file edits and **never silently
  discards them**."*
- `design/reconciliation.md` → *Conflict*: *"**Discard is always explicit, never the default, never
  silent** — no data loss."*
- `design/reconciliation.md` → *What reconciliation does NOT do*: *"**No silent discard, ever.** Every
  block surfaces; every absorb surfaces … There is **no door exemption** from this sentence."*
- and the adopter-facing one, `crates/cli/guides/MIGRATING.md` item 8: *"Hand edits are detected and
  routed — never silently merged, never forbidden."*

Two further surfaces are false on this path (tier-3 riders, not the finding): `file-state.un-baselined`'s
route *"the doc is baselined on its next author or finalize"* (an author write baselines nothing), and
`design/reconciliation.md` → *Detection timing*, which says task `start` *"baseline-adopt[s] unknowns"*
and a write through the CLI *"re-probe[s] before staging"* (neither persists a baseline in rc.24 — had
either done so, this cell would block). `--help` text carries no statement of the behaviour.

## 5 · Tier verdict

**Tier 1.**

*Strongest case for.* The predicate is met literally: a committing door, exit 0 on every channel,
bytes present before and absent after from every place git or jigc could hold them. The contract is
unambiguous (four sentences, one of them "no door exemption"), the identical sequence blocks when the
baseline exists, and the precondition needs **no act at all** beyond `git clone` — the state the docs
themselves call legitimate and standing. The surfaces on the way say *no action needed* twice at the
very path being overwritten. It reaches both committing doors and both doctype kinds.

*Strongest case against.* (a) The bytes are uncommitted worktree bytes written outside jigc into a doc
the task had already taken a staged copy of — the posture jigc tells agents not to create, and a
`git add` before the door leaves a recoverable blob. (b) The mechanism is old (2026-05/06), not a
regression of the M54/M55 range, and has shipped in every release candidate. (c) A neighbouring cost of
the same cause is declared and pinned, so the cause is known and accepted in one order. (d) Per task,
the co-incidence (first task in a clone × a direct edit to the same doc after the task's first write ×
left uncommitted) is uncommon.

*Why tier 1 anyway.* None of (a)–(d) removes a half of the predicate. (a) is the precise posture the
conflict guard exists for — `VISION.md` principle 3 and the adapter's "adapter-enforced, not
sandboxed" boundary both assume direct edits happen and promise they are routed. (b) The exit rule
grades what 1.0.0 ships, not what the last two milestones changed. (c) The declaration is of a merge;
a declared milder cost does not cover a loss, and the docs elsewhere declare replacement explicitly
where they mean it. (d) is likelihood, which weighs triage urgency, not the tier.

## 6 · How a real adopter or agent gets here

Precondition one — no baseline — is **standing, not exceptional**: a teammate's clone, a new machine, a
CI checkout, and every ephemeral cloud or container agent session, where each session is "a second
clone before its first finalize" and its first task is usually its only one. `jigc validate` on such a
clone says *no action needed*. Precondition two — a direct edit to a managed doc after the task's first
jigc write to it, left uncommitted — happens when (i) a coding agent writes a slot through jigc and
then touches the same file with its own edit tool (the bypass the design explicitly bets against rather
than prevents), or (ii) the human fixes a line in the doc in an editor while the agent's task is open.
Likelihood per task: low-to-moderate in ephemeral-clone agent setups, low on a long-lived developer
checkout (the window closes at the first landed finalize). When it happens it is silent: clean
`git status`, a green finalize, and the edit is gone.

## 7 · Code (read-only; nothing edited)

**Site.** Two functions make the cell:

- `crates/engine/src/file_state.rs` : `reconcile_committed` — the `None =>` (UNKNOWN) arm adopts the
  on-disk hash as the baseline and returns the advisory **without consulting `task_touched`**; only the
  `Some(_) if task_touched` arm can reach `conflict_block_finding`. `reconcile_committed_store` computes
  `task_touched` and passes it in; the UNKNOWN arm ignores it.
- `crates/cli/src/task.rs` : `promote` — `std::fs::copy(&promotion.source, &dest)` over the destination
  unconditionally; the `PreImage` it captures is rollback-only and in memory.

Contributing: `crates/cli/src/doc.rs` : `read_or_copy_in` → `engine::state::copy_in` records only the
provenance kind (`edited-from-base`), never the hash of the bytes it copied, and no write door persists
a baseline — so with the record absent nothing remembers what the task started from.

**Introduced (git log / blame — read, not driven on an older binary).** The classifier and its
UNKNOWN arm: `1860b8bb`, 2026-05-31 (*reconciliation OOB classifier*). Copy-on-first-touch wired into
the `--task` edit path: `cd66e216`, 2026-06-04. The pair that pinned the other order: `35c98e02`,
2026-08-18 (M46 Increment 1 / T4). **Outside the new code** — not M54, not M55, not the co-author
trailer.

**Class — every path sharing the mechanism.**

1. `jigc task finalize` × any promoted doc, placement or location (driven: `vision`, `adr`).
2. `jigc milestone finalize` × the same (driven) — and it prints no finding row at all.
3. Every way the baseline is absent: clone (driven) · `jigc unmanage` before or after the block
   (driven before; the record drove after) · the sanctioned cache deletion (not driven) · a key dropped
   by a save that timed out or by any future forgetting writer.
4. The `UNKNOWN` + non-conformant branch of the same arm: an advisory that tells the user to *fix the
   file*, followed by the overwrite of that file in the same run (driven).
5. **A sibling with the baseline present (driven once, not bounded, not graded here):** a task driven
   from a user-made linked git worktree. `repo::jigc_home` binds the doc store and the task area to
   the **main** checkout, so the reconciler reads the main checkout's `VISION.md` (in sync) while
   `promote` and the commit land in the linked worktree, where the hand edit lived. Exit 0, one
   `file-state.staged-copy` advisory, the edit in no ref and no blob. Same destroying site, a different
   reason the guard misses. The record's `(R1, F5)` knows the hook's sweep asks about the main checkout
   from a linked worktree; it does not record this loss. **This should be triaged as its own lead.**
6. The declared silent merge (hand edit before the copy-in) is the same arm in the other order — a fix
   will move it too, and its pinned test.

**The contract a fix must restore.** *A committing door never replaces on-disk bytes of a managed doc
that differ from what the task copied in, unless a finding says so and the door blocks* — i.e.
"no silent discard, no door exemption" must hold **independently of whether the gitignored cache
happens to hold a key**. It must keep: the pulled-edit absorb (M55 L1), the migration task's sanctioned
`unmanage <source>` exit (which lands a rewrite through this very arm), and first-encounter adoption of
an untouched doc as a plain advisory.

**Cheap vs robust — a genuine fork.**

- *Cheap:* make the reconciler's UNKNOWN arm task-aware — when the task has a staged copy of the doc
  and there is no recorded hash, decide from the evidence already plumbed to that function (the blob at
  the task's base pin) instead of adopting blindly. Small and local. Costs: it also turns the declared
  silent merge into a block, so `reconciliation_baseline_contrast` arm B and the `storage.md` paragraph
  change with it; the answer for a failed or absent pin lookup must be chosen (the record door passes no
  pin); it collides with the migration exit above unless that path is carved out; and it does nothing
  for sibling 5, where the guard reads a different checkout than the one promoted into.
- *Robust:* give the task its own memory of what it copied in (recorded at the copy-in, or a baseline
  persisted at the write door as *Detection timing* already describes) and make the **promote** itself
  compare the destination against it before writing — the compare-and-swap discipline the rollback
  family already uses, applied to the forward write. The guard then sits at the destroying site and
  does not depend on the cache or on which checkout the reconciler read, so it closes the class
  including sibling 5. Costs: a working-area format addition (live tasks minted by an older binary carry
  no such record), a new or reused blocking finding with a route, interplay with first-touch
  canonicalization and the same-path migration carve-out, and more tests.

No patch is proposed.

## 8 · The pin

`crates/cli/tests/reconciliation_baseline_contrast.rs` ::
