# canary-one — the test set

One row per instrument item: its kind, the clause of the closing condition it judges, whether it runs on every candidate or only in a round whose test set reaches it, the doors and the registries it covers, and its brief. Written by `dev/stabilize-record` and never by hand. The harness runs a fixed chain of agents per kind; which items a round runs is computed from this table and the round's doors.

| item | kind | clause | runs | doors | registries | brief |
|---|---|---|---|---|---|---|
| `row-doc-list` | `review-row` | `no-lost-files` | in-scope | jigc doc list | - | The review row of ONE door, `jigc doc list`, kept small on purpose. The source pass: the path from the verb's dispatch in crates/cli/src/cli.rs to everything it reads - does a verb that only reads write, remove or commit anything at exit 0? The driver's table, on the binary of the BINARY line, in throwaway repositories under the scratch root: the verb in a repository `jigc setup` never ran in, and in one it ran in that holds an untracked file - per row the exit status, what it printed, and `git status --porcelain` before and after. |
| `cross-cutting` | `audit-cross-cutting` | `no-lost-files` | every-candidate | - | - | The cross-cutting pass of the audit, bounded for a canary to ONE question over the round's doors: does any code path a door reaches write to the working tree or to git at exit 0 without the user having asked for it? Read the source; drive no more than a finding needs. |
| `arm-control` | `trial-arm` | `usable-by-agents` | every-candidate | - | - | Walk arm 00 of the trial protocol, the positive control (completions/artifacts/RC-rc24/protocol.md, section 2, Instruments): the script completions/trial-driver/arms/walk/00-positive-control.sh, run INSIDE the trial image through completions/trial-harness/run-session.sh with --exec, on a corpus instantiated from completions/trial-corpus-template/. It is scripted: it needs no blind session and no credential. Rehearse: the image answers and the script starts. Run: the arm. Score: its pass condition, from the evidence copied out of the container. |
| `gate` | `held-gate` | `working-product` | every-candidate | - | - | The full gate on the candidate, AS A HELD COMMAND of dev/stabilize-step (`hold-start --kind gate`): answered from the candidate's own gate, which every stage holds once - it is not run twice. This item's result is written from that verdict's file. No agent runs a command off this brief. |
| `regression-set` | `held-regression` | `working-product` | every-candidate | - | - | The regression set, first part - a long scripted check, about thirty-five minutes, AS A HELD COMMAND of dev/stabilize-step (`hold-start --kind regression`): the previous release's commit 91834b5e011de2c36e2be2b79e96c0b9f60a803c against the candidate's, over the list completions/artifacts/M55/stabilization-build/regression-set/intended-changes.tsv as the candidate holds it. The tool starts it, waits for it and reads the verdict out of the ONE line dev/regression-set prints; this item's result is written from that verdict's file. No agent runs a command off this brief. |
