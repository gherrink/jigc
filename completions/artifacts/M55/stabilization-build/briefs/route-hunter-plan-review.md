### B2. The hunt's site set is computed from `sites.tsv` and `scheduled.tsv`, but the catalog's own sites are not limited to those two files. H3 as written would refuse ids the catalog uses and hold the wrong set.

- **Evidence.**
  - `route_catalog.rs` `Claim::id` (around line 1642) mints ids of the form `file::function::<code>#dynamic-N`, for example `crates/engine/src/finalize.rs::setup_dirty_install_finding::setup.dirty-install-path#dynamic-1`. None of these ids is in `sites.tsv`. `CLAIMS` holds 24 `claim(` rows, and the doc comment says *"A claim makes a site: the code at the dynamic site it names owes a case like a listed one."*
  - `MINTED_AT` (line 1777) assigns the codes of catalogued families to dynamic sites. Examples: `finalize.commit-rejected` and `finalize.amend-rejected` at `render::commit_rejection_finding`, and `finalize.rollback-conflict` at `rollback_conflict_finding`.
  - Those dynamic sites sit in `sites.tsv` under `unassigned`. So the `task finalize` family's rows, from either file, leave out gate refusals the gate actually prints.
  - H3 says *"Ids are held to `sites.tsv`; the partition is held to the family (or to `scheduled.tsv` under F3-B)"*. That partition is wrong in both directions: it refuses claim ids and it misses MINTED_AT sites. F3-B (*"deterministic from two committed files"*) has the same gap.
  - The one place that knows a family's true site set is the catalog suite: `CLAIMS`, `MINTED_AT`, `IN_PART`, `READINGS` (causes, `without_case`, `not_followed`), `REASONS` and the scheduled list.
- **Fix.** Make F3-A's "answers file" a **projection generated by the catalog suite and held equal to it**, as `sites.tsv` is held to the scan (the `UPDATE_GOLDENS` pattern, refused under CI). Key it by family. Each family's entry should hold: its sites, with claimed and MINTED_AT-assigned dynamic sites included; each site's answer (cases with their causes, reasons, `without_case`, or `scheduled`); and the residual dynamic sites no family claims.
  - Add a task for it. **No H-task builds this file today**, although F3-A requires it. It changes `crates/`, so it lands before the opening (reshape plan §1, fact row F15: after the opening, `crates/` moves only through a round).
  - H3, if built at all, holds ids and the partition to this file and to nothing else.
