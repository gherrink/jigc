# Lessons of the stabilization workflow's build and repair — to fold into the workflow docs at the pass's close

*Written 2026-10-06 by the orchestrating session, before a context compaction, so that they do not live only in a session's memory. Each names the doc that should carry it; none is folded yet. The fold-back itself is the close's (`implementation/milestone-completion-workflow.md` → Close; the fix pass's README → What is owed next, step 3).*

1. **An orchestration script is not built until something has run it.** About 2,400 lines of harness were written and patched over four tasks without one executed stage; two independent reviews then found eight serious defects, three of them by driving the script with stand-in agents in minutes. Two builders and a reviewer had each written and thrown away such a simulation. *Rule:* the executable simulation of a harness (real record script, real git, scripted agents) is the first task of building it, not a repair. → `implementation/stabilization-workflow.md` → Why this shape; `implementation/increment-workflow.md` → Validation hardening.
2. **A third patch task on the same logic is the signal to stop and redesign.** Four follow-up tasks each closed the holes the previous one left in one state machine, and each left more. The repair that worked was a plan of a few structural changes with every finding mapped onto one, not a fifth list. (The tooling-level sibling of *a tier-1 finding inside a fix wave's own mechanism is a fix pass, not a wave*.) → `implementation/milestone-completion-workflow.md` → Plan (triage).
3. **State and decisions belong in a tested script; an agent only relays.** The harness has no filesystem; every fact an agent "read off a table" and every decision computed in a prompt was a place for a silent error. Once the run's state and its next step came out of one command as data, both reviewers could attack it by construction. → `implementation/stabilization-workflow.md` → Why this shape.
4. **A green local gate is not a green CI.** Every fixer of the fix pass reported a green gate while CI had been red on the branch for two days (a Linux-only failure); the pass's record never mentioned it. *Rule:* after a push, the pushed commit's `ci-ok` is read, and its result is part of what a record says. → `implementation/dev-workflow.md` → Gate.
5. **Review a plan before the human sees it, and verify each finding.** The two reviews of the plan found what fourteen rounds of question and answer had not (the red CI, a triage path that could shrink the human's list, an invariant the first tuning commit would trip, publish checks after the irreversible merge); one "blocking" finding was simply wrong. → `implementation/milestone-planning-workflow.md` → Review (it already says most of this; add *before showing*, and *a reviewer can be wrong*).
6. **Build agents will not edit `CLAUDE.md`, and sometimes nothing under `.claude/`, on an orchestrator's relay of the human's approval.** Three declined in a row and recorded the edits as owed by the main session. *Rule:* plan such edits as the main session's own small, gated commit; a task whose subject is a harness or a definition is accepted. → `implementation/increment-workflow.md` → Orchestration.
7. **An agent killed by an API error is resumed, not replaced.** Resuming the same agent from its transcript, with the instruction to re-read its whole diff first (it cannot know whether its last edit completed) and to treat any gate started before the cut as no evidence, recovered three interrupted tasks without loss. This is the first move before the *three tree states* classification. → `implementation/increment-workflow.md` → Halt and resume.
8. **One commit, one gate — say it per commit.** A builder asked for two commits gated only the final tree, because a `git stash` to gate the first alone was denied; the first was gated afterwards in a detached worktree. Briefs now say *the full gate on the tree of each commit*. → `implementation/dev-workflow.md` → Gate.
9. **Before putting open decisions to the human, have an independent agent write the sheet.** For each: what a user does and what the tool does today, what the previous release did, who decided what, the alternatives with their cost, which clause it touches, whether reversing it changes code — and an order that puts first the ones whose reversal changes code the next hunts will read. Twenty-three items were ruled in nineteen short questions; six of the rulings differed from the sheet author's recommendation. → `implementation/stabilization-workflow.md` → Triage, the human's list and the forks.
10. **Where one option makes the structure carry a rule and the other adds a list or a guard, the human takes the structural one** — the tooling tests' own directory over an exempt list; an end marker in the hook over byte comparison; a code of its own where the remedy differs; land a part by revert over a second landing path. Price it honestly, and do not let file count alone make it "later". → orchestrator's memory; `implementation/milestone-planning-workflow.md` → cheap-vs-robust already owns the principle.
11. **Swapping a binary under built tests: a plain re-run puts the old binary back and reads green.** The regression measurement only held once the swapped run went through the test runner's reuse-build path, with the binary's hash checked before and after. → the regression set's own doc, when part 1 is built.
12. **Two streams in two worktrees work when their paths are disjoint.** Product fixes under `crates/` and tooling repairs outside it ran side by side on two branches; the shared logs are the only overlap and the project's merge tool owns them. → `implementation/stabilization-workflow.md` → Orchestration.
13. **A ruling can rest on a fixer's factual sentence, and that sentence can be false.** The human ruled that `migrate-corpus` *blocks a symlinked doc like every other block — the run stops there*; the second clause came from an earlier fixer's report and was true of one kind of halt only, and the next fixer halted on it. *Rule:* the facts on a decision sheet are driven, not quoted from a report; a ruling states the premise it rests on, so a fixer who finds the premise false halts instead of building it. → `implementation/stabilization-workflow.md` → Triage, the human's list and the forks.
14. **A test that writes a file and then executes it fails on Linux only, and only sometimes.** A child forked by another test thread during the write inherits the write handle, and Linux refuses to execute a file with an open writer; macOS does not check, so no local gate shows it. The tooling suites now place such files through a child process, behind a source fence; the product suites still have the pattern. → `implementation/pinning.md`; `implementation/dev-workflow.md` → Gate (beside *a green local gate is not a green CI*).
15. **A private target directory is named by a normalized path.** Two gates were red from stale test binaries built under a target path containing `..`, not from the code. → `implementation/dev-workflow.md` → Gate (`--private-target`).
16. **A builder who drafts the tool before its suite says so, and shows the suite red against a stub and its mutants killed.** That is weaker than red-first and stronger than nothing; a brief that wants red-first for tooling must say what counts when the tool is one script. → `implementation/dev-workflow.md`.

*Added 2026-10-08, by the task that corrected the workflow doc after the second repair of the `test` half (the plan's `K8`). Each is grounded in a commit of that repair or in a probe's judged result; where a count is the orchestrating session's and no committed record holds it, the lesson says so. None is folded.*

17. **Probe the runtime before cutting tasks on it.** Three tasks of the second repair were cut on what the Workflow runtime does, and nobody had seen it do anything. Four probes of minutes each (`1d21024e`; the judged results under `re-review-test-half/probes/`) found that a line relayed through an agent never arrives byte for byte, that a return which omits a required field throws — three tries of three — and that a detached job outlives its starter. A canary of several hours would have stopped in its first minute, at the first state read. *Rule:* a fact about a runtime that a task is cut on is observed first, by an invocation that works on no run and that a script judges. → `implementation/stabilization-workflow.md` → The runtime probes; `implementation/milestone-planning-workflow.md` → Detect gaps.
18. **A simulation whose stand-ins copy bytes proves nothing about a relay through a model.** The committed simulation ran the harness through whole stages on every gate and relayed every line byte for byte; the real relay failed twelve of twelve (`probes/relay.json`), because an agent's structured return decodes the escapes a tool prints. On a line that is ASCII by construction it was whole twelve of twelve (`probes/relay-digest.json`). *Rule:* what goes through an agent's hands and is held to a hash is semantic, ASCII and a bounded digest — ids, words of a fixed list, counts, hashes — never a document; and a stand-in for the relay does to a line what the runtime was observed to do (`c2169e19`, `a99b7639`). → `implementation/stabilization-workflow.md` → The simulation of a stage; `implementation/pinning.md`.
19. **A named workflow is loaded once per session.** The harness's self-test reported 373 checks invoked by name and 421 invoked by path, in a session that had edited the script between the two (`probes/README.md`). Nothing in a script can know that it is the stale copy. *Rule:* a workflow is invoked by its script's path in any session that may have edited it — and a tool that prints an invocation prints the path (`8c0513e5`). → `implementation/stabilization-workflow.md` → Invoking the harness; `implementation/increment-workflow.md` → Orchestration, for the build harness.
20. **An agent that improvises a shell stops on a permission prompt.** Told to start a command *in the background* and wait *in slices*, the hold probe's agent composed a waiting shell that no permission rule can name, and stopped on a prompt nobody was watching (the human's ruling of 2026-10-07). *Rule:* every command of an unattended stage is one plain invocation of a committed tool — no pipe, no redirect, no second command — and a fence holds the prompts **as composed**, not the source: its first run was red on 152 faults (`bbe873eb`, `a182c92e`). → `implementation/stabilization-workflow.md` → Reading the next step; `implementation/increment-workflow.md` → Orchestration.
21. **An allow rule needs the tool to hold the line the deny rules held.** The settings' deny list binds what an agent *types*: a rule on a typed `git push` does not see a push made inside a tool. So a tool that is allowed by its first word must itself be unable to do what an agent may not — the step tool takes no branch name without a prefix, forces nothing, and vets every push it makes (`e76ef470`), and its suite reads every git call it can run (the re-review's `harness-doc.md` → *Checked and correct*). *Rule:* before a tool is put on an allow list, its own suite holds every act of it to *What agents may not do*; the allow rule is then written from the list a fence prints, never from memory. → `implementation/release.md` → What agents may not do; `implementation/stabilization-workflow.md` → Who owns which rule.
22. **Scale is the human's question, asked early.** The second review round returned thirty-six findings, and the review of the plan for them ten more (`plan-review.md`, `B1`–`B10`). Put to the human as one question, he chose to repair before first use only what can publish unscanned, record falsely or strand state, and to tune the rest across real rounds, as recorded rows (`c89d2cab`; `DECISIONS.md` → *2026-10-07 — The second repair of the `test` half, reviewed and ruled on scale*). *Rule:* when a review returns more than a plan can close before the thing is used, the scale is put to the human before the plan is recut — what must hold before first use, against what a real run may tune — and every finding that is not fixed gets a row with a due point in the same motion. → `implementation/milestone-completion-workflow.md` → Plan (triage); `implementation/stabilization-workflow.md` → Why this shape.
23. **Builders decline to edit agent definitions and settings on a relayed approval — so those edits are the orchestrating session's own gated commits.** Lesson 6, met again: a builder asked to follow the harness in nine definitions declined, and the plan had already reserved the step (`083d4745`, `6d30208f`; the entry of 2026-10-08 calls it the third on record). *Rule:* a plan lists every edit under `.claude/agents/` and of the settings as a step of the orchestrating session, each small and each behind its own gate — and a permission is put to the human, never granted by an agent. → `implementation/increment-workflow.md` → Orchestration.
24. **Red-first slips under pressure.** Several builders of the core wrote tests after code and said so: the two scripts before their tests (`e76ef470`), the harness before its arms (`a99b7639`), a change drafted in a scratch copy while a gate ran (`b36b8c93`), and single arms in four more commits, each held by mutants afterwards — the orchestrating session counts four builders of nine. What made it hold where it held was naming it first in the brief and asking for the red output in the return. *Rule:* a brief says *red first* before anything else and asks that the red output be kept and returned; where it slipped the builder says so, shows the suite red against the parent and its mutants killed (lesson 16), and the commit says which arms those were. → `implementation/dev-workflow.md` → Red.
25. **A repeated paragraph is fenced byte-identical.** A sentence added to six of the eight definitions that carry one paragraph turned the harness fence red, and a gate with it (`6d30208f`: arm (e)). *Rule:* a sentence added to a paragraph that several definitions repeat goes into every copy or into none — search for the paragraph's opening words first. → `implementation/increment-workflow.md` → Orchestration.
26. **A commit's gate is on the committed tree — so the status is read before the commit.** The first of two commits on the definitions went out without its `DECISIONS.md` entry and said so, and the second carried it (`083d4745`, `6d30208f`); by the orchestrating session's account an entry that silently failed to be written was caught only because the status was read before committing. *Rule:* `git status` and the diff's stat are read after the last edit and again before the commit; a file an edit reported written and the status does not show is not in the tree, and a gate that ran before it was written is a gate of another tree. → `implementation/dev-workflow.md` → Gate.
