# F4 (EC-26) — the robust case

## 1. The hole is in a declared surface, not a capability wish
`design/assistant-adapter.md:52` — *"`setup` commits its own install, and only its own install (M48)"*, *"enumerated, never a blanket `git add -A`"*, purpose: *"so the scaffolding never rides the user's first `finalize`."* At HEAD that sentence is **true of paths and false of bytes**. Razor leg 0/1 is fully available; the charter's Tier-3 "capability cell" label is the mis-tiering B4 names.

## 2. Driven on `1.0.0-rc.14` (installed binary, `dev/jigc-rig bare`)
**Cell A — the staged intermediate disappears.** User commits `CLAUDE.md`, stages version A, keeps editing to B:
```
git status --porcelain → "MM CLAUDE.md"   (staged A, worktree B)
jigc setup             → EXIT=0, ack says nothing
git show HEAD:CLAUDE.md → v1 + STAGED-ONLY-LINE-A + WORKTREE-WIP-B
git status --porcelain → (empty)
```
Both the staged and the unstaged WIP land in `chore(jigc): install jigc workspace config`, and **the tree ends clean**. There is no residual signal that WIP existed; the staged intermediate survives only as a dangling blob.

**Cell B — the adopter who already had hooks (worse, and in no EC row).** Pre-existing `pre-commit` rejecting `AWS_SECRET`; user has an uncommitted `AWS_SECRET=hunter2` line in `CLAUDE.md`:
```
jigc setup → EXIT=0;  git show HEAD:CLAUDE.md → contains AWS_SECRET=hunter2
```
`setup.rs:1709` passes `--no-verify`, so the adopter's *own policy gate* was bypassed on the adopter's *own bytes*. The recorded rationale (`setup.rs:1603`, *"the only hook present is the warn-only pre-commit setup just installed"*) is driven false — setup preserved the user's hook and then skipped it. And in the **same commit** setup installs `.claude/skills/jigc/SKILL.md:275`: *"jigc never passes `--no-verify` — your `pre-commit`/`commit-msg` hooks are policy."* One invocation authors a law-1 lie and violates it.

## 3. Narrating is consent-after-the-fact, and the record already settled this direction
`finalize.md:159` is explicit: the M30/B1 *"surfaced, not prevented"* rationale stands for the **left-out** direction and is **superseded for the carried-in one** — a foreign pre-staged change silently riding a jigc commit earns *"a second sanctioned refusal."* Cheap re-applies the retired answer to the exact direction the record retired it for. A print after `git commit` is a receipt, not consent: by then history moved and the tree is clean.

**Same class as M43, harder cell.** M43's gate was the lacon trial's #1-ranked v1 gate. It binds the doors where the user has *already met jigc*. `setup` is the **first door any adopter ever runs** — no `--carry-staged` habit, no jigc mental model, and the pathspec is precisely where a user's own edits live (`CLAUDE.md`, `.claude/settings.json`, `.jigc/.gitignore`).

## 4. One-way door
Two ways. (i) **Consent shape is a 1.0 contract**: adding a refusal + flag at `setup` after 1.0 breaks any dirty-tree/CI invocation — under F6's own policy a behaviour break, i.e. expensive-to-impossible. Now it is free. (ii) **Every adopter takes the swallow once**, at install, before they know jigc exists to blame.

## 5. The cheap counters
- *"Idempotent, and the commit is recoverable."* Idempotence covers setup's own files, not the user's bytes. Cell A ends with a **clean status** — nothing prompts recovery; cell B's harm is committed history and a bypassed policy gate, which `git reset` does not undo once pushed.
- *"M49 declared bootstrap must not be circular."* That bound is about refusing over a **drifted managed corpus** — a jigc-state question setup can't answer un-installed. This question ("do my eight paths carry bytes I didn't write?") is answerable by `git` alone, pre-install. And the guard need not block the **install** — only the **commit**, leaving the files written and staged with a route. Non-circular by construction.
- *"A pathspec-scoped snapshot is a new primitive."* G5 verified `decide_carryover(snapshot, current)` takes **in-memory** values, and setup mints+commits in one invocation, so nothing persists and `MINT_DOORS` is untouched. The delta is a **filter of the snapshot by the pathspec setup already computes** — a filter, not a primitive. (Unscoped would be wrong: baseline §4 drove that an unrelated staged `feature.txt` is correctly untouched.)

## 6. Minimal-correct scope
Filter the staged/worktree probe to setup's own pathspec; if any member carries bytes setup did not write, **refuse the install commit** (files stay written+staged), one blocking routed finding per path, `--force` as the single consent (the destroying-door mold), plus scope or drop `--no-verify` for that commit. Docs: revise the two locked sentences with their basis (subject widens from *task-minting door* to *any door committing paths it does not own*), re-derive `assistant-adapter.md:52` to say bytes, scope the guides' `--no-verify` universal — that last half is owed under either arm. D1's stated-at owe-set question is already open for EC-2; setup rides it.

**Honest weakness:** `--force` at a first-run door risks reflex-training (M46's measured ground for refusing the `--ignored` refusal). Answer: unlike build output in a worktree, user bytes at exactly those eight paths are *not* the ordinary success path, so the guard is rare, not routine.

**Verdict: robust-now** — a declared sentence is false at the one door every adopter runs first, it swallows the user's bytes and bypasses their own commit policy at exit 0 with a clean tree afterwards, and the consent shape is cheap only before the 1.0 pin.
