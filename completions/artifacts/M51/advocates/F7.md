# F7 — the robust case (independent advocate)

## The hole the cheap cut leaves

`design/command-output-contract.md:446` states the wave's own rule: *"an undeclared key on a
pinned envelope is a defect, not an addition, whichever wave mints it"*, and *"from that pin
this contract's shapes evolve solely by an explicitly versioned extension."* **The rule
quantifies over a set that has no extension anywhere.** Verified at HEAD: `Tier` in
`crates/cli/tests/text_json_parity_axis.rs:91` has exactly two members — `Fenced` and
`Judgment` — i.e. *fence-ability*, never *pinned-ness*; `grep -c "as_object\|\.keys()"` in that
file returns **0**, so no key-set is asserted anywhere. Doc-side, *"The three surfaces this
pins"* (`:13`) covers composed output, write-acks and findings — and ~14 shipped envelopes ride
in none of them while the same doc later declares keys on four of them.

So on 1.0.0 day the rule is unanswerable in both directions: a driver cannot ask *is
`identity` on `unmanage` contract?*, and the next wave's fixer cannot ask *may I delete it?*
That is a **hollow declared surface** — the contract is shipped, its subject is not reachable.

## The one-way-door tell — and why the cheap cut is worse than nothing here

The 1.0 pin is the canonical one-way door: after it, deleting a key is **command-output
contract v2**. The cheap arm's `keys:` column *derived from what the binary emits today*
therefore does not merely fail to close the hole — it **blesses 17 accidents into contract by
construction**, converting "arguably not pinned, therefore deletable" into "asserted by a
standing test as the key set." I re-derived the class independently rather than relaying it:
of 12 sampled keys (`uninstalled`, `identity`, `reslugged`, `overlay`, `layer`, `rejected`,
`prose_mentions`, `moved`, `displaced`, `guide_file`, `install_commit`, `knobs`), **11 appear
in no `design/` file at all** and `knobs`' single hit is `multi-pack.md` in an unrelated sense.

EC-3's own premise is falsified in the same motion — `hook_committed` **is** declared
(`assistant-adapter.md:56`, 1 hit) — and its class is ~4× the stated four. That is precisely
the signature this repo has now hit **five consecutive waves**: *a fix applied where its wave
pointed is not applied at all* (M45's claim; M49/M50 audits each found larger classes than
reported). The cheap arm is that failure, at the one boundary where it is irreversible.

## Trajectory, not generality

This is not a hypothetical need. The vision commits to the CLI as the **sole channel** and this
doc declares itself the owner of *command-output contract v1* (`:399`). *Which envelopes are
pinned* is the first question a driver asks, and `--format json` exists for machines only — an
operator reads text. Naming the set a locked doc already quantifies over is **the job**, not
gilding.

Three anomalies make the cost concrete, each free to decide now and a v2 to decide later:
`task list` is a top-level **array** (`render.rs:3285`) that can carry no `schema_version`, no
`findings`, no discriminator — pin it and a driver can never deserialize one envelope shape;
`milestone execute` is a **fourth** composed producer against the doc's *"three verbs"*, and
the shipped registry already says so in its own words while the locked doc does not;
`milestone finalize` landed emits `{committed}` **alone** (`render.rs:4040`) against `task
finalize`'s `{committed, findings, schema_version}` — two sibling committing doors, frozen
mid-disagreement.

## The strongest cheap counters, answered

- **"47 hand-written key lists are churn."** The table exists:
  `format_json_success_axis::Recipe` (`:389`), 47 rows, already bijected against the clap tree
  and already driving every verb to a genuine success. This is a **column**, not a table. It
  goes stale only when a verb's envelope changes — which is exactly when it must redden.
- **"A registry is itself a one-way door."** The doors are asymmetric. `Unpinned(reason)` is
  reversible — pinning later is additive and the window's successor regime handles it. A key
  blessed into the pin is not: deletion costs v2. Take the reversible door.
- **"Most of those 14 are operator-facing, not driver-facing."** Then say so — that is one row
  each, and saying it *is* the deliverable. Left unsaid, the pin decides it silently and
  wrongly.
- **"The additive window is open, keys can be added later."** The window closes **at the pin**
  (both evolution-posture homes key it there, deliberately not to a wave name). And the problem
  is not adding; it is deleting and disclosing.

## The robust scope — minimal-correct, and narrower than the fork states

1. `Recipe` gains `arm` + `Pinned(&[&str]) | Unpinned(reason)`; the bijection reshapes from
   distinct-path to distinct-(path, arm) — needed anyway for the two arm splits.
2. The 17 undeclared keys **disposed before** the pin: declare in the doc's own paragraph form,
   or delete (candidates: `hook_output` on the `VerbKind::Read` verb, structurally always `""`).
3. `command-output-contract.md`'s three-surface section names the registry as the list.
4. `schema_version`: fence the **partition** against that registry — typed result values carry
   it, ad-hoc `json!` envelopes do not. **Concede the fork's maximal arm:** adding
   `schema_version` to ~40 envelopes is real gold-plating; refuse it on the record.
5. The three anomalies decided, one row each.

Also concede: the **doc-side** half (a parser reading key bullets out of markdown) should be
refused — `pinning.md` §3 already refuses that class by name.

Shape and size match M50's `WORK_UNIT_ID_DOORS` (25 doors × 4 cells) and `MINT_DOORS`: **one
increment**, of a kind this repo has now shipped four times.

**Verdict: robust-now** — the contract's own rule is unenforceable without the set, the cheap
`keys:` column actively pins 17 accidents, and this is the last wave in which any of it costs
less than a v2.
