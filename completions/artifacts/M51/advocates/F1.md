## 1. The hole two guards leave

The cheap cut answers *this* defect at *these two* sites. After it the path family is still the only one of five with **no registry, no ⇔ fence, no axis suite** (tokens §1). Left open: `config insert-step <file>` lands arbitrary host bytes as a committable in-repo file that **composes into the step text `jigc start` hands the agent** (`repositoryformatversion = 0` rendered into a workflow, driven, §2d) — the adapter boundary, not a papercut; `value` at `config set docs-root` is `Plain`, becomes a path component at a **moving** door, and sits in Tier 3 under a different predicate with no shared decision (§B10); and `worked-examples.md:3358`, a **locked acceptance chapter**, still asserts *"no caller-supplied token becomes a path component without the door validating it"* over *"Four token families"* — M46's razor shape exactly: stated in one place, violated in another.

## 2. What the registry buys that two guards do not

The precedent is this repo's own. M50 derived `DOCTYPE_DOORS` from a hand-kept `*_ARG_IDS` allowlist; `spec_addr` was not on it; `milestone add-from-spec spec:../../../<outside>/planted` **read outside the repo at exit 0** — the M50 audit's HIGH. The fix was totality: erase the complement, so a new argument reddens until someone answers. `ArgToken::Plain` is total over **ids** and silent about **path-ness** — `cli.rs:1545` says so: *"nothing can check `Plain` from the outside."* The identical failure mode is live one level down: the next path-taking argument joins `Plain` and no test notices. Two door guards do not move that; a ⇔-fenced registry does. Same class the record names six times (*a fix is complete over its class's axis, not its reported repro*).

## 3. One-way door

## 4. The cheap counters, answered

- **"Five members ask four different questions."** Correct, and irrelevant: `ROOT_KNOBS` is already one registry over **three** predicates (`unusable_root_reason`, `is_workbench_root`, `untrackable_reason`). A registry claims *enumerated membership with a stated answer per member* — never a shared predicate. The robust arm as chartered explicitly admits *a stated no-rule-and-why*.
- **"`from_file` is an unbounded read by design."** Then that is its row, in one sentence, fenced. Today `from_file`'s licence and `path`'s **absence** of a rule are the same token (`Plain`) — indistinguishable to the next author. Note `file` ≠ `from_file`: it persists host bytes in-repo and into agent context; the by-design argument was never made for it.
- **"A list wearing a class costume."** The charter already permits shipping it as a named list with a fence over the list, and saying so — still strictly more than two guards, with its falsification test written.
- **"Premature generality."** The property is already claimed in a locked acceptance chapter. It is the job.
