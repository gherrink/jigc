# F3 (EC-29) — the robust case: the transaction restores the worktree too

## 1. The hole the cheap cut leaves

The cheap arm does not *keep* a declared rule — it **declares a new one**, and pays for it by
narrowing two existing statements at the 1.0 pin. `finalize.md:178`'s *"worktree untouched"* sits
**inside the restore mechanism's parenthesis** (`update-index --cacheinfo` does not touch the
worktree); every sibling row restores worktree bytes explicitly (`:174`, `:175`, the record row's
*"the worktree never reset to HEAD"*). Two independent gap reports reached that reading
(decisions §B9, docs §B6). And `DECISIONS.md:4788` — written by the M45 audit that *made* this
fix — says it rolls back **"every path jigc's own staging contributed"**. The people who built it
believed the sweep was complete. Cheap means editing that sentence to say less.

## 2. Driven: the residue's worst cell is unrecoverable loss under a clean status

Spike (debug rc.14, `dev/jigc-rig committed-singletons`, script at
`scratchpad/advocates/f3-spike3.sh`). A user adds a private line to `.jigc/.gitignore` and has not
committed it; the committed copy is canonical:

```
BEFORE-STATUS:  M .jigc/.gitignore     ← worktree: …logs/ + "# my own note" + "my-private-dir/"
jigc task finalize …  (pre-commit exits 1)
  "`git commit` was rejected (no commit was made): … task … is intact — nothing was committed"
FINALIZE EXIT=1
AFTER  .jigc/.gitignore: tasks/ index/ state/ milestones/ worktrees/ logs/ displaced/
AFTER  git status --porcelain:            ← EMPTY. the tree now reads CLEAN
HEAD unchanged
git log --all -p -- .jigc/.gitignore | grep -c my-private-dir  →  0
```

The user's bytes exist in **no git object**: unrecoverable. And because the rollback restored the
index, `git status` is **clean** — so the transaction that reports *"nothing was committed"*
destroyed user content and left no signal at all. That is a law-1 lie in the single message a user
reads while recovering, and M47 built the survivable-hook-rejection frame precisely to carry a
**per-door state-truth clause**. Honest bound: this cell is EC-29 ∧ EC-18 — which is why the
charter's robust arm names both. Fix EC-18 alone and the loss goes; the dirty-tree residue stays
(baseline §5 drove `.jigc/version` on a differing build: clean tree in, ` M .jigc/version` out).

## 3. Common path, not an edge

*Upgrade jigc → finalize → hook rejects.* No perturbation. Hooks reject routinely (that is what
they are for), and `.jigc/version` differs from the committed stamp for **every** user on the
finalize after an upgrade — the exact case `:178`'s own justification names. `.gitignore`'s arm
fires for any corpus whose `.gitignore` predates an `ENTRIES` addition — i.e. every pre-M39 corpus.

## 4. The cost is small because the primitive exists

`milestone.rs:706` `RecordPreImage` is already `(bytes: Option<Vec<u8>>, index)` with the
*"absent means absent, never unreadable"* discipline written down, plus
`rollback_record_pre_image`. The config layer needs the same two-axis pre-image over
`jigc_config_layer_pathspecs()` (3 specs), captured **before** `task.rs:2778`
`gitignore::ensure` and restored at the existing failure site `task.rs:2882` — **one capture
point, one restore point, both already there**, and that site covers every arm including the
fan-out `--ff-only`. Plus EC-18's amend-or-refuse (~6 lines; G10 prices idempotence across four
callers and the golden re-derivation). Tests: {stamp differs, entry missing, first finalize
(absent)} × {stage fail, commit reject}. This is one increment, not a wave.

## 5. The strongest cheap counters, answered

- **"M45 decided it deliberately."** It decided the *index* leak. The prose that reads as a
  decision is a mechanism clause, and the wave's own summary contradicts it. Under M45's own
  complete-fix contract the axis is {5 families} × {index, worktree}; four worktree cells are
  covered, one is not — the incomplete-sweep shape, on the doc that names the sweep.
- **"A re-stamped `.jigc/version` is arguably correct state."** Conceded as arguable — but
  `storage.md` grants the refresh to a **store-writing op**, and this op wrote nothing. If the
  stamp really is correct-to-keep, that is a **per-path exemption**, which is the robust arm's
  shape (`Snapshot::Exempt(<reason>)` already models it), not a reason to leave the dimension
  un-swept while `.gitignore` sits in the same pathspec set.
- **"A worktree restore could clobber the user's edit."** Inverted: the capture is taken *before*
  jigc writes, so the restore puts back **the user's bytes** — the very bytes today destroys. The
  only window is a concurrent edit mid-finalize, which promotions (`:174`) already accept.

## 6. Why "declare the residue" is the regretted move

The record has twice recorded a cheap-with-a-declaration whose warrant was later **driven false**
(M50's `milestone discard` narrating arm — *"its worktree refusal already carries the consent"*;
M46's stale bounds struck). Here the warrant is falsified *before* the decision: the declaration
would ship at the 1.0 pin, into guides that are SKILL.md by construction, while the driven cell
loses bytes.

**Verdict: robust-now** — the residue's driven cell is unrecoverable user data loss reported as
*"nothing was committed"* under a clean `git status`, the reach is the ordinary upgrade→reject
sequence, the capture primitive already ships, and the cheap arm's premise (an existing
declaration to keep) is false in the doc it cites.
