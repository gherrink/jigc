# M51 — the envelope key census

**What this is.** [settle-record.md](settle-record.md) → D5 decided the pinned-envelope registry is minted **code-side, before the pin**, with the recipe table's one-per-verb bijection **reshaped to `(path, arm)`**, each row `Pinned(<declared key set>)` or `Unpinned(<reason>)`, and *"the 17 undeclared keys across 10 verbs disposed **before** the pin"*. This document is the census that decision rests on: **every leaf verb × every arm that produces a distinct top-level key set**, driven, with each key's declaration, its test, its value's nature, and a proposed disposition.

## Provenance

- **Binary:** `target/release/jigc`, `jigc 1.0.0-rc.14`, repo HEAD `74627547`, worktree clean. No `cargo` invoked.
- **Axis:** `cli::cli::VERB_KINDS` (`crates/cli/src/cli.rs:1412-1465`) — **47** leaf verbs (13 top-level · 11 `doc` · 6 `task` · 8 `config` · 9 `milestone`), fenced total against the clap tree by `cli_parse::every_leaf_verb_is_classified`.
- **Corpora:** `dev/jigc-rig bare` and `dev/jigc-rig fresh`, plus two derived bases (`adr` — one committed ADR through a finalized `single-task`; `spec` — one committed spec with a populated repeatable) built by driving the binary. Every arm ran in its own `cp -a` copy.
- **Driving scripts:** `$SCRATCH/key-census/{lib,a-top,a-top2,a-doc,a-task,a-cfg,a-ms,a-rest,a-last}.sh`; raw envelopes in `$SCRATCH/key-census/raw/`; the consolidated run log in `all-arms.txt` (**122 driven invocations**). The 48-row predecessor sweep — [baseline-envelopes.md](baseline-envelopes.md) §1, `$SCRATCH/baseline3/sweep.sh` — was reused for its three bases and re-driven for every row it covered; **every one of its 48 rows reproduced byte-identically**.
- **Declaration column rule:** *declared* means the key name appears in a `design/` document **in prose or a JSON block about that verb's envelope**. A name that appears only in prose about a *different* envelope is marked **homonym** and counted undeclared, because a driver reading coc:43's `removed` learns nothing true about `jigc uninstall`'s. A name that appears only in a Rust doc-comment is **undeclared** — `design/` is where the contract lives.
- **Test column rule:** **closed-set** = a whole-object/whole-stdout equality (a stray key fails). **value-carry** = `text_json_parity_axis::carries()` — the key is present *and* value-identical to the field the text printed. **presence-only** = the key is read but its value is not compared. **none** = no test names the key.

## 4 · The anomalies

### 4.1 · `jigc task list` — the only top-level array (F-new-3, reproduced)

Driven: `jigc --format json task list` returns `[]` on an empty corpus and `[{"id":…,"intent":…,"workflow":…}, …]` on a populated one (`render.rs:3285` `json(&rows)`). Every other one of the 58 success arms is an object or — on `doc show`'s two fragment arms — a bare scalar/map. Consequences, all driven:

- It **cannot** carry `schema_version`, so `doc-read-surface.md`:185's *"a top-level key on **every** result envelope"* is false here by construction, not by omission.
- It carries no `op`, so a driver that deserializes one ack shape across the `task` family has to special-case this verb.
- `task_list_parity` (`text_json_parity_axis.rs:848-870`) value-carries the three **row** keys and asserts nothing about the array-ness, so the shape is pinned by nothing.

**Disposition: Declare, not reshape.** D5's own asymmetry argument runs the other way here — a `Pinned` row is irreversible but a *shape change* to `{tasks: […]}` is a breaking change to a surface a driver reads on every loop, and the 1.0 pin is the next gate. Declare the array form in `command-output-contract.md` with the three row keys, and state the two things it therefore cannot carry.

### 4.2 · `jigc milestone execute` — the fourth composed producer (F-new-1, reproduced)

`command-output-contract.md` §1: *"**Three verbs** emit this composed shape … `jigc start`, `jigc workflow`, and `jigc migrate`. All three render through the one `render::composed` json arm."* Driven: `jigc --format json milestone execute cache-rework` → `{"task": "…", "text": "…"}`, rendered at `crates/cli/src/milestone.rs:3485` `render::composed(format, &view)` — **a fourth**. `text_json_parity_axis.rs`'s registry entry for `milestone execute` says so in its own words, so the code-side census knows and the contract doc does not.

**And the closed-key fence covers two of the four.** All five `assert_eq!(keys, ["task","text"])` sites (`compose_task_minted.rs:332`, `compose_statefulness.rs:325`, `compose_create_gates.rs:237`, `flow45_acceptance.rs:542`, `start_compose.rs:2481`) drive `start`/`workflow`. Neither `migrate` nor `milestone execute` has one.

**Disposition: Declare** — §1's producer list becomes four, and the registry row for `milestone execute` is `Pinned(["task","text"])`, which is the mechanism that stops the list and the binary disagreeing again. D5 already settled this direction (*"the doc takes the registry's membership, because the code-side census names `render::composed` explicitly"*).

### 4.3 · `hook_output` on `jigc milestone list-tasks` — a commit-hook key on a read verb (F-new-2, reproduced)

`milestone list-tasks` is `VerbKind::Read` (`cli.rs:1459`) and emits `{"hook_output": "", "text": …}`. It shares `render::milestone` (`render.rs:3698`) with five **write** siblings, and `hook_output`'s declaration (coc, the M45 additive-key ¶, widened 2026-07-24) is scoped to *"the landed-commit envelopes… the `rename`/`migrate-corpus` reports and the milestone **record-only op acks**"*. A read verb is none of those; it commits nothing, so no hook can ever speak, and the value is structurally `""` forever.

**Disposition: Delete** — D5 already decided this one. The mechanism is a read-specific arm off `render::milestone`, not a declaration; the five write siblings keep the key.

### 4.4 · Three further anomalies this census found beyond the Settle's list

- **The exit-4 migration review hold is an entirely undeclared, entirely untested envelope.** `jigc task finalize <migration-task>` without `--approve` emits `{review, rewrites, source, task}` at exit 4 (`render.rs:4176-4192`). The *exit code* is declared (`command-output-contract.md`:389); **not one of the four keys is**, and `grep '"review"\|"rewrites"' crates/cli/tests/` returns zero assertions. This is the one envelope a **human-gated** door hands a driver, and `review` can only ever hold the string `"pending"`.
- **`jigc start` has a fourth orientation arm the 48-row sweep never reached.** Driven on a repo with a live task, orientation emits `{header, next_steps, schema_version, state, **tasks**, workflows}` — six keys, not five. On a repo with no `.jigc/` it emits `{state, schema_version}` — **two**. So `start` alone spans three distinct key sets, which is exactly why D5 reshaped the bijection to `(path, arm)`.
- **`jigc config set`'s relocation is invisible in the envelope, reproduced.** Driven on the `adr` base: `jigc --format json config set docs-root documents` relocated one committed doc (stderr narrated the `git mv`; `git status` showed `R docs/decisions/cache-strategy.md -> documents/…`) and stdout was **byte-identical** to the non-relocating arm — `{committed, key, op, value}`. EC-4 confirmed on the live path, and the D5 rider (`ConfigAck::Set` gains `relocated`) is the fix.
