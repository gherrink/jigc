## 2 · The hole, driven by me on `1.0.0-rc.15` (not relayed)

**(a) The revert cell — exit 0, every commit door, git's own recovery destroyed.**
```
git revert --no-edit <sha>            # conflict; .git/REVERT_HEAD + .git/MERGE_MSG written
<resolve>; git add rz.txt             # a real resolution, staged
jigc milestone create "Mno milestone" # exit 0 · "record commit: 49735db — ... anything else you had staged stayed staged"
ls .git | grep REVERT_HEAD            # (none)
git revert --continue                 # error: no cherry-pick or revert in progress / fatal / exit 128
```
**What the user loses**, priced from the bytes I captured before the door ran: `REVERT_HEAD`
(`35cd310…` — *which commit was being reverted*) and `MERGE_MSG`:
```
Revert "z1"

This reverts commit 35cd3102faab308456ffe175105c910c45e33019.

# Conflicts:
#	rz.txt
```
Both destroyed. The payload survives in the index, orphaned: no operation, no message, no target sha
except from the user's memory. The ack's *"anything else you had staged stayed staged"* is true of
the bytes and a **law-1 lie about the operation**. This is tier 0 by M52's own predicate — repository
harm at exit 0 through a committing door.

**(b) A cell no baseline drove: the *clean*, non-conflicting `git merge --squash`.** Not an error
state — the ordinary workflow, awaiting the user's commit message:
```

jigc milestone create "Sq milestone"  # exit 0
ls .git | grep SQUASH_MSG             # (none)  — the squash message, every commit it listed, gone
git status --short                    # A  feat.txt   (payload staged, now unattributable)
```
The baseline's L3 showed the *conflicted* squash swallowed whole by `task finalize --carry-staged`.
This shows the **common-case** squash damaged by a **pathspec** door — git's partial-commit guard,
which accidentally protects the cherry-pick cell, does not exist where git wrote no marker it reads.
Any argument that the un-named states are exotic dies here.
