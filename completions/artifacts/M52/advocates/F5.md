## 1 · The hole the cheap cut leaves

**(a) The one-alias cell, driven end to end — the product acts on an identity it does not have.**

```
$ jigc doc set-slot "roadmap:bogus#milestones/m-alpha/proves" --from-file - --task advocate-one-alias
  exit=0   set slot roadmap:bogus#... (copied in for update — re-promoted at finalize)
$ jigc doc set-slot "roadmap:bogus#milestones/m-alpha/decomposition" ... --format json
  {"chars":24,"copied_in":false,"findings":[],"op":"set-slot",
   "target":{"doctype":"roadmap","item":"m-alpha","leaf":"decomposition","section":"milestones","slug":"bogus"}}
$ jigc task finalize advocate-one-alias   → exit 0 · finalized c75cd36 · promoted docs/roadmap.md
$ git show --stat HEAD                    → docs/roadmap.md | 4 ++--
$ jigc validate                           → exit 0
$ jigc doc list                           → roadmap:roadmap  docs/roadmap.md  managed   (no `bogus` row)
$ jigc doc show roadmap:bogus             → exit 1 store.not-found ("its only address is roadmap:roadmap")
```

The committed repository is **materially and correctly rewritten**. Every read surface says the
identity that wrote it does not exist. The pinned write ack hands the driver `target.slug:"bogus"`
with `findings: []` — a clean success keyed on an identity the stable `(code,target)` contract can
never match against any later finding.

**(b) The new datum — the cell defeats M48's read-back fence structurally, not by omission.**
Between the write and the finalize there is **no address at which the agent can read what it wrote**:

```
$ jigc doc show roadmap:bogus  --task advocate-one-alias → exit 1 store.not-found
$ jigc doc show roadmap:roadmap --task advocate-one-alias → exit 1 store.not-staged
        "…is not staged in this task — only its committed copy exists"
        route: `jigc doc show roadmap:roadmap…` — the task-less read serves the committed copy
```

An agent that does exactly what M48's `read.staged-read-back` fence trains it to do is told, twice,
that its own in-flight work does not exist — and the route it is handed serves the **stale committed
bytes**. That is the 1.0.0-gate trial's headline measurement (4/4 VERB on the read-back) landing in a
cell where the capability it measured cannot answer. The cheap arm closes this *at the six doors it
names*; it leaves nothing behind that explains why the surface behaved this way anywhere a driver
reads.

**(c) `rename --slug`, re-driven first-hand — jigc's own printed route lands the write.**

A `COMMITTING_DOORS` ∩ `MovesOnBehalf` member commits a rewrite of the real `VISION.md` under a
never-existing identity, and it does so **because the refusal one cell earlier told it to**. This is
G-1's un-admitted row: in fork 5's class, reached by no arm the charter states.

**(d) The declared surface is hollow, and the pack points at the hole.** `doc schema roadmap
--format json` (contract-version 6, driven) emits `"add-item": "roadmap:<slug>#milestones"` — the
1.0-pinned, separately-versioned *schema-read contract*, whose whole purpose is that a driver can
construct only valid addresses, teaching the exact token five write doors then accept. And it is not
one step that points there: **five** methodology author steps compose *"The `<ty>` schema is the
authority on what you write into it … every address a write can take"* for a **placement** doctype
(`author-vision`, `author-roadmap`, `author-decisions`, `author-decision`, `author-ledger`) — in
`author-vision.yaml` eight lines after *"The slug is fixed (`vision`)"*. The product's own composed
instruction sends the agent to a surface that contradicts the instruction.

## 2 · The one-way-door tell — it fires, and this is the last wave before the pin

`doc schema`'s `contract-version` is the **only** channel by which this fact can reach a driver, and
`doc-read-surface.md:108` states the projection has **no additive carve-out** — every structural
change bumps. The same doc's evolution posture (`:88`, `:90`, the M48 discharge and M49's "last
spend") closes the window **at the 1.0 pin**, after which "an absent key is a decision, not an
oversight" and the identical addition is a minted versioned extension for the life of `1.x`.
M52 is chartered as the wave before that call. Deferring the projection is not "later"; it is
**never, or at 2.0 cost**.

**The bump is cheap, and the fork should not be argued as if it were expensive.** `contract-version`
is a serde field on `cli::doc`'s projection struct (`doc.rs:4580`). `schema_hash` is blake3 over
`erase_presentation(schema)` — an **exhaustive destructure of `engine::schema::Schema` alone**
(`manifest.rs:76-89`: `ty`, `location`, `id_from`, `description`, `usage`, `display_title`,
`placement`, `singleton`, `sections`). The projection is not a `Schema` field, carries no manifest
entry and touches no instance. **6→7 moves zero schema-hashes, zero `schema-version`s, zero corpora.**
The wave's stated freeze boundary is untouched.

And the fact needs **no new producer**: `engine::compose::projection_home_line`
(`compose.rs:1194-1215`) already answers for all three home shapes, including the one nothing else
handles (`location:` + `singleton`). The robust arm is *ask the shipped answer*, not invent one.

## 3 · The committed trajectory — this is the vision's own line, not "more"

- **Stable opaque IDs; identity changes only through one atomic CLI op.** Six write doors and a
  committing mover currently accept an identity the store cannot hold. That is not a gap in a
  nice-to-have; it is the invariant named in `VISION.md` and in CLAUDE.md's invariant list, violated
  at the doors that write.
- **The LLM places nothing, so it can misplace nothing.** Driven, the CLI *lets* it place — and then
  tells it, through the pinned ack, that the placement succeeded. The determinism boundary holds only
  if the CLI owns identity; here the caller's typo owns it.
- **Law 1 (nothing lies) at a `Route::mechanical` producer.** (c) is a printed route that, followed
  verbatim, commits the harm the same door just refused.
- **M45's complete-fix contract.** A rule-shaped fix names its axis. The axis here is *fixed-identity
  doctypes × every door that takes a `<slug>` head*, not *placement doctypes × the doors in the
  review's table*.

## 4 · The two stock rationalizations, refuted

**"No live case — it needs a manufactured pack."** False for the headline: every cell in §1 is driven
on the **shipped** packs, on the **release** binary, on a stock corpus. The manufactured pack is
needed only for the *`location:` + `singleton: true`* divergence (gap-doctypes B2) — and PB-1 ships
project packs as a supported capability (M49), so that shape is adopter-reachable, not hypothetical.
The cheap arm's `placement.is_some()` predicate is complete over today's **corpus** and incomplete
over the **rule** — which is exactly the shape the last five completion audits each widened.

**"Premature generality."** The unified predicate is *narrower* work than the cheap arm, not wider:
one boolean disjunct (`placement.is_some() || singleton`) on a predicate that already exists at
`store.rs:254`, and it retires `cli::doc::is_singleton_type` — a function **named** `is_singleton_type`
that never reads `Schema::singleton` (`doc.rs:6259-6262`). Four shipped seams already key on
`singleton` (`Schema::fixed_title`, the mint slug-fix, the pack-load copy-in fence,
`projection_home_line`); two key on `placement`. Unifying them is deleting a contradiction, not
generalising against a hypothetical.

## 5 · The cheap arm's price — and it is **not cheaper to build**

Measured, not estimated: **all six write doors plus both read doors already funnel through one
function.** `parse_verb_addr` (`doc.rs:6120`) has **nine call sites, every one in `doc.rs`** —
`run_set_field`, `run_unset_field`, `run_set_slot`, `run_add_item`, `run_remove_item`,
`run_retitle_item`, `run_doc_rename`, `run_show`, `run_show_staged` — and it **already holds the
pack**, so the schema is in hand with no new plumbing. A guard there is **one line in one home**.
The three remaining doors resolve their schema separately: `rename` (`rename.rs:986`),
`milestone add-from-spec` (`milestone.rs:1410`), `task bind` (`task.rs:2687`).

So the cheap arm's "guards at the six write doors + `rename --slug` + `add-from-spec`" is **eight
edits**; the robust arm at the parse boundary is **four homes** (one + three). The cheap arm is the
*more* scattered fix. What it actually saves is (i) one boolean disjunct and (ii) the projection bump
— and (ii) is the one-way door.

**The eighth door the cheap arm guarantees.** `task bind`'s singleton cell is unreachable today for
exactly one contingent reason: both shipped packs declare **one** `reads:` role and it is typed
`spec` (driven, baseline-tokens §2.3). The day any workflow declares `reads: [{role: vision, type:
vision}]`, door 8 opens with no guard and no fence that reddens. Under a `placement`-keyed predicate
the `location: + singleton: true` shape is door 9 and is **already open, driven** (B2) — a location-homed
singleton enforces its one-instance rule *nowhere*, and `doc show adr:bogus` there routes at
`doc create adr --title bogus`, which the same binary refuses. Post-1.0 that is a fix without a
channel to tell a driver about.

## 6 · The robust scope — the minimal-correct version

1. **One fixed-identity predicate**, in one home, reused by the read guard and the new door guard:
   `placement.is_some() || singleton`. Replaces `is_singleton_type`'s mis-named body; retires the
   two-predicate split `storage.md:216` blessed for the direction it stated and never for the converse
   (**revise** that paragraph's scope, with the driven converse quoted — not a silent reword).
2. **Land it at the parse boundary, not in `canonical_path`** — see §7.  One guard in `parse_verb_addr`
   + three sibling sites (`rename`, `milestone add-from-spec`, `task bind`).
3. **`rename --slug` refuses on the same predicate, and its `write.identity-change` route stops
   composing the caller's token** — it must print the canonical slug or no `--slug` at all.
4. **`doc schema` projects the home/identity fact** from `projection_home_line`'s existing answer,
   `contract-version` **6→7**, pooled with LD-2's `base` compound so the pin moves **once**.
5. **`author-vision`'s authority sentence** (and its four siblings) stops contradicting itself.

## 7 · Where the cheap side is right — conceded, on the altitude and on one pooled item

- **`canonical_path` is the wrong altitude, and I concede the robust arm's own worded default.**
  The *mechanism* lives there (`store.rs:49-55` never reads `slug` on the placement branch) but the
  *question* — "did the caller type an identity this doctype can have?" — is a **door** question, not
  a resolver one. The resolver has legitimate internal callers that pass a slug a placement doctype
  does not own (promote/reconcile/index paths resolving by type id); 35 grep-visible call sites across
  both crates, several on 1.0-pinned paths, with no measurement behind a behaviour change to any of
  them. Guarding there would be a wide blast radius bought for nothing the parse boundary does not
  already buy. **Robust predicate, door altitude** — that is the honest robust arm, and it is smaller
  than the arm as worded.
- **`milestone-record.base`'s `set:` kind (B3) should be the record correction, not the schema bump.**
  Bumping `milestone-record`'s schema **is** a hash move plus a corpus migration; the three locked
  records are what drifted. Correct the records. Only LD-2's *projection* half (type `string` vs
  `doc show`'s `{sha, short}`) belongs in the 6→7 move, and it is the weaker half of the pooling — the
  fork-5 case must not rest on it.
- **Honest bound on my own case:** the ≥2-alias silent payload loss is baseline-driven, not re-driven
  by me; §1(a)'s one-alias cell and §1(c)'s `rename` cell are mine, first-hand, on the release binary.

## Verdict

**robust-now.** The cheap arm is not the cheaper build — measured, it is eight edits against four,
because the six write doors already share one parse boundary. What the cheap arm actually buys is
deferring the **one-way door**: `doc schema`'s projection is the only channel that can tell a driver
`vision:alpha` is not an address, `contract-version` 6→7 moves **no schema-hash, no `schema-version`,
no corpus**, the answer already ships at `compose.rs:1194`, and the window closes at the 1.0 pin this
wave precedes. Defer it and the pinned contract teaches the wrong address for the life of `1.x`,
while a `placement`-keyed predicate leaves door 8 (`task bind`, one workflow line away) and door 9
(PB-1's `location:` singleton, already open and driven) unguarded — the un-swept-axis shape that has
widened five consecutive completion audits.
