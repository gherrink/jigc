# Why jigc — the evidence dossier

**Purpose:** the collected, sourced case for using jigc — every claim below carries its evidence and its honest bound. This is the raw material for positioning/adoption material; it is *not* marketing prose. Updated as evidence lands (last: 2026-07-25, at the final unseeded trial).
 One rule governs this file: **no claim without a source, no source without its caveat.**

## The thesis, in one line

Take every *structural* operation away from the LLM and give it to a deterministic CLI; leave the LLM only the prose. ([VISION.md](VISION.md) — the determinism boundary.)

## The name

**jigc** — pronounced **"jig-see"** — is **a jig for coding agents**. In woodworking and machining, a jig is the device that holds the workpiece and guides the tool so the cut lands in exactly the right place, reproducibly, regardless of who wields the tool. That is the product: the CLI is the jig, the LLM is the tool — structure is held deterministically, the prose is the cut. A jig doesn't do the cutting, and it doesn't let the cut wander; it makes the *tool's* work land true. Second reading, equally sanctioned: **j**ust-**i**n-time **g**enerated **c**ontext — the CLI assembles exactly the context a task needs, when it needs it. (Settled 2026-07-03; availability verified clean on crates.io/npm/GitHub/web.)

## Measured results (jigc's own studies — controlled, but ours)

- **The cost win (M35, pre-registered, 2026-07-02).** On the rename surface, jigc is *strictly cheaper than a plain agent* on all three models tested (Sonnet 4.6 $0.080 vs $0.125 · Sonnet 5 $0.129 vs $0.262 · Opus 4.8 $0.193 vs $0.266 per rename) **and ≥ static on completeness** (1.0 vs 0.875/1.0), at 3.5–4.6 turns/rename vs 8.3–14.4 manual. Verb engagement was 100% (64/64) — availability *did* induce usage. *Bounds:* directional not powered (2–3 reps/cell; ordering identical in every rep), synthetic seed. ([completions/artifacts/M35/VERDICT.md](completions/artifacts/M35/VERDICT.md))
- **Enforcement holds where instruction decays (long-horizon replication, n=16/arm, 2026-06-22).** Over a many-edit sequence: drift rate plain **88%** · jigc **19%** · jigc-with-gate **0%** · static instruction **0%**. The honest reading both ways: jigc's gate arm matched the best static arm at zero drift, **and** a well-maintained static instruction also hit 0% on this task size — jigc's durable edge is that the guarantee is *salience-independent* (it doesn't decay as instructions age or context fills), which a single-task study cannot show decaying. ([completions/artifacts/differentiator-pilot-study1/REPLICATION.md](completions/artifacts/differentiator-pilot-study1/REPLICATION.md))
- **A newer model closes the correctness gap but widens the cost gap (M35 Sonnet-5 cell).** Capable models get renames *right* unaided — at 14.4 turns/rename. The cost win is the durable differentiator; detection is the capability-dependent backstop. Empirically-backed design rule: **own the verb, don't police the mistake.**

## Field evidence — the RC adoption trial (naturalistic, instrumented, 2026-07)

A real brownfield PHP/JS monorepo, migrated from a GSD `.planning/` tree and then worked under jigc through four blind probe sessions (the executing agents were told nothing about jigc or what was under test; every invocation logged). Records: [migration half](completions/artifacts/RC-adoption/rerun-rc4/trial-record.md) · [implementation half](completions/artifacts/RC-adoption/impl-rc5/trial-record.md). *Bounds, stated once for the section:* single repo, single stack, agent-reported experience — anecdotal-but-instrumented, not a controlled study.

- **The anchor gate held on brownfield, unprompted — the headline claim's first live proof.** A warranted refactor deleted two classes cited by five `cites-code`/`implemented-by` anchors across four managed docs (two of them ADRs) the task never touched. Finalize blocked and named all five; the blind agent: *"I would not have found those on my own — I'd have shipped a clean-looking commit that left four managed docs pointing at files that no longer exist. That single behaviour changed the outcome of this session."* And from the migration half, the same property at authoring time: jigc refused an arch-doc citing a symbol that was imported, not declared, at the cited file — *"jigc makes that class of lie structurally impossible to commit."* *Caveat:* the same session exposed the inverse bound — the gate checks **symbols, not claims** (see Honest limits).
- **Planning's Settle checkpoint caught a one-way door — and a contradiction its own author had missed.** A milestone increment forked on an open question recorded in the project's VISION; Settle surfaced it at exactly the moment work depended on it, *and* flagged that the VISION stated the same point both as a settled invariant and as an open question — a self-contradiction the human had authored and never noticed. Observer's verdict: *"the feature working better than designed … It's the best argument for jigc I've seen."* detect-gaps in the same run caught an increment blocked on a write path that didn't exist and built it first. *Caveat:* the same milestone exposed the surface's two real gaps — the work-unit mis-fits sequential-spine milestones, and the completion close was skippable (see Honest limits).
- **Spec-criteria injection is the context-compiler thesis working.** After `task bind spec`, the 13 committed acceptance criteria rode every re-compose: *"I was working from the committed criteria as text in front of me rather than from my memory of a file I'd read 40 tool calls earlier … I never once had to re-open the spec file."* Same session on the commit doctype: *"The resulting commit message is better than what I'd have hand-rolled."* *Caveat:* the same agent's top complaint was the compose surface's statelessness (satisfied gates keep printing) — fix-shaped, chartered.
- **The first real committed-corpus schema migration was clean and auditable.** `migrate-corpus` carried a 41-doc corpus rc.4→rc.5 (an enum rename across 41 entries): byte-stable, idempotent re-run, 42 lines changed / 42 accounted / zero prose touched, `blocked` a first-class output, and the binary ships its own transform evidence — the agent verified the remap against the embedded schema + rationale *"instead of trusting it. More tools should ship the evidence for their own transforms like this."* The migration session ran 27/27 invocations clean. *Caveat:* the *routing around* the transform had a confirmed false-green hole (validate blind to stale placement-doctype stamps; setup re-stamps over them) — chartered as the top rc.6 fix; until it ships, the ordering `migrate-corpus` → `setup` is on the operator ([MIGRATING.md](MIGRATING.md)).
- **The noise floor dropped an order of magnitude across waves.** Findings signal: migration half 8 actionable vs 607 advisory (1.3%); implementation half ~33 actionable-context vs 88 advisory instances, with the dominant rc.4 noise code (`unsupported-language`, the Vue blindness) at **zero** under rc.5 — replaced by the genuinely actionable `symbol-exists` catch above. *Caveat:* one repo's profile; `file-state.baseline-adopt` (54) is the next noise candidate.

## Field evidence — the verification trial (project-alpha-3.0, 2026-07-21/22)

The same brownfield PHP/JS monorepo as the adoption trial above, taken as a **fresh copy under a deliberate rename** (`project-alpha-3.0`) so no session could draw on memory of the earlier runs — then re-migrated from GSD and driven through **eight separate-session designed probes** on rc.8, including a dedicated adversarial pass and the **first live milestone fan-out**, exercising surfaces no prior trial touched (success-emitting git hooks, the gitignored `vendor/` runtime under worktrees, Pest test anchoring). Records: [trial-record](completions/artifacts/RC-alpha3/trial-record.md) · [findings-verification](completions/artifacts/RC-alpha3/findings-verification.md). *Bounds, stated once:* agent-reported; same corpus/stack as the section above (a replication, not stack diversity); the rename held as the cross-run contamination control, but intra-trial handovers carried knowledge forward; and every claim below survived adversarial re-verification against the code — 3 of the trial's own claims did not.

- **The fan-out held its first live run.** Five parallel detached worktrees, real project work, one join commit — and a *designed* same-path collision probe: finalize hard-blocked with a precise route, committing nothing; a deliberate symlink shortcut proved the isolation boundary load-bearing ("it visibly blew up"). The blind agent: *"This directly retires the migration-era fear that drove me to serialize every finalize"* — *"I'd trust it to parallelize finalize."* This substantially discharges the M39 honest bound ("proven by an N-process sim — confirm at adoption"). *Caveats:* `join` validates docs only (code collisions surface at finalize — chartered), and worktrees ship without runtime deps (`vendor/` — the biggest practical gap found).
- **The anchor gate's second unprompted live catch — this time by an agent with no memory of the first.** A single-task renamed an arch-doc-anchored PHP class; finalize blocked on `symbol-exists` — *"Real, not decorative."* *Caveat:* the same session re-proved the symbols-not-claims bound a third time (inverting the symbol's documented behavior with the name intact → zero findings; see Honest limits).
- **The completion loop recorded an honest RED.** A real milestone audit landed verdict RED with dispositioned findings: *"it let me record an honest RED verdict … and never once pressured me toward a false green."* And validate-as-dry-run caught the one shippable trap first: *"That single feature turned bug #1 from 'shipped broken' into 'fixed in ten seconds'. Don't ever lose this."*
- **The guardrails held under a dedicated adversarial pass.** promote-clobber (protected an untracked file at a doc's destination), concurrent-write base-mismatch (no clobber), dirty-worktree discard refusal, reference-integrity on a deleted cited ADR — every one blocked with the right exit code and a followable route. The route floor drew unanimous praise across all nine reports ("the single best design choice").
- **Prior fixes survived their exact provocations.** The M44 task-id path-hash carried 17 same-directory migrations with zero collisions; the fidelity boundary-guard ran silent on a repo literally named `project-alpha-3.0` (the false-alarm exemplar it was built against); and `maps-to-test` got its **first field writes ever** — the rc.6 prompting fix demonstrably worked at pull.
- *The other column, stated plainly:* the same trial found **two latent v1-gating defects on the fourth corpus** — item-slot slot-prose corruption (the write guard never covered the item path) and commit trailers silently dropped (dead on the entire real write path) — plus a git-invisible file-state blocker. Zero regressions, but ~19 findings were incomplete-fix siblings; the rc.9 wave is chartered on exactly that lesson ([findings-verification](completions/artifacts/RC-alpha3/findings-verification.md) → §4–5).

## Field evidence — the final unseeded trial (project-alpha-4.0, 2026-07-25)

The first trial to run the **unseeded clean-room half** of the protocol: five worker sessions on rc.9, each started fresh with a verbatim prompt only — no handovers, no archives, no prior trial knowledge (the record closes with an explicit honesty statement on what leaked: at the content level, nothing). Three of the five sessions walked into **designed traps they were never told existed**. Records: [trial-record](completions/artifacts/RC-alpha4/trial-record.md) · [findings-verification](completions/artifacts/RC-alpha4/findings-verification.md). *Bounds, stated once:* fifth run on the same corpus family (the rename identity-break held; blindness is argued in the honesty statement, incl. one operator log record); agent-reported; every claim below survived adversarial re-verification with live repros — 4 of the trial's own claims did not.

- **A blind agent found the committed decision before touching the code — through the tool, unprompted.** The designed ADR trap: an image-size task whose obvious fix (an Alpine base swap) a committed ADR explicitly rejects. The unseeded worker ran `doc list` + `doc show` on that ADR *before minting its task*, respected it (slimmed within the constraint, recorded its own ADR), and repointed the ADR's code anchor through jigc when its refactor would have orphaned it — no silent contradiction, no OOB edit: *"no managed doc file was ever opened for writing."* This is the pull tier working blind — prior trials showed read-first behavior only in seeded sessions. *Caveat:* the same worker grepped `docs/` raw for *discovery*, because no search verb exists — the gap now demonstrably causes the read-rule violations it forces (chartered input to the M46 Settle).
- **The forged-future-stamp trap never produced a false green, in three separate sessions.** An out-of-band `schema-version: 99` was committed under an innocuous message (the exact door of the confidence-audit's headline finding, on its first field run). The store sweep surfaced it blocking with the exit flip every time; the fifth session traced it to the planting commit via git history and correctly routed it to the human rather than force-editing; the unexercised doors were closed by repro (`migrate-corpus` blocks the doc by name; `set-field` refuses the stamp as machine-maintained).
- **The carryover plant lost nothing.** Operator-staged state before task mint — a modification, a staged deletion, a staged untracked file — and the task's one commit carried none of it; all three paths survived intact. *Caveat, the honest half:* the gate itself never fired — the worker was warned by the composed workflow prose and unstaged preemptively, because `task validate`'s advertised finalize preview omits the carryover probe (the trial's strongest defect; M47 tier 1). The gate's per-path firing, deletion handling, and labeled `--carry-staged` override are repro-confirmed, not trial-confirmed.
- **The fixed corruption edge held under blind provocation.** A heavy batch-author session over multi-slot roadmap items and nested changelog entries — the exact edge the M45 sweep closed — landed zero corruption with byte-stable re-reads. The same trial's voluntary fifth session ran a full milestone loop naturally, including a hook-rejected finalize recovered cleanly through the survivable frame.
- *The other column, stated plainly:* **zero data-loss/corruption defects and zero regressions** — the confirmed set is surface-tier (the validate preview contract; the migrate-corpus hook-rejection dead end, which forced the trial's only raw commit of jigc-owned bytes; a stale exit-code absolute on the agent preload), and the four refuted claims were all agents missing shipped capability — the fifth consecutive trial with that signature. The rc.10 wave (M47) is chartered on exactly this set: fixes + understandability, no new functionality, accepted by a three-probe greenfield trial ([DECISIONS.md](DECISIONS.md) → 2026-07-25).

## Independent validation (evidence whose authors never saw jigc)


A 12-axis research corpus (external/web sources only, provably jigc-blind — zero jigc mentions) independently converged on jigc's four load-bearing bets:

- **The determinism boundary** — "an MCP server has no intelligence… never decides anything"; deterministic tool surfaces for agents (Anthropic tool-design guidance; research 06/08).
- **CLI-first as the agent channel** — "CLIs are the most context-efficient way to interact with external services" (Anthropic; research 08 §1).
- **Core/interface separation** — the engine/cli split matches the researched library-CLI discipline (research 06 §2).
- **Agent-native CLI surface** — structured output modes, distinct branchable exit codes, self-describing help (vendor checklists, research 08 §3). jigc ships `--format agent|json|human`, exit codes 0/1/2/3/4, and `jigc describe`.

Also independently corroborated: the one-bounded-primitive concurrency stance (Google Research: diminishing returns past ~5 agents; sequential degradation −39…−70%) and the small-batch/atomic-commit design (DORA 2025: under AI, throughput rises but stability needs the guardrail more). *Circularity caveat, stated once:* the same corpus's KB layer used jigc as its top exemplar — process/doc-hygiene agreements from that layer are jigc echoing jigc and are **not** cited here; only the jigc-blind research track is.

## Engineering facts (verified, current at 2026-07-02)

- **1427 tests, 0 failed, 0 ignored**; clippy `-D warnings` clean; 36/37 worked-example flows have real-binary acceptance coverage (the 37th is a human protocol).
- **Zero panics across ~35 hostile probes** (corrupt front-matter, invalid UTF-8, deleted section markers, git index.lock mid-commit, garbage payloads) — every failure path returns a handled, routed error.
- **Byte-stable writes** — `render(parse(x)) == x`, proptest-fuzzed on the highest-risk doctypes; human out-of-band edits are detected and routed (absorb / block / route-to-human), never silently merged or forbidden.
- **Transactional boundaries** — finalize and rename commit atomically and roll back cleanly on failure (rollback paths test-verified).
- **Frozen-v1 schemas with a real migration path** — schema changes are version-gated (pack-load hash assertion blocks un-migrated changes loudly) and `jigc migrate-corpus` carries a committed corpus across versions deterministically (measured v1→v2 facts, M34).
- **Scale sanity** — a 1000-doc corpus: `ingest` 30ms, `validate` 44ms.
- **Injection-safe git integration** — all production git calls are arg-vector `Command::new("git")`; no shell interpolation.

## The one-paragraph answer to "isn't this just another workflow framework?"

The critique ("orchestration frameworks create an illusion of work") is answered through its own rationale, with data: jigc's M35 study was *pre-registered to lose* if the framework only added ceremony — instead jigc was strictly cheaper than no-framework on every model, because it owns a structural operation the agent otherwise does by hand across 8–14 turns. Where the framework *would* add only ceremony (prose judgment, code correctness), jigc deliberately owns nothing: no DAGs, no runtime, no auto-authored prose, no LLM calls in the core. The boundary is the answer.

## Honest limits (say these before an adopter finds them)

- Prose quality and code correctness are the agent's, not jigc's — jigc validates structure and reality (refs, anchors, presence), never content.
- **The gates check symbols, not claims** — the trial's sharpest bound (2026-07-12): docs whose *prose* a commit falsifies stay green ("green validate, lying docs"), and `spec` is the doctype where it bites — three implemented specs asserted their bugs in present tense while validate reported clean, and `maps-to-test`, the field that could bind criteria to evidence, was written zero times until the rc.6 prompting fix — the project-alpha-3.0 trial (2026-07-22) wrote the first field anchors, and *re-proved the bound a third time* (a symbol's documented behavior inverted with the name intact → zero findings). *"jigc now guarantees your docs name real code. It does not yet guarantee they say true things about it."* The spec lifecycle is parked ([ideas/spec-criterion-status.md](ideas/spec-criterion-status.md)); the cheap surface (docs anchoring your staged diff) was re-Settled to the M46 capability wave, 2026-07-23 ([ideas/symbol-mention-sweep.md](ideas/symbol-mention-sweep.md); [decisions-pending.md](implementation/decisions-pending.md) → the capability wave, entry 6).

- **The milestone close is skippable** (as of rc.5): dropping the work-unit ends a milestone with no completion-record, no verdict, no gate — the trial's milestone landed six commits on a red suite and nothing at the boundary noticed. To jigc's credit it said *nothing* rather than producing a false pass (strictly better than the GSD failure it replaces) — but an audit you can walk around is not an audit yet. *(The abandon half closed at M42 — `jigc milestone discard` settles the record instead of leaving it lying; the run-it-honestly half has field proof since project-alpha-3.0's RED verdict. The remaining truth: nothing yet *compels* the close — the checkpoint/gate-record fork was re-Settled to the M46 capability wave, 2026-07-23, and the project-alpha-4.0 trial added its 5th independent demand.)*

- The adapter boundary is ergonomic, not enforced — a determined agent can edit files directly (the enforcement hook is a parked, evidence-gated decision).
- The value evidence is strongest on structural-op-heavy work (renames, supersessions, drift); on a single small task, a well-maintained static instruction ties or wins.
- Single-store concurrency is one agent per store (fan-out sub-agents excepted, by design).
- *(Closed 2026-07-24, kept for the record:)* the two latent write-path defects the project-alpha-3.0 adversarial pass found at rc.8 — item-slot heading corruption and silently-dropped commit trailers — **were fixed at M45 (rc.9)** over their full class axes (the item-region validate-after on every slot-write seam; the trailer render joining the on-disk round-trip suite), and the item-slot fix **held under blind heavy provocation** at the project-alpha-4.0 trial (2026-07-25, the P3 probe: zero corruption, byte-stable).
