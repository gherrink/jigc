# Working principles

Rules of judgment the human has set that hold across every workflow — design, dev, increment, milestone, stabilization — and that no single workflow doc owns. Each is one section: the rule, why it holds, how it is applied, and the `DECISIONS.md` entry that set it. A rule that belongs to one workflow lives in that workflow's doc, never here; a rule here is pointed at, never restated.

## Neither the doc nor the code is the oracle — the behaviour that makes sense wins, and whichever is wrong changes

**The rule.** A question of what the product should do — a doc is silent, says two things, allows what a sibling command or the project's invariants contradict, or disagrees with the code — is judged on the **behaviour first**: what makes sense for a user, the architectural invariants, the exit rule, how the sibling commands behave. Only then does it name which of the doc, the code, or both is wrong, and that one changes. Neither *"the doc catches up with the code"* nor *"the code obeys the doc"* is an answer on its own, and readings are not chosen so that every sentence already written, or every line already built, stays true.

**Why.** The design docs were written one milestone at a time, and a sentence often records a local fix: true when written, narrower than the rule it sits beside. The code is the same kind of record. Taking either as the oracle freezes a local fix into a rule and loses the project's general invariants — writes are transactional, a refusal changes nothing, a conflict is blocked and routed and never silently merged, one command behaves as its siblings do ([VISION.md](../VISION.md), [CLAUDE.md](../CLAUDE.md) → Architectural invariants).

**How it is applied.** It binds every agent that judges — triage, verify, the robust advocate, and the builders and fixers of a test table — and the orchestrator. A question put to the human leads with the robust end state: what the product *should* do by the project's general principles, then which of the doc and the code would change (a finding, routed like any other), and only then the readings. A finding may be against the doc, the code, or both, and says which. A test or table built before the ruling follows the stricter reading and marks the cell, as it does today.
