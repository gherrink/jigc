# Public hygiene — what may enter this repository

This repository is public, and so is every commit it has ever carried: a blob that reaches `main` stays readable by sha long after a later commit deletes it, so the only fix for a leak that landed is a history rewrite. **These rules keep that from being needed again.** They were written when the history was rewritten before publication ([completions/artifacts/M54/pre-public-audit.md](../completions/artifacts/M54/pre-public-audit.md) records the method and the verdict); the guard at the end enforces the mechanical half.

## The rules

1. **Trials and evals run on synthetic or public corpora.** The trial tooling builds synthetic corpora for exactly this reason ([trial-corpus-template](../completions/trial-corpus-template/), [`dev/jigc-rig`](../dev/jigc-rig)); a public open-source project is the other acceptable subject.
2. **A trial on real work keeps its raw evidence outside the repository.** Transcripts, invocation logs, `git log` dumps and copied documents from a real employer or client repository stay on the machine that ran the trial. What is committed is the aggregated, anonymized finding: the defect in jigc, its repro against a synthetic corpus, and the counts — never the subject repository's content.
3. **No raw transcripts, unless a tool or a test reads them as a named fixture.** A transcript that a test opens by path (the `completions/trial-driver/` suites read a small, named set) is a fixture and may stay; a transcript kept "for the record" is raw evidence under rule 2. A synthetic-corpus transcript still passes through rule 4 before it is committed — a `git log` inside a session prints the machine's own identity.
4. **Never commit, in any file or commit message:**
   - a credential, token, key or password — **including a revoked one**, and including one quoted inside a record or a transcript;
   - an internal hostname or URL;
   - an employer's, client's or internal project's name, or a name derived from one (a repository name, a slug, a trial id, a directory name, a code identifier);
   - an issue tracker's ticket keys from a non-public tracker;
   - another person's name or email address.

   The author's own public identity (the git author line, the public GitHub handle, the author's own public projects) is not covered by this rule.
5. **When a real subject has to be referred to at all, use the fixed token vocabulary** — never an ad-hoc abbreviation, which leaks by being guessable:

   | Token | Stands for |
   |---|---|
   | `acme` | the employer |
   | `project-alpha`, `project-beta`, `project-gamma`, `project-delta` | a real internal or client project (a version suffix keeps its shape: `project-alpha-2.0`) |
   | `project-kb` | a real internal knowledge-base project |
   | `client-1`, `client-2`, … | a real client, when the project itself need not be named |
   | `TKT-<n>` | a real ticket key |
   | `[credential-redacted]` | a credential value |

   Existing tokens keep their meaning; a new subject takes the next free one.
6. **No absolute host path and no session or agent id enters the repository: a path is written relative to the repository root, and a home path with `~`** (the human's ruling of 2026-11-06 — [DECISIONS.md](../DECISIONS.md) → *2026-11-06 — No absolute host path enters the repository, and the fifteen-minute promise is watched, not enforced*). A host path is a home directory under `/Users/<name>/…` or `/home/<name>/…`, or a macOS temp root, `/var/folders/…` or `/private/var/folders/…`: each is one machine's, and a home names its owner. It is **not** a generic container home (`/home/node`, `/home/runner`), a synthetic path a test fixture needs (`/Users/x/proj`-style), or any other path inside a container image. The exemptions are a narrow list, each with its reason, written once in [`dev/hygiene-scan`](../dev/hygiene-scan)'s header (`dev/hygiene-scan --help` prints it); a test that needs a host-shaped fixture uses a shape that list exempts, or puts the path together at run time so that no added line holds it whole. The [M54 pre-public audit](../completions/artifacts/M54/pre-public-audit.md) kept machine paths on purpose, as the author's own identity under rule 4; this rule changes that **for new content only**. The records under `completions/artifacts/` that already carry one stay as they are: they are records, some are read byte for byte, and the history that holds them is public anyway — **and so does such a record moved**: a file whose bytes are a blob of the history before the rule (a pure rename, a copy, a file restored whole by a revert) is not read for a host path or an id, nor is an id in a new path that a path before the rule already names. **A line of such a record edited is new, and held**; so is a record moved and changed in the same commit, and each line a partial revert restores — those lines are rewritten with `~` and a relative path.

   **What the scan reads as a host path, and what it does not.** It reads one standing where no path runs — after a space, a quote, `=`, `(`, `\/` (a JSON-escaped slash, read as the `/` it stands for), and after a `>` unless that `>` closes one of the placeholders the scan's header lists (`<tmp>`, `<scratch>`, `<repo>`), so a redirect (`cmd >/Users/…`, `2>`, `&>`) and an element's text (`<string>/Users/…`) are read — and runs its name to the end of `[A-Za-z0-9_.-]`. **Outside the pattern, and not read:** a Windows home (`C:\Users\…`), a lower-case `/users/…` (an API path takes that shape), a path reached through `..` (`/Users/x/../../Users/…`), a name whose bytes run past `[A-Za-z0-9_.-]` after an exempted one (`/Users/x@host`, `/home/u$/x`) or that opens with any other byte. These are judgment, with rules 1–4.

   **Ids, alongside.** The standing rule that no agent or session id is committed is held the same way: a Claude Code agent id (`agent-a` and sixteen hex characters, standing whole), a session id (`session_` and a run of twenty or more letters and digits holding a digit and a capital), and a session's scratch path (`/tmp/claude-<n>/…`, `/private/tmp/claude-<n>/…`, opening as a host path does), in any line a commit adds — a binary file's included — in any path it adds, and in any commit message. The one exemption a message has is its `Claude-Session:` trailer line, which every commit carries and the M54 audit kept; a file has no such exemption. A bare `a` and sixteen hex characters is not held, because a hash takes that shape as often as an agent id does; nor is `agent-a` with any other number of hex characters.

## The guard

The guard is mechanical, and it is a floor, not a review: it catches the names someone has already written down and the secret shapes gitleaks knows. Rules 1–3 are judgment and stay with the author.

- **The denylist** is the private list of terms that must not appear — one POSIX extended regex per line, matched case-insensitively; blank and `#` lines are ignored. **It never lives in this repository**, because a committed denylist is itself the leak. [`dev/hygiene-scan`](../dev/hygiene-scan) runs it over a revision range — every commit message and every *added* line, a merge's own conflict resolution included (`--remerge-diff`), plus, with `--tree`, the tracked working tree — and reports a hit by commit, path and line number only, never by the matching text, because a CI log is public. **What git prints is read by where a line stands, never by what it opens with**: an added line whose own text opens `++ ` prints as `+++ …` and was once taken for a file header, scanned by nothing; inside a hunk the hunk's header says how many lines are added, and where a commit begins is a byte git wrote that no commit can hold (`DECISIONS.md` → *2026-10-07 — The core's script-side tasks, reviewed for three dangers*, item 4). A pattern a matcher rejects is a setup error (exit 2, named by its denylist line, never by its text), never a clean scan: one typo in the secret would otherwise switch the whole guard off while CI stays green.
- **The built-in rules** (rule 6) are mechanical in full, and live in [`dev/hygiene-scan`](../dev/hygiene-scan) beside the denylist, because their patterns are no secret and belong in the repository. The host-path rule reads **every line a range adds and nothing else** — never the tree, a removed line or a commit message; the id rule reads every added line, every added path and every commit message but its `Claude-Session:` trailer. A hit is reported by where — `hostpath <commit> <path>:<line>`, `id <commit> <path>:<line>`, `idpath <commit> <path>`, `idmsg <commit>` — because what matched holds a name or a session. They run with the denylist and, where the private list is absent, alone (`--no-denylist`); `--no-hostpath` leaves the host-path rule out for a caller that holds its text to a stricter one (a stabilization run's writers). A line or a message that a commit before the rules added is history: the scan holds no commit that the rules' base commit (named in the script) holds, **in a repository that has that commit** — a branch's first push in CI scans the whole history, and does not trip on the records rule 6 keeps; a clone without it (a shallow one, an old fork's own CI) is held whole, and fails loudly. **No file hides its lines:** both scanners and the denylist read every line as text — a binary file's, a NUL byte's, one a `binary` or `-diff` attribute of the checkout or `core.bigFileThreshold` would hide, one a `textconv` driver would rewrite (`--text --no-textconv`) — and the denylist reads every path a range adds, an empty file's included (`addpath <commit> <path>`).
- **CI** ([.github/workflows/ci.yml](../.github/workflows/ci.yml)) opens its `hygiene` job with the **branch-name rule** — not a leak check, but the same job because it is just as cheap and just as mechanical: a push to, or a pull request from, a branch outside the closed set of [CLAUDE.md](../CLAUDE.md) → Branches fails in seconds with the allowed patterns listed ([`dev/branch-name`](../dev/branch-name), held to jigc's slug grammar by `crates/cli/tests/branch_name_fence.rs`; a tag push is not checked, nor a pull request from a fork — [CLAUDE.md](../CLAUDE.md) → Branches states the exemption, and the steps below run on a fork's pull request unchanged). It then runs two steps over the pushed range (the push's `before..HEAD`, a pull request's `base..HEAD`, and the whole history on a branch's first push), in its own `hygiene` job, beside the cargo jobs: **gitleaks** (pinned version, `--redact`, with this repository's [.gitleaks.toml](../.gitleaks.toml) allowlisting the one known false positive), and **the denylist** with the built-in rules, the denylist read from the `JIGC_DENYLIST` Actions secret. With the secret unset — a fork's pull request, or a repository that never set it — the denylist step says with a notice that the denylist did not run, rather than passing silently, and runs the built-in rules alone.
- **Locally**, [`dev/gate`](../dev/gate) prints a hygiene advisory before its steps: the denylist from `~/.config/jigc/denylist` (or `$JIGC_DENYLIST_FILE`) over the unpushed commits and the working tree, the built-in rules over those commits — alone where there is no denylist — and gitleaks over the unpushed commits when it is installed. It is an advisory like the deps count — it warns and names the file, and never joins the step list or the verdict — so the hard stop is CI's, and the advisory is how a hit is found before the push that CI would refuse.
- **A stabilization run's own pushes are scanned before they are made.** The run's step tool makes every push of a stage, and before each it runs the two scanners above over every commit no branch of the remote holds yet — the same two commands, over the same kind of range, as the `hygiene` job — and refuses the push on a hit (a host path on an added line under the word `host-path`, the word a run's writers refuse one with; an id under `hygiene`), or when a scanner cannot run ([stabilization-workflow.md](stabilization-workflow.md) → The record step, *What is vetted, and where*, which also says what a run's own records are held to beside the scan). **A push made by hand with plain git is outside it**: there the advisory is what comes before the push, and CI what comes after.
- **A known limit: on a fork's pull request, the exemptions approve themselves.** The pull request runs its own `dev/hygiene-scan` — its exemption list, its placeholder list and its base commit included — so a pull request that adds an exemption beside the line it exempts passes CI. Nothing here can close it: CI runs the code under review, and a scan fetched from `main` would refuse every legitimate change to the scan itself. Review is what holds it — a change to `dev/hygiene-scan`'s header is read as a change to the rule — and the arm that requires every exemption to be driven by a passing test only forces a test edit beside it.
- **A hit is fixed before the push, not after.** An unpushed commit is rewritten (`git commit --amend`, an interactive rebase); a pushed one needs a history rewrite and a force-push, and the old objects stay reachable on the host until it garbage-collects them — which is why the local advisory exists.
