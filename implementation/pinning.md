# Pinning — how a verified fact stays verified

The foundation for the M45 testing-infrastructure scope (the complete-fix contract's buildable half — [DECISIONS.md](../DECISIONS.md) → 2026-07-23 M45 planning: the Settle; [roadmap.md](roadmap.md) → Milestone 45; evidence base [RC-alpha3/findings-verification.md](../completions/artifacts/RC-alpha3/findings-verification.md) → §4). **Definitions and load-bearing decisions only — no code ships with this doc.** The forks this doc waited on are **settled** — their outcomes are recorded below *by reference*, never restated. This is **build discipline** — how this repo's own tests hold a fact — so `implementation/` is its home: [dev-workflow.md](dev-workflow.md) carries the complete-fix rule whose axis-iterating test runs on this substrate, [milestone-completion-workflow.md](milestone-completion-workflow.md) the repro-block delivery rule §3 pins the shape of; both link back here.

**The problem, one line:** facts established by hand — an audit driving the binary, a trial triage, a wave re-verify — were observed once and held by nothing, and later waves moved them silently (the address grammar, the exit-code taxonomy, JSON purity; the commit round-trip exemption is the same hole in fixture form). Three drift modes, three mechanics: **contract drift** → property suites, **surface drift** → compose goldens, **fact drift** → repro blocks. The fourth piece (the fixture builder) is the shared substrate the first two run over.

## 1. The compose-golden suite (surface drift)

**Claim it pins:** the composed surface — everything `start`/`workflow --preview`/`describe`/`doc schema` print — changes only when someone *means* it to, and a pack edit's blast radius is a reviewable diff, not an invisible propagation.

**Why it is cheap:** composition is deterministic by core invariant (same resolved cascade in → same workflow out), so the entire surface is snapshottable. The goldens are generated, never authored.

Load-bearing decisions:

- **Enumeration comes from the registries, never a hand list** (the axis principle; *a grep is not a fence*). The workflow set and doctype set are read at test runtime from the loaded pack registry **through a lib re-export** — `crates/cli` has been a real library since M45, `crates/cli/src/lib.rs` exposing the pack registry and the clap tree to `tests/*.rs`; it was a **prerequisite** rather than the one-line task the first draft assumed, and the shape + cost that made it its own increment are recorded under *Sizing* below — and **never by parsing `describe`'s printed text**, a non-contractual surface. (Verified: `describe` does enumerate the *unfiltered* set incl. suppressed workflows, so it wouldn't hide members — but text-parsing is still the wrong linkage.) **Build packs the CWD-free way:** `EmbeddedPack::new()`, `EmbeddedPack::methodology()` and `CompositePack::new()` are already `pub` and read no ambient state; `make_pack()` resolves against the **process CWD** and is a hazard under parallel tests — the suites take the former, never the latter. **Measured registry breadth (at M50's close — it moves whenever a pack gains a member, which is the point):** dev = 17 workflows / 6 schemas, methodology = 17 / 11, composite `[dev ▸ methodology]` = **34 workflows / 16 doctypes** — 17 schemas dedup to 16 because `commit` ships in *both* packs and dev wins by precedence, and **the two `commit` schemas differ in bytes**: a live cross-pack collision the sweep resolves one way silently, so the golden doubles as the record of which one won. `list()` returns sorted, deduped ids, so sweep order is stable with no test-side sorting. A workflow added to any pack, or a whole new pack composed in, joins the sweep with zero test edits.
- **Surfaces swept per member:** `jigc workflow <id> --preview` for every workflow (the mint-free compose — M44); `jigc start --workflow <id>` for **every** workflow — a `creates-task: true` member mints (part of its surface), a `creates-task: false` member composes with no mint, so the router output (the model-free selection path) and the degenerate no-context walks are pinned too (swept since 2026-07-24 — sibling-hunt finding 5; the original `creates-task`-set filter was a code-structure skip that bypassed `EXCLUSIONS`); the front-door composite surfaces — bare `jigc start` (orientation), `jigc start "<intent>"` (the cascade-default router selection), and their `--format json` variants; `jigc describe` (whole catalog); `jigc doc schema <type> --format json` + human form for every doctype; and the AGENT.md render (the `.jigc/AGENT.md` bootstrap file `jigc setup` writes, goldened as file bytes rather than an invocation). **Each × every fixture state from §4, by default** — an exclusion is an entry in a `const` in the suite with a stated reason (executable metadata), never a pre-test judgment (the create-fresh blind spot came through exactly that judgment). **A golden captures stdout, stderr *and* the exit code** — not stdout alone: under `workflow --preview`, the 4 preview-refusing members are exactly the `creates-task: false` set (`increment`, `ingest-existing`, `milestone-execution`, `router`), and they exit **1** with **empty stdout**, their whole refusal surface on **stderr** — a stdout-only golden would snapshot four empty files forever and pin nothing. The `start` arms *mutate* their fixture (mint task dirs; single-active-task serializes them), so each state is built once and copied per mutating arm — bytes preserve provenance (copy caveat: §4).
- **Cost, measured on the binary the suite actually runs.** The earlier ~9 ms figure was the *release* binary (release ≈ 11–12 ms/invocation); `CARGO_BIN_EXE_jigc` is the **debug** build at ≈ **52 ms**, so all surfaces × 6 states is ≈ **38 s of serial subprocess time, ~7 s wall** across six parallel `#[test]`s (measured end-to-end at the M47 whole-tree regeneration: **≈ 13 s wall**, the six fixture corpora built inside that). Cheap, but not "seconds" — budget it as an ordinary integration suite, not a free rider. **And the all×all sweep is redundant by far more than the ~6:1 first estimated — measured over the regenerated tree, not estimated:** `doc schema` (both forms) and `describe` are **byte-identical across every state**, only **2 of 33** previews differ by state (`form-vision`, `implement-from-spec`) — and `start`, assumed here to be *the* state-sensitive dimension, differs by state for **exactly those same two** workflows and nothing else. So **4 of 102 members vary across the six states: 24 of the 612 golden files, ~4%,** carry state-distinct information. All×all still stands, and stands *harder* on the real number, because **the invariance is itself worth pinning**: any of the 98 invariant members — a `doc schema` above all — that starts varying by corpus state is a finding, and no narrower sweep would notice. Stated outright so a regen's reviewer meets 612 files as a decision, not a surprise.
- **Normalization is minimal and explicit:** absolute repo paths → a `<REPO>` token; nothing else. **Verified empirically (rc.8, two independently-created repos):** all six swept surface kinds were byte-identical across repos *before* any normalization, and invariant under TZ/locale changes, differing git identity, and a renamed branch — **with one qualifier: bare `jigc start` (orientation) embeds the absolute project-config path**, which is exactly what `<REPO>` handles and the only thing it handles. No compose surface embeds a date (the `{{schema:}}` skeleton excludes CLI-stamped fields by construction and placeholders author dates as `"<YYYY-MM-DD>"`; `today_iso()` stamps only write-path instance content); task ids never serial-suffix (a slug collision hard-rejects with a resume route). Also newly verified and worth pinning: **debug and release output are byte-identical** — not free, since `route_fence::install()` is debug-live and release-inert — so goldens generated from the debug binary describe the shipped one. One future fence: a fixture doc's stamped date can reach a golden only through a *header*-including doc-slice, and no shipped placeholder slices headers — if one ever does, that is a *finding* (reproducibility of structure is the product claim), not something to normalize away silently.
- **Golden layout:** `crates/cli/tests/goldens/compose/<pack>/<surface>--<member>--<state>.txt` — per-member files, so diffs are per-surface and regen writes never contend. **Regen is one step** — `UPDATE_GOLDENS=1 cargo test -p cli compose_goldens::` (cargo's own test filter scopes a partial regen; `git diff` *is* the changed-golden manifest; the suite is a module inside the `g_compose` group target since the M47 test-target consolidation, so `--test compose_goldens` no longer names it) — and the regenerated diff is part of the commit under review. **The suite asserts `UPDATE_GOLDENS` is unset when `CI` is set** (the insta convention — already a dev-dependency precedent), so a regen can never green CI. Goldens are for *noticing*, not forbidding: a red golden without regen means "you changed a printed surface without looking at what else changed"; the answer is to look, then regen, never to hand-edit a golden.
- **Byte goldens, not structural assertions.** The judgment tier (prose wording) is exactly what has no other fence — a structural assertion would exempt it again. The style-guide review still governs *quality*; the golden governs *awareness of change*. Machine surfaces (`doc schema --format json`) are double-covered **on purpose**: the contract test pins the *shape*, the golden notices *value* drift across all doctypes.
- **`describe` is double-pinned today, and the golden wins.** `crates/cli/tests/describe.rs` already byte-pins `describe` via `insta` — the repo's only cli snapshot — alongside a load-bearing **non-contractual-prose format predicate** (the output is not JSON/YAML: no machine-bindable surface, [introspection.md](../design/introspection.md)). **Decision: the `insta` snapshot folds into the golden sweep** (which pins `describe` × every state regardless — two regen paths over the same bytes is the one-file-one-purpose violation, and they drift), **and the format predicate stays in `describe.rs`** — it asserts a *property*, not bytes, and nothing in the sweep replaces it. **The tension, stated rather than absorbed:** `describe` is *declared* non-contractual while byte-goldening makes it de-facto pinned. That is tolerable only under this doc's own rule — goldens are for *noticing*, not forbidding — so a red `describe` golden is looked at and regenerated, never treated as a promise to a consumer.

## 2. The contract property suites (contract drift)

**Rule of shape (revised — the first form's own instances violated it two ways out of three):** **one suite per pinned *statement*, named for the statement, its module doc-comment naming and linking the owning doc section — and that link is what the rule requires.** The first form said *"one file per contract, named after the contract doc that owns the statement"*, which the wave's own three instances break: both the exit-code taxonomy and stream discipline home in [command-output-contract.md](../design/command-output-contract.md) while their suites are `exit_codes.rs` and `machine_output.rs` — two statements, one doc, and no filename can name both. The purpose is unchanged — *revising the doc and breaking its fence are visibly the same event* — but it is served by the **linkage**, not by the filename, and the linkage survives two statements sharing a home. The three instances, all satisfying the revised rule: `exit_codes.rs` and `machine_output.rs` → `command-output-contract.md` (the taxonomy · stream discipline), `doc_read_surface.rs` → [doc-read-surface.md](../design/doc-read-surface.md) (the address grammar). Each suite iterates a *real registry*, so new members join automatically. **Two of the three statements had no owning doc when this section was written** — the exit-code taxonomy sat scattered across four docs with no owner, and `command-output-contract.md` carried nothing at all about stream discipline — so even the linkage was unsatisfiable; both homes are minted by the M45 planning docs pass ([DECISIONS.md](../DECISIONS.md) → 2026-07-23, Decisions 6 + 9). **The suites assert those docs' statements; this doc does not carry a second copy of them** — a restated contract is one more thing to drift.

- **Address grammar** (`doc_read_surface.rs` + write-side), two halves. **Law-1 half:** round-trip **every address the projection advertises** (`doc schema --format json`, contract-v3) — set → show → resolve parity, every doctype in both packs, plus the documented alias forms (bare single-hop `#type` ↔ `#header/type`, bare singleton addresses, `{#id}` anchors) — a projection that advertises a dead address goes red. **Completeness half (the cross-review's load-bearing catch):** the projection is generated from the schema model by exhaustive match, so omission can enter only through its two deliberate settability predicates (`set:`-stamped fields excluded; the `id-from` leaf routed to the verbs that *do* write it) — and those predicates are **duplicated on the write path, not shared**. The fence is a **parity assertion, not a second registry**: for every leaf in the engine-loaded schema model, either the projection advertises an address for it or a write to it is refused — advertised-set == accepted-set, both derived, no re-implemented walk. **It needs a *third* state, not two.** Once the projection advertises an `id-from` leaf under its mint/retitle verbs (an M45 deliverable — and **not** uniformly `retitle-item`: that verb addresses the **item**, one hop shallower than the leaf, and refuses an **enum** id-from outright, so the shape is per-leaf; the precisions are [doc-read-surface.md](../design/doc-read-surface.md)'s → Three settability states, not restated here), *advertised ⟺ settable* is false as written — a leaf advertised **under a different verb** must be distinguishable from both "advertised and settable" and "not advertised at all". So the assertion is three-valued per leaf: a settable address is advertised **and** a write is accepted · the leaf is advertised **under its owning verb** and a `set-field` write is refused *with that verb's route* · nothing is advertised and a write is refused. Recorded here because otherwise two M45 deliverables contradict each other — and because any projection change is a `contract-version` 3→4 bump with **no additive carve-out**, so all projection changes land in **one** increment ([DECISIONS.md](../DECISIONS.md) → 2026-07-23). *(Pins the rc.5-verified fact that drifted un-fenced, and the refuted `#type` claim from the project-alpha-3.0 trial.)*
- **Exit-code taxonomy** (`exit_codes.rs`, named for the statement, linked to its home): for every verb family, provoke each outcome class (success · usage error · blocking finding at a task gate · store-scope exit-flip · review hold) and assert the severity→exit mapping against **one table constant**, which also becomes the source the AGENT.md preload line is asserted against (statement == constant, and the constant is context-parameterized — the M43-corollary lesson). **That table constant does not exist:** `0`/`1`/`2` are bare literals across ~8 decision sites and the two named consts are `pub(crate)` inside the binary, so **minting the table and rewiring those sites is part of this work**, not a given the suite can assume — and it is a **third consumer** of the lib re-export, independent of §1's registry and §2's `CommandFactory`. *(Fork 3 is settled — the statement is amended, the codes are unchanged; the suite pins the amended statement, which lives in its own doc, not here. [DECISIONS.md](../DECISIONS.md) → 2026-07-23, Decision 6.)*
- **JSON purity** (`machine_output.rs`): **stated per outcome class, because the unqualified form is false.** On a **success or validation outcome**, a verb's `--format json` stdout parses as exactly **one** JSON document. On the **error class** — clap usage errors *and* operational errors alike — **stdout is empty** and the message rides stderr, so the property there is *stdout empty, stderr the sole channel*, with the **clap carve-out declared** (clap formats and prints its own usage error before any jigc code runs, so it can never emit the envelope). The authoritative statement is the contract doc's ([command-output-contract.md](../design/command-output-contract.md), which gains stream discipline this wave) — the suite asserts it, this doc does not restate it. Verbs enumerate programmatically from the clap `Command` tree via `CommandFactory` (through the lib re-export's `pub mod cli` half — which §1's registry sweep does *not* need; no hand list; `--format` is a **global** arg, so every verb is in scope by construction, and the tree has no hidden/dynamic subcommands). Two arms by fixture need: the **error/usage surface is asserted for every enumerated verb fixture-free** (auto-joining — a new verb is swept the day it lands), and the **success-path arm rides the golden sweep's invocations** rather than a second per-verb metadata registry (a typed command-contract registry would be a hand list with a bijectivity test bolted on — rejected at cross-review). Both arms run under the chatty-hook fixture state. **[Corrected 2026-08-08 — M47 increment 7: the success arm does *not* ride the golden sweep, and could not.]** The sweep invokes only the compose surfaces, so a verb it never calls is invisible to it — precisely how `task diff` shipped parsing `--format` and printing plain text at exit 0. The success half is swept by its own suite over the clap-tree verb axis (`crates/cli/tests/format_json_success_axis.rs`); its per-verb driving recipes are held to the enumerated leaf set by a **bijection**, which is what keeps them from being the authoritative hand list the rejected registry would have been. *(The charter's `hook_output` premise is corrected: hook output under `--format json` is **relayed to stderr**, never merged into stdout and never dropped — the field experience is real, the contract is already conformant — so this arm pins existing behavior rather than a fix.)*
- **The commit round-trip repair** rides with the trailer fix (tier 1), not here: commit joins the on-disk round-trip fixture suite, and one finalize-path test authors a trailer **through the write verbs** and asserts it in `%(trailers)`. Named in this doc because the *exemption* was the pinning hole.

## 3. The repro-block pipeline (fact drift)

The delivery-format rule is landed convention ([milestone-completion-workflow.md](milestone-completion-workflow.md) → Audit): every CONFIRMED **and REFUTED** verdict arrives with a repro block. This section pins the block's shape and the conversion discipline.

**Block shape** (illustrative — flag: notation not frozen):

```yaml
claim: "set-field commit:<t>#type errors (bare single-hop form)"
verdict: REFUTED
setup:            # throwaway repo state, builder state name or explicit steps
  - fixture: fresh          # a §4 state name, or argv steps
  - ["jigc", "start", "probe intent"]
repro:
  - ["jigc", "doc", "set-field", "commit:<task>#type", "--value", "docs", "--task", "<task>"]
expect:
  exit: 0
  stdout_json: { "findings": [] }
pinned-by: doc_read_surface::bare_single_hop_alias_resolves   # or "UNPINNED: <why>"
```

**Conversion discipline:** confirmed claims' blocks become the fix's red test (the dev workflow already demands this — no change); **refuted claims' blocks are the new obligation** — each becomes a standing test in the wave's fix increments, in a `pinned_facts/` module per domain, doc-comment citing the findings-verification row it pins (provenance walkable both ways). The `pinned-by:` field is filled when the test lands; an audit finds any block still `UNPINNED` without a stated reason. **No script-runner harness:** blocks are converted to Rust tests by hand (they're small), not executed as YAML — a bash/YAML runner is a second test framework to maintain and a platform-fragility source; the block is a *specification for a test*, not a test format. **Honesty note (cross-review adjudicated):** `pinned-by:` is **declared list-enforced** — audit-checked prose verified at the wave's completion audit (which already walks every block), not machine-enforced — because the machine-checkable half (a test *name* exists) is not the load-bearing half (the test *content* pins the claim); a symbol-existence parser would be a finder wearing a fence's badge (*a grep is not a fence*, applied honestly to ourselves).

## 4. The trial-shaped fixture builder (shared substrate)

One test-support builder (`crates/cli/tests/support/trial_corpus.rs` or equivalent) producing named corpus states. **The rule, narrowed at cross-review (the unqualified form was unsatisfiable — jigc has no verb that authors foreign hooks or vendor dirs):** **managed-doc state and provenance are built only by driving the binary** — so `edited-from-base`, staged copies, and index state are real, never simulated — while **unmanaged repo furniture** (code files, the foreign chatty hook, `.gitignore`d runtime dirs, per-repo git config) is written directly, exactly as every existing flow suite already does. New suites reuse the universal isolation pattern (per-test tempdir keyed pid+nanos, per-repo git identity, `$HOME`/`JIGC_PACK_DIR` scrubbed) — 211 integration test files run in parallel today with zero serialization machinery, **each re-implementing that pattern inline**, so `crates/cli/tests/support/` would be the repo's **first shared test module**. **Adoption is uneven, so the module is the strict version and says so:** 207/211 use the pid+nanos tempdir, 199/211 set `$HOME`, but only **38/211** scrub `JIGC_PACK_DIR` — and a suite that inherits a developer's `JIGC_PACK_DIR` reads a different pack than the one it claims to sweep, which for a *golden* suite means a whole regen of wrong bytes.

|---|---|---|
| `fresh` | `jigc setup` only | baseline |
| `committed-singletons` | vision/roadmap/decisions-log created + finalized | the create-over-committed / copy-in paths |
| `migrated` | docs landed via `migrate --approve` (retired sources, committed) | the form-vision-class traps; fidelity paths |
| `refs-post-hoc` | edges set by `set-field` on committed docs (a *live task*, so this is the `edited-from-base` state) | role-binding, index overlay paths |
| `chatty-hooks` | an active pre-commit emitting stdout on success | JSON purity under the merged-stream reality |
| `vendored` | a gitignored runtime dir + tracked code | worktree provisioning, ingest funnel |

**`edited-from-base` is not a property any *finalized* state can carry** — it is task-working-area provenance, erased at finalize — so it belongs to `refs-post-hoc`, which already is that state; the charter's `migrated` parenthetical claimed it and was wrong ([DECISIONS.md](../DECISIONS.md) → 2026-07-23).

**Shape-class coverage is the rule; the doctype list is only today's instance.** The six states above cover **no dev-pack doctype at all**, and the shape cells they miss are exactly where the headline defects live. The rule: **every schema shape class either pack can express is populated in at least one state** — single-slot repeatable · multi-slot repeatable · nested repeatable · `id-from` enum · `placement` · code-anchor field — and a class with no populated instance is a missing state, not an accepted gap. Today that requires three additions: a **populated roadmap milestone** (the only multi-slot repeatable in either pack), a **populated changelog** (the only nested repeatable — and simultaneously the only `id-from` enum, the only `placement` doctype, and the set's first dev-pack member), and a **populated `spec`/`arch-doc`** (single-slot repeatable + a resolving code-anchor).

**Copying a built state is a plain recursive copy — unsafe for any state carrying provisioned worktrees.** A copied fixture's `.git/worktrees/*/gitdir` and each worktree's `.git` file hold **absolute paths back into the source fixture**, so the copy silently reads and writes the *original*: cross-test contamination, not a clean failure. Recorded now because M45's residue is worktree work and a `fan-out` state will want to join this set — a worktree-bearing state is **built fresh per arm, or re-provisioned after the copy**, never `cp -a`'d.

**`chatty-hooks` replaces a hook `jigc setup` already installs.** The pre-commit hook is setup's own, so the fixture must decide **replace vs append** deliberately and state which: replacing drops jigc's own hook behavior from every test running that state; appending keeps it and changes the stream the JSON-purity arm observes.

**The git-state axis is a second builder, not a seventh state** (`crates/cli/tests/support/git_state.rs`, M52 Increment 2): the twelve un-concluded git operations the posture family answers over are an *overlay* on any corpus state rather than a state of their own — folding them into `State::ALL` would multiply a set three suites sweep serially (§1 measures ~38 s across six states) by twelve — so a git state is built by driving real git, entered **last** over a built corpus or over a from-scratch repo, and asserted by the marker git writes. `dev/jigc-rig --git-state <member>` is that builder's **shell front door** — the same twelve members, the same constructions, over any corpus state or standalone (`unborn`'s only form) — and `dev_rig_parity.rs` fences its member set against `GitState::ALL` exactly as it fences the corpus states against `State::ALL`.

**Growth rule:** when a trial surfaces a new load-bearing corpus state — or the shape-class rule above finds an unpopulated class — it is added *here* (one place), upgrading every suite that iterates states — the axis card applied to test substrate. The golden suite and property suites take states by name; a new state auto-joins any suite that iterates "all states."

## 5. Classifying coverage (a classification is a claim about the code)

> **A coverage classification is a claim about the code. Derive it from the code — the enumeration, the registry, the suites — never from the artifact in front of you (a changed-file list, a charter, a previous analysis). A file-level diff is a proxy for behaviour and fails wherever a verb's behaviour lives in a file that does not bear its name; and `reachable` is not `exercised`.**

It binds **at the moment of classification** — the moment someone writes *untouched*, *reached by no probe*, *already covered* — not at review. The derivation is nearly always one command, which is the whole point: the rule costs a grep and the failures below cost a wave's acceptance instrument.

**The evidence — three recurrences in two days (2026-08-08/09), twice by agents and once by a reviewer whose job was to catch it:**

- `jigc rename` was classified **untouched by M47** from a **file-level** diff. True of `rename.rs`; false of *the verb*, whose behaviour moved in `cli.rs` — it gained `rename.commit-rejected` and the survivable frame, and `ERROR_CODE_REGISTRY` went 2 → 10.
- A set of surfaces was then asserted **"reached by no probe, therefore needs a trial arm"** — first by the orchestrator, afterwards and independently by the reviewer — **without grepping the suites**. Checking took one command and dissolved most of the list: `commit_rejected_axis.rs` already drives `rename`, all four milestone record-only doors and `migrate-corpus` under a rejecting hook, with its door set **derived from `ERROR_CODE_REGISTRY`**; `ingest_flow12.rs` drives the near-miss route.

Both halves are this repo's own ***a grep is not a fence*** rule wearing a new costume: the census was of **files**, the property was about **behaviours**.

**The mechanical floor.** `crates/cli/tests/verb_suite_coverage.rs` derives the leaf-verb set from the clap tree and asserts each is **named by at least one suite**, printing the verb → naming-suites map on failure (and, uncapped, via `cargo test -p cli verb_suite_coverage -- --ignored --nocapture`) — because the recurring failure was not knowing where to look. Its bound is stated in its own module doc and restated here so nobody promotes it: **named-by is not fenced-by**; it catches a verb with *zero* coverage, never one with shallow coverage. Everything above that floor — *does a suite reach this behaviour?* — is judgment, and this rule is what governs it.

**The three-column partition** a wave's acceptance is derived through — **trial-reached · test-fenced (naming the suite) · neither** — is the same rule applied to a diff; it lives at [decisions-pending.md](decisions-pending.md) → *Acceptance — the pre-1.0.0 trial* and [DECISIONS.md](../DECISIONS.md) → 2026-08-09, and is not restated here.

### §5 addendum — the count is five, and the first *positive* instance (2026-08-13)

**The recurrence continued: two more misclassifications in one session**, both by the same actor, both the same shape — classifying from the artifact in hand instead of from the code. **What is new is the first instance where applying it *prevented* work rather than correcting it.** The latent-surface sweep (2026-08-13, `20800f7`) derived its scope from the verb registry and the `verb_suite_coverage` map and checked every candidate **by test content, not by test name**. Three outcomes, none of which a changed-file table would have produced:

- `relocate` looked like the headline hole (two naming suites, both incidental) and mostly was not — its happy path and frozen-doctype refusal are fenced, and it is **correctly** absent from `ERROR_CODE_REGISTRY` because it `git mv`s and stages but never commits.
- `milestone join` looked thin (three suites) and is not — five call sites, and it commits nothing.
- **The leftover re-`provision` left the sweep entirely**, because the trial had just confirmed it as a data-loss defect: a standing test over its *current* behaviour would have **pinned data loss as expected output**. It routes to that fix's red test instead.

That last one is the point worth carrying forward: **the classification question is not only "is this covered?" but "would pinning it now pin the bug?"** A sweep that fences current behaviour on an unfenced surface is not neutral — over a defect it is actively harmful, because the guard then defends the defect against its own fix.

## §3 addendum — a citation is verified by what a test asserts, and the near-miss is the product (2026-08-18)

§3 already refuses a `pinned-by:` symbol parser. The 1.0.0-gate trial's ledger closed 17 of 17 and
produced the concrete reason that refusal is right — **three citations that read apt and assert
something else**, each found only by opening the test:

- `unknown_subcommand_tip::no_read_intent_is_answered_with_a_write_verb` looks like the pin for *"a
  read-shaped near-miss answers with nothing"*. Its axis is `(parent node, token naming no real
  child)` — unknown **subcommands**. An unexpected **positional at a leaf verb** is a shape that axis
  never enumerates.
- `changelog_gate_advisory.rs` reads apt by name and genuinely pins three arms of the *correct*
  behaviour — while touching none of the cells the finding is about.
- `start_resume::sub_task_read_doors_keep_the_blanket_base_pin_refusal` **is** a valid pin, and is
  also a hazard: it asserts the emitted route text, so it pins a route a later wave wants to change
  as expected output. A fix there must **revise** the assertion, not add one — otherwise a correct
  change meets a red test and looks wrong.

**The rule this yields, and it is cheap to apply:** when citing, write the one clause saying *what
the test asserts*. If that clause cannot be written from the test's own assertions, the citation is
not one. A near-miss discovered while writing the clause is worth more than the citation would have
been — it is a test that will fight a future fix, found before the fix rather than during it.
