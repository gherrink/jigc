# Decisions pending — the forward look

Two altitudes of "surface it before it's forced," each **consulted at a fixed trigger** so a deferral can't evaporate into [DECISIONS.md](../DECISIONS.md) prose and be forgotten:

> **A trigger that is a claim about the code should be a test, not a note (M42, 2026-07-14).** Every entry below names a **trigger** — the condition that resurfaces it. Where that condition is a *fact about the code* (*"if packs are ever loaded from the filesystem"*, *"when a doctype bumps past v1"*, *"when a placement doctype carries a code-anchor"*), **prose is the wrong medium**: it fired once already and nobody noticed — the freeze-assert hole was deferred on exactly that trigger, **multi-pack shipped at M14 and made it true**, and the hole was found two milestones and an RC trial later. **A condition you can assert should be asserted**: write the test that holds *today* and **reddens on the commit that makes the trigger true**. Then the trigger **fires itself**, in the gate of the person who triggered it, instead of waiting for someone to re-read this file. *(Pack-shape: an optional `trigger-test: code-anchor` field on the `deferral-ledger` entry, `check: symbol-exists` — [methodology-docs.md](../design/methodology-docs.md) → the four doctypes. Triggers that are genuinely judgment — "when an adopter corpus surfaces a measured floor" — keep the prose field; that boundary is the A-3 bound, not a gap.)*

- **Before planning a milestone** — consulted at [milestone-planning](milestone-planning-workflow.md) → **Scope**. The **discuss-later log**: milestone-keyed *discussion topics / design forks* that earlier work deferred "to settle before milestone N." When we park a topic with a trigger milestone, it lands here, so the next planning run *starts* by pulling its due topics into the done-picture and gap list — instead of relying on memory that "we said we'd discuss this before then." The backlog to triage these from is [VISION.md](../VISION.md) → Open questions (the categorized index); this log adds the missing piece — each due topic's **trigger milestone**.
- **Before building an increment** — consulted at [milestone-planning](milestone-planning-workflow.md) → **Detect gaps**. Increment-keyed decisions a dev-workflow run will **force**, tagged **(D)** a genuine open *design* question or **(I)** an *implementation* pick (crate/algorithm that falls out at pickup) — surfaced so nothing ambushes a build mid-task.

This is a *decision/discussion* backlog, not a *task* backlog — tasks are still cut per-increment at pickup ([roadmap.md](roadmap.md)). Entries **graduate to [DECISIONS.md](../DECISIONS.md) when settled; delete them here once logged.**

**How entries arrive — the write side (everyone, not just the planner).** Whoever *defers* a topic to a future milestone — in a [design](design-workflow.md) discussion, a [dev](dev-workflow.md) run, a planning [Settle](milestone-planning-workflow.md#the-loop-one-milestone), or a [completion](milestone-completion-workflow.md) triage — **records it here in the same motion as the deferral**, keyed to its trigger. The split is the point: [DECISIONS.md](../DECISIONS.md) logs what was *decided*; this file logs what is *owed and when it comes due*. A deferral that lives only in a DECISIONS sentence has no trigger and will be forgotten — which is the exact failure this log exists to prevent.

> **A charter fork that engages a record quotes the record's scope sentence verbatim — never a paraphrase (M43, 2026-07-17).** Charters are written at triage speed, and a paraphrase is where the drift enters: the M42 charter over-scoped the M30/B1 "surfaced, not prevented" record, M42's Settle corrected it — and the **M43 charter re-minted the identical over-scoping** (fork 7), plus mis-imported the A-3 bound into pack-metadata territory its recorded rationale never governed (forks 3/6). Three mis-citations across two consecutive charters, each caught only because a gap-detector went and read the record. So: when a fork here says *"engages record X"*, paste X's own scope-defining sentence next to the claim. The planning gap pass still verifies — but the charter should not need the correction.

**The concept — the surface contract.** Everything jigc prints (composed output, findings, routes, help, author templates, acks) becomes a contracted surface under three laws, each fenced where the surface is *generated* (the M42 lesson binds: a census cannot enforce a predicate — no grep-checklists over prose):

1. **Nothing lies.** Every claim a surface makes is generated from the thing it describes or asserted against it. Templates never hand-enumerate what the schema can project (the "fixed four-part schema" lie → section lists generated from the resolved schema, the M40 fillable-skeleton precedent); every printed path is repo-real or rendered as an identity (`commit:<task> — transient`, never the fictional `docs/commit:*.md` staging key); behavior claims match knobs (the "routes among the workflows" footer for a step that routes nothing). Fence: assert at the render/serialization seam (the M42 closure-claim precedent); strongest form is making the lie unrepresentable (strings built from the schema/`Command` value).
2. **Nothing hides.** Every affordance that is the designated recovery for a state is named by the surfaces that produce that state: finalize/compose footers name `start --task <id>` (resume) and `task validate <id>` (what's-left); `doc show` on a doc with staged edits hints at `task diff`; the composed prose says `--task` is an override with a single-task default; the fresh-authoring steps model `doc author` (today only the migrate templates do). Fences: routes and `Run:` lines must parse against the real CLI (extends the existing `command-ref-resolves` check to routes + help examples); any suppression flag (`selectable: false` and kin) carries a reason + expiry trigger, asserted at pack-load (the slug-rule-fence mold) — the `decided-task` lesson made mechanical.
3. **Nothing ambushes.** Every constraint is stated where it binds, before it can fail: the slot heading-depth ceiling, the `--from-file -` stdin convention, the `--approve` gate + clobber/retire contract, the slug word-cap rule — each named in the template/step/help that solicits the write that would trip it. Fence depth is Settle fork 3 (presence asserted via a declared stated-at mapping vs audit-only; the A-3 bound holds — presence, never content).
