# Adding a new doctype — the registration checklist

**Consult this whenever a doctype is added or reshaped; update it whenever a registration surface changes.** Derived from the 2026-07-10 doctype × capability audit ([completions/artifacts/RC-adoption/capability-matrix.md](../completions/artifacts/RC-adoption/capability-matrix.md) — the full matrix + file:line evidence for every surface): the trials kept finding per-doctype holes one at a time (`idea`'s invisible required `trigger`, no migrate path for any methodology doctype, lowercase singleton H1s) because a doctype's obligations were never listed in one place. This is that list.

The rc.4 wave (M40, shipped 2026-07-11 — [DECISIONS.md](../DECISIONS.md) → 2026-07-10 M40 planning: Settle; [roadmap.md](roadmap.md) → Milestone 40) closed several of the audit's holes; every caveat this doc used to flag forward was re-verified against the shipped fix and now reads as fact.

## Schema file (`<pack>/schemas/<ty>.yaml`)

- [ ] `type`, plus **both** `description:` and `usage:` — `describe` weaves both; a schema with neither is dropped from the menu.
- [ ] **Exactly one home:** `location: <dir>/` (docs-root applies) · `placement: {file: …}` + `singleton: true` (literal path, bypasses docs-root) · neither = transient — then you must own a finalize sink (the `commit` precedent).
- [ ] `id-from:`; and `display-title:` for any singleton whose H1 must not read as the lowercase type id (`# roadmap` was the shipped counterexample — M40 A4.3 added `display-title:` to the three affected singletons, roadmap/decisions-log/deferral-ledger, mint-only; the obligation stays yours for new ones, and for a manifest member it is now a version-gated shape change).
- [ ] **Single-word section ids** — the multi-word title-case reparse defect; every schema routes around it except changelog's deliberately-fixed one.
- [ ] **For every header field, decide the mint story:** give it `default:` or `set:` (date/on-create, schema-version, on-transition — a **closed vocabulary** since M49: any other spelling is refused at schema load, naming the honored set, rather than silently exempting the field from `required-field-present` forever) — or accept that it is **invisible in the create skeleton and blocking at finalize** (the `idea.trigger` failure class; worst case `dogfood-record`, 14 invisible fields). If unavoidable, the author step MUST name the field and instruct the `set-field`. Since M40 **both mitigating halves are live** — the generalized fillable skeleton (every author-required header field pre-stamped as an empty `key:` line, via the shared engine `is_author_required` predicate) **and** the `jigc doc schema` read surface — but the decide-the-mint-story discipline stays yours: an empty pre-stamped `key:` line still blocks at finalize until filled. The mint-story decision also governs **clearability**: `jigc doc set-field --unset` (M41) clears a scalar field iff it is **not** author-required and carries **no** `default:`/`set:` — a defaulted, stamped, or author-required field is refused (so `schema-version` and a defaulted enum like adr `status` can never be unset), while a genuinely-optional scalar gains a clearing path it had none of before ([write-commands.md](../design/write-commands.md) → `set-field --unset`).
- [ ] **Repeatables:** per-item `id-from`; know that **zero items never gates** — since M40 the `schema-conformance.repeatable-populated` advisory flags a required repeatable with zero items (adopt-time triage annotation + store scope; exempt a legitimately-empty-at-adopt section via the `validation.schema-conformance.repeatable-populated.exempt` knob), but it is an advisory, never a block. If ≥1 item is semantically required, say so in the author step.
- [ ] **Refs:** only to doctypes inside the composed schema universe; forward cardinality `0..*`/`0..1` — never required (create-deadlock guard; the spec `derived-from` lesson); declare `inverse:`; inverse-cardinality is a store advisory only. Cross-pack targets → a plain `string` field (the `trigger`/`task-id` precedent).
- [ ] Pack field types (`code-anchor`) need a `config/field-types.yaml` entry binding the adjudicator.
- [ ] `owned-location` fields: the value must be a tracked path under `completions/artifacts/<milestone>/`, and the field is author-required (the mint-story item above applies).

## Freeze / versioning

- [ ] **Frozen (dev) pack:** add the manifest entry (`type` + `schema-version` + `schema-hash` via `engine::manifest::schema_hash`) — pack-load asserts set-equality, so an unlisted shipped schema fails loudly; add `schema-snapshots/<ty>.v<k>.yaml`. Any later shape **or home** change = version bump + versioned corpus migration (location is inside the hash — the M38 changelog precedent).
- [ ] **Methodology pack (manifest-governed since M40):** the pack ships its **own** `schema-manifest.yaml` — all eleven shipped schemas listed, the transient `commit` shadow included (the freeze assert is strict set-equality; stamp-excluded like the dev precedent), the ten persisted doctypes stamp-injected + freeze-asserted + migrate-corpus-owned; `schema-snapshots/` starts absent at v1 — first populated at the first v1→v2 bump ([corpus-migration.md](../design/corpus-migration.md) → The freeze-exempt sibling, the M40 revision). A new methodology doctype needs a manifest entry **exactly like the frozen pack** (the bullet above applies verbatim) — and **only** that: minted at schema-version 1 it moves no other doctype's hash and owes **no** `schema-snapshots/` entry, there being no prior shape to diff against (`planning-record`, M49, is the worked instance); home changes version-gate, and `jigc relocate <ty> --from <prior>` covers only genuinely manifest-less doctypes.
- [ ] **Before you bump: find your change in the matrix below.** Pre-M42 a version bump the transform could not express did not fail — it **stranded the corpus**: the unclassified change diffs to `[]`, the stamp flips anyway, and every instance lands at v2 failing its own conformance gate (or "migrates by accident" with nothing spliced and a declared `default:` that silently never lands). Both fix waves learned it the same way — M41 built `ValueRemapped` rather than bump without it; M42 built three more after the charter's own bumps fell into the holes. **The rule: a bump without a kind strands the corpus. Build the kind first, then bump** ([DECISIONS.md](../DECISIONS.md) → 2026-07-13 M42 Settle).
- [ ] **M42 makes that rule mechanical — the empty-diff backstop.** A **`schema-hash` change whose *conformance-relevant projection* moved but which classifies to zero transform kinds is now a **migration refusal**: `jigc migrate-corpus` **refuses loudly**, routed to *build the transform kind first* ([corpus-migration.md](../design/corpus-migration.md) → The empty-diff backstop). **Know where it fires:** at the **`migrate-corpus` run** — *not* at `cargo build` and *not* at pack-load (the freeze assert sees a bumped version + a recomputed hash and passes clean, as it should). An earlier draft of this line called it *"a build error, not a migration"*; that was wrong about the surface, and you would have gone looking for it in the wrong place. Everything **outside** that projection (`description`/`usage`/`hint`, and also `default:`/`set:`/`inverse:`/`inverse-card:`/`check:`/`title-names-symbol`) classifies as `PresentationOnly` and **ships**. **Whether it costs a version bump split at M47:** the three authored-prose keys (`description:`/`usage:`/a slot `hint:`) left the frozen `schema-hash` — it is now a **presentation projection** ([corpus-migration.md](../design/corpus-migration.md) → The freeze) — so rewording one is free at the freeze gate and needs no bump at all; the six **semantics** keys (`default:`/`set:`/`inverse:`/`inverse-card:`/`check:`/`title-names-symbol`) are still inside the hash, so changing one is still a version bump + a `migrate-corpus` run to restamp, classified `PresentationOnly` and folding to zero content bytes. So the ⛔ rows below are no longer *"it silently doesn't classify"* — they **stop the migration**, which is the whole point: you find out here, not from an adopter's stranded corpus a wave later. The checklist is no longer the only thing standing between you and a silent strand — but it is still what tells you **which kind to build**.

### The transform-kind coverage matrix

What `jigc migrate-corpus` can actually express — the **kind inventory, not the schema-definition format, is the real limit on what a frozen doctype can become**. This section exists because per-doctype holes were being found one at a time; the matrix is that lesson applied to the *changes* as well as the doctypes. Design home: [corpus-migration.md](../design/corpus-migration.md) → The deterministic transform · Relocation · Value-semantic renames · The classifier's holes · **The structural projection** (which enumerates, as a set, exactly what "conformance-relevant" means — the line every row below is on one side of).

**Reading this before rc.6 ships:** the **(M42)** kinds, the generalized idempotency guard, the silent-classification fixes (field removal · `card` direction, at a section's own leaves and at its item block · the `optional: true → false` tightening — the sixth hole, unnamed until the review), and the **empty-diff backstop** are the rc.6 wave's deliverable ([roadmap.md](roadmap.md) → Milestone 42) — until it lands, the **⚠** clause in each affected row *is* the live behaviour, and an unclassifiable bump **strands the corpus silently** instead of refusing. Flagged forward in this doc's own convention, and folded back on ship, exactly as the rc.4 caveats were.

| The schema change you want to make | Transform kind | What happens |
|---|---|---|
| Add an **optional** field to a header/simple section | `AddedOptionalField` | ✅ classified + spliced (the schema-version stamp itself — v0→v1 on every doctype) |
| Add a field carrying `default:` | `AddedOptionalField` | ✅ the declared value lands in every doc |
| Add a field carrying `set:` with **no** `default:` | `AddedOptionalField` **(M46)** | ✅ classified, then a **byte no-op** — `validate::is_author_required` exempts a derived leaf, so its absence **already conforms**, and an `on-create` / `on-transition` value does not exist for a historical doc. The run **names** what it left unfilled (`migrate-corpus.set-field-unfilled`, advisory), so the no-op is quiet rather than silent. A caller that *does* hold a deterministic value threads it in **as a `default:`** — the version stamp's `with_stamp_default` — and rides the row above. ⚠ *Pre-M46 the transform returned `Unsupported` here and the doc collected `prose-needed`: a **permanent** dead end, since the route said author the prose and re-run while the gate never asked for the field, so re-running changed nothing (M46 Inc-4)* |
| **Widen** a field's `card` (`0..1` → `0..*`) | `WidenedCardinality` | ✅ classified; a byte no-op by design — **in a simple/header section *and*, since M42, inside a repeatable item block**. ⚠ *Pre-M42 this row shipped an unqualified ✅ the classifier did not honour: `diff_item_fields` emitted **only** `ValueRemapped` ([schema_diff.rs:250-273](../crates/engine/src/schema_diff.rs)), so a `card` widen on an item-block field diffed to `[]` (the planning spike recorded it verbatim: `item-block card widen → []`).* M42's item-block leaf diff — the same code path `AddedItemField` builds — closes it, together with the direction fix below |
| **Rename** an enum member (`D` → `Decision`) | `ValueRemapped` | ✅ classified — but the old→new **map is authored** (unrecoverable from the schema pair). A bump shipping *no* map entry **blocks loudly**, never strands (M41). Any non-superset `of:` delta lands here, member *removal* included |
| **Widen** an enum (`[a, b]` → `[a, b, c]`) | `EnumWidened` **(M42)** | ✅ a byte no-op — every committed value is still a declared member, so **no map entry is needed**. ⚠ *Pre-M42 this misclassified as a rename and the transform **blocked** with an empty map* |
| Add a wholly-new **optional slot** section | `AddedOptionalSection` | ✅ the empty `## Heading` is minted at its schema-ordered offset. ⚠ *Pre-M42 this stranded, permanently and with a dead-end route, any doc that **already carried** the heading — live in the shipped `adr` v1→v2 `options` migration; M42 generalizes the idempotency guard to every heading-minting kind* |
| Add a wholly-new **repeatable** section | `AddedRepeatableSection` **(M42)** | ✅ the empty `## Heading` is minted; a **zero-item repeatable conforms** (`repeatable-populated` is a store advisory, not a break). ⚠ *Pre-M42: **empty diff** — the stamp bumped and the whole corpus failed its own gate* |
| Add a field to a **repeatable item block** | `AddedItemField` **(M42)** | ✅ classified — **three arms, mirroring `classify_added_field`** ([schema_diff.rs:324-330](../crates/engine/src/schema_diff.rs)), *not* "every item spliced" (an earlier draft of this row said that, and it is wrong for the optional case) and *not* the M42 correction that replaced it either (which still counted a derived leaf as placed — wrong for a `set:` with no `default:`, fixed at M46 Inc-4): **carries a `default:`** → the value is spliced into every item, via **`write::set_item_field_or_insert`** ([write.rs:3186-3216](../crates/engine/src/write.rs) — the **insert-capable** primitive; `set_item_field` is **update-only** and refuses an absent bullet, [write.rs:1382-1386](../crates/engine/src/write.rs), which is every item here) · **an absence that already conforms** (`optional:`, an optional `ref`, a pack type, or a `set:` with no `default:`) → classified but a **byte no-op** (an item without the bullet already conforms; there is no deterministic value to write), the derived one named as unfilled · **author-required, with no value source** → `ProseNeeding{leaf: Some}`, blocks and routes to the agent. ⚠ *Pre-M42: **empty diff** — optional → "migrated by accident" (a `default:` silently never lands); required → a **permanent mutual dead-end** (validate says "run the migration", migrate says "author the prose")* |
| Add a **slot** to a repeatable item block — i.e. a **per-item Framing-A prose handoff** (author prose per repeatable item) | `AddedItemSlot` **(M49)** | ✅ classified over the whole **arity × requiredness** axis, driven through the real binary by [migrate_corpus_item_slot.rs](../crates/cli/tests/migrate_corpus_item_slot.rs): **0 → 1, optional** (a slotless item block gains its first slot) folds to **zero content bytes** — a lone slot renders bare, under no sub-heading, so a slot-less item already carries the v2 bytes and the stamp is the migration's only delta; **1 → 2** (and 2 → 3) re-keys each item's committed prose under the **old** leaf's `#### <Leaf-Title>` sub-label and mints the added leaf empty at its schema-ordered offset, through **`write::insert_item_slot`** (`set_item_slot` is **update-only**, so it refuses every committed item by definition of this change), reading the committed prose through the **old** schema because a v1-shaped instance does not parse under a v2 multi-slot template. **The whole-item re-render is fenced**: it reproduces the item under the old template first and compares byte-for-byte, so committed bytes the parse does not model — prose hand-appended after the item's `<!-- fields -->` group, invisible to `doc show` and to `validate` — refuse the doc at `migrate-corpus.item-unmodelled-content` instead of being silently destroyed (**No-data-loss**, the property that refuses `RemovedItemSlot`), and the axis the suite iterates carries that third dimension: arity × requiredness × **whether the item block bears fields** (a field-less block has no `<!-- fields -->` group, so it can hold no such bytes and proves nothing about them). **One kind carries both requirednesses and the per-doc gate adjudicates**: an **optional** added slot leaves every item conformant and the doc migrates; a **required** one leaves the minted leaf empty, `schema_conformance` breaks on it, and the doc is routed `migrate-corpus.prose-needed` — the doc-authorable Framing-A handoff, bytes rolled back and stamp unmoved, never a build-the-kind route. ⚠ *Until M49 the item-block loop classified `Field` leaves only, so an added slot leaf reached the residual and the migration refused `unclassified-change` with a route naming `crates/engine/src/transform.rs` — a file no adopter can edit — while `validate` sent the operator back the other way: a mutual dead end at every arity (M49 Inc-4 T1)* |
| Add a **required** slot to a *section*, or a field with **no value source** | `ProseNeeding` (`leaf: None` / `leaf: Some`) | ⛔ **blocks by design** and routes to the agent (Framing A) — the CLI mints the empty slot and never authors prose. A slot is always **author-required**; a field is iff `validate::is_author_required` says so — the predicate the conformance gate itself asks (M46): required, no `default:`, no `set:`, and neither an optional `ref` nor a pack type. Anything it exempts is a byte no-op — the `set:`-without-`default:` row above, and the optional / optional-`ref` / pack-type shapes with it — never a block. `leaf: Some` is the item-block arm M42 **names** rather than silently diffing to `[]` — the item block's *field* leaf, that is: **a required slot added to an item block is the `AddedItemSlot` row above, not this one**, and routing it here is unreachable by construction, since `per_doc_changes` drops a `ProseNeeding` whose section heading the doc already carries and an item block's always is (M49 Inc-4 T1) |
| Promote a fixed `<<slot>>` to a repeatable | `FixedSlotToRepeatable` | ✅ built + engine-tested; no shipped corpus migration yet |
| Move the doctype's **home** (`location:` / `placement:`) | `Relocated` | ✅ file move + file-state re-key (the M38 `changelog` → root `CHANGELOG.md` precedent). Location is inside the schema-hash, so a home change **is** a version-gated shape change |
| Add or change `display-title:` | `DisplayTitleChanged` | ✅ a one-line H1 splice, every other byte preserved |
| **Anything outside the conformance-relevant projection** — reword a `description:` / `usage:` / a slot `hint:` · add or change a `default:` / `set:` · change `inverse:` / `inverse-card:` / `check:` / `title-names-symbol:` | `PresentationOnly` **(M42)** | ✅ classifies, then folds to **zero content bytes** — stamp-only, byte-stable. **The kind's *extent* is wider than its name** (kept from the Settle record): it is *everything a committed doc's bytes cannot violate* — semantics as well as presentation. The test is not "is it cosmetic" but "**can a conformant doc become non-conformant?**"; if no, it lands here ([corpus-migration.md](../design/corpus-migration.md) → The structural projection, which enumerates both sides as a set). **The version-bump cost splits at M47, along a line the migration classifier does not draw.** The **three authored-prose keys** (`description:` · `usage:` · a slot `hint:`) are **out of the frozen `schema-hash`**: `schema_hash` hashes `erase_presentation(schema)`, not the whole struct ([manifest.rs](../crates/engine/src/manifest.rs) → `erase_presentation`), so a typo fix in an authoring hint moves no hash, needs no bump, and never reaches this row. The **six semantics keys** (`default:` · `set:` · `inverse:` · `inverse-card:` · `check:` · `title-names-symbol:`) are **still inside it** — they change what the tool *writes and adjudicates*, which is a declared contract change — so each is still a full version bump + a `migrate-corpus` run to restamp, landing here. *(Pre-M47 both halves lived in the hash and an authoring-hint typo fix was a frozen-schema event; that surprised everyone and is what M47 fixed — [corpus-migration.md](../design/corpus-migration.md) → The freeze.)* The kind exists so the backstop does not turn every edit in this row into an *unshippable* one — which, as first drafted (it swept only `description`/`usage`/`hint`), it would have |
| **Relax** a slot or field to optional (`optional: false → true`) | `OptionalRelaxed` **(M42)** | ✅ a **relaxation** — every doc conformant under the strict rule is conformant under the loose one, so it is safe and byte-free. It still *emits*, because the backstop requires every real change to be named. Fires at **every locus** (a simple/header section's fields, a repeatable item block's and — since M50 Increment 6 — a nested item block's) and at the **slot** level — the **one shared rule** `slot_flag_change` serves the section's anonymous slot and the item block's named slot leaf alike. ⚠ *The **slot** half of that claim was false at an item block until M49 Inc-4 T2: `item_field` dropped a slot leaf at every pass, so an item slot's `optional:` delta was invisible in both directions. A slot carries no `default:`, no `set:` and no pack-declared type, so `is_author_required`'s exemptions cannot apply and the field rule's refinement collapses — a tightening on a slot is **always** `ProseNeeding`.* ⚠ *Pre-M42: **empty diff*** |
| **Tighten** a slot or field to required (`optional: true → false`) | `ProseNeeding` **(M42)** | ⛔ **blocks by design** — *iff the leaf thereby becomes **author-required*** — and routes the agent to author it: this **can render a currently-conformant doc non-conformant** (an optional slot legitimately left empty, an optional field legitimately absent, now fails `required-slot-present` / `required-field-present`). A doc that **already carries** the prose migrates clean and restamps: the tightening **mints nothing** (the idempotency guard drops it), so the per-doc conformance gate is the adjudicator. ✅ **Not a block on a field carrying `default:`/`set:`** (or an optional `ref` / pack type): it is not author-required, so no committed doc can fail — it classifies the no-op kind and ships, since refusing it would be a **false refusal**. ⚠ *Pre-M42: **empty diff** — the **sixth hole, and nobody had named it**: the stamp bumped and the corpus silently stranded at v2 failing its own gate* |
| **Edit a leaf inside a nested repeatable** (a field or slot on `changelog.releases.changes`) | the **leaf's own kind**, at the **nested locus** **(M50)** | ✅ classified — `diff_item_fields` **recurses** into the nested block and applies the *same* rules one level down, so every kind the item locus carries the nested item locus carries too, driven kind by kind by [migrate_locus_axis.rs](../crates/cli/tests/migrate_locus_axis.rs). The refusal and its route interpolate the **locus path** (`releases/changes`), never the outer section id. **Two `kind × locus` cells are classified but not yet folded** — splicing an added slot leaf into a nested item, and remapping a nested enum value: `locus_disposition` marks them and `transform` **refuses**, naming the kind and the locus path, rather than splicing an item-locus primitive at the wrong depth (M50 Increment 7 builds the byte work). The comparison is over the **erased** projection (`projected_leaf`, recursing to any depth), so a hint reword *inside* a nested block stays the `PresentationOnly` no-op it is instead of becoming a false refusal. ⚠ *Pre-M50 `diff_item_fields` compared the nested leaf **wholesale**, so every one of those kinds answered `unclassified-change` one level down with a route naming `crates/engine/src/transform.rs` — a file no adopter can edit; M49 Inc-4 T2 had made it refuse **explicitly** rather than be dropped beside a classified change, which is as far as that wave went (pre-M42: unclassified → empty diff → stranded corpus)* |
| **Add**, **drop** or **re-key** a nested repeatable *block* (`changelog.releases.changes` itself) | — **none**, but the delta **names itself** **(M49)** | ⛔ **build the kind first** — `AddedNestedRepeatable` stays deferred with its trigger ([decisions-pending.md](decisions-pending.md)) and the migration **refuses**. The block is outside the `kind × locus` table deliberately: no transform kind mints, drops or re-slugs a nested block, and the block's own `id-from` is a **non-leaf** key that a leaf-only recursion would never see. Each emits the backstop kind **explicitly**, so it refuses even when it rides **alongside a classified change**, where the residual — which fires only over an otherwise-empty diff — never saw it and the doc was restamped at a version whose nested shape it does not carry (M49 Inc-4 T2) |
| **Remove** a section · **reorder** sections · insert a section anywhere but its schema-ordered offset | — **none** | ⛔ **build the kind first.** No driver today; the backstop **refuses the migration** (pre-M42: unclassified → empty diff → stranded corpus) |
| **Remove** a slot from a repeatable item block | `RemovedItemSlot` **(M49)** | ⛔ **refused**, on `RemovedField`'s recorded pick (*refuse, not strip*) and one sharper than it: what a strip arm would splice away here is the entry's **authored prose**, not a field line, so the exception to **No-data-loss** would be the larger one. It is `RemovedField`'s sibling kind rather than a reuse of it, because the *route* cannot transfer — telling an author to restore a field the schema never declared is a route nobody can follow — so the refusal names the **slot** (`migrate-corpus.removed-item-slot`, a schema-authoring route: restore the leaf, or build the strip arm), with the doc's bytes and stamp untouched. A kind, not a backstop ride, for `RemovedField`'s reason: the backstop is a *residual*, so a removal riding alongside any classified change would leave the diff non-empty and be silently dropped |
| **Remove** a field (simple section **or** repeatable item block) | `RemovedField` **(M42)** | ⛔ **refused** — the recorded pick ([DECISIONS.md](../DECISIONS.md) → 2026-07-13 M42 Inc-5 T5): **refuse, not strip.** A strip arm is deterministic but **destroys the committed values**, a knowing exception to the census's **No-data-loss** property — and *no frozen doctype needs a removal* (M42's own bumps add), so building it is premature generality; the **silent** hole was the defect, and refusal closes it at zero risk. Purely additive to build later (a data-loss opt-in), which is *build the kind first* applied to itself. The route is a **schema-authoring** one — restore the leaf, or build the strip arm — never a doc instruction; the doc's bytes and its committed value are untouched. **It is a kind, not a backstop ride:** the backstop is a *residual*, so a removal riding **alongside** any classified change leaves the diff non-empty and would be **silently dropped**. ⚠ *Pre-M42 the diff looped **v2's** leaves ([schema_diff.rs:298-320](../crates/engine/src/schema_diff.rs)), so a removal classified as **nothing at all**: stamp bumped, every doc keeping a field line the schema no longer declares* |
| **Narrow** a field's `card` (`0..*` → `0..1`, and `0..*` → `1..*` — a raised minimum narrows too) | `NarrowedCardinality` **(M42)** | ⛔ **refused** — the recorded pick ([DECISIONS.md](../DECISIONS.md) → 2026-07-13 M42 Inc-5 T3): a narrowing is **content-affecting, not a no-op** (the corpus may hold instances violating the new bound), and *nothing counts a doc's edges against a `card` bound anywhere*, so the validating arm is net-new validation surface. The route is a **schema-authoring** one — restore the wider bound, or build the validating arm — never a doc instruction. ⚠ *Pre-M42 **any** `card` delta classified as `WidenedCardinality` regardless of direction, so a narrowing quietly **no-op'd** past the gate — in a simple section; **inside an item block it classified as nothing at all** (see the widen row).* M42 classifies on direction at a section's own leaves and at its item block, M50 Increment 6 one level down as well |

The ⛔ **"none"** rows are the **over-build line, held deliberately** — they stay unbuilt because no frozen doctype has needed them, and premature generality is what the freeze's minimalism rejects. They are listed here, not merely absent, because *that* is the fix: the previous over-build line rested on the clause **"no frozen doctype needs them"** and expired the moment one did, silently, in a wave planned around the bump ([corpus-migration.md](../design/corpus-migration.md) → the over-build line, revised at M42). An author who needs one of these builds the kind **first** — exactly as M41 did for `ValueRemapped`, M42 did for the three above, and M49 did for `AddedItemSlot`, whose change sat in this ⛔ *none* group until the kind existed — and adds its row here. **What M42 changes is the failure mode, not the line:** you now get a loud refusal at the **`migrate-corpus` run** rather than a silent strand at the corpus, so "build the kind first" is enforced instead of merely written down.

## Authoring surface

- [ ] `steps/author-<ty>.yaml` enumerating **every** author-required field and slot (`dogfood-record`'s step is the gold standard). An inline create-block in a shared step is livable only if it enumerates fully — adr's block in `steps/implement.yaml` was the anti-pattern until M40 A4 made it enumerate all three required slots plus the optional `options` slot with their `set-slot` commands. Add a `{{cli.create-<ty>}}` macro in `config/commands.yaml` if steps reference it.
- [ ] A driving workflow with `allows-create: [{type: <ty>, as: <role>}]` — `doc create` is gate-blocked otherwise; set `when:`/`selectable:` for router reachability.
- [ ] **Foreign instances plausible in the wild? Ship `migrate-<ty>.yaml` + `author-migration-<ty>.yaml`** (a full `doc author --from` payload template). The workflow *name* is the entire registration (`migrate.rs` resolves `migrate-<doctype>` by convention) — there is no other switch to flip, and no error until a user hits the missing workflow.
- [ ] **Migration templates are mechanical decision trees** (M40, all seven methodology templates shipped this way): the template carries every decision pre-made — the **historic-date TRANSCRIBE/OMIT rule** (migration mode suppresses `set: on-create`, so an untranscribed date silently goes dateless) plus any per-doctype mapping decisions (the deferral-ledger `[D,I]` kind mapping, vision's omit-`grounded-in`) — so the agent **transcribes, never derives** ([DECISIONS.md](../DECISIONS.md) → 2026-07-10 M40 Settle, decision 5).
- [ ] **Machine-maintained doctype** (the `milestone-record` precedent): all leaves `set:`-bearing, **no** author step, engine write arms + CLI drivers; a compound field projection needs a `doc.rs` JSON special-case (the `base` `{sha,short}` precedent).

## Pack-load fences — what refuses a load

Everything above is checked when something reads it. This section is the set that is checked **at pack-load**, inside the pack-source factory — so a defect here does not surface at the door you were testing, it refuses **every** door of the binary, `describe` and `validate` included. Design home: [surface-contract.md](../design/surface-contract.md) → The fences.

**The set is derived, not listed by hand.** A pack-load fence is a top-level function of [`crates/cli/src/pack.rs`](../crates/cli/src/pack.rs) whose return type is `anyhow::Result<()>` — pass or refuse, no value a caller could use — that is reachable from `make_pack`. `crates/cli/tests/doctype_authoring_fences.rs` re-derives that set on every run and reddens when a member has no row below, or a row names a member the code no longer reaches: a fence keyed on its *name* would let the next one join the load path under a different prefix and quietly falsify this file's opening claim.

**Two scope rules cover the whole family.** Every fence runs over **manifest-shipping constituents, each checked in isolation** — a pack opts in by shipping `config/schema-manifest.yaml`, so a seeded or project-local pack without one stays unchecked, wholesale. And most of these are **conditional**: a machine-maintained doctype with no author step (the `milestone-record` precedent) clears the last three by construction, and one that ships no workflow of its own clears two more.

- [ ] **`assert_schema_freeze`** — the manifest freeze gate. **Fires:** at every door, for every constituent that ships a manifest. **Satisfy:** the manifest entry from *Freeze / versioning* above — the check is strict **set-equality**, so an unlisted shipped schema and a listed-but-absent one fail alike, and a pack that ships a manifest is held to all of it (an omitted `slug-rule:` block is a failure, not a quieter opt-out).
- [ ] **`assert_project_schema_shadows`** — the freeze's project-layer arm. **Fires:** only when a project ships a whole-file shadow at `.jigc/config/schemas/<ty>.yaml` for an id a manifest-shipping pack also ships. **Out:** nothing to do at registration — it is the same hash rule one layer up, and it changes only what a *user* of your doctype may shadow (reword `description:` / `usage:` / a slot `hint:`, which M47's presentation projection erases from the hash; never the shape or the home).
- [ ] **`assert_workflow_front_matter`** — the suppression + catalog-shape sweep. **Fires:** on every workflow your pack ships, so on your driving workflow and on `migrate-<ty>` if you ship one; a malformed front-matter now blocks here, naming the workflow. **Satisfy:** a workflow the router catalog *carries* (`creates-task: true` **and** `selectable: true`) needs non-empty `when:` / `description:` / `usage:`; a workflow the catalog *leaves out* — hidden **or** task-less, both causes — needs `suppressed: {reason, expires}`, with `expires: never` the honest value for a structural absence. `migrate-<ty>` is `creates-task: true`, so it lands in the first arm.
- [ ] **`assert_when_shape`** — the `when:` line's mechanical half. **Fires:** only inside the row above, on a catalog-carried workflow that declares a `when:`. **Satisfy:** one line, no trailing period (it interpolates mid-sentence into the router catalog), at most `CATALOG_WHEN_MAX_CHARS` — the craft convention's checkable half ([workflow-dialect.md](../design/workflow-dialect.md) → The `when:`-line craft convention).
- [ ] **`assert_stated_at`** — the ambush-class tier. **Fires:** once per pack, over jigc's own fixed code set (`AMBUSH_CLASS_CODES`): some step of that pack must declare each code in its `states-constraints:` front-matter. **Out:** for a doctype added to a shipped pack — dev's and methodology's finalize steps already declare all four, and your doctype adds no member (the set is jigc's, not the pack author's). It binds only if you ship a **new** pack.
- [ ] **`assert_singleton_copy_in_stated`** — the per-soliciting-step tier, and a **biconditional**. **Fires:** iff a step body carries `{{schema:<T>}}` with `T` a **singleton** — so only for a singleton doctype with an author or migration template. **Satisfy:** state the copy-in contract above the solicit (the committed body is copied in as the edit base; slots overwrite) and declare `create.singleton-copy-in`. Both directions bind: declaring the code with no resolvable singleton ref also fails, because the composed step keeps promising a payload that no longer follows. And if the solicited schema declares ≥1 `repeatable:` section, the same prose must state the append/collision half — authored items **append** beside the committed ones, and one whose title mints an id the doc already holds is refused `write.already-present` with the **whole payload** rejected, so that item is edited **in place**.
- [ ] **`assert_staged_read_back_stated`** — the write-solicit tier, the M48 wave's own claim. **Fires:** on any step that solicits a managed-doc write, detected from two structural signals it already renders — a lone-line `{{cli.<id>}}` whose catalog entry is a `jigc doc <write-verb>` call, **union** a `{{schema:<T>}}` authoring payload. **Satisfy:** name the staged read-back in the step body — `jigc doc show <addr> --task {{task.id}}` — and declare `read.staged-read-back`. A **machine-maintained doctype with no author step clears this by construction**; so does a step that writes only through literal hand-written command lines, which carries neither signal (a declared bound, not a loophole to aim for — state the read-back there anyway).
- [ ] **`assert_named_facts_stated`** — the named-fact tier, which is what makes the three declarations above worth anything. **Fires:** on any step declaring one of jigc's own fenced codes (`CONSTRAINT_REQUIRED_TOKENS`); a pack-authored code carries no token requirement. **Satisfy:** the declaring step's prose must actually contain that contract's named phrases — matched over a case-folded, whitespace-collapsed view, so hard-wrapping and sentence case are free. The M47 review deleted 590 characters of contract prose, kept the code, and every other fence stayed green; this is the one that reddens.
