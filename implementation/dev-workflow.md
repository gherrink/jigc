# Dev workflow (TDD)

The loop for **building jigc** — how a single implementation task is taken from "not started" to "committed," test-first. This is distinct from the **design-collaboration loop** in [CLAUDE.md](../CLAUDE.md) → How we work together: that one governs *decisions* (discuss → converge → write a design doc); this one governs *code tasks*. It runs **per task within an increment** ([roadmap.md](roadmap.md)); tasks are cut when an increment is picked up. This is the **inner** loop: the [increment workflow](increment-workflow.md) is the outer one that cuts an increment's tasks, runs each through the loop below, then independently validates the increment and fixes until clean.

The loop is shaped as named, ordered steps on purpose: each maps onto a future jigc `step:` and the whole onto a future `workflow:dev-task`. We run it by hand now; when jigc can compose, it promotes into the workflow dialect almost verbatim ([workflow-dialect.md](../design/workflow-dialect.md)).

## The loop (one task)

1. **Scope** — restate the task in one line, and its **done-criteria as an observable check**: a test that passes, a command that exits clean. Read the design-doc section the task implements (the [roadmap](roadmap.md) increment names it). If the restatement reveals a different problem than the task assumed, stop and check (understand before acting; make success verifiable). **If the task fixes a rule-shaped defect** — a guard, a printed statement, a workflow demand, a contract — **fill the axis card before cutting the red test**: name the *class*, sweep the standing axes (doctype shape · write path · verb family · surface · task/store scope · corpus state), and mark every member **covered / already-safe / excluded-with-reason** (see *a fix is complete over its class's axis*, below).
2. **Red** — write the failing test(s) that encode the done-criteria **first**. Run them; confirm they fail, and **for the right reason** (not a compile error standing in for the assertion). Parser / serialization work is **golden + property/fuzz** tests — the #1-risk discipline ([parsing.md](parsing.md) → Round-trip guarantees) lives here, not as an afterthought.
3. **Green** — the **minimal** implementation that makes the test pass. No extra scope, no speculative generality (keep it minimal).
4. **Refactor** — tidy while green, touching **only what this task touches**. Pre-existing mess is not this task's to fix (stay in scope).
5. **Gate** — the verification gate; all four pass or the task isn't done:
   - `cargo fmt --check`
   - `cargo clippy --all-targets -- -D warnings`
   - `cargo test`
   - `cargo build`

   **A green gate does not prove a proptest-guarded invariant holds** (see *A proptest is not a gate*, below). If your change touches behavior an existing property test guards, **pin the invariant with a deterministic case in the same commit** — and if you mean to *retire* an invariant, reconcile its proptest explicitly and state a rationale you have actually checked.
6. **Commit** — one logical change, conventional message. One task = one focused concern = one commit.

## Why this shape

Two framing notes, not extra steps:

- **One task, one concern.** The unit of work is a single focused thing — the smallest change with its own observable done-criteria. Keeping tasks small is what keeps the loop honest (a vague "make it work" task has no red step).
- **The loop is jigc in miniature.** Scope ≈ `jigc start` / compose, Gate ≈ `jigc task validate`, Commit ≈ `jigc task finalize` (one task → one commit, [finalize.md](../design/finalize.md)). Running it by hand is deliberate dogfooding — the friction we hit informs the real `single-task` workflow we're building.
- **One agent when orchestrated.** Run as a workflow, a single agent carries this whole per-task loop (scope → commit) and yields the one commit — the [increment workflow](increment-workflow.md) → Orchestration spawns one such agent per task.
- **A recorded rationale is a claim, not a fact** (M41, 2026-07-11 — [DECISIONS.md](../DECISIONS.md)). A justification written into `DECISIONS.md`, a doc-comment, or a commit message is **load-bearing**: the next reader — human or agent — trusts it and *stops questioning the choice*. So **never record a rationale you have not actually checked.** M41 produced **two false ones in a single wave**: an increment retired `slugify`'s idempotency invariant on the claim that *"the fixed-point set was exactly the valid-slug set within the caps"* (demonstrably false — and it is precisely *why* the un-reconciled proptest went unnoticed for two increments), and another wrote a doc-comment asserting a slug-only finding key was chosen *"so two dangling targets yield distinct keys"* (backwards — the full `<type>:<slug>` is strictly **more** distinct). Both passed a green gate; both survived an independent same-model review; the second fell only to a cross-model pass. A confident falsehood is worse than an admitted gap, because it **disables the next reader's skepticism**. If you cannot check it, write what you actually know and mark the rest open — an honest *"unverified"* is cheap. **Pack-shape** ([DECISIONS.md](../DECISIONS.md) → 2026-06-21 Direction): **step prose in `step:implement`** — it binds while the agent is *writing* the rationale, so it must be in front of it then, not in a doc it read last week.
- **A proptest is not a gate** (M41, 2026-07-11 — [DECISIONS.md](../DECISIONS.md)). `cargo test` runs the property/fuzz suites over **random** inputs, so a green gate means *"no counterexample was sampled this run,"* not *"the invariant holds."* An invariant guarded **only** by a proptest is therefore not gate-enforced: a change can break it, pass its own increment's gate, and surface runs later (or in the wild) once a run happens to sample the counterexample — which is exactly what happened to `slugify`'s idempotency in M41 (an edge-stopword change broke "a slug is a fixed point of normalization," passed its increment green, and was caught two increments later when the shrink seed persisted and made the failure deterministic). Two obligations follow: **(1)** a load-bearing invariant gets a **deterministic** case alongside its proptest — the proptest explores, the point test *enforces*; **(2)** an invariant is never retired by silence — if a change means to drop one, say so, reconcile the test in the same commit, and check the rationale (M41's break shipped a rationale that was demonstrably false, which is what let the un-reconciled proptest stand). Randomized coverage is a *finder*, not a *fence*. **Pack-shape: step prose in `step:gate`** — it binds at the moment the agent would otherwise accept a green run as proof.

- **A defect at a distance — fence the assumption where the set is *defined*, not where it is *used*** (M42, 2026-07-14 — [DECISIONS.md](../DECISIONS.md)). The bug class no diff review can catch, **by construction**. M42's flagship: `strip_stamp(current)` — the corpus-migration v0 arm — was written **2026-06-25 and was correct**: every doctype was at v1, so *"a v0 doc's shape is the current schema minus the stamp"* was **true**. On **2026-07-03**, **57 commits later**, `adr` bumped to schema-version 2 — also correct — and **that commit did not touch `migrate_corpus.rs` at all**. Two clean diffs; a permanent dead-end bug living in the space between them. **A reviewer looking at either change sees nothing wrong, because nothing *in* either change is wrong.** The defect is in the *relationship*, and it was created by a later, unrelated, **correct** decision quietly falsifying an earlier assumption. *(Same shape: the freeze-assert hole was accepted with the trigger "revisit if packs are ever loaded from the filesystem"; multi-pack shipped at M14, **the trigger fired, and nobody noticed** — it was prose in a ledger.)* **The rule: when your change rests on an assumption about a *set* — every doctype is at v1 · every pack is embedded · every finding has an address · every serializing surface is one of these three — do not merely satisfy it. Fence it, at the point the set is defined**, so that **growing the set trips your fence and reddens the *other* author's gate.** Had `strip_stamp`'s assumption been an assert against the manifest, M36's bump would have gone red **in its own build**, and the conversation would have happened then, for free. **This is the same medicine as *a grep is not a fence*, aimed backwards in time:** that rule says *don't enforce a property with a list*; this one says *don't leave an assumption unfenced just because it is true today*. **Pack-shape: step prose in `step:implement`** — *"Does this change assume something about a set that someone else can grow? Name the set. Then put the assumption where the set is defined, as an assert, so their change fails and not yours."* **And prefer tier-1: an assumption you can assert is not a rule at all.**
- **A grep is not a fence** (M42, 2026-07-14 — [DECISIONS.md](../DECISIONS.md) → *a census cannot enforce a predicate*). The exact sibling of the rule above, one level up: **a search finds the members you told it to look for.** A census done *by grep* — which [methodology-docs.md](../design/methodology-docs.md) → the `census` gate already requires over a hand-list — is still a census, because **the pattern encodes an assumption about where the members live.** M42 proved it nine times over. The `schema.location` census greped `schema.location` and missed `prior.location`. The `finalize.*` census greped `finalize.rs` and missed two members in the CLI. The finding-key census enumerated five clusters and missed two more (47 codes). Each fix added the missed members — **and the list stayed a list**, so it rotted again the moment the set grew. **The rule: if a property must hold of every member of a growing set, the check must live where membership is *decided*** — on the constructor, the trait impl, the serialization — **never on a list of the places you currently remember.** M42's own worst instance is the tell: the finding-key *membership* census was correctly replaced by a **predicate** (*a finding projects a key iff it serializes as a `Finding`*) — and then the predicate's **enforcement** was installed at *three hand-listed funnels*, and a fourth surface was silently emitting a different key for the same defect. The doc comment said, in as many words, *"call it at each of the three funnels."* **A guard that has to ask to be called is not a guard.** Searched coverage is a *finder*, not a *fence* — the same relationship a proptest has to an invariant. *(This binds on methodology too, not just code: a rule that lives in a workflow doc the actor must remember to read is the same object. See [milestone-completion-workflow.md](milestone-completion-workflow.md) → the serial-fixer rule, which was written after M38 and broken again at M42 by the orchestrator who had not re-read it.)*

  **Pack-shape: step prose in `step:gate`**, phrased to be inert when it does not apply (the dialect bars conditionals — a step always composes). Text to encode: *"If this change establishes a property that must hold of every member of a set, say where the property is **enforced**. If the answer is a list of sites — a grep, a census, a call-site enumeration — it is a finder, not a fence, and it will rot when the set grows. Move the check to where membership is decided (the constructor, the trait impl, the serialization), or state honestly that it is list-enforced and expected to rot."* **This one has a tier-1 sibling and the sibling is better:** where the property *can* be structural, no step is needed at all — which is what M42's finding-key seam now does in code.
- **Two masking shapes M42 added to the ban** (2026-07-14). The [gate](#gate)'s no-masking rule already forbids weakening an assertion to get green; these two pass a *green* gate while proving nothing. **(1) A snapshot assertion where the claim is an invariant.** M42's flow-43 discard arm asserted the record settled and the workbench was gone — and then **never ran a milestone verb afterwards**. The claim (*"a discarded milestone stays discarded"*) is a **lifecycle invariant**; a snapshot of the moment after the op cannot witness it, and `provision` cheerfully resurrected the milestone from its own settled record. **If the claim is a property that must hold *over subsequent operations*, the test must perform them.** **(2) A proof fixture built with the defective path.** Increment 7's `setup_partially_joined_milestone` minted its "partially-joined" record by doing `finalize` → `add-task` — i.e. **the fixture that proved the claim was itself an instance of the bug it was proving absent.** Ask of every fixture: *could this state have been reached only by the defect?* If yes, the test is circular and its green is worth nothing. **Pack-shape: step prose in `step:gate`**, folded into the existing no-masking rule's slot. Text to encode: *"Two questions before you accept a green: (1) if the claim is a property that must hold **over subsequent operations**, does the test perform them — or does it snapshot the moment after? (2) Could this fixture's state have been reached **only by the defect**? If yes, the proof is circular."*
- **Widen a guard's trigger, re-derive its response across the *whole* new domain** (M44, 2026-07-21 — [DECISIONS.md](../DECISIONS.md)). When you generalize a check, advisory, or derivation from its *motivating case* to a broader domain — the guard now fires for more inputs — its **response** (the message, the route, the edge-behaviour) was written for the narrow case and does **not** automatically stay correct across the widening. M44's completion audit caught this **twice in one wave**: the byte-floor migrate advisory was generalized from `--as adr` to *every* doctype, but its message and route stayed adr-specific (`jigc start --workflow record-decision`), so a trivial `--as changelog` migration was told to author an **ADR** — the surface-contract law-1 lie the wave itself was built to remove; and the fidelity word-boundary guard was widened from "kill `project-alpha-2.0`" to "reject any dotted run preceded by an alphanumeric," which also silently rejected the conventional `v1.0.0`. Both changes were locally reasonable and *looked* like tightening; both left the response mis-fitted to the widened domain. **The rule: when a change widens what a check *triggers on*, enumerate the new domain and re-check the response holds across all of it — most sharply at its edges (the doctype with no from-knowledge path; the `v`-prefixed version) — because the response was only ever validated on the case that motivated the check.** *(This is the build-side sibling of the planning reuse lesson — [milestone-planning-workflow.md](milestone-planning-workflow.md) → "generalize X to all cases" mis-verified at the primitive — the same generalize-without-re-deriving-the-widened-domain shape at two altitudes.)* **Pack-shape: step prose in `step:implement`**, beside the *set-fence* prompt above (both fire while the generalization is being written): *"Does this change widen what a check fires on? Enumerate the new domain and re-derive the response — message, route, edges — across all of it; the response was written for the case that motivated the check, not the domain you just gave it."* This one has **no** tier-1 sibling — "did you re-check the response across the domain" is a judgment, not a structural assert — so it stays a prompt.
- **A fix is complete over its class's axis, never its repro** (the project-alpha-3.0 verification trial / M45 charter, 2026-07-22 — [DECISIONS.md](../DECISIONS.md); evidence [RC-alpha3/findings-verification.md](../completions/artifacts/RC-alpha3/findings-verification.md) → §4). The trial's dominant finding class — **~19 of ~44** — was the same defect returning through an axis the original fix never swept, and the axis is almost always one the engine already *enumerates*: the slot-heading guard covered the section-slot **write path** while the item-slot path corrupted at every depth (M1 guard, M16 delimiter, never joined); ref-edge workflow demands were fixed **per-field** twice (maps-to-test at M42, cites at M41) and never generalized over *doctypes-with-refs*; the staging-contract statement landed on the single-task steps and never the fan-out **siblings**. M41's audit had already named the mechanism ("the un-enumerated sibling… committed in the fix for it") — this rule is its scope-time fence. **Two obligations: (1)** at Scope, fill the **axis card** (the standing axes: doctype shape · write path · verb family · surface · task/store scope · corpus state) — a brainstormed edge-case list is a *finder*, the enumerated axis is the *guarantee*; **(2)** at Red, the acceptance test **iterates the axis** (for every shipped doctype shape × slot context …), so a member added later is covered by construction, not by memory. And prefer the **fix-shape hierarchy**, strongest first: **unify the seam** (N sibling paths is the bug behind the bug) **> derive from the registry** (the M41 erase-the-complement precedent — new members refuse loudly) **> property test iterating the real enumeration > hand-enumerated cases > prose**. *(Kin, one level apart: the set-fence rule above guards an **assumption** about a set; this guards a **repair** over one. The M43 corollary from the same trial: a seam-generated statement is only as true as its constant — a context-dependent rule needs the context as a fence input, or the fence guarantees the lie renders consistently everywhere.)* **Pack-shape: step prose in `step:scope` (the card) + `step:red` (the axis-iterating test).**
