# The surface contract

**Status: settled at M43 planning (2026-07-16); built across M43.** The record: [DECISIONS.md](../DECISIONS.md) → 2026-07-16 M43 planning: the Settle. Provenance: the lacon trial ([completions/artifacts/RC-lacon/](../completions/artifacts/RC-lacon/trial-record.md)) — zero correctness bugs, a recurring discoverability class: *the capability exists, no composed surface names it*.

Everything jigc prints — composed output, findings, routes, help, author templates, acks — is a **contracted surface**: it obeys three checkable laws, each **fenced where the surface is generated**, plus a written style guide for the judgment tier no fence can hold. The M42 lesson binds throughout: *a census cannot enforce a predicate* — no fence in this doc is a grep-checklist over prose; every fence is either a type that makes the lie unrepresentable, an assert at the seam where the property is decided, or a structural declaration checked against enumerable data.

This doc owns the **laws, their fences, and the style guide**. It deliberately does *not* restate what its neighbours own: the findings envelope, route kinds, and stable `(code, target)` key ([command-output-contract.md](command-output-contract.md)); the route floor's rule text and per-family route strings ([validation.md](validation.md)); the `when:`-line craft format ([workflow-dialect.md](workflow-dialect.md) → the catalog line); the `description:`/`usage:` field boundary ([introspection.md](introspection.md)); the read-surface postures ([doc-read-surface.md](doc-read-surface.md)); the finalize manifest vocabulary ([finalize.md](finalize.md)). The **AGENT.md preload tier** is a law-2 surface class named below (M44 Inc 4), but its **body content** stays owned by [assistant-adapter.md](assistant-adapter.md):48 — this doc cross-references it as a surface, never restating its paragraphs.

## The three laws

**Law 1 — nothing lies.** Every claim a surface makes is generated from the thing it describes, or asserted against it. Templates never hand-enumerate what the schema can project; every printed path is repo-real or a typed identity; behaviour claims match knobs; an ack that says "created" distinguishes created from already-existed. The strongest form is making the lie **unrepresentable**: the string is built from the schema / the `Command` value / the enforcing constant, so drift has no representation.

**Law 2 — nothing hides.** Every affordance that is the designated recovery for a state is named by the surfaces that produce that state — resume (`jigc start --task <id>`), what's-left (`jigc task validate <id>`), the staged read (`jigc doc show <addr> --task <id>`), `task list` on a wrong id, a write against a not-yet-minted item id → the containing section's read (`jigc doc show <type>:<slug>#<section> --task <id>`, whose live item ids reveal the right address — M44 Inc 2, detailed in [validation.md](validation.md)). Routes and `Run:` lines parse against the real CLI. Any suppression flag (`selectable: false` and kin) carries a machine-visible reason + expiry, asserted at pack-load — a hidden capability whose hiding condition expired is the `decided-task` lesson made mechanical. The **AGENT.md preload tier** — the one surface loaded before the model plans — is the law's push-side complement (M44 Inc 4, rc.7 discoverability rerun): it names the machine-output facts a driver would otherwise reverse-engineer by scraping text (`--format json` on every success/validation outcome; the `.task` id on the composed producers) and the binary-introspection path that supersedes a stale-source reach (`jigc --help`/`describe`/`doc schema`), so a capability the model would improvise around is preloaded instead of hidden. Body owned by [assistant-adapter.md](assistant-adapter.md):48; fenced there by the whole-body golden plus the `--format`-is-global assert.

**Law 3 — nothing ambushes.** Every constraint is stated where it binds, *before* it can fail: the slot heading-depth ceiling, the `--from-file -` convention, the `--approve`/clobber/retire contract, the slug word-cap — each named in the template/step/help that solicits the write that would trip it. A block whose contract first appears in the block message is an ambush even when the block is correct.

**The pre-dispatch stream rule (M52).** The three laws bind on every phase of a run, **including the phases before a verb is dispatched** — and that has to be said, because the surfaces that live there are the ones no verb owns. [command-output-contract.md](command-output-contract.md) → *Stream discipline* settles what a **verb** emits (its document's stream, and — since M52 Increment 1 — that on the arm whose document is stderr's, nothing else is written there). Its unstated half is everything that can speak **before** the verb: reading the process working directory, locating the repository, assembling the pack-set — each of which can fail, and two of which used to answer in bytes no contract covered. So: **a failure before dispatch answers on the same arms a verb's failure does, through the same funnel, and nothing writes beside it — and a run that dispatches no verb at all emits nothing of jigc's own.** The second clause is the sharper one: `--help`, `--version` and a clap-rejected argv are the [declared carve-out](command-output-contract.md) (plain text, the stated exit), and a carve-out means *clap's bytes*, not *clap's bytes plus whatever a pre-parse surface felt like adding*. Through rc.15 both clauses were false — 23 dispatch arms printed `cannot determine the current directory` as prose under `--format json`, and a corrupt `packs.yaml` put two `warning:` lines on stderr from a `make_pack` call that runs before `Cli::try_parse()`, so even `jigc --version` emitted them. Fenced by `crates/cli/tests/pre_dispatch_faults.rs`: a `PRE_DISPATCH_FAULTS` registry — one row per fault, carrying the **phase** it fires in (before-discovery · after-discovery · after-pack-load), which is what decides *which leaves can reach it* — driven × `VERB_KINDS`, every cell carrying a declared `(arm, exit)` and the sweep **panicking** on a cell no row claims.

## The fences

Enforcement posture is **per-class, by the existing records** ([DECISIONS.md](../DECISIONS.md) → 2026-07-11 M41 Inc-3 (the seam-assert posture) and → 2026-07-13 M42 Inc-6 (the freeze-assert discharge)):

- **Render/serialization-seam asserts** on jigc's own producers are `debug_assert!` — enforced by the test suite exercising the seam, never a release-build panic on a user's finding.
- **Pack-load asserts** are release-real, in the pack factory (`make_pack`), because filesystem packs load in production (the M42 lesson). They require the **eager workflow-front-matter sweep** — net-new at M43; today workflows parse lazily. Scope: the **shipped embedded packs** (the factory sees pack bytes only; project-layer cascade deltas are consciously outside these fences — declared bound, not a hole).

### The route fence (law 2)

`Finding.route` becomes an **internal `Route` value** — `Mechanical { argv, tail } | Human(String) | Informational(String)` — constructed at the producer, **serializing byte-identical to today's string** (the pinned golden in `finding.rs` does not move; the wire tagged-union stays deferred, [decisions-pending.md](../implementation/decisions-pending.md)). The fence: a `Mechanical` route **cannot be constructed** from a command that does not parse against the real CLI (`Cli::try_parse_from` over its argv parts, placeholder args substituted). `From<String>` maps to `Human`, so migration is per-producer. The parse assert lives at the **CLI seam** (the engine cannot see clap); it is the third assert on the M42 finding-key seam.

**The route floor widens to blocking validation/gate findings** (revising [validation.md](validation.md)'s advisory scoping — a blocked finalize is the highest-stakes surface and today prints no recovery). Two exemptions are **re-affirmed on their own rationales**: purely-positional parser conformance diagnostics (the located message *is* the repair) and the hook-rejection route-exempt error identity (git's verbatim stderr *is* the correction signal, [finalize.md](finalize.md):78). With the floor true, [assistant-adapter.md](assistant-adapter.md)'s "every finding carries a route" sentence becomes true rather than fixed down.

**Pinned mechanics (review-baked, 2026-07-16):** the floor's *presence* half (`severity == blocking ⇒ route present`) asserts at the same M42 finding-key serialization seam, with the parser-diagnostic exemption carried by **one exemption function in one place** (the `is_declared_singleton` pattern — a list of exceptions checkable from the code alone, never a census of call sites). The `Route::mechanical(argv…)` constructor follows the seam-assert class posture: `debug_assert!` that the argv parses (`Cli::try_parse_from`, with `<PLACEHOLDER>`-class args substituted by a single declared dummy table beside the constructor) — enforcement rides the suite, never a release-build panic. **The future wire union is the kind taxonomy** (`Mechanical`/`Human`/`Informational`) — [validation.md](validation.md)'s earlier `fill-leaf`/`run-command`/`reconcile` sketch is retired in the fold-back (rationale engaged: a driver needs act-vs-inform; `Mechanical{argv}` subsumes `run-command`, and fill-leaf/reconcile are mechanical routes to specific verbs).

**P6 — route-followability (M47).** The parse fence proves a mechanical route **runs**; it cannot prove it runs *here*, at the address the finding names, because it sits on `Route::mechanical` and never sees the finding. A route that reaches a driver still carrying `<doctype>` or `<address>` therefore passes every fence above and is still unrunnable — law 2 failing at the last inch. So a second, **finding-side** property: *a placeholder whose value is derivable from the finding's own `key.target` must be substituted before the finding is projected*, asserted at the finding-serialization seam (the fourth assert there, debug posture like its three siblings). Derivability is declared per placeholder — one row per member of the CLI-seam dummy table, each carrying a verdict **and its reason**, in the engine beside `is_route_exempt`/`is_declared_singleton`, with a test asserting the two tables declare the same set in the same order. Exactly two are derivable: `<address>` (the target itself — **narrowed to the top showable hop on a `jigc doc show` route**, since a read verb resolves a doc or a section and never the absent item a `write.not-present` names, so echoing the target there would mint a concrete dead end) and `<doctype>` (the target's `<type>` head). The rest are declared non-derivable with their reason, and **`<task-id>` is the honest carve-out**: one doc is written from many tasks, so no rule derives it from an address — it needs a different source (the CLI dispatch that resolved the task supplies it at every enriched write-verb producer) and stays outside the property rather than being faked. Human-route prose spans are outside it too: the property reads an argv, which only a mechanical route has.

**Producer migration is per-producer, and reshaping a route is when it happens (M47 inc-10).** `From<String>` keeps an un-migrated producer compiling as `Human`, so the fence only reaches a route when someone edits it. The rule the rc.10 wave applies: **a route whose text is a single leading backticked real argv (± trailing prose) is constructed through `Route::mechanical`** — the shape `Route`'s one composition rule already renders (`` `<argv>` `` + verbatim tail), so it costs nothing and buys the parse assert. A two-argv route, or one whose command sits mid-sentence, does not fit the constructor and stays `Human` — the constructor is not to be contorted to claim a conversion. Two routes qualified in that wave: the `add-from-spec` no-`criteria` block (now `jigc doc show <spec-addr>`, naming the sections the addressed doc does carry) and `jigc ingest`'s near-miss (now the same `jigc migrate <rel> --as <doctype>` the store sweep's orphan sibling has handed over since M40 — the two surfaces had one file, one repair, and only one of them followable).

**A route offered on a wider domain must be gated on that domain, not on the case that motivated it** (the build-side *widen-a-guard* rule, applied to routes). `jigc ingest`'s near-miss fires for every non-conformant candidate at a managed home — which includes an **already-adopted** doc, for which adoption is not the repair at all — so the migrate argv is gated on the candidate being both unregistered and its doctype migratable, and each other arm says which of the two it is. A mechanical route that hard-rejects, or repairs the wrong thing, is law 2 failing one level down.

**The quoting half, and where it lives (M51 completion audit).** The parse fence proves a route's argv is a real command; it cannot prove that the *text* an agent pastes splits back into that argv, because the text is `argv.join(" ")` and a shell re-lexes it. That half is `engine::finding::shell_token` / `shell_safe` — **bare** for the shell-inert alphabet ids, slugs, addresses and flags live in, POSIX **single**-quoted otherwise. It sits in the engine and not beside the parse assert, for a stated reason: quoting is a lexical property of the emitted bytes and needs no clap, while the engine mints routes of its own (`file_state`'s conflict block, `validate`'s owner-artifact `git add`, `finalize`'s `git restore --staged`) — homed CLI-side it was enforced in exactly the half of the codebase that did not need it, and every engine-side producer interpolated its path raw.

It is enforced at **two** seams, because one alone is blind, and the blindness is the commoner spelling:

- **the span fence**, on all three `Route` constructors over the composed text: every backticked `git …` / `jigc …` span — a `Human` route's prose command, and the prose **tail** a `Mechanical` route carries, neither of which the argv check can see — must carry only shell-safe tokens (a `<placeholder>` the reader fills is legal bare or as a quoted span);
- **the subject fence**, at `Finding::graded`: an unquoted path holding a space is not one bad token, it is two perfectly inert ones, so `` `git add -- my notes.md` `` passes every token check and exits **128** when run. The missing information is the word boundary, and the finding carries it — `Location::address` is the token the route is talking about — so when a finding's own located subject is not shell-safe, a command span naming it must name it quoted.

Both are debug posture like their parse sibling, so a fence firing is a report that the **producer** is wrong; the quoting belongs at the producer, never at the fence. The driven class this closes: `jigc migrate 'my notes.md' --as adr` routed to `` `git add -- my notes.md` `` (exit 128, pathspec `my`) and a re-run that exits 2; `jigc ingest` over a non-conformant `docs/decisions/my notes.md` panicked the whole run on the argv check; and `jigc task finalize --approve` of any migration panicked before it committed, because the conflict block's `jigc unmanage <source>` argv is built eagerly for every migration task. The axis that failed to see it is `crates/cli/tests/path_arg_occurrence_axis.rs`, whose nine escape cells were all shell-safe by accident of spelling — it now carries a tenth, and asserts of **every** cell that the command spans a door prints can be run.

**Declared bound: a control byte in a path is a *rendering* question, not a route-safety one, and is deliberately not answered here.** Driven on the fixed binary, a source named `two\nlines.md` routes to `` `git add -- 'two\nlines.md'` `` — correct bytes, which a shell re-lexes as the one real path — while the rendered message, the `at:` locus and the route all span two lines on screen, and the flattened `error` envelope carries the same break inside one JSON string (the M50 flattening gap, not this one). Escaping the byte **in the route** is the wrong fix: an escaped route names a different file. Escaping it on the printed surface is a change to every path-printing render (`crate::render::repo_relative`'s domain, law 1's printed-path fence), one axis out from this class, and is left open rather than half-taken.

Route text that lives in anyhow error strings (outside `Finding`) is in scope for the law-2 rewrite, **bounded to shipped verbs' error strings that carry command spans**: each such site either becomes a `Finding` or constructs a `Route` for its spans — an errorish surface is still a surface; prose-only error text is untouched.

### The schema projection (law 1)

A new compose placeholder **`{{schema:<doctype>}}`** — CLI-filled read path, the `{{source}}` seam mold — renders the resolved schema's section/field/enum tree **and the author-payload skeleton** into the step that solicits the authoring. **Unfed or dangling blocks**: `workflow-refs.schema-ref-resolves` (blocking; fires at the store-scope sweep — enumerated per workflow per origin pack, **resolved against the composed cascade's full doctype set** (a methodology step legitimately solicits a dev doctype — the composition model, not per-origin doctype scoping) — *and* at compose; never silently empty, which would be a new lie). The new check id joins the [validation.md](validation.md) single-source-of-truth inventory (intrinsic-floor class, severity blocking, un-tunable) **and** both packs' `knobs.yaml` mirrors in the same increment. Joins the dialect grammar + the `workflow-refs` check ([workflow-dialect.md](workflow-dialect.md) owns the grammar row). The renderer reads the *resolved current* schema, so a future schema bump re-renders correctly by construction. Migration **judgment** prose (foreign-status mapping, drop-to-prose rules) stays hand-written — that is the style guide's tier.

### The printed-path fence (law 1)

**M50 Increment 12 / T1** ([RC-m50 findings-verification](../completions/artifacts/RC-m50/findings-verification.md) → N25). Law 1's *every printed path is repo-real or a typed identity* was a rule with **no home**: `strip_prefix(repo_root)` was hand-written at seven sites, none of them a surface renderer, and the four destroying/provisioning doors named their subject with the host path of the machine they ran on — `` `/private/var/folders/…/repo/.jigc/worktrees/do-a-thing` already holds 1 item(s) `` plus the same absolute again as the `at:` locus, printed one line under a `Spawn:` line that spells that same path `.jigc/worktrees/<id>`. Two breaks, not one: a locus is the address a reader pastes and a driver keys, and an absolute one is **not portable across the two checkouts of the same repo a fan-out is made of**.

The rule now has one home — `crate::render::repo_relative(repo_root, path)`, repo-relative and `/`-separated, `.` for the root itself, and the honest absolute for a path genuinely outside the repository (inventing `../..` would name a different location from every other cwd). It canonicalizes on the retry, because the fan-out doors build their subjects off `jigc_home.canonicalize()` to match the paths git stores at `worktree add` time, so the plain strip misses on a symlinked root.

**An absolute that stays says why, at the site, and is disposed in one table.** Three reasons are admitted — one about the *path*, two about the *screen*:

- **no repo-relative spelling exists** — a `JIGC_PACK_DIR` pack's resolving path (`--explain`'s `Pack input:` line) and the team cascade layer's cross-project home (`~/.config/jigc`, on the orientation header) are outside the repository, and the orientation header is composed in the *engine*, which ships empty and filesystem-free by invariant and has no repo root to be relative to;
- **quoting an invocation** — a line whose subject is the command that failed (`` `git status --porcelain` in worktree <wt> failed: <git's own stderr> ``) prints the argument jigc handed git, beside git's own words naming that same absolute; relativizing one half misquotes the other;
- **pasteable shell bytes** — a `route:`/remedy span the operator pastes into a shell of unknown cwd (`rm <shadow>`). Pack-load's freeze refusal is the boundary case, and it is absolute for both reasons at once — it has no repo-root subject to be relative to, since it runs before any verb has resolved a repository.

**Since M53 the third reason is a rule over a class, not a disposition granted one remedy at a time** (the cwd census, the route class — `completions/artifacts/M53/cwd-census.md` → Census 1). It was applied to exactly two remedies, and driven, the second of them was not even absolute; meanwhile ~15 operator-facing `git` spans across both crates carried a **repo-relative** path operand, which git resolves against the **caller's** cwd. Driven from an ordinary subdirectory, `git restore --staged -- <p>` exited **1**, `git add -- <p>` exited **128** (against a doubled `docs/deep/docs/deep/`), and `git -C .jigc/worktrees/<id> bisect reset` exited **128** because `-C` takes a *directory*, not a pathspec — and from a linked worktree the pathspec forms reach the **wrong index** entirely, which no relative spelling can fix, since `:/` means that worktree's top.

The rule: **every operator-facing backticked `git` span carrying a path operand renders as `` `git -C <absolute checkout> <subcommand> [flags] -- <repo-relative path>` ``**, from one home — `engine::finding::git_at`, in the engine because engine producers mint these spans too (`finalize`'s `git restore --staged`, `validate`'s owner-artifact `git add`, `file_state`'s `git mv`) — and the engine is **handed** the absolute home rather than discovering one, it being filesystem-free by invariant. `engine::finding::unaimed_git_span` is the standing fence, installed on all three `Route` constructors beside the quoting fence and in the same debug posture. It admits three shapes and nothing else: the **aimed** form; a span with **no operand**, which names a command rather than a file (`git add`, `git worktree list`, `git stash -u`); and a **declared non-path command** — `init`, `switch`, `checkout`, `config`, each carrying its reason in code, and each exempt only while the span carries no `--`, which is git's own announcement that what follows is a pathspec.

**The *same spelling* clause is narrowed here, deliberately, and this is the one place law 1 names one path two ways on one screen.** The message, the `at:` locus and the `(code, target)` key stay **repo-relative**: they are read and keyed, and an absolute one names a *machine* rather than a repository — not portable across the two checkouts a fan-out is made of, and the key leak M50 Increment 12 closed. The route's `-C` operand is absolute, because those bytes are *run*. The two are different acts rather than two spellings of one act; where the subject genuinely coincides — a fan-out worktree named in the message and aimed at in the route — the trade is taken with this reason, and the machine surfaces are **asserted** free of the absolute (`crates/cli/tests/git_span_aim.rs`). `mkdir -p <dir>` emitted as a prefix to an aimed `git mv` takes the absolute too, for the same reason and with no `-C` available to carry it: the two halves of one pasted line have to run in the same place.

**Fenced three ways** (`crates/cli/tests/repo_relative_paths.rs`): a **driven** door table over a fixture root minted by `mktemp -d`, scanning each door's whole stdout+stderr for that root's prefix — with **one carved-out region and no other**, a backticked aimed-`git` span, whose reason is written where the carve-out lives (`crates/cli/tests/support/route_spans.rs`) and whose producers are enumerated with a verdict each in `crates/cli/tests/git_span_aim.rs` → `GIT_SPAN_SITES`; a **disposition table**, one row per site, `Relative` / `DeclaredAbsolute(reason)`, each verdict checked against the source rather than believed (the `located_finding_text` third-verdict idiom); and a **standing fence** — no production `.display()` in `crates/cli/src/milestone.rs` outside a declared-absolute site, so the next hand-rolled render reddens rather than shipping. **Declared bound:** the class's domain is *what those doors print*. `jigc setup`'s own surfaces (the installed-hook report, the probe-extract refusal, the hook script body) render paths whose subject is the installing binary or the git hooks dir — not repo paths — and are deliberately outside it.

### The suppression fence (law 2)

Workflow front-matter gains `suppressed: { reason: <text>, expires: <condition> | never }` required on **every workflow the router catalog leaves out** (and any future hiding flag). **`never` is a legal declared value** for permanent-by-design hides (`sub-task` is spawned, never picked; the `migrate-*` family is verb-routed) — the reason still says *why* it's permanent, and the fence never forces a fake expiry (which would be its own law-1 violation). The expiry-audit obligation applies only to non-`never` conditions. Asserted at pack-load over the shipped packs: missing ⇒ fail (required-field-shaped, so the loader's unknown-key tolerance cannot defeat it — a `deny_unknown_fields` flip is consciously not taken; project packs may carry vendor keys). `jigc describe` prints the reason for a hidden workflow, so `describe` and the orient catalog stop contradicting each other.

**The subject is the catalog's complement, not one of its two causes (M49).** The catalog's population is `creates-task: true && selectable: true`, so a workflow falls off it *either* by being hidden (`selectable: false`) *or* by minting no task (`creates-task: false`) — and `step:route-to-workflow` promises the reader a reason for **every** absence. Keyed on `selectable` alone, the fence bought half that promise: `router`, `ingest-existing` and `increment` sat off the catalog narrating nothing at all, while `milestone-execution` — `creates-task: false` and voluntarily carrying a `suppressed:` block — showed the declaration was already the right shape for the wider set. No second key is minted: `expires: never` is the honest value for a structural absence, exactly as it is for a permanent-by-design hide. The narration is unchanged (*"It is hidden from the router catalog: `<reason>`"*), and so is the structural `router_hidden` key it carries ([introspection.md](introspection.md) → Command surface).

**The door a hidden workflow is reached through is declared, not implied (M52).** The block carries an optional third key, **`door: <argv string>`** — the real command line behind the absence (`jigc migrate <path> --as adr`, `jigc workflow sub-task --task <task-id>`, `jigc milestone execute <milestone-id>`). Fourteen members declare it: the twelve `migrate-*` workflows, whose `reason` already named that command line in prose no machine could follow, plus `sub-task` (spawned by a fan-out) and `milestone-execution` (run off the verb). It is **optional** because the other eight suppressed workflows are off the catalog for reasons no single command line answers, and **the fourteen is a declaration, not a derivation** — nothing in the front-matter discriminates verb-routing from the rest, so no fence can prove a missing fifteenth member; what is fenced is the other direction and the shape. **Present ⇒ checked exactly as a `Mechanical` route's argv is checked**, in two halves that cannot disagree because they read one tokenizer (`engine::compose::Suppressed::door_argv`): the **lexical** half in the engine — non-blank, leading with `jigc`, every token shell-inert (the [route fence](#the-route-fence-law-2)'s own `shell_safe`) or a `<placeholder>` the caller fills; and the **parse** half at the CLI pack-load seam, which alone can see the verb tree, asked as a question through the shipped argv fence rather than by constructing a route (whose own check is a debug-only panic). Either half's refusal is the block's own `workflow-refs.suppressed-malformed`, naming the workflow **and the layer that declared the door** — because a door that does not run is worse than no door: it is a surface that names a command and hands back an error.

**Both halves bind at every layer a definition is served from, and the parse half did not when it shipped.** The lexical half is asked on every workflow read, so it always reached a project-layer shadow; the parse half took the subject every *statement*-shaped pack-load fence uses — the manifest-shipping constituents, `origin_packs(Config, schema-manifest)` — and that scope is wrong for a door. It was driven at `dbb35b8c`: a `.jigc/config/workflows/<id>.yaml` shadow **and** a `packs.yaml`-listed pack shipping no manifest each declared `door: jigc migraaate <path> --as adr`, passed the lexical half, and reached the compose door, which panicked the debug binary at exit **101** on `Route::mechanical`'s own construction check and in release emitted a route an agent cannot run. The manifest opt-in is an opt-in to being held to what a pack *states*; it is not available for what a pack *hands an agent to run*. So the parse half's subject is the composition — every constituent that ships the workflow id, winner or loser, manifest or none, plus the project layer's whole-file shadows — and the compose door re-asks the same question in **every** posture before it builds the route, so a producer that cannot prove its argv parses refuses with a finding instead of constructing one.

### The catalog shape fence (style guide's floor)

Pack-load asserts on the shipped packs: `when:`/`description:`/`usage:` **present** on every selectable work-workflow (extending the existing catalog-build assert into the factory) and `when:` **mechanically shaped** (one line, period-less, length-capped — the [workflow-dialect.md](workflow-dialect.md) craft rules' checkable half). The when-NOT-clause assert is **declined** — that is prose semantics, the barred census; the when-NOT discipline lives on `usage:` via the review checklist. [introspection.md](introspection.md):84's skip-on-absent stays intact for project-authored workflows (honored via scoping; its :86 shipped-pack obligation is what these asserts implement).

### The stated-at fence (law 3)

Tiered by what the constraint's source is:

- **Seam-generated** where a code-owned source exists: the slug rule's statement renders from `MAX_WORDS`/`MAX_CHARS` (the constants the manifest already fingerprints); the heading-depth ceiling's statement is co-located with the enforcing check and rendered via the schema-projection generator. Statement and enforcement share one source; drift is unrepresentable. *(As settled at M43; the ceiling half is revised immediately below.)*

  **Revised at M45 — the shared source must carry the rule's context, not just its value.** The rationale above holds exactly as far as it claims, and it is unchanged for a **context-free** constant: the slug cap is one number for every slug everywhere, so `MAX_WORDS` *is* the rule and generating from it makes the lie unrepresentable. ### The carryover gate (law 1 + 3 at the commit boundary)

**The gate's subject is *a door committing paths it does not own* — since M51 no longer only a task-minting one.** Two members ship, with two predicates, and both sit in Increment 2's **commit-on-behalf** partition (`cli::cli::BEHALF_DOORS`; [validation.md](validation.md) → The M51 registrations): the three task-minting doors below, whose predicate is the mint-time staged snapshot, and `jigc setup`'s install commit, whose predicate is its own install pathspec against `HEAD`. **The widening stops at that class, and that is a scope rather than an omission** — stated over *every* committing door the sentence would be **false at HEAD**, because `jigc rename`, `migrate-corpus` and the milestone record-only doors commit without asking this question at all, so it names the doors that ask and records the ones that do not rather than replacing one law-1 overclaim with a wider one (`completions/artifacts/M51/settle-record.md` → §13).

**The first member — the task-minting doors.** Each of the three (`jigc start` compose forms, `jigc migrate`, `jigc milestone create` for the shared checkout's aggregate index) snapshots the staged state into the workbench: the staged set (path + staged blob hash) **and the staged-deletion set** (HEAD entries absent from the index — a pre-task `git rm` is a carryover the entry-only snapshot is structurally blind to, and it is verbatim the trial's A7 case). Finalize preflight computes the **carryover set** — index entries whose (path, blob) match the snapshot, plus snapshot deletions still staged — i.e. *staged before this task existed*, deterministically. Non-empty ⇒ finalize **refuses**: **one blocking routed finding per carried path** (`finalize.carried-staged`, file-path target form, keyed per file — the `migrate-corpus.*` one-refusal-per-candidate precedent; joins the finalize sub-table in [command-output-contract.md](command-output-contract.md)); override with `--carry-staged` (the `--approve` mold — undecidable intent converted to a declared one; on a migration finalize it composes with `--approve`, two independent declarations). The migration's own retire pathspec is exempt (that deletion is the task's). **Missing snapshot ⇒ fail-open** (a task minted pre-M43 finalizes as today — declared bound). The manifest labels carried entries `carried-over` at all four render sites (dry-run forecast, pre-commit print, landed text, landed JSON — the identical-set invariant holds; the JSON kind value is a pre-1.0 additive extension, declared as it ships). This revises [finalize.md](finalize.md)'s "surfaced, not prevented" paragraph on its changed factual basis (the lacon A6/A7/A10 evidence postdates the M42 re-affirmation); the M42 left-out **print** settle is distinguished and untouched; [worked-examples.md](worked-examples.md) flow 41 arm 1 stays green *by design* (its pre-staged `git rm` happens after mint → not in the snapshot). Fan-out worktrees are provisioned clean, so the sub-task snapshot is trivially empty.

**The second member — `jigc setup`'s install commit (M51 Increment 3, corrected by its completion audit).** It mints no task, so it snapshots nothing: its predicate is **its own install pathspec against `HEAD`**, asked **once, before the install writes a byte**, and acted on there. Non-empty ⇒ the door refuses having installed **nothing**: **one** blocking routed `setup.dirty-install-path` over the whole sorted set (no `location` — the set is the subject, the `uninstall.dirty-worktree` mold at this same door), every named path left exactly as found, and **`jigc setup --force`** the single consent — the only meaning `--force` carries at this door, since Increment 2 gave posture refusals no override. The *refuse only what is still dirty afterwards* conjunction it first shipped with, and the whole-rewrite carve-out that justified it, are **struck with their falsifying datum**: a path the install rewrites whole reads clean afterwards *because* the adopter's bytes are gone, so the second leg could not see the loss it was reasoning about. What survives is an **ownership** question defaulting to refuse — exempt only where an oracle reads the file and says the bytes are jigc's own (the guide's recorded digest, the version stamp's shape). **And one exemption that is not about ownership, stated per member** (the rc.24 fix pass, `(R1, F1)`): on an unborn `HEAD`, an *untracked* file at a path whose writer **preserves** what it finds rides the repository's first commit — the on-ramp; where the writer **replaces**, the door refuses there too, and its route is worded for a repository with no commit, since `git stash` cannot run in one. **The predicate is asked of the files where `git status` cannot answer it** (the rc.24 fix pass): a tracked path whose index entry hides its change is dirty at every member, and a file git ignores is a subject at a path the install replaces, exempt only where its bytes are jigc's own generated content — recognised per member, and across an upgrade by the install footprint record — with each such path routed at an act git performs on it, never at the *commit or stash* it would ignore. The same predicate is re-asked over the settled pathspec before the commit as a **backstop** for the hook, the one pathspec member the pre-write enumeration cannot name; where that arm fires the install is written and staged and its finding says so. **`--force` consents, it does not preserve** — the install runs over those bytes, and the advisory `setup.forced-install-path` names every path the consent was spent on. Full contract: [assistant-adapter.md](assistant-adapter.md) → The install commit's pathspec; the inventory row: [validation.md](validation.md) → The M51 registrations — Increment 3.

### The error-code namespace

Not every non-commit is a `Finding` (the [measurement.md](measurement.md):62 rationale). The **error-code vocabulary** — dotted identities carried on `Outcome` into the invocation log — lives as a **code-side registry const** with a test asserting no member collides with the finding-code inventory (this doc's own medicine — a prose anti-collision rule would be the census the preamble bars).

**The vocabulary is per-door, not per-verb and not shared (M47).** M42's registry closed at two members on the recorded rationale *"deliberately not a per-verb code mint — errored verbs already write records; the registry closes at the identities the log genuinely could not distinguish without."* That was sound while exactly **one** door framed its rejection. Once the survivable frame sweeps every committing door ([finalize.md](finalize.md) → 6. Commit), reusing `finalize.commit-rejected` on the non-finalize ones puts a **lying** code in the log — a law-1 violation on the very surface M42 built to stop the log lying. So the rationale is revised with its rationale engaged: one identity per **door**, and every member is still an identity the log could not otherwise distinguish (a rejected `jigc rename` and a `jigc rename <absent>` are both exit 1 with no findings). The anti-collision rule above is untouched and still checkable: it bars a member from colliding with the **finding-code inventory** — the probe/check vocabulary `engine::result::check_inventory_codes()` projects — so that a log reader cannot mistake one family for the other. None of these twelve is in that inventory, and a `*.commit-rejected` is not a check any probe runs; it is one event, named once, readable on both surfaces. That log read is load-bearing: `Outcome::error`'s membership check is a `debug_assert!`, compiled out of the release build an acceptance trial actually runs, so a test that only exercised the constructor would prove nothing about the shipped binary. One list, two consumers — a door added without a code is a red test, never a silent log entry naming the wrong verb ([DECISIONS.md](../DECISIONS.md) → 2026-07-26 M47 the Settle, Decision 6, and the cross-model review's condition on it). **And the table above is the registry's third consumer (M51 Increment 7):** `crates/cli/tests/count_fences.rs` reads this file and asserts the identity column lists `ERROR_CODE_REGISTRY` member-for-member, in order, with the size the sentence states — until then the registry's own unit test named this file in its assert message while no test had ever opened it, so the mirror was a promise rather than a fence.

## The surface style guide (the judgment tier)

For the prose no fence holds. The milestone-completion audit checks pack-prose changes against this list; it is a review checklist, never a machine gate.

- **Workflow catalog descriptions are routing surfaces.** `when:` does one job: disambiguation against the neighbouring workflows — name the discriminating trigger axes (records a decision? test-first? touches managed docs? spec-bound?), the axes an agent actually decides across. `usage:` carries the fuller story **including when NOT to use it** and its nearest-neighbour handoff ("if it renames a documented symbol, pick single-task"). `description:` says what it is, never mechanism. (Format rules: [workflow-dialect.md](workflow-dialect.md); field boundary: [introspection.md](introspection.md).)
- **Step prose leads with the action; constraints before the solicit.** State what the agent is about to do in the first sentence; state every constraint that gates the solicited write *above* the `Run:`/heredoc that solicits it (law 3's prose form — the M42 staging-contract sentence is the mold).
- **Routes name the exact next command for the state at hand** — one command, real, copy-runnable where mechanical; "no action needed" says so in the first clause. (Route kinds and per-family strings: [command-output-contract.md](command-output-contract.md), [validation.md](validation.md).)
- **Help verbs lead with the one-line common case**; contract detail, posture notes, and design-doc pointers go below the fold, never in the subcommand table line.
- **A statement about a surface is quantified over what that surface actually serves** (M47 Inc 10 / T6 — RC-alpha4 D1 + the `describe --format json` gap). An affordance advertised over a catalog it refuses part of (`--preview` over every `<id>` when it serves only the task-minting ones), or a posture asserted over an arm the same verb serves (*"don't parse it"* over a `--format json` that emits a keyed object), is a law-1 lie **even when the behaviour underneath is right** — and both refusals here were right. The repair is scope, never a behaviour change: name the scope, and name what the members outside it do instead (the direct run; the versioned `jigc doc schema` read). A reader cannot infer the scope from a catalog that does not mark it.
- **A located finding says where, and says it the same way everywhere.** A finding that carries a `location` renders it — the address *and*, when the producer claimed one, the source line — on every surface that renders that finding as text, not only in the machine envelope. A surface that withholds the locus does not merely inconvenience a reader: it can falsify a rule written about it, which is exactly what happened to the `conformance.*` route exemption ([validation.md](validation.md) → the route floor). One renderer (`cli::render::finding_locus`), one glyph (`  at: <address> · line <n>`), and a source-derived sweep over every production read of a finding's message.
- **Advisories say what happened + whether to care, in the first clause.** An advisory an agent should usually ignore must read as ignorable in clause one — habituation is a real, measured cost (three trials).
- **Acks state the effect, not just the target.** Created vs already-existed; what a discard threw away; `task minted: <id>`.
- **Verdict words bless legitimate end-states.** `unmanaged`/`unregistered` describe; they do not imply everything must migrate — staying plain is a correct outcome for off-home files (the at-home squatter keeps the one-story adopt-it rule, [doc-read-surface.md](doc-read-surface.md)).

## How each fence is proven (the unit-vs-flow split)

A flow arm cannot trip a `debug_assert` without an injected defect, so the acceptance cut splits by posture: **debug-posture fences** (route construction parse, floor presence, key discrimination) prove via unit/integration tests through the seam (the M42 `finding.rs` test pattern); **release-real pack-load fences** (suppression, catalog shape, stated-at, freeze) prove via mutated-filesystem-pack arms (the `freeze_enforcement.rs` pattern) *and* are flow-testable; **behaviour changes** (carryover refuse, staged read, same-path approve, created-vs-existed, generated templates) prove via flow-44 arms through the real binary.
