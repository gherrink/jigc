# The surface contract

**Status: settled at M43 planning (2026-07-16); built across M43.** The record: [DECISIONS.md](../DECISIONS.md) → 2026-07-16 M43 planning: the Settle. Provenance: the lacon trial ([completions/artifacts/RC-lacon/](../completions/artifacts/RC-lacon/trial-record.md)) — zero correctness bugs, a recurring discoverability class: *the capability exists, no composed surface names it*.

Everything jigc prints — composed output, findings, routes, help, author templates, acks — is a **contracted surface**: it obeys three checkable laws, each **fenced where the surface is generated**, plus a written style guide for the judgment tier no fence can hold. The M42 lesson binds throughout: *a census cannot enforce a predicate* — no fence in this doc is a grep-checklist over prose; every fence is either a type that makes the lie unrepresentable, an assert at the seam where the property is decided, or a structural declaration checked against enumerable data.

This doc owns the **laws, their fences, and the style guide**. It deliberately does *not* restate what its neighbours own: the findings envelope, route kinds, and stable `(code, target)` key ([command-output-contract.md](command-output-contract.md)); the route floor's rule text and per-family route strings ([validation.md](validation.md)); the `when:`-line craft format ([workflow-dialect.md](workflow-dialect.md) → the catalog line); the `description:`/`usage:` field boundary ([introspection.md](introspection.md)); the read-surface postures ([doc-read-surface.md](doc-read-surface.md)); the finalize manifest vocabulary ([finalize.md](finalize.md)). The **AGENT.md preload tier** is a law-2 surface class named below (M44 Inc 4), but its **body content** stays owned by [assistant-adapter.md](assistant-adapter.md):48 — this doc cross-references it as a surface, never restating its paragraphs.

## The three laws

**Law 1 — nothing lies.** Every claim a surface makes is generated from the thing it describes, or asserted against it. Templates never hand-enumerate what the schema can project; every printed path is repo-real or a typed identity; behaviour claims match knobs; an ack that says "created" distinguishes created from already-existed. The strongest form is making the lie **unrepresentable**: the string is built from the schema / the `Command` value / the enforcing constant, so drift has no representation.

**Law 2 — nothing hides.** Every affordance that is the designated recovery for a state is named by the surfaces that produce that state — resume (`jigc start --task <id>`), what's-left (`jigc task validate <id>`), the staged read (`jigc doc show <addr> --task <id>`), `task list` on a wrong id, a write against a not-yet-minted item id → the containing section's read (`jigc doc show <type>:<slug>#<section> --task <id>`, whose live item ids reveal the right address — M44 Inc 2, detailed in [validation.md](validation.md)). Routes and `Run:` lines parse against the real CLI. Any suppression flag (`selectable: false` and kin) carries a machine-visible reason + expiry, asserted at pack-load — a hidden capability whose hiding condition expired is the `decided-task` lesson made mechanical. The **AGENT.md preload tier** — the one surface loaded before the model plans — is the law's push-side complement (M44 Inc 4, rc.7 discoverability rerun): it names the machine-output facts a driver would otherwise reverse-engineer by scraping text (`--format json` on every success/validation outcome; the `.task` id on the composed producers) and the binary-introspection path that supersedes a stale-source reach (`jigc --help`/`describe`/`doc schema`), so a capability the model would improvise around is preloaded instead of hidden. Body owned by [assistant-adapter.md](assistant-adapter.md):48; fenced there by the whole-body golden plus the `--format`-is-global assert.

**Law 3 — nothing ambushes.** Every constraint is stated where it binds, *before* it can fail: the slot heading-depth ceiling, the `--from-file -` convention, the `--approve`/clobber/retire contract, the slug word-cap — each named in the template/step/help that solicits the write that would trip it. A block whose contract first appears in the block message is an ambush even when the block is correct.

## The fences

Enforcement posture is **per-class, by the existing records** ([DECISIONS.md](../DECISIONS.md) → 2026-07-11 M41 Inc-3 (the seam-assert posture) and → 2026-07-13 M42 Inc-6 (the freeze-assert discharge)):

- **Render/serialization-seam asserts** on jigc's own producers are `debug_assert!` — enforced by the test suite exercising the seam, never a release-build panic on a user's finding.
- **Pack-load asserts** are release-real, in the pack factory (`make_pack`), because filesystem packs load in production (the M42 lesson). They require the **eager workflow-front-matter sweep** — net-new at M43; today workflows parse lazily. Scope: the **shipped embedded packs** (the factory sees pack bytes only; project-layer cascade deltas are consciously outside these fences — declared bound, not a hole).

### The route fence (law 2)

`Finding.route` becomes an **internal `Route` value** — `Mechanical { argv, tail } | Human(String) | Informational(String)` — constructed at the producer, **serializing byte-identical to today's string** (the pinned golden in `finding.rs` does not move; the wire tagged-union stays deferred, [decisions-pending.md](../implementation/decisions-pending.md)). The fence: a `Mechanical` route **cannot be constructed** from a command that does not parse against the real CLI (`Cli::try_parse_from` over its argv parts, placeholder args substituted). `From<String>` maps to `Human`, so migration is per-producer. The parse assert lives at the **CLI seam** (the engine cannot see clap); it is the third assert on the M42 finding-key seam.

**The route floor widens to blocking validation/gate findings** (revising [validation.md](validation.md)'s advisory scoping — a blocked finalize is the highest-stakes surface and today prints no recovery). Two exemptions are **re-affirmed on their own rationales**: purely-positional parser conformance diagnostics (the located message *is* the repair) and the hook-rejection route-exempt error identity (git's verbatim stderr *is* the correction signal, [finalize.md](finalize.md):78). With the floor true, [assistant-adapter.md](assistant-adapter.md)'s "every finding carries a route" sentence becomes true rather than fixed down.

**Pinned mechanics (review-baked, 2026-07-16):** the floor's *presence* half (`severity == blocking ⇒ route present`) asserts at the same M42 finding-key serialization seam, with the parser-diagnostic exemption carried by **one exemption function in one place** (the `is_declared_singleton` pattern — a list of exceptions checkable from the code alone, never a census of call sites). The `Route::mechanical(argv…)` constructor follows the seam-assert class posture: `debug_assert!` that the argv parses (`Cli::try_parse_from`, with `<PLACEHOLDER>`-class args substituted by a single declared dummy table beside the constructor) — enforcement rides the suite, never a release-build panic. **The future wire union is the kind taxonomy** (`Mechanical`/`Human`/`Informational`) — [validation.md](validation.md)'s earlier `fill-leaf`/`run-command`/`reconcile` sketch is retired in the fold-back (rationale engaged: a driver needs act-vs-inform; `Mechanical{argv}` subsumes `run-command`, and fill-leaf/reconcile are mechanical routes to specific verbs).

**P6 — route-followability (M47).** The parse fence proves a mechanical route **runs**; it cannot prove it runs *here*, at the address the finding names, because it sits on `Route::mechanical` and never sees the finding. A route that reaches a driver still carrying `<doctype>` or `<address>` therefore passes every fence above and is still unrunnable — law 2 failing at the last inch. So a second, **finding-side** property: *a placeholder whose value is derivable from the finding's own `key.target` must be substituted before the finding is projected*, asserted at the finding-serialization seam (the fourth assert there, debug posture like its three siblings). Derivability is declared per placeholder — one row per member of the CLI-seam dummy table, each carrying a verdict **and its reason**, in the engine beside `is_route_exempt`/`is_declared_singleton`, with a test asserting the two tables declare the same set in the same order. Exactly two are derivable: `<address>` (the target itself — **narrowed to the top showable hop on a `jigc doc show` route**, since a read verb resolves a doc or a section and never the absent item a `write.not-present` names, so echoing the target there would mint a concrete dead end) and `<doctype>` (the target's `<type>` head). The rest are declared non-derivable with their reason, and **`<task-id>` is the honest carve-out**: one doc is written from many tasks, so no rule derives it from an address — it needs a different source (the CLI dispatch that resolved the task supplies it at every enriched write-verb producer) and stays outside the property rather than being faked. Human-route prose spans are outside it too: the property reads an argv, which only a mechanical route has.

**Producer migration is per-producer, and reshaping a route is when it happens (M47 inc-10).** `From<String>` keeps an un-migrated producer compiling as `Human`, so the fence only reaches a route when someone edits it. The rule the rc.10 wave applies: **a route whose text is a single leading backticked real argv (± trailing prose) is constructed through `Route::mechanical`** — the shape `Route`'s one composition rule already renders (`` `<argv>` `` + verbatim tail), so it costs nothing and buys the parse assert. A two-argv route, or one whose command sits mid-sentence, does not fit the constructor and stays `Human` — the constructor is not to be contorted to claim a conversion. Two routes qualified in that wave: the `add-from-spec` no-`criteria` block (now `jigc doc show <spec-addr>`, naming the sections the addressed doc does carry) and `jigc ingest`'s near-miss (now the same `jigc migrate <rel> --as <doctype>` the store sweep's orphan sibling has handed over since M40 — the two surfaces had one file, one repair, and only one of them followable).

**A route offered on a wider domain must be gated on that domain, not on the case that motivated it** (the build-side *widen-a-guard* rule, applied to routes). `jigc ingest`'s near-miss fires for every non-conformant candidate at a managed home — which includes an **already-adopted** doc, for which adoption is not the repair at all — so the migrate argv is gated on the candidate being both unregistered and its doctype migratable, and each other arm says which of the two it is. A mechanical route that hard-rejects, or repairs the wrong thing, is law 2 failing one level down.

Route text that lives in anyhow error strings (outside `Finding`) is in scope for the law-2 rewrite, **bounded to shipped verbs' error strings that carry command spans**: each such site either becomes a `Finding` or constructs a `Route` for its spans — an errorish surface is still a surface; prose-only error text is untouched.

### The schema projection (law 1)

A new compose placeholder **`{{schema:<doctype>}}`** — CLI-filled read path, the `{{source}}` seam mold — renders the resolved schema's section/field/enum tree **and the author-payload skeleton** into the step that solicits the authoring. **Unfed or dangling blocks**: `workflow-refs.schema-ref-resolves` (blocking; fires at the store-scope sweep — enumerated per workflow per origin pack, **resolved against the composed cascade's full doctype set** (a methodology step legitimately solicits a dev doctype — the composition model, not per-origin doctype scoping) — *and* at compose; never silently empty, which would be a new lie). The new check id joins the [validation.md](validation.md) single-source-of-truth inventory (intrinsic-floor class, severity blocking, un-tunable) **and** both packs' `knobs.yaml` mirrors in the same increment. Joins the dialect grammar + the `workflow-refs` check ([workflow-dialect.md](workflow-dialect.md) owns the grammar row). The renderer reads the *resolved current* schema, so a future schema bump re-renders correctly by construction. Migration **judgment** prose (foreign-status mapping, drop-to-prose rules) stays hand-written — that is the style guide's tier.

### The suppression fence (law 2)

Workflow front-matter gains `suppressed: { reason: <text>, expires: <condition> | never }` required on every `selectable: false` (and any future hiding flag). **`never` is a legal declared value** for permanent-by-design hides (`sub-task` is spawned, never picked; the `migrate-*` family is verb-routed) — the reason still says *why* it's permanent, and the fence never forces a fake expiry (which would be its own law-1 violation). The expiry-audit obligation applies only to non-`never` conditions. Asserted at pack-load over the shipped packs: missing ⇒ fail (required-field-shaped, so the loader's unknown-key tolerance cannot defeat it — a `deny_unknown_fields` flip is consciously not taken; project packs may carry vendor keys). `jigc describe` prints the reason for a hidden workflow, so `describe` and the orient catalog stop contradicting each other.

### The catalog shape fence (style guide's floor)

Pack-load asserts on the shipped packs: `when:`/`description:`/`usage:` **present** on every selectable work-workflow (extending the existing catalog-build assert into the factory) and `when:` **mechanically shaped** (one line, period-less, length-capped — the [workflow-dialect.md](workflow-dialect.md) craft rules' checkable half). The when-NOT-clause assert is **declined** — that is prose semantics, the barred census; the when-NOT discipline lives on `usage:` via the review checklist. [introspection.md](introspection.md):84's skip-on-absent stays intact for project-authored workflows (honored via scoping; its :86 shipped-pack obligation is what these asserts implement).

### The stated-at fence (law 3)

Tiered by what the constraint's source is:

- **Seam-generated** where a code-owned source exists: the slug rule's statement renders from `MAX_WORDS`/`MAX_CHARS` (the constants the manifest already fingerprints); the heading-depth ceiling's statement is co-located with the enforcing check and rendered via the schema-projection generator. Statement and enforcement share one source; drift is unrepresentable. *(As settled at M43; the ceiling half is revised immediately below.)*

  **Revised at M45 — the shared source must carry the rule's context, not just its value.** The rationale above holds exactly as far as it claims, and it is unchanged for a **context-free** constant: the slug cap is one number for every slug everywhere, so `MAX_WORDS` *is* the rule and generating from it makes the lie unrepresentable. The heading-depth ceiling is **context-dependent** — the reserved set is a function of the target address (section slot, item nesting depth, multi-slot sub-label; [implementation/parsing.md](../implementation/parsing.md) → Slot heading-depth ceiling) — and it was generated from two global constants. The fence did its job perfectly and proved the wrong property: statement == constant, while the constant was context-blind. The result is worse than an ungenerated sentence, because the fence guarantees the falsehood renders **consistently, everywhere** — it rendered *"`####` is safe"* into the planning workflow, whose primary writes are `roadmap` milestone item slots, where `####` is the corrupting depth. So the corrected model: **a context-dependent rule takes its context as a fence input** — derive the statement from the same schema-resolved source the enforcement derives from (`(Schema, section_id, item-id chain)`), never from a constant that outranks the context. M45 parameterizes the ceiling statement accordingly, so the projection renders the reserved set for *the address being solicited*.

  **One carve-out, taken consciously.** `jigc doc set-slot --help` is **address-independent** — clap renders help before any address exists, so no target's reserved depth is knowable there. It states the **general** rule (the ceiling is schema-relative; the projection at the solicit names the depths for your address) rather than a specific depth, and the verbatim-equality drift assertion at `crates/cli/tests/help_truth.rs:209` relaxes accordingly: the help text can no longer be byte-equal to a statement that only exists per-address. This **re-opens M43's law-3 fence-depth settle** (that wave's Settle fork 3 — seam-generated constraint text wherever a code-owned constant exists, fenced here by the help containing `slot_ceiling_statement()` verbatim) — re-opened on its own rationale, not by oversight: verbatim equality bought unrepresentable drift while exactly one statement existed; with the statement parameterized per address, insisting on it would force the help back onto a global constant and re-mint the exact lie ([DECISIONS.md](../DECISIONS.md) → 2026-07-23 M45 planning: the Settle).

  **The census is five further sites, not one — enumerated, because a partial relaxation leaves the lie rendering somewhere.** `slot_ceiling_statement()` has six consumers, and the carve-out above names only the help pair. In full, split by what each becomes:

  | consumer | becomes |
  |---|---|
  | `jigc doc set-slot --help` text (`crates/cli/src/doc.rs`) + its verbatim drift assertion (`crates/cli/tests/help_truth.rs:209`) | **general-rule prose**; the assertion relaxes off byte-equality (the carve-out above) |
  | the second verbatim drift assertion (`crates/cli/tests/surface_polish.rs`), over the composed `single-task` / `dev-task` / `decided-task` flows | relaxes the same way — it pins composed step prose against the one global statement, which is exactly the byte-equality that cannot survive parameterization |
  | the `{{schema:<doctype>}}` projection seam (`crates/engine/src/compose.rs`) | **address-parameterized** — the one site that *can* know the target, so it is the one that renders the reserved set for the address being solicited |
  | the hand-written pack-step copies: `crates/cli/pack/steps/implement.yaml` + `crates/cli/pack/steps/author-commit.yaml` (M47 Inc 5 split the one dev copy across the two steps that now solicit slot prose — the ADR slots and the commit summary), `packs/methodology/steps/author-commit.yaml` (the same M47 split in the methodology pack — the copy travelled out of `finalize.yaml` with the solicit it guards, so it still sits in the step that owns the write), `packs/methodology/steps/author-decision.yaml` | **general-rule prose** — a step's prose is composed before any address is chosen, so it states the schema-relative rule and defers the depths to the projection in the same step. The rule is **path-local**: it is stated once per step that solicits slot prose, above that step's first `set-slot`, never hoisted into one home a later step could sit below |

  Each of these carries a static *"`####` or deeper"* claim today, and each such claim **remains a law-1 lie wherever its solicit targets a multi-slot or nested item slot** — the `roadmap` milestone-slot case that made the defect real. Relaxing the two assertions without converting all four prose sites would simply stop *detecting* the lie; converting the prose without parameterizing the projection would leave every solicit unable to name any depth at all.
- **Structural stated-at** for irreducibly-prose contracts (the `--approve`/clobber/retire contract; the staging contract): the soliciting step's front-matter declares `states-constraints: [<finding-code>, …]`; the pack-load assert checks every member of the declared **ambush-class code set** has at least one shipped-pack declarer. The set is a **code-side const beside the assert** (not pack config — the obligation is jigc's, not the pack author's); initial membership: `finalize.promote-clobber` (the `--approve`/retire contract) · the staging-contract pair — `finalize.nothing-staged` (a minted finding code) + `finalize.left-out` (**not** a minted finding code: its production surface is the M42 pre/post-commit left-out *print*, per the print-over-refuse settle — the string names the staging contract only) · `finalize.carried-staged`. Both sides are structural (the set is a fixed list of constraint identifiers — most are M42-keyed finding codes, one a declared print-surface contract; the declaration is YAML) — and, as settled at M43, the assert never read the prose at all. **The no-prose-matching clause and the honest bound below are revised by the named-fact tier two bullets down (M47)**; as originally settled they read: the assert proves the *obligation* is carried, not that the prose is good; prose quality is the review checklist's job.
- **Per-soliciting-step stated-at** (M44 Inc 6, D5 — the path-local-guidance owe-set) for a contract whose *owe-set is enumerable from the step itself*, not a fixed global list: a step whose body references `{{schema:<T>}}` where `T` is a **singleton** doctype (a create-or-update singleton author solicit) must declare `create.singleton-copy-in` — the copy-in/append contract (an already-committed singleton is copied in as the edit base, so authored items append / slots overwrite; same-path migration is the blank-seed exception). The owe-set is **derived from the enumerable structural signal the step already renders** — the `{{schema:<T>}}` ref × `T`'s `singleton` flag; the `authors-into:` marker considered at Settle is **dropped as circular/drift-prone** (B2-baked, single source of truth). So the pack-load assert is *per soliciting step*, not per-global-code: any manifest-shipping step that solicits a singleton yet omits the code reddens at pack-load, naming the step and the code (the seven migrate author steps' path-local guidance caught by construction, not template diligence). `create.singleton-copy-in` is a code-side const beside its assert (**not** a minted `Finding` code — its production surface is the migrate step's own guide prose, the A-3 presence-only tier). Per-origin schema resolution suffices — each soliciting step references a singleton of its own origin pack. Same honest bound: presence-of-obligation, never prose quality — **revised at M47 to presence of the contract's *named facts*** (the tier immediately below).
- **Named-fact stated-at** (M47 Inc 9 — the tier that makes the two above buy something). A declaration is a receipt, and a receipt outlives what it stands for: the M47 pre-decompose review demonstrated it live, deleting 590 characters of copy-in/append contract prose from a migrate step while keeping its front-matter code — every fence stayed green. So each fenced code carries a **required-token set** in a code-side map (`cli::pack::CONSTRAINT_REQUIRED_TOKENS`), the phrases the declaring step's own body must contain:

  | code | required tokens |
  |---|---|
  | `finalize.promote-clobber` | `--approve` · `retire` · `fidelity diff` |
  | `finalize.left-out` | `unstaged` · `untracked` · `left out` |
  | `finalize.nothing-staged` | `nothing staged` · `refuse` |
  | `finalize.carried-staged` | `--carry-staged` · `this task was minted` |
  | `create.singleton-copy-in` | `copies the committed body in as` · `edit base` · `overwrites` |
  | `read.staged-read-back` (M48 — the write-solicit tier two bullets down) | `jigc doc show` · `--task` |

  **The conditional tier (M47 Inc 9 T2): the append half is owed wherever items can double.** The map above is *flat* — it carries what binds at **every** declarer of a code. The copy-in contract has a second half that binds only where the solicited singleton can hold repeating items: authored items **append** to the committed ones, so re-authoring one the doc already holds **would double** it. Flat-mapping those two tokens onto `create.singleton-copy-in` would force methodology's `author-migration-vision` — whose `vision` schema is slot-only and correctly states that the slots OVERWRITE — to state a falsehood, a law-1 lie demanded by the fence itself; omitting the tier leaves five declarers free to un-state half a contract they still declare. So the tier's owe-set is **derived, like the per-soliciting-step tier above, from the structural signal the step already renders**: the solicited singleton's own schema declares ≥1 `repeatable:` section ⇒ the step must also state `cli::pack::COPY_IN_APPEND_TOKENS` (`append` · `would double`). The condition is read off the same schema load the copy-in fence already performs — no second signal, and **never an exclusion list**. It partitions the six shipped declarers exactly: the five whose singleton repeats (`record-changelog` + `author-migration` over `changelog`; `author-migration-roadmap` / `-decisions-log` / `-deferral-ledger`) owe it, `author-migration-vision` does not and stays **inert, never in error**. Both sides are swept through the real binary from the trees themselves (`crates/cli/tests/stated_at_fence.rs`): each owed append fact deleted in turn blocks pack load naming step, code and token, and the exempt declarer is proven to state neither token *and* to load clean — the exemption asserted, not assumed.

  Matching is over a **whitespace-collapsed, ASCII-case-folded** view of the body — both halves are load-bearing over the shipped prose (methodology's `finalize` opens a sentence with "Unstaged"; the copy-in sentence wraps across a hard line break in every declarer) — and the tokens are authored in that same normalized form, fenced by a unit test so an unsatisfiable token cannot ship. Scope is the **fence family**, not `finalize.yaml` parity: every declaring step of every manifest-shipping constituent, in both packs — the break was demonstrated on a migrate step's `create.singleton-copy-in`, so a finalize-only guard would be a fix that does not sweep its own axis. **This stays inside the A-3 presence-never-content bound** ([methodology-docs.md](methodology-docs.md)): what is bought is the *named facts of a contract jigc itself owns* — never register, order, phrasing, or quality — which is why each code demands a handful of tokens and why the map is **bijected** against `AMBUSH_CLASS_CODES` + `create.singleton-copy-in`, so jigc never puts prose demands on a pack author's own vocabulary. Declared bounds: a **project-layer forked step** (`.jigc/config/steps/*.yaml`) is outside this fence exactly as it is outside every pack-load fence (manifest-shipping constituents only); a **pack-authored code** outside jigc's fenced set carries no token requirement; a manifest-less pack stays on skip-on-absent; and any future cross-pack parity assertion is over **contract facts, never a field list** (dev shadows methodology — `pack.rs`, *"dev first = dev-highest"* — and the two `commit` schemas genuinely differ). The axis is machine-swept, never hand-listed: every (declaring step × declared code × required token) triple of the two shipped trees, deleted in turn from a copied pack, must block pack load naming step, code and token (`crates/cli/tests/stated_at_fence.rs`).
- **The obligation direction** (M47 Inc 9 T3 — `create.singleton-copy-in` becomes a **biconditional** with the `{{schema:<T>}}` ref it guards). Every tier above runs one way: *ref ⇒ declaration ⇒ named facts*. That leaves the sharper sibling of the deleted-prose break open — delete the **ref** instead, and the obligation itself disappears: the per-soliciting-step tier and both named-fact tiers go inert (there is no solicit left to fence), the pack loads clean, and the step's prose keeps promising a payload that never follows. Demonstrated live on the dev pack's `record-changelog`: with `{{schema:changelog}}` deleted, `jigc start` exits 0 and the composed step still reads *"The target schema and its batch payload … follow — one call places the whole entry over the staged buffer:"* above nothing, then tells the agent to pick a category from "the enum members the schema above lists". So the reverse direction is fenced too: a step declaring `create.singleton-copy-in` must reference a `{{schema:<T>}}` whose `T` resolves to a singleton, or pack load fails naming the step and the code. [validation.md](validation.md)'s `workflow-refs.schema-ref-resolves` guards only the **opposite** case (ref present, schema absent) and structurally cannot see this one. The check is **structural, not token-based** — no prose-matching of the promise sentence, which would leave the A-3 bound — and it reads the same enumerable signal the tiers above already read, so it costs one branch on a load already performed. It lands **inert**: all six shipped declarers reference a singleton today (`record-changelog` + `author-migration` → `changelog`; `author-migration-roadmap` / `-decisions-log` / `-deferral-ledger` / `-vision` → their own). Declared boundary, recorded rather than silently narrowed: a step that deletes **both** its ref and its declaration leaves the fence family entirely — the family is *every step carrying a `states-constraints:` code* — so that case is out of scope by the family's own definition (a pack author deliberately retiring an obligation, which the review checklist owns, not a receipt outliving what it stands for). Swept from the trees like the tiers above: all six declarers (two dev, four methodology, enumerated never hand-listed) stripped of their ref in turn through the real binary, with the shipped compositions and the manifest-less control staying clean (`crates/cli/tests/stated_at_fence.rs`).
- **Write-solicit stated-at** (M48 Inc 3 — the fourth tier, and the first one carrying a **law-2** obligation rather than law 3). The three tiers above all fence a *constraint*: something the write can trip. This one fences an *affordance* the write creates the need for — **the read-back**. `jigc doc show <addr> --task <id>` has served the task's staged copy since M43, and six consecutive trials went to the filesystem to read their own in-flight work anyway; the pre-1.0 trial made the mechanism countable rather than described (exactly one pack step file named `doc show`, and it was a committed-doc id lookup, not a read-back of in-flight work — the count and the binary it was measured on live in [decisions-pending.md](../implementation/decisions-pending.md) → *The rc.11 wave (M48)*). A seventh instance-fix would have named it in the steps that happened to be reported, so the obligation is fenced where writes are solicited instead: a step that solicits a managed-doc write must declare `read.staged-read-back` (a code-side const beside its assert, **not** a minted `Finding` code — its production surface is the step's own prose, the A-3 presence-only tier) and, through its `CONSTRAINT_REQUIRED_TOKENS` row, state the read (`jigc doc show` · `--task`).

  The owe-set is **derived from the two enumerable structural signals a soliciting step already renders** — the same B2-baked discipline as the per-soliciting-step tier, and for the same reason: a marker maintained by hand would drift off the writes it claims to track.

  | signal | what it reaches |
  |---|---|
  | a lone-line `{{cli.<id>}}` ref whose catalog entry is a `jigc doc <write-verb>` call — the write-verb partition being the **production** one (`cli::doc::doc_write_verbs`: the built clap `doc` leaf set minus the declared read verbs `show`/`schema`/`list`, the same split the rejected-write exit-code sweep consumes) | the per-leaf author steps, which solicit their writes through the catalog |
  | **union** a `{{schema:<T>}}` ref — the authoring-payload projection | the migrate author templates, which solicit their whole write through the projection and carry no `{{cli.<id>}}` ref at all |

  Either signal alone misses half the surface, so the union is the rule and the suite proves it *is* a union (each arm reaches a step the other does not). The catalog is read **per origin pack**, like the schema resolution beside it. The statement is **path-local** in the M45 sense — once per soliciting step, naming that step's own address shape, never hoisted into one home a later step could sit below — and the addresses it names are real: doc-level, transient `commit:<task-id>`, bare placement singleton and `#section` slice were each run before the prose claiming them shipped.

  Declared bounds, recorded rather than silently narrowed. **The direction is solicit ⇒ declaration only** — no biconditional sibling. `create.singleton-copy-in` earned its reverse arm (M47 T3) because deleting *its* ref leaves the composed step promising a payload that never follows; withdrawing a write solicit leaves no such dangling promise, so the reverse case is out of scope on its own rationale rather than by oversight. And a step soliciting its writes as **literal** command lines only — the dev pack's `locate-from-spec` sets fields with hand-written `jigc doc set-field` lines and no catalog ref — carries no structural signal for either arm; it states the read-back and its fence-invisibility is declared, not papered over with a hand-added declaration the derivation would then reject. The axis is machine-swept from the trees (`crates/cli/tests/read_back_fence.rs`): the owe-set is recomputed from the copied tree, its own catalog and the code-side read partition, asserted equal to the tree's declarer set, then each member's declaration withdrawn in turn must block pack load naming step and code — with the shipped compositions clean and a manifest-less copy unchecked.
- **Guide-only** where the constraint is already demonstrated at every solicit (`--from-file -` appears verbatim in ~20 steps and its `Run:` lines fall under the route-parse fence).

### The carryover gate (law 1 + 3 at the commit boundary)

**Every task-minting door** (`jigc start` compose forms, `jigc migrate`, `jigc milestone create` for the shared checkout's aggregate index) snapshots the staged state into the workbench: the staged set (path + staged blob hash) **and the staged-deletion set** (HEAD entries absent from the index — a pre-task `git rm` is a carryover the entry-only snapshot is structurally blind to, and it is verbatim the trial's A7 case). Finalize preflight computes the **carryover set** — index entries whose (path, blob) match the snapshot, plus snapshot deletions still staged — i.e. *staged before this task existed*, deterministically. Non-empty ⇒ finalize **refuses**: **one blocking routed finding per carried path** (`finalize.carried-staged`, file-path target form, keyed per file — the `migrate-corpus.*` one-refusal-per-candidate precedent; joins the finalize sub-table in [command-output-contract.md](command-output-contract.md)); override with `--carry-staged` (the `--approve` mold — undecidable intent converted to a declared one; on a migration finalize it composes with `--approve`, two independent declarations). The migration's own retire pathspec is exempt (that deletion is the task's). **Missing snapshot ⇒ fail-open** (a task minted pre-M43 finalizes as today — declared bound). The manifest labels carried entries `carried-over` at all four render sites (dry-run forecast, pre-commit print, landed text, landed JSON — the identical-set invariant holds; the JSON kind value is a pre-1.0 additive extension, declared as it ships). This revises [finalize.md](finalize.md)'s "surfaced, not prevented" paragraph on its changed factual basis (the lacon A6/A7/A10 evidence postdates the M42 re-affirmation); the M42 left-out **print** settle is distinguished and untouched; [worked-examples.md](worked-examples.md) flow 41 arm 1 stays green *by design* (its pre-staged `git rm` happens after mint → not in the snapshot). Fan-out worktrees are provisioned clean, so the sub-task snapshot is trivially empty.

### The error-code namespace

Not every non-commit is a `Finding` (the [measurement.md](measurement.md):62 rationale). The **error-code vocabulary** — dotted identities carried on `Outcome` into the invocation log — lives as a **code-side registry const** with a test asserting no member collides with the finding-code inventory (this doc's own medicine — a prose anti-collision rule would be the census the preamble bars).

**The vocabulary is per-door, not per-verb and not shared (M47).** M42's registry closed at two members on the recorded rationale *"deliberately not a per-verb code mint — errored verbs already write records; the registry closes at the identities the log genuinely could not distinguish without."* That was sound while exactly **one** door framed its rejection. Once the survivable frame sweeps every committing door ([finalize.md](finalize.md) → 6. Commit), reusing `finalize.commit-rejected` on the non-finalize ones puts a **lying** code in the log — a law-1 violation on the very surface M42 built to stop the log lying. So the rationale is revised with its rationale engaged: one identity per **door**, and every member is still an identity the log could not otherwise distinguish (a rejected `jigc rename` and a `jigc rename <absent>` are both exit 1 with no findings). ## The surface style guide (the judgment tier)

For the prose no fence holds. The milestone-completion audit checks pack-prose changes against this list; it is a review checklist, never a machine gate.

- **Workflow catalog descriptions are routing surfaces.** `when:` does one job: disambiguation against the neighbouring workflows — name the discriminating trigger axes (records a decision? test-first? touches managed docs? spec-bound?), the axes an agent actually decides across. `usage:` carries the fuller story **including when NOT to use it** and its nearest-neighbour handoff ("if it renames a documented symbol, pick single-task"). `description:` says what it is, never mechanism. (Format rules: [workflow-dialect.md](workflow-dialect.md); field boundary: [introspection.md](introspection.md).)
- **Step prose leads with the action; constraints before the solicit.** State what the agent is about to do in the first sentence; state every constraint that gates the solicited write *above* the `Run:`/heredoc that solicits it (law 3's prose form — the M42 staging-contract sentence is the mold).
- **Routes name the exact next command for the state at hand** — one command, real, copy-runnable where mechanical; "no action needed" says so in the first clause. (Route kinds and per-family strings: [command-output-contract.md](command-output-contract.md), [validation.md](validation.md).)
- **Help verbs lead with the one-line common case**; contract detail, posture notes, and design-doc pointers go below the fold, never in the subcommand table line.
- **A statement about a surface is quantified over what that surface actually serves** (M47 Inc 10 / T6 — RC-alpha4 D1 + the `describe --format json` gap). An affordance advertised over a catalog it refuses part of (`--preview` over every `<id>` when it serves only the task-minting ones), or a posture asserted over an arm the same verb serves (*"don't parse it"* over a `--format json` that emits a keyed object), is a law-1 lie **even when the behaviour underneath is right** — and both refusals here were right. The repair is scope, never a behaviour change: name the scope, and name what the members outside it do instead (the direct run; the versioned `jigc doc schema` read). A reader cannot infer the scope from a catalog that does not mark it.
- **A located finding says where, and says it the same way everywhere.** A finding that carries a `location` renders it — the address *and*, when the producer claimed one, the source line — on every surface that renders that finding as text, not only in the machine envelope. A surface that withholds the locus does not merely inconvenience a reader: it can falsify a rule written about it, which is exactly what happened to the `conformance.*` route exemption ([validation.md](validation.md) → the route floor). One renderer (`cli::render::finding_locus`), one glyph (`  at: <address> · line <n>`), and a source-derived sweep over every production read of a finding's message.
- **Advisories say what happened + whether to care, in the first clause.** An advisory an agent should usually ignore must read as ignorable in clause one — habituation is a real, measured cost (three trials).
- **Acks state the effect, not just the target.** Created vs already-existed; what a discard threw away; `task minted: <id>`.
- **Verdict words bless legitimate end-states.** `unmanaged`/`unregistered` describe; they do not imply everything must migrate — staying plain is a correct outcome for off-home files (the at-home squatter keeps the one-story adopt-it rule, [doc-read-surface.md](doc-read-surface.md)).

## How each fence is proven (the unit-vs-flow split)

A flow arm cannot trip a `debug_assert` without an injected defect, so the acceptance cut splits by posture: **debug-posture fences** (route construction parse, floor presence, key discrimination) prove via unit/integration tests through the seam (the M42 `finding.rs` test pattern); **release-real pack-load fences** (suppression, catalog shape, stated-at, freeze) prove via mutated-filesystem-pack arms (the `freeze_enforcement.rs` pattern) *and* are flow-testable; **behaviour changes** (carryover refuse, staged read, same-path approve, created-vs-existed, generated templates) prove via flow-44 arms through the real binary.

## Honest bounds

- The seam asserts are debug-posture: they hold via the suite, not in a user's release binary (the recorded class posture). **And their enforcement is exactly as strong as the suite's traffic through the seam** — the M43 completion audit found four producers violating the route floor under a fully green suite (one never serialized by any test, three rendering via `Display` and never reaching serde).
