# The command-output contract — the pinned `--format json` of composed output, write-acks, and findings

**M41 design of record.** Where the *machine-consumed output of the write/compose verbs* is pinned. This is the write/compose-side sibling of [doc-read-surface.md](doc-read-surface.md): that doc pins the **read-back** of committed content (`jigc doc show`/`schema`); this one pins what a machine driver reads back from the **acting** verbs — the composed workflow a `jigc start` emits, the acknowledgement a `jigc doc set-field`/`author` emits, and the findings envelope a block or advisory carries. `jigc` is a *context compiler for coding agents*, and in both adoption trials the agent built a driver over `--format json`; this surface is the contract that driver stands on. **M45 adds the two statements that frame those shapes rather than sit inside them** — the **stream discipline** (which stream carries the document, and what rides the other one) and the **exit-code taxonomy** (the vocabulary a driver reads before it reads a byte, previously scattered across four documents with no owner): both below, each the home a standing property suite names and links ([pinning.md](../implementation/pinning.md) → §2).

Reads right after [doc-read-surface.md](doc-read-surface.md) (its read-side sibling) and after [write-commands.md](write-commands.md) (whose acks it pins) and [workflow-dialect.md](workflow-dialect.md) (whose composed output it pins). Homed as its own part-doc — **not** folded into `doc-read-surface.md` (whose charter is explicitly the *committed-doc read*, [doc-read-surface.md](doc-read-surface.md) → charter — it disowns the compose/write outputs) and **not** left implicit in `workflow-dialect.md` (which frames composed output as an *ephemeral view*, true of the view-as-workflow-state but silent on its *machine projection*).

## Why this is a contract (and why now)

The read side pinned its machine contract at 1.0 with a stated rationale ([doc-read-surface.md](doc-read-surface.md) → "a one-way door, pinned now rather than left to the first implementation"). The **write/compose** side is consumed by the *same driver* and had no such pin — composed output was `{"text": …}` (prose-in-a-box, no task id), and write-acks were ad-hoc `serde_json::json!` with an opaque `address` string. Pinning one side and not the other is an unprincipled split at the exact freeze milestone.

The load-bearing insight (M41 Fork 1, [DECISIONS.md](../DECISIONS.md) → 2026-07-11 M41 planning Settle): **the one-way door is the *posture*, not the field count.** After the 1.0 pin a declared contract evolves "only by an explicitly versioned extension"; an *undeclared* output calcifies into a *de-facto* contract with no evolution rule, so the first shipped shape silently becomes the 1.0 contract. Declaring the surface a contract with an evolution posture is the strictly-one-way, cheap-now move; the field breadth is the part that could stage. The human's call was **full pin** — pin the whole driver contract this wave, in the still-open pre-1.0 additive window, rather than pay the versioned-extension tax post-pin.

## The three surfaces this pins

### 1 · Composed output — `jigc start` / `jigc workflow` / `jigc migrate` `--format json`

The composed workflow a work-minting or plain compose call emits. Today `ComposedWorkflow` carries only `text` ([compose.rs](../crates/engine/src/compose.rs) → `ComposedWorkflow`); the minted task id is in hand at compose time but never surfaced structurally, so a driver had to scrape it from prose (the rc.4 trial's `--task (\S+)` backtick-scrape blew up shell substitution).

**Three verbs emit this composed shape** — the id-carrying composed producers: `jigc start`, `jigc workflow`, and `jigc migrate`. All three render through the one `render::composed` json arm ([render.rs](../crates/cli/src/render.rs)), so the pin holds identically across them; `jigc migrate` mints an off-router per-file migration task and composes the `migrate-<doctype>` workflow over the source seam ([auto-migration.md](auto-migration.md)), so its `--format json` carries the minted migration id in `task` exactly as a work-minting `jigc start` does.

```json
{ "task": "<task-id>" | null, "text": "<composed workflow prose>" }
```

- **`task`** — the task id, present whenever the compose mints or re-composes a work unit: a work-minting `jigc start` (the freshly minted id), `jigc workflow --task <id>` (the given id, re-composed), and `jigc migrate <path> --as <doctype>` (the minted per-file migration task id); **`null`** only for a non-minting compose (orient, a `creates-task: false` router selection). The id is the handle every subsequent call requires; surfacing it structurally retires the scrape. *(Implementation: the minted id is in hand CLI-side at `start.rs`/`migrate.rs`; whether `task` is threaded onto the engine `ComposedWorkflow` or added by the CLI render wrapper is a build choice — the contract is the `{task, text}` shape either way. `jigc migrate`'s id-carrying `task` is asserted through the real binary at `crates/cli/tests/migrate_adr.rs`.)*
- **`text`** — the composed workflow prose, unchanged (the agent-facing instruction stream).

### 2 · Write-acks — `jigc doc set-field` / `set-slot` / `add-item` / `remove-item` / `retitle-item` / `create` / `author` / `task bind` / `task discard` / `task diff`

The acknowledgement a successful managed-write emits ([render.rs](../crates/cli/src/render.rs) → `DocAck`). Today the write target is a single opaque `address` string (`spec:my-spec#criteria/item-3/title`), forcing every driver to re-parse the write-grammar address it already handed in. **And the envelope has a coverage gap:** only `set-field`/`set-slot`/`remove-item`/`retitle-item` emit a `DocAck` today — `create`, `add-item`, and `author` print a *bare address string* on success, outside the envelope entirely. The contract **brings every write verb into the envelope**, **decomposes the address into structured components**, and **carries findings-as-data**:

```json
{ "op": "set-field",
  "target": { "doctype": "spec", "slug": "my-spec",
              "section": "criteria", "item": "item-3", "leaf": "title" },
  "value": "<the written value, shaped as in doc show's fields>",
  "findings": [ … ]  // the findings envelope below; [] on a clean write
}
```

- **`op`** — the write verb (`set-field`/`set-slot`/`add-item`/`remove-item`/`retitle-item`/`create`/`author`, joined at M42 by the two task-state verbs `task-bind`/`task-discard`, and at M47 by the task-state *reader* `task-diff` — both below).
- **`target`** — the decomposed write address: `doctype` + `slug` always; `section`/`item`/`leaf` present exactly when the address reaches that depth (a whole-doc `author`/`create` carries only `doctype`+`slug`; a section-item write carries `section`+`item`; a leaf write adds `leaf`). Mirrors the `doc show` `#fragment` depth ladder so read and write addresses project identically. **`add-item`'s target is the *new* item** — `section` + the **minted `item` id** (not the bare section), so a driver reads back exactly what it created without re-deriving the id.
- **`value`** / op-specific effect keys — a **`set-field`** ack carries `value`, the written field value shaped exactly as `doc show`'s `fields` project it (scalar → string, list → array), so a write-back and a read-back read through one shape. The other verbs carry their own effect keys, **not** `value`: **`set-slot`** → `chars` (the written prose's length; the prose is read back via `doc show`, never echoed into the ack), **`remove-item`** → `removed`, **`retitle-item`** → `title`; **`create`** / **`author`** / **`add-item`** carry no `value` — their effect is the whole doc / the new item at `target`, read back via `doc show`. Every verb carries `op`, `target`, and `findings`.
- **`existed`** — the **`create`** ack's create-or-update discriminator (M43; additive, **always present** on `op: create`): `false` on a fresh mint; `true` when a committed doc already occupied the slug's canonical home and was **copied in for update** (the engine copy-in is doctype-blind since M43 — `edited-from-base` provenance, an ordinary re-promote at finalize, never the blank-seed clobber ambush). The agent-text surface states the same fact (`<addr> (already existed — copied in for update)`); a fresh mint keeps the bare-address line. Law 1's "an ack that says 'created' distinguishes created from already-existed" ([surface-contract.md](surface-contract.md)), made a key.
- **The first-touch copy-in note** — the same fact `existed` carries, stated by the **five edit verbs** on the surface they have (M47 Inc 10 T3, RC-alpha4 P4-6). `set-field` (both arms), `set-slot`, `add-item`, `remove-item` and `retitle-item` all copy a base-committed doc into the working area on the task's first touch of it (`Task::read_or_copy_in`, the only production caller of `state::copy_in`) and said nothing about it: M43's create-door fix was **incomplete over the verb axis**, and the trial's worker learned their task had staged — and would re-promote — a committed ADR from the *finalize* output. So each of those acks' agent/human line appends `(copied in for update — the committed doc is now this task's staged copy, re-promoted at finalize)` on the write that copied it in, and **only** that write: a second edit in the same task reads the already-staged copy and stays quiet. Rendered in **one** place off a single `DocAck::copied_in()` (`render.rs`), so a verb cannot join the copy-in seam and stay silent.

  > **Revised at M48 — the fact is now on both surfaces.** M47 shipped this text-only and said so: *"the JSON ack shape is unchanged — no new key … the wave's boundary is what surfaces say, not what they are."* That was an **M47 scope** reason, not a contract one, and M48's parity fence re-poses it under the rule the pre-1.0 additive-key window closes on — *a value the text prints but the envelope withholds is a gap* ([DECISIONS.md](../DECISIONS.md) → 2026-08-13 the Settle). The claimed structural substitute does not hold for the five edit verbs: `existed` rides **`op: create`** only, and "did this write copy the committed doc in?" is not answerable from a `doc show --task` read without a second read to compare against. So **every** `doc` write ack now carries **`copied_in`** (additive, always present, `false` on the two doors that state the effect their own way — `create`'s `existed`, `author`'s whole-doc write). Inserted in the same one place the text note is appended, off the same predicate.
- **`findings`** — the findings envelope (below); an empty array when the write raises no intrinsic advisory. **Scope is the doc's own intrinsic, authoring-stage-agnostic advisory: `surplus-sections-absent`** (an undeclared section in the staged doc is an anomaly at *any* authoring stage) — the pure-function check that takes just `(schema, staged-buffer)`, needs no index or subprocess, and is computed from the staged working-area file right after the write persists. **Completeness** advisories are deliberately excluded: `repeatable-populated` (an empty repeatable) and `required-slot-absent` are *expected* mid-authoring (a fresh `create` legitimately has empty sections), so surfacing them on every early write is noise, not signal — they stay adopt-/store-scope on `jigc validate`. The cross-doc / subprocess families (`ref-resolves`, `inverse-cardinality`, `mention`, `doc-code`) likewise stay store-scope: they answer "is the *corpus* complete," which a single mid-authoring write cannot adjudicate. **So `findings: []` means "no intrinsic single-doc advisory," not "passes full validation"** — a driver runs `jigc validate` for corpus-completeness (this bound is stated so a driver does not over-trust the empty array). *(Not a new idea: `jigc task finalize --format json` already emits success-path findings — the wave extends that pattern to `DocAck`.)*

**The task-state verbs join the envelope (M42).** `jigc task bind` and `jigc task discard` both **mutate durable state and print nothing at all — in every format**: `bind` records a context-role binding in the task's `roles.json` ([task.rs:281-284](../crates/cli/src/task.rs)) and `discard` `remove_dir_all`s a task's whole working area ([task.rs:259-266](../crates/cli/src/task.rs)); `dispatch` receives a `format` and both arms drop it. A driver that binds a role cannot confirm the binding, and one that discards a task cannot tell a real removal from an idempotent no-op. The asymmetry is precise: `--format json` **does** emit an envelope on these verbs' **failure** path (the operational error) — the gap is exactly the **success** path, so today a machine driver's only signal of success is silence. That is the M41 lesson's exact shape (above: *an undeclared output calcifies into a de-facto contract*), and "prints nothing" is a de-facto contract too. Both verbs join the ack envelope with a declared posture:

```json
{ "op": "task-bind",    "task": "<task-id>", "role": "<role>",
  "target": { "doctype": "adr", "slug": "use-rust" }, "findings": [] }

{ "op": "task-discard", "task": "<task-id>",
  "dropped": ["adr:use-sqlite", "commit:<task-id>"], "findings": [] }
```

- The **subject of a task-state verb is a work unit, not a doc**, so it carries **`task`** — the task id — where a doc-write carries only `target`. `task-bind` *also* carries `target`: the bound doc, decomposed exactly as above (a bind targets a whole doc, so `doctype` + `slug` only) plus the `role` it was bound to — the two values the bind actually established. **`task-discard` carries no `target`** (it addresses no doc) **and no effect key** — but since 2026-07-17 it carries **`dropped`** (additive, always present, `[]` when the working area staged nothing): the staged docs the removal threw away, as sorted `<type>:<slug>` identities. The pre-fix ack silently dropped staged doc edits — the surface-comprehension review's B3, against the style guide's own ack rule ("what a discard threw away"). The agent-text line enumerates the same set and marks a transient doctype's instance `(transient)` — its staged copy was never going to commit as a file, so nothing would-be-committed was lost; JSON carries the bare identities (transience is a schema fact a driver reads from `jigc doc schema`).

  > **⚠ Correction — a recorded rationale that was not checked (2026-07-14).** This bullet first pinned a `discarded` effect key, *"`false` on the idempotent already-absent no-op (`task.rs:257-266` — an absent area is not an error), so 'removed' and 'was already gone' stop being indistinguishable."* **The premise is false**, and Increment 9's planner **halted the build rather than pin it**: `jigc task discard <absent-id>` **exits 1** with `{"error": "no task …"}`. `TaskArea::resolve` (`task.rs:374-390`) bails before `run_discard`'s `if task.dir.exists()` guard ever runs — **that guard is dead code, and `run_discard`'s own doc comment claiming idempotence is false** (it is corrected in the same increment; a lying comment authorizes the next wrong pin). So `discarded` was unreachable-as-`false` and could only ever hold the constant `true` — **a dead key, one increment from a 1.0 freeze.**
  >
  > **The key also solved a non-problem.** "Removed" and "was already gone" were *never* indistinguishable: **exit 0 + the ack** says removed; **exit 1 + the error envelope** says it was already gone. Engaging the rationale rather than overruling it: the distinction it wanted **already exists, one layer up**, and no key is needed to carry it.
  >
  > **And making it reachable would have been worse than dead.** An idempotent discard exits 0 on *any* absent id — including a **milestone** id, which `milestone_finalize_base_guard.rs:266-275` asserts must **fail** (*"the dead end the old route pointed at, verbatim"*), and which is the very dead end Increment 7's unit-aware route fix is **justified by**. It would turn an honest dead end into a **lying route** — the disease this wave exists to cure. *This is the fifth un-enumerated-sibling / unchecked-rationale catch of M42, and the first one caught by the build refusing to proceed.*
- **`findings`** is `[]` on both: neither verb writes managed content, so the intrinsic single-doc advisory scoped above has nothing to compute over. The key is present anyway — every ack carries `op` + `findings`, so a driver deserializes one envelope shape.
- Both verbs also gain a **one-line plain-text ack**; "success is silence" is not a posture, it is an absence of one.

**`jigc task diff` joins the envelope (M47).** It appeared in **none** of this doc's enumerations, and the omission had teeth: `TaskCommand::dispatch` was handed a `format` and its `Diff` arm — the one arm of six — dropped it, so `jigc --format json task diff <id>` printed markdown, and over a working area that staged nothing with no code change it printed **zero bytes on stdout, zero on stderr, exit 0**. That is the same de-facto-contract-by-silence the two task-state verbs were fixed for, one layer worse: silence a driver cannot distinguish from a crash. It is a **reader**, not a write-ack, but its subject is the same work unit and its envelope is the same mold, so it homes here:

```json
{ "op": "task-diff", "task": "<task-id>",
  "base": { "sha": "<full>", "short": "<abbrev>" },
  "code_diff": "<the working tree's diff against base.sha, \"\" when there is none>",
  "staged_docs": [ { "id": "commit:<task-id>" }, { "id": "changelog:changelog" } ],
  "findings": [] }
```

- **`base`** — the task's own recorded pin (`.jigc/tasks/<id>/base.json`), the commit `code_diff` is taken against, projected exactly as it is stored.
- **`code_diff`** and **`staged_docs`** are **present-always** — `""` and `[]` — under the same absent-versus-empty rule `dropped` and `hook_output` follow: it is not a discrimination a driver should have to infer. That present-always posture is precisely what makes **the empty state non-empty** and closes the zero-bytes silence.
- **`staged_docs[]` carries one key, `id`** — the `<type>:<slug>` identity of each doc the working area has staged, sorted. **The id *is* the read-back address:** feed it verbatim to `jigc doc show <id> --task <task-id>` and that staged doc comes back ([doc-read-surface.md](doc-read-surface.md) → What it reads — the staged read). There is no `address` key, because it could only ever hold `id`'s value, and a contract does not carry the same fact twice — the rule the sibling `doc list` projection already states of `type`/`slug` (`cli/doc.rs` → `DocRow`), applied here ([DECISIONS.md](../DECISIONS.md) → 2026-08-05, the increment-7 plan halt).
- **Bodies are refused.** Echoing the staged bytes would mint a *second*, unversioned managed-doc content-read path beside the separately-versioned `doc show` — two read contracts over one corpus, one of them un-versioned ([doc-read-surface.md](doc-read-surface.md) → The version/posture map). The row points at `doc show` instead, which is the whole reason the identity is the thing carried.
- **`findings` is structurally always empty**, and stated so rather than left to look incidental: `task diff` adjudicates nothing — it runs no sweep, and the exit-code taxonomy (below) restricts the blocking verdict to the three task-scope gate verbs. The key is present anyway so a driver deserializes one envelope shape.
- **The agent-text arm is byte-unchanged** — the `# code changes vs base <short>` and `# staged docs` sections exactly as before, each omitted when empty. Its own empty state therefore stays silent; that is a surface question, not a contract one, and it is left to the surface batch rather than ridden in here.

### 3 · The findings envelope — carried by every verb that emits a finding as data

One envelope shape, pinned once here, consumed **everywhere a finding is emitted as data**: a write-ack's `findings[]`; the error payload of **any acting verb that blocks** (`jigc doc …`, `jigc start`, and — the one the M42 pass's first scope statement omitted — **`jigc task finalize`**, whose blocked run emits its findings as JSON and is the single most driver-consumed block in the loop); `jigc validate --format json`'s findings list (which **inherits** this shape rather than inventing its own — reconciling the separately-deferred "stable `validate --format json` as a CI-gating contract", [decisions-pending.md](../implementation/decisions-pending.md)); and — **the consumer the first funnel list missed** — **`jigc ingest --format json`**, whose triage rows carry a routed `Finding` each (`cli/ingest.rs:59`), keyed at the candidate's **managed identity** when it has one and at its **path** when it does not (below, *The membership test*, and the target-form table's path row).

**The consumer list is descriptive, not constitutive** — and it is stated that way because the earlier, narrower enumeration ("acks, blocked *writes*, `validate`") was read as a *boundary*, and twelve `finalize.*` codes sat outside the key spec on the strength of it. A verb that hands a driver a `Finding` **is** a consumer of this envelope, whatever a list happens to name. So the key spec below covers **every finding that projects a `key`** — a set fixed by a mechanical predicate, *not* by any enumeration of consumers, verbs, or files (below, *The membership test*). The earlier spelling of this claim — *"every finding constructor in the tree"* — is **retired**: it is both too broad (a `finding_to_err`'d constructor projects no key and owes no target) and, in practice, too weak (it invites a census of constructors, which is exactly how two groups were missed).

```json
{ "code": "doc-code.symbol-exists",
  "severity": "blocking" | "warning" | "advisory",
  "key": { "code": "doc-code.symbol-exists", "target": "arch-doc:overview#components/api/implemented-by" },
  "message": "<the located, human/agent-legible message>",
  "route": "<the repair direction>" | "<informational 'no action needed' value>",
  "location": { "line": <n>, "col": <n> } | null
}
```

- **`code`** — the finding code (`<probe>.<check>`), the existing stable identifier for the *kind* of finding.
- **`severity`** — `blocking` / `warning` / `advisory` (the engine `Severity`, floor `advisory` — there is no off/silent level; a finding is emitted or it is not).
- **`key`** — **the stable per-instance identity** (below): `{ code, target }`, where `target` is a stable identifier in one of the six **declared target forms** (below — the doc URI, the file path, the doctype id, the work-unit ref, the pack-resource id, the cascade delta target), **never** line/col. This is what lets a driver dedupe/track a finding across sweeps and what a future acknowledge-ledger keys on ([decisions-pending.md](../implementation/decisions-pending.md) → the deferred ledger). Which findings carry a `key` at all is a **mechanical predicate**, not a list — below, *The membership test*.
- **`message`** — the located message (unchanged).
- **`route`** — the direction, **always present** (M41 Fork 2 / V15 floor rule, [validation.md](validation.md) → the advisory-route floor; never `null`). Two route *kinds*, distinguished so a driver/agent reads the right intent: a **repair route** names an action — mechanical (`run jigc …`) *or* a non-mechanical human one ("correct or drop the mention", "author a referrer" — a real fix jigc can't execute); an **informational route** ("no action needed — uncheckable by design", e.g. `unsupported-language`) marks a genuine no-op. The floor rule is "every finding routes," **not** "every route is 'no action needed'" — flattening the two would tell an agent a dangling mention needs no action (a regression). This honors [validation.md](validation.md)'s rationale (`none` was fine only where there is no *mechanical* route) by reifying that case as an explicit route value rather than a null. (Supersedes the earlier "route is optional / `none` is fine" model.)
- **`location`** — line/col when the finding has a source position, else `null`. **Advisory only** — `location` is *not* part of the stable key (it churns under edits); it is a convenience pointer for a human reader.

#### The store sweep's envelope — `jigc validate --format json` (M47)

The store sweep wraps the findings list in three top-level keys of its own (`render::validation_store`), because a store-scope report says two things a task-scope one does not: *which* scope produced it, and whether its exit is a verdict.

```json
{ "schema_version": 2,
  "findings": [ … ],                       // the envelope above, inherited unchanged
  "scope": "store",
  "report_only": true,                     // false iff the exit flips (validation.md → Exit semantics)
  "blocking_probes": ["doc-code"] }        // sorted, de-duplicated; [] when nothing blocks
```

- **`scope`** / **`report_only`** — the scope marker and the machine half of the exit contract: the sweep is detect-and-report, so a `blocking` severity token on a *finding* is a claim about where it gates, not about this run's exit ([validation.md](validation.md) → Exit semantics — report-only, with the exit-flipping exceptions `render::STORE_EXIT_FLIPS` enumerates). `report_only` reads the same predicate as the exit code, so the two can never diverge.
- **`blocking_probes`** — the **sorted, de-duplicated probe names** of the findings whose resolved severity is `blocking`, `[]` when none. It carries no fact the findings list lacks; it carries it in a shape a **shell** consumer can bind. The installed warn-only pre-commit hook ([validation.md](validation.md) → Auto-firing the sweep) must answer *"did anything blocking come from `doc-code`?"* from a script, and a grep that reaches into a finding object has to bind a key to a member **across nested `{}`** — unsound, and the reason the hook previously warned on advisory findings too. A flat array of plain strings is a **`]`-delimited region**: a match bounded by the array's own `]` structurally cannot escape into `findings`. Greppability is a property of the delimiter you can rely on, not of JSON in general. (Severity is the engine's *resolved* one, so a project that demotes a check through the cascade demotes it here as well.)
- **Scope bound: the store sweep only.** `jigc task validate`'s envelope is untouched — its **exit code** already carries the blocking verdict for the one scope where blocking *is* a gate, and no consumer greps it.

## The stable finding key — `{ code, target }`

Findings-as-data is a sound 1.0 contract only if a finding has a **stable per-instance identity** — otherwise a driver cannot tell "the same finding as last sweep" from "a new one," and the pin freezes an unusable key. Today a `Finding` is keyed only by its line/col `location` ([finding.rs](../crates/engine/src/finding.rs)), which moves on every edit.

The key is **`(code, target)`**:

- **`code`** — the dotted finding id (`<probe>.<check>`), stable and present on every finding. The key uses `code` (per-code granularity for dedup), *not* `(probe, check)` — that pair stays the *severity* handle, a separate concern (the two diverge only where several codes share one check).
- **`target`** — a stable address in the **URI normal-form** `<type>:<slug>[#<fragment>]` — jigc's canonical identity, which survives reorder/retitle and changes only through `jigc rename` (which repoints referrers). Explicitly **not** the filesystem-path form (`<location>/<slug>.md#…`) some findings emit today, which breaks on rename and is not the addressing grammar. `location.line/col` is never part of the key (it churns under edits).

**Normalizing `target` — the wave's real work.** Finding addresses coexist in several states (spike- and cross-review-verified against the constructors). Each family lands on a **declared target form** (below — the doc URI for every content family, one of four non-doc forms otherwise) via at most a **flip** of the identifier it already holds and/or a **discriminating fragment** (when it can emit more than one finding per subject that would otherwise collide). The per-family spec — this is the pinned normal form, `(code, target)` is unique-per-instance under it:

**Read the first column as history, not HEAD — and now that is true of every row.** It is the **pre-normalization state** each sweep recorded: M41 shipped the flip for the rows above `write.*`, and **M42 shipped the rest** (`write.*`, `create.*`, `pack-probe-integrity`, `finalize.*`, the twelve parse-`conformance.*`, `override-default.*`, `workflow-refs.*`). The cites land on the **fixed** constructors, each carrying the pinned target/fragment (and saying so in a code comment pointing back here). **The three un-normalized families join the table (M42) — the M41 sweep scoped them in and swept none of them.** §3 above **explicitly scopes** *"a blocked write's error payload"* and *"`jigc validate --format json`'s findings list"* into this envelope, and the key spec pins `target` to a stable address — but the normalization sweep covered the validate/store **content** families only, so `write.*`, `create.*`, and `pack-probe-integrity.*` were left setting **no `Location::address` at all**. The consequence is a broken key on the surfaces a driver hits most: **`(write.wrong-shape, null)` is one key for every failed write of that code in the entire corpus** — indistinguishable across docs, sections, and items, so a driver can neither dedupe write blocks nor track one across attempts, and the future acknowledge-ledger has nothing to hang on. Each family's fix is the same **plumbing** shape — an identifier the constructor already holds, moved from the message into the key:

- **Address-bearing writes** — `set-field` / `set-slot` / `add-item` / `remove-item` / `retitle-item`. The address is already in hand at the block: it is literally the argument the caller passed and the string the route echoes back. These carry the **URI normal form at the depth the write named** (`adr:use-rust#status/status`, `spec:my-spec#criteria/item-3/title`), the same address the ack's decomposed `target` projects and the same address `jigc doc show` now resolves ([doc-read-surface.md](doc-read-surface.md) → The slice grammar). No synthesis, no path→URI flip — a **plumbing** fix: the address travels from the argument into the `Finding`. `write.id-from-field`'s bare fragment (`criteria/it-renders-fast/title`) is the same defect one step short — it is qualified to the full URI, not left half-normalized.
- **Doctype-scoped blocks** — `create.gate-blocked`, `create.unknown-doctype`, `create.empty-title`. Their subject is a **doctype**, not a doc: no instance exists and none is going to (the create-gate refused it / the type is unknown / the title slugs to nothing), so there is no `type:slug` URI to emit and a synthesized one would be a lie — a `type:<invented-slug>` that addresses nothing and that a driver could try to read back. **M42's own first pass declared these *nullable-by-contract*, and that was wrong** — it broke the uniqueness this very section pins, and the cross-model review caught it. In a task whose workflow grants no gates, `jigc doc create adr …` and `jigc doc create spec …` are **two distinct real blocked creates** that both key to `(create.gate-blocked, null)`; the doctype lived only in the message and the route, never in the key. **It goes in the key.** The doctype is in hand at every constructor (each takes `type_name` — `state.rs:950`, `:982`, `:998`), and `target` is the **bare doctype id** (`adr`, `spec`). This is not an invented shape: it is the form the read path **already** emits for a doctype-scoped block (`store.unknown-type` addresses the bare doctype — `Location::addressed(doctype, …)`, `doc.rs:1724-1729`) and the form `jigc doc schema <doctype>` already takes. It is deliberately **not** URI-shaped — a bare id cannot be mistaken for a doc address a driver could `doc show`. *(This corrects a call the M42 design pass recorded earlier the same day; the nullable declaration is retired, not narrowed.)*
- **Probe-integrity meta-findings** — `pack-probe-integrity.probe-failure`, the same defect one surface over: `ingest_probe_run(probe_id, …)` (`probe.rs:249`) holds the probe id and spends it on the message, while `meta_finding` (`probe.rs:285-296`) passes `None` for the location. So **every misbehaving probe in a sweep collides on one key** — on the family that is *also* the store-scope exit-flip class ([validation.md](validation.md)), i.e. the one an operator most needs to tell apart. `target` is the **probe id**. (The `(probe, check)` severity handle already carries the failure *reason* — `timeout` / `crash` / `malformed-output` — but `key` is `(code, target)`, and all three reasons share one descriptive `code`; a run yields at most one status per probe, so the probe id alone restores uniqueness.)

**`file-state.*` keys on the filesystem path** — the one long-standing non-URI form. Its subject *is* a file that may carry no committed URI identity (a drifted, foreign, or unmanaged file), so it keys per-file — transient drift findings that drain as state reconciles. M42 gives it three new members from the `finalize.*` family (below), whose subjects are files for the same reason.

**The rule, stated generally, so the next finding does not repeat this.** A finding whose subject is not a doc still needs a **stable, discriminating target — nullability is not a licence for a degenerate key.** The `code` determines the target's **namespace**; there are **six declared forms**, and a seventh is a decision, not a default:

| Subject | `target` form | Members |
|---|---|---|
| a managed doc, or a node inside one | the **URI** `<type>:<slug>[#<fragment>]` | every content family in the table above — `doc-code.*`, `ref-resolves`, `mention-resolves`, `inverse-cardinality`, `schema-conformance.*` (**except `unadopted-instance`**, whose subject is a foreign *file* — next row), all twelve `conformance.*`, `surplus-sections-absent`, `write.*`, `finalize.forward-ref-dangling` |

**The sixth form — the cascade delta target (M42).** The doc's own line above (*a further form is a decision, not a default*) is the line this exercises, so the decision is recorded with its reason. **The subject of an `override-default` finding is a recorded *delta*, not the pack resource the delta points at.** `jigc upgrade` classifies the project layer's recorded deltas against the current pack ([overrides.md](overrides.md) → Classify) and reports what no longer lines up; the thing a driver must tell apart, dedupe, and eventually acknowledge is **the delta**, and a delta has no id of its own — the target string *is* its identity (`override_default.rs`'s `render_target` says exactly that: *"a delta has no stable id, so this string is its identity in every finding"*).

Two of the three delta-kind variants (`step:<step-id>#<fill-id>`, `workflow:<workflow-id>#<step-id>`) happen to *look* like the pack-resource form, but they address **the delta's target**, not the resource itself — filing them under pack-resource would be a coincidence of shape, not a statement of subject. The third (`scalar:<knob-key>`) fits **none** of the five that preceded it, which is what forces the call. **One named form, one rationale, all three variants.**

Rejected: **widening the pack-resource form** — a knob key is not a pack resource; it is a key *into the resolved cascade*, and stretching a form to fit a thing it isn't is how the next reader mis-files the one after that. **A declared non-unique exception** — the discriminating string **already exists and is already computed** (`override_default.rs:205`, `:254`, `:379-381` build it, spend it on the message and the route, then drop it); declaring an exception while holding the answer is the *exact* `nullable-by-contract` mistake this section already caught once, one family over.

**Every finding that projects a `key` lands in exactly one of those six forms, or in one of the named exceptions below** — the closure claim, and it is now stated over the set it is actually about (see *The membership test*, next). A finding that genuinely cannot be discriminated is a **declared non-unique (or singleton) exception, named as such with its reason** — never `null`, never silent. Anywhere else `target: null` is the un-swept state of a family nobody has looked at, and it reads to a driver as a key when it is not one.

### The membership test — *does this finding project a `key`?*

**The claim above is scoped to the findings that project a `key`, not to "every finding constructor in the tree" — and the difference is load-bearing.** The M41 pass wrote the closure claim over *the tree*, and **that over-claim is precisely why the sweep missed two groups**: a claim about "every constructor" invites a census of constructors, and a census keyed on where you expect the members to live will miss the ones that live somewhere else. So the claim is now stated over the set it is actually about, and **membership is a mechanical predicate, not a census**:

> **A finding is in the envelope-projecting set iff it is serialized *as a `Finding`*.** `Finding`'s `Serialize` impl (`crates/engine/src/finding.rs:434`) writes `key` **unconditionally** (`:465`), and `key.target` is *derived* from `Location::address` (`Finding::key`, `:478`) — so **every** serialized finding carries a key, and a null `address` is a null key.

**There is no funnel list.** An earlier draft of this section named *"exactly three serialization funnels"* and the check was called at each. **That enumeration was itself a census** — the very failure mode this section exists to name, one level up — and it rotted immediately: `jigc ingest`'s `TriageRow` (`crates/cli/src/ingest.rs:59`) derives `Serialize` and holds an `Option<Finding>`, so a triage row's finding *is* serialized as a `Finding` and *is* a member by the predicate above, yet it passed through no check and had no declared form. It shipped a **second key for one defect**: the same undeclared field in the same arch-doc keyed at `arch-doc:nasty-arch#components/alpha/bogus-key` from `jigc validate` and at `docs/architecture/nasty-arch.md` from `jigc ingest`. So the enforcement is now **structural — on the serialization, where the predicate says membership is decided**:

> - **Presence** rides `Finding`'s own `Serialize` (`finding.rs:452`): a finding with no `key.target` — and no declared-singleton exemption — **cannot be projected at all**, on any surface, present or future. Nothing to enumerate; a fifth serializing surface passes the check *by construction*.
> - **Uniqueness needs the set**, so it cannot live in one element's `serialize`. It rides `Findings` (`finding.rs:312-324` — the newtype and its `Serialize`) — a newtype that is **the sanctioned way a *collection* of findings serializes**, carrying the pass on its own `Serialize` and projecting the plain array unchanged. The collection surfaces are migrated onto it: `ValidationReport::findings` (`result.rs:193`), `DocAck::findings` (`cli/render.rs:758-809`), `ProbeResponse::findings` (`probe.rs:116`), `JoinOutcome::findings` (`milestone.rs:1024`).
> - **The one honest bound**: a container that holds findings **indirectly** — `jigc ingest`'s report is a `Vec<TriageRow>`, one `Option<Finding>` each — cannot reach `Findings`' impl, so it runs the same pass from **its own** `Serialize` (`cli/ingest.rs:81-95`, calling `finding::debug_assert_keys_discriminate`). That is still a guard *on the projection* (unbypassable for that type), not a caller who must remember to call one — but it is per-type, so a future report-of-rows shape owes the same three lines. The presence half has no such bound: it is universal.

Both halves are `debug_assert`-class (no release cost): the obligation is an invariant of **jigc's own** producers, exercised by the whole suite through the real projections — never a runtime condition on user input.

The **exception lists stay** (`is_declared_singleton`, `finding.rs:205`; `is_declared_non_unique`, `:237`) — a list of *exceptions to a rule*, checkable from the code alone, is not a census of *places to check*.

The predicate has a clean complement, which is the other half of why the earlier claim over-reached: **a finding consumed by `finding_to_err` projects no key at all.** That helper (six definitions — `cli/{describe,config,milestone,task,doc,start}.rs`) **discards the `Finding`**, keeping only `message` + `route`, and the verb exits through the operational-error path — `{"error": "<message>\n  route: …"}`, no `code`, no `key`. A family whose *every* constructor is consumed that way is outside the envelope, and the contract's completeness claim is **not** falsified by it.

**Three families are outside, verified at HEAD** (each reproduced through the real binary, not inferred):

- **`config.*` (7 codes)** — every constructor flows to `config.rs:1055`'s `finding_to_err`. `jigc config set no-such-knob x --format json` → `{"error": "…is not a settable knob…"}`.
- **`structural-target.*` (8 codes, `cascade.rs:120-127`) and `slot-fill-target.*` (6 codes, `:322-327`)** — the delta-manifest **target-string parse errors**. They *are* `Finding`s (`Finding::blocking(…, Location::at(1,1))` — `cascade.rs:154`, `:348`), but **every production caller flattens them**: `StructuralTarget::parse` / `SlotFillTarget::parse` are `.map_err(finding_to_err)?` at `cli/config.rs:398`, `:452`, `:493`, `:532` and `cli/start.rs:2446`, `:2456`, `:2478`, `:2486`, `:2496`, so a malformed target **bails the verb** rather than filling a report. Verified: a hand-written malformed `target:` in the project manifest yields `jigc upgrade --format json` → `{"error": "structural-op target needs a `workflow:<id>` scheme"}`. **They need no target form** — neither the file-path form nor a non-unique exception, because they never enter the envelope. *(This is the answer the predicate gives that a census would not: they were candidates for the sixth form on the strength of their `override-default` siblings' shape, and the predicate excludes them on a fact about where they go, not what they look like.)* **Revised at the M43 completion audit:** "never enter the envelope" is a fact about today's callers, not a decision, and the route floor's seam assert made the accident visible — a future serializing path would have panicked. The family is now **seam-admissible by decision**: each parse error carries the correct-the-target-string human route ([validation.md](validation.md) → The route floor), and the codes are **declared singletons** (`(code, null)` — the parsers are fail-fast `Result<_, Finding>`, one finding per invocation, every caller bails the verb, so two instances of one code never coexist in one output; the same is declared for `overrides.project-step-missing`, `CascadeStepSource`'s one-slot error sink). The callers still flatten via `finding_to_err` — which now renders the route — so nothing above changes at HEAD; what changes is that the floor's truth no longer depends on it.

**The obligation this lays on the code, and it is a *test*, not a promise — and it now *is* one (M42).** A claim checkable only by a census someone must remember to repeat **will** rot — that is the wave's own three-for-three lesson turned on this document, and the first shipped enforcement rotted *in the same way* by installing the predicate's check at a hand-listed set of funnels (above). So the predicate is enforced **on the serialization itself**. **It checks the closure claim — `(code, target)` *unique-per-instance* — which is two properties, and a check of only the first is a check of a strictly weaker claim:**

> 1. **Present** — every serialized `Finding` carries `Some(Location::address)`, except the codes `finding::is_declared_singleton` names (at most one instance can exist, so `(code, null)` is already unique). On `Finding`'s `Serialize`.
> 2. **Discriminating** — no two findings in one emitted slice share one `(code, target)`, except the codes `finding::is_declared_non_unique` names (collapsed on purpose, each with its reason — the four below). On `Findings`' `Serialize` (`debug_assert_keys_discriminate`).

The presence half **alone** passes a degenerate key, and that is not a hypothetical: `schema-conformance.required-slot-present` shipped three byte-identical `(code, adr:<slug>)` keys for one pristine ADR *through this very seam*, because its target was non-null — **under-discriminating, never address-less** (the correction above). A check keyed on the symptom that made the class visible (*null*) cannot see the class; a check keyed on the property the doc **claims** (*discriminating*) reddens on it. It is a `debug_assert`: the obligation is an invariant of **jigc's own** producers, so it fails the suite loudly and never turns a user's finding into a panic in a release build. The whole workspace suite runs **through** those seams, which is what makes the closure claim mechanical rather than remembered: a new family that forgets its target form — or gives two of its instances one key — reddens the gate instead of shipping a degenerate key, and each exception list is one function, in one place. **The claim and its check land together, or the claim rots exactly as this one did.**

**The sweep is closed, and it is closed *because* a partial close is how this class returns.** The M42 pass first bounded the sweep to §3's three named consumers and left the nine `finalize.*` codes and twelve `conformance.*` codes outside it. That bound was too clever: **the contract *claims* unique-per-instance keys, so shipping 1.0 with more than thirty codes that violate the claim — across five families — makes the claim false at the pin** — and the finding key is exactly the kind of contract that **cannot be repaired additively afterwards** (a driver's dedup and the acknowledge-ledger's rows both hang on it). It is also, precisely, the **un-enumerated-sibling pattern this wave has already been bitten by three times** — the `schema.location` census that under-counted twice, the empty-diff backstop whose *own* false-refusal class only surfaced while writing it, and the `git add` pack prose that was missing from four workflows and named in one ([DECISIONS.md](../DECISIONS.md) → 2026-07-13 M42 planning: the Settle). Closing a class **partially** is how it bites a fourth time.

> **The pattern is the milestone's central lesson, and it repeated inside its own remedy — three times.** The first two misses came from reasoning about *where* findings live (a file, a verb, a named consumer list) instead of *what they are* (a `Finding` that gets serialized). The third came from a **null-shaped census** of a *degenerate-key* class: `required-slot-present` was never address-less, only **under-discriminating**, so a hunt keyed on `target: null` — and a check that only asserts *presence* — could not see it. **The fourth is the sharpest**: the increment that *replaced the membership census with a predicate* then installed that predicate's **enforcement as a census** — "call it at each of the three funnels" — and the fourth funnel walked straight through it. **The lesson has a second half, and this is it: when you find a census, do not just fix its entries — ask what makes it a census, and put the check where the property is decided.** The seam is now on the serialization; there is nothing left to enumerate.

**The parse-`conformance.*` family — the address is built in three stages (M42; a fourteenth code joins at M49, below).** Of the family's thirteen codes only `conformance.section-missing` carried a fragment; the other **twelve** set none, so `attribute_to_doc` addressed them at the **bare `type:slug`** and *two unknown fields in one doc collide on one key* — a real, driver-visible collision, not a theoretical one. ### The `migrate-corpus.*` sub-table (M42 completion audit — Finding 2)

`jigc migrate-corpus` refuses a doc it cannot migrate and lists it under the report's `blocked`. Those entries were **not findings at all** — untyped `[path, route]` string tuples, no `code`, no `key`, no `(code, target)` — so the three Increment-5 refusal classes the roadmap calls **"refuse loudly"** were *inaudible to a machine*. And the run **exited 0**, which with Increment 4's `validate` exit-flip is an **infinite CI loop**: `validate` → exit 1, *"run `jigc migrate-corpus`"* → `migrate-corpus` → exit **0** → `validate` → exit 1 → forever, with nothing machine-readable naming why. They are real `Finding`s now, riding the structural serialization seam (a `Finding` cannot project without a declared target; a *set* of them projects through `Findings`), and **a refused migration exits non-zero** — the interim-state intuition was right about the *doc* and wrong about the *run*: a corpus with a refused doc in it is **not migrated**, and the caller that asked for it to be must hear so.

| `migrate-corpus.*` code | Subject | Refusal |
|---|---|---|
| `missing-snapshot` | a below-version doc whose prior-shape snapshot is not shipped | ship the snapshot |
| `unclassified-change` | the empty-diff backstop — a structural change no transform kind classifies | build the kind |
| `narrowed-cardinality` | a `card` narrowing (content-affecting, no adjudicating kind) | restore the bound, or build the arm |
| `removed-field` | a dropped declared leaf (committed values would be destroyed — **No-data-loss**) | restore the leaf, or build the strip arm |
| `destination-collision` | a relocating doc whose destination already holds a **different** document | fold the two homes by hand |
| `prose-needed` | the Framing-A handoff — the folded doc **breaks its own conformance gate** (a required slot the fold minted empty, or one the doc already carried empty) | author the prose, re-run |
| **`fold-refused`** (M46 — the non-gate halt, see below) | a halt the gate never saw: the transform driver refused the change, or the bytes it produced do not parse under the new schema | a **schema-authoring** repair — build the arm, or declare the migration input it lacks |
| **`item-unmodelled-content`** (M49 — the byte-fidelity guard) | an `added-item-slot` fold whose committed item region holds bytes the parse does not model (prose after the `<!-- fields -->` group), which the whole-item re-render would destroy — **No-data-loss** | move those bytes into a declared leaf (or delete them), re-run |
| `deferred` | a doc left untouched behind the run's first blocker (WIP-safety) | resolve the blocker, re-run |
| **`set-field-unfilled`** (M46 — **not a refusal**, see below) | a **migrated** doc's added leaf whose declared field carries `set:` with **no** `default:` | none — the doc migrated; the run *names* what it left unfilled |

**The one member that is not a refusal — `set-field-unfilled` (M46 Increment 4).** Every row above is a doc the verb could **not** migrate; this one is a doc it **did**. M46 Increment 4 stopped the fold refusing an absence the conformance gate already accepts — a `set:`-derived field with no `default:` is not author-required (`engine::validate::is_author_required`), so no author can write it and no re-run changes it, and the Framing-A route it used to collect was a permanent dead end ([corpus-migration.md](corpus-migration.md) → The classifier's holes). Folding it to zero bytes is correct and **silent**, which is its own hazard: a doctype author who adds a `set:`-bearing field expecting the corpus to carry a value would read `1 migrated` and nothing else. So the run reports it — one **advisory** per unfilled leaf, riding the report's own **`unfilled`** key and never `blocked`, whose emptiness *is* the exit rule, so the exit stays **0**. Three specifics, because each is a decision:

- **The target keeps the file-path form and adds the leaf fragment — `<path>#<section>/<field>`, at *both* loci**, so **two unfilled leaves in one doc discriminate** rather than collapsing onto one `(code, target)`. The path half is the family's form for the family's reason (above); the fragment half is the **declared leaf's schema locus** — the section it was added to and its field id. It is deliberately **not a write address**, and at the item locus it could not be one: a leaf added to a repeatable section's item block is written at `#<section>/<item-id>/<field>`, and this report holds no item id. Minting one finding *per item* to get concrete ids is refused for a reason the whole rider rests on — a repeatable section carrying **zero** items still has an unfilled leaf, so a per-item key would go **silent** on exactly the corpus a doctype author most needs to hear about — and collapsing the item locus onto `#<section>` would re-open the very collision the fragment was added to close. So the *key* names the leaf, and the **route** carries the locus (next bullet). Nothing is lost by that split: no `migrate-corpus.*` target is followable as a jigc address anyway — the family keys on the **file path**, never the doc URI (above), so `docs/decisions/alpha.md#status/date` resolves through no verb either. (M46 completion audit, finding F2: through rc.11 one locus-blind renderer emitted the simple form's *message and route* for both loci, which **did** claim a write address that does not exist.)
- **The route splits on the `set:` *kind*, through the one authority** (`engine::schema::is_machine_maintained_absolute`): a **machine-maintained absolute** (the freeze stamp, a milestone transition) takes an **informational** route — no `jigc doc` write may set it, so naming an action would be a route nobody can take; an **author-overridable** `on-create` takes a **human** route naming the write path **at the leaf's own locus** — for a simple/header leaf, `#<section>/<field>`; for an **item** leaf, the item-qualified *form* `#<section>/<item-id>/<field>` together with the read that enumerates the real ids (`jigc doc show <doc-address>#<section> --task <task-id>`), which is the `store.no-such-section` precedent: name the form, route at the read, invent no id. Neither is **mechanical**: a `jigc doc set-field` argv needs a task id and a migration report holds none, and a mechanical route is a promise the command runs from where the reader stands ([surface-contract.md](surface-contract.md) → The route fence).
- **A caller-threaded value is filled, not unfilled.** The CLI hands a deriver's value in **as a schema `default:`** (`with_stamp_default`), which is why the derivation keys on `set.is_some() && default.is_none()` **against the schema the fold used** — the schema-version stamp is excluded by construction rather than by a second list of exceptions.

**The halt cause decides which refusal the doc gets — `fold-refused` (M46 Increment 4).** One doc's migration can fail at three points — the transform driver refuses the change, the bytes it produced do not parse under the new schema, or those bytes parse and break the conformance gate — and through rc.11 all three collapsed into one outcome the report rendered as `prose-needed`: *"`<path>`'s migration mints a new **required** prose slot … author the new required prose, then re-run"*. Two thirds of that is unfollowable. An enum rename the authored old→new map does not cover is repaired in the **map**, not in the doc; a doc whose *pre-existing* empty slot breaks the gate had nothing minted at all. The fold's route was a **permanent dead end** followed exactly — the same class Increment 4 closes on the transform side ([corpus-migration.md](corpus-migration.md) → The classifier's holes). So the halt carries its cause out to the CLI, which renders it through an **exhaustive** match — a fourth cause cannot be added without deciding what it says. Two rules fall out, and both are contract:

- **`prose-needed` is now exactly the gate cause, and its message relays the gate's own findings.** It keeps its code and its route byte-identical, because it is the one halt an author clears *from the doc* — which is what the route directs. What changes is that the report stops narrating over the gate: the finding set is in hand, so it is repeated verbatim rather than re-diagnosed. Two surfaces describing one break in two vocabularies is precisely the failure this wave exists to close.
- **Every non-gate halt takes `fold-refused` — with one named exception (M49) — and its route is a schema-authoring repair.** That is the treatment `unclassified-change` / `narrowed-cardinality` / `removed-field` already get *pre-fold*, on the same recorded reason — nothing an operator or agent does to *this doc* unblocks it — so the fold's own halt path stops being the one place that pretends otherwise. It is a **refusal**, so it rides `blocked` and holds the run's exit, unlike `set-field-unfilled` above. **The exception is `item-unmodelled-content`** (M49): the schema pair is sound and the transform arm is built — what stops the fold is that the *doc* carries bytes outside the shape it conforms to, so a schema-authoring route would be the very lie this split exists to stop. It is the second cause an author clears from the doc, which is why the split is stated as *who can repair it* rather than as *the gate versus everything else*.

**`target` is the file path, not the doc's `<type>:<slug>` URI — and that is a decision, not an oversight.** A committed managed doc *has* a URI, and every content family keys on it. But the subject of a migration refusal is the **file the verb could not move or rewrite**, and mid-relocation the URI is precisely the thing that is **contested**: the prior-home strand and the placement home can both claim one identity — which is the entire content of `destination-collision`. Keyed on the URI those two refusals would **collide on one `(code, target)`**; keyed on the path they discriminate, and the operator reads back exactly the file to repair. So they join the **file-path** form for the same reason as `file-state.*`, `finalize.promote-clobber` and `schema-conformance.unadopted-instance`: the finding is about a file whose managed identity is absent — or, here, disputed. Uniqueness needs no exception: the fold pushes at most one refusal per candidate file and moves on.

`message` carries the diagnosis and `route` the repair, never the two fused — the tuples had it the other way round, a single string that opened with the diagnosis and trailed the repair, so a driver could not act on the route alone.

**`workflow-refs.*` — the pack-resource form, keyed at the resource. In scope, and the count is exact: 28 distinct codes across 37 production constructor sites** (`compose.rs`, 28; `data_value.rs`, 9 — verified at HEAD; the M41 pass's *"26 sites"* was short). Their subject is a **pack definition** that failed to load or compose (a workflow, a step, the command catalog), so they take the **pack-resource** form: `workflow:<id>` / `step:<id>` (the workflow dialect's containers are addressable under the same grammar — [structural-grammar.md](structural-grammar.md) → Addressing: *"one grammar, every reference"*), or the catalog's resource id for the two pack-load codes (`malformed-command-catalog`, `duplicate-command-id`). The id is **not** in hand at the constructors — they are pure helpers over bytes (`load_command_catalog(bytes)`, `find_run_shadow(body)`, `parse_data_value(text)`) — but it **is** in hand at the load/compose boundary (`validate.rs:426-431` loops per `StoreWorkflow`, holding `workflow.id`), so the same outward-attribution pass applies.

**They are in the envelope-projecting set, and the roadmap's arithmetic said otherwise.** Increment 9's enumerated clusters totalled ~28 codes *excluding* `workflow-refs` entirely, while **this doc already pins them** (the form table's pack-resource row, and this paragraph). The pin is honoured, because the predicate above says it must be: `workflow-refs.*` findings reach a `ValidationReport` through **`jigc validate`'s store sweep** — family 2, `compose::workflow_refs_store` at `validate.rs:427`, into `ValidationReport::new` at `:536` (CLI caller `cli.rs:834`) — and they collide there today, verified through the real binary: two unresolvable `{{cli.…}}` refs in one step yield two findings keyed `{"code": "workflow-refs.command-ref-resolves", "target": null}`, byte-identical, in one array. Shipping 1.0 with the doc claiming they are keyed and the code emitting `null` is the **same false-claim-at-the-pin** problem this whole section exists to fix.

*One nuance the predicate exposes, worth stating because it is not a contradiction:* the **same code** is keyed on one surface and flattened on another. On the **compose** path (`jigc start` — `start.rs:759`, `:1038`, `:1723`) the first blocking finding is `finding_to_err`'d to `{"error": …}`, so it projects no key; on the **validate** path it is a keyed report finding. The obligation attaches to the *finding*, not the surface: a constructor whose finding can reach **any** funnel needs a declared form.

**Keyed at the resource, and declared non-unique below it**: two malformed data-values in one workflow collapse to one key. That is the *correct* granularity, not a concession — a workflow-def load failure means **the pack is broken**, a defect a pack author fixes once, not a corpus finding a driver tracks across sweeps.

**The declared exceptions come in two kinds** — *non-unique* (a real target, deliberately collapsed below a certain granularity) and *singleton* (`null`, because at most one instance can exist). Both are named, not smuggled, and each carries its reason.

**The declared non-unique exceptions — five, each with its reason.** Every one still carries a **non-null, discriminating-to-its-subject** target, and `location.line` still separates the instances for a human reader. They are named in code as well as here — `finding::is_declared_non_unique` (`crates/engine/src/finding.rs`), the exemption list the seam's uniqueness half reads, so the list is one function in one place and an addition to it is a visible edit, not a silent collision.

- **`conformance.item-heading-unanchored`** → `type:slug#<section>`. An item heading with no `{#id}` anchor **has no identity** — that is the finding. The heading text is not an identity (heading and id diverge by design after `jigc doc retitle-item`), and a position would violate the never-positions invariant ([VISION.md](../VISION.md) → Stable IDs). The key that would discriminate is precisely the thing that is missing. *(M45 renamed the code from `item-anchor-missing` — the message now names the reserved-depth **cause**, since a heading at item depth with no anchor is byte-identical to stray slot prose that broke out and to a genuinely anchor-less new item, so it carries both repairs; [validation.md](validation.md) → The M45 registrations. The **key is untouched**: the reason it collapses is the same missing identity.)*
- **`conformance.item-anchor-malformed`** → `…#<section>/<found>`. **The same reason, one step along, and it is the *second* member of the degenerate-key class** (M42, Increment 9 validation): an item whose anchor is malformed has no *valid* identity either — the anchor text **is the defect, not an identity** — so the fragment discriminates the *bad text*, and **two items carrying the same bad anchor emit one key twice**. Both findings are still emitted, and that is the difference from its sibling row `item-anchor-duplicate`: one duplicated id is one shared defect and **one** repair (collapsed at the producer), whereas two broken anchors are **two** items and **two** repairs, so suppressing the second would hide a defect. What is forgone is telling them apart *by key* — the only sub-discriminators on offer are heading prose (unstable, and rejected as an identity for `item-heading-unanchored` directly above) and position (excluded by the never-positions invariant). Keep the malformed text in the target: it is what the repair needs, `location.line` separates the instances, and it collapses only in the narrow case where the two defects are textually identical.
- **`conformance.item-slot-delimiter-shadowed`** → `…#<section>/<item>`. The subject is the **item's prose**. The only sub-discriminator on offer is the shadowing heading's *text*, and a prose-derived key **churns under exactly the edits the key exists to survive** — an unstable key is worse than a collapsed one.
- **`conformance.slot-setext-heading` / `slot-heading-depth`** → the owning slot's address. Same reason: the subject is the slot's prose; the alternatives are line number (excluded from the key by construction) or prose text (unstable). The two codes already split the two defects.
- **`workflow-refs.*`** → the pack resource. Per-resource by design (above).

**The declared singleton exception — `target: null`, and correct, because at most one instance can exist.** This is the one place `null` is a *value of the pin* rather than an un-swept default, and it is stated by its **predicate**, not by a list someone must remember to extend: *a finding whose emission path can yield at most one instance has nothing to discriminate against, so `(code, null)` is already unique-per-instance.* Its members:

- **`store-version.binary-mismatch`** (`cli/setup.rs:100-130`, joined to the store report at `cli.rs:868`). Its subject is **the store**, of which there is exactly one per repo.
- **Every `setup.*` (16 codes) and `uninstall.*` (8 codes)** — M42, and **they were missed by the sweep, which had them filed as projecting no key at all** (the correction above). They *do* project one: they ride the third funnel, `setup_block` (`cli/render.rs:1008`), which serializes a **bare `Finding`** — so `jigc setup --format json` outside a git repo really does emit `{"code": "setup.repo-root", "key": {…, "target": null}, …}`. The keys are nonetheless **sound**, by construction rather than by luck: `setup::run` and `setup::run_uninstall` are **`Result<Summary, Finding>`** (`cli/setup.rs:693`, `:1173`) — fail-fast, **exactly one finding per invocation**, and `setup.rs` builds no `Vec<Finding>` anywhere. Two instances of one code can never coexist in one output, so there is nothing for a target to discriminate. *(That the reason differs from `binary-mismatch`'s — "the verb emits one" vs "the store is one" — is why the exception is declared by its predicate: both reduce to **at most one instance can exist**.)*
- **Every `structural-target.*` (8 codes), `slot-fill-target.*` (6 codes), and `overrides.project-step-missing`** — M43 completion audit, declared in the same motion as the family's routes (the route floor). The same "the verb emits one" reduction: `StructuralTarget::parse` / `SlotFillTarget::parse` are fail-fast `Result<_, Finding>` and every caller bails the verb on the first error; `overrides.project-step-missing` lands in `CascadeStepSource`'s one-slot error sink, drained as the verb's single located error. Not a census, and **not a check *called* at a census of funnels either** (the first shipped enforcement was exactly that, and the fourth funnel walked through it): the guard is **on the serialization** — presence on `Finding`'s `Serialize`, uniqueness on `Findings`' — so a surface cannot project a finding without passing it. Seam tests pin both halves in both directions, on the projection: it fires on a non-exempt address-less finding and on a non-exempt colliding key, and passes a declared singleton and a declared non-unique collision. This claim had been false twice at its own pin, and the third statement of it shipped a check of a **strictly weaker** property than the claim; the check now tests the claim, everywhere the claim applies.

**The check's bound, stated because leaving it implicit cost a ninth sibling — and the bound is now much narrower than the one first written here.** The first shipped seam asserted an address was **present**, never that it **discriminated**, and this paragraph then declared that strengthening it "is not mechanically available." **That was wrong, and it was wrong in the wave's own signature way** — it reasoned about the hard version of the property (*prove each code's subject granularity*, which really would need per-code knowledge) and concluded the easy version was unavailable. The easy version is the one the contract actually claims: **two findings in one emitted array must not carry one key**, and that is a single pass over a slice already in hand at every funnel. It is shipped, and it reddens on `required-slot-present`'s three-key ADR. What remains **human-checked** is only the residue: a code that under-discriminates but whose instances happen never to **co-occur in one emitted slice** is invisible to the seam (nothing collides), so the `#<fragment>` column still fences *that* case — a new finding whose subject can occur more than once per target owes a fragment, and only this table will tell you so. The division of labour: **the seam fences the address-less case *and* every collision that reaches an output; the table fences the latent under-discrimination that has not collided yet.** One further bound, stated because the funnel census taught this section not to leave one implicit: **uniqueness is enforced per *serializing container***, so a container that holds findings indirectly (a report of rows) must run the pass from its own `Serialize` — `jigc ingest` does (`cli/ingest.rs:81-95`), and a future report-of-rows shape owes the same. The **presence** half has no such bound: it rides `Finding`'s own `Serialize` and is therefore universal.

## Stream discipline — which stream carries the document

The three shapes above pin *what* a driver deserializes and say nothing about *where to read it*. That silence was not academic. Three separate project-alpha-3.0 sessions reported *"`finalize --format json` emits non-JSON"*, and the verification **refuted** it: stdout was pure JSON and the `--- hook output ---` relay rode **stderr**, exactly as the M19 discipline pins it (`relay_hook_output`, `cli/task.rs`; [finalize.md](finalize.md) → 6. Commit) — the parse failures were agent harnesses **merging** fd 1 and fd 2 in arrival order ([RC-alpha3/findings-verification.md](../completions/artifacts/RC-alpha3/findings-verification.md)). The contract was conformant and written in no document, so the refutation had nothing to point at and nothing to pin. It is stated here, and it is the property the M45 JSON-purity suite fences ([pinning.md](../implementation/pinning.md) → §2).

**The rule.** Under `--format json`, **the structured document owns stdout and every agent-text side channel goes to stderr** — the hook relay, the `left-out` and carried-over advisories, the stale-read hint ([doc-read-surface.md](doc-read-surface.md) → What it reads), any plain diagnostic. Under `agent`/`human` the split inverts (the human render owns stdout; there is no document to protect). Per stream, and this is the pinnable form: **the JSON-bearing stream parses as exactly one document, and the other stream carries no JSON at all.**

**Which stream is the JSON-bearing one is decided by the *outcome class*, never by the exit code.** The naive "stdout is the JSON stream" is false for two whole classes, and a suite written against it reddens on its first fixture:

| Outcome class | The JSON document | The other stream | Exit |
|---|---|---|---|
| **An adjudication jigc completed** — composed output, a write-ack, a landed finalize, a validation report (clean *or* blocking), a migration review hold | **stdout**, exactly one document — *whatever the exit code*, so `jigc --format json task finalize > report.json` captures a block rather than an empty file | stderr: the hook relay, the advisories, the plain-text diagnostics | 0 · 3 · 4 — **and 1** on a store-scope exit flip, where the report still prints and the code says the sweep is untrustworthy (`cli.rs` → `run_validate_store`) |
| **A reject** — the run produced no adjudication: an operational error (the single-key `{"error": …}` envelope, `render::operational_error`) or a blocked write (the findings envelope of §3) | **stderr**, exactly one document | stdout: **empty** | 1 |
| **A clap-resolved outcome** — a usage error, `--help`, `--version` | **none** — plain text | — | 2 (stderr) · 0 (stdout, help/version) |

**How a driver *finds* the document, in one predicate: parse stdout; if stdout is empty, parse stderr.** Exit **1** appears in two rows with *different* JSON-bearing streams, so the code cannot discriminate them — but the two classes are disjoint on emptiness: an adjudication always writes its document to stdout, a reject always leaves stdout empty. The clap row needs no third branch — neither stream holds JSON, so the stderr parse fails and the exit code says why. Stated as a predicate because that is the form the M45 JSON-purity suite asserts against ([pinning.md](../implementation/pinning.md) → §2); a driver that branches on the exit code instead reads the wrong stream on exactly one of the two.

**The clap carve-out is declared, not discovered.** `--format` is jigc's own flag, parsed by the same clap pass that rejects a bad argv, so a usage error is adjudicated **before any jigc code reads the format**: the parse **failed**, so there is no format value to honour and nothing enters the JSON funnel — plain text, exit **2** to stderr on a usage error, exit **0** to stdout for `--help`/`--version`. *(The reason is the failed parse, and stating it as **who formats the message** was falsified at M48: `main()` no longer prints every clap error verbatim — for the **unknown-subcommand** kind jigc composes the block itself, so a curated near-miss tip lands in the tip slot instead of below clap's contradicting did-you-mean, a law-1 repair on the reject surface ([surface-contract.md](surface-contract.md) → law 1; `DECISIONS.md` → 2026-08-13 the Settle, F8, and the M48 Increment 6 T2 entry). The carve-out is untouched by that: the block is still plain text on stderr at exit 2, because plain text is what the missing format value leaves.)* That is why the AGENT.md machine-output paragraph scopes its claim to *"a successful or validation outcome"* ([assistant-adapter.md](assistant-adapter.md) → The managed bootstrap body, the M44 N4 carve-out), and the scoping is load-bearing rather than cosmetic: **a purity suite that enumerates verbs from the clap tree must assert the clap surface as its own arm** — plain text, the stated exit — or the first `jigc doc show` with no argument reddens it. The crack was named at the M44 Settle (*"every verb speaks JSON" is law-1-false at the clap-error surface*); here it is contract.

**`hook_output` — the field the split earns (M45).** The discipline above is correct and *predictably fragile*: git exposes one combined hook stream, a great many agent harnesses merge the two fds, and every merged-stream driver hits this wall identically. Relaying to stdout would corrupt the envelope the discipline exists to protect; dropping the output would hide a user's hook. So the text is carried **both ways** — the stderr relay stays exactly as it is (agent-text, verbatim and unwrapped, [finalize.md](finalize.md) → 6. Commit), and **the landed-commit envelopes gain a `hook_output` string**, the same captured text inside the document the driver is already parsing.

- **Shape** — `"hook_output": "<the captured non-blocking hook output>"`: **always present**, the **empty string** when no hook spoke. Present-always for the reason `dropped` is (§2) — absent-versus-empty is a discrimination a driver should never have to infer.
- **Where — the producer axis** (swept 2026-07-24, the confidence-audit `hook_output` fix; shipped at M45 on the finalize envelopes alone): the envelopes of **every verb that runs a hook-capable commit**, i.e. exactly the sites that relay — `jigc task finalize`'s landed shape; `jigc milestone finalize` / `join`'s landing manifest, where a `squash: false` boundary folds **every** chain commit's stream in commit order (the N per-sub-task code commits + the aggregate — never the aggregate's alone); the `jigc rename` and `jigc migrate-corpus` reports; and the `jigc milestone` record-only op acks (`create` / `add-task` / `add-from-spec` / `discard`, beside `text` — empty on the read-only ops sharing that envelope). The one exclusion: `jigc setup`'s install commit is `--no-verify` by recorded design (its hook must not self-trigger on the commit that installs it) — no hook runs, nothing to carry. Every producer routes through the one returning commit seam (`cli/task.rs` → `git_commit_capture`), and the axis is iterated per producer by `tests/hook_output_axis.rs`.
- **One capture, two channels** — relay and field carry the *same* string from the *same* seam; the field does not re-run the hook, re-trim, or re-format it. Two renderings of one fact would be a second truth to keep in sync.
- **The M19 discipline is honoured, not qualified away.** What it forbids is the **relay** riding the document's stream — raw hook text merged into the envelope or interleaved on stdout ([finalize.md](finalize.md) → 6. Commit). `hook_output` is not the relay: it is a **declared string key inside** the document, escaped like every other value, so stdout still parses as exactly one document and stderr still carries the verbatim relay. The rule above is unchanged in both halves — the structured document owns stdout, agent text owns stderr — and this key is a *value in the document*, not a side channel that moved.
- **Why an integrity wave takes it at all — the T3 override, written rather than ridden in.** M45's valve routes genuinely new capability to M46, and this field **is** capability: the trial complaint was **refuted** (stdout was pure JSON; the harnesses merged the fds), so no compliant agent produces or discards bytes over it (**T1** clear), and it excludes no axis-card member (**T2** clear). It is taken anyway on two grounds, recorded so it reads as a decision: the additive window **closes at the 1.0 pin**, after which mirroring one already-captured string costs a versioned extension of the driver contract; and the wave that first writes the stream rule down is the right place to answer the merged-fd reality that rule predictably meets ([DECISIONS.md](../DECISIONS.md) → 2026-07-23, Decision 1 + *Riders and adjudications accepted*).
- **Posture** — an **additive key inside the still-open pre-1.0 window**, the kind M43's `carried-over` and M44's `item-count` already spent; adjudicated below in *Evolution posture*. No version integer is minted and none is bumped — this contract has none, by declaration.

## The exit-code taxonomy

**Homed here, and until M45 it was homed nowhere.** The `0/1/2/3/4` vocabulary is the **first** contract a pipeline binds — it carries no version field and no additive carve-out ([validation.md](validation.md) → Exit semantics, the third exception) — and it was stated across four documents, none of which owned it: the AGENT.md one-liner ([assistant-adapter.md](assistant-adapter.md) → The managed bootstrap body), the exit-3 mint ([measurement.md](measurement.md) → the three soundness increments), the store-scope exit rules ([validation.md](validation.md) → Exit semantics), and the migration refusal's *loud* ([corpus-migration.md](corpus-migration.md) → What "loudly" costs). Each is true of its own surface and none states the vocabulary. It homes in this doc because the exit code is the outermost layer of the very envelope this doc pins — a driver reads the code before it reads a byte — and because the M45 property suite that pins it must **name and link the doc section owning the statement** ([pinning.md](../implementation/pinning.md) → §2) — and until this section existed there was nothing to link. *(Two statements home here — this one and stream discipline — which is exactly why that rule keys on the linkage and not on the filename.)*

**The codes do not move; the *statement* is what M45 amends** ([DECISIONS.md](../DECISIONS.md) → 2026-07-23 M45 planning: the Settle, Decision 6). *"3 = blocking findings"* was true of the gate that minted it and false as a general claim, and the repair is the qualifier, not a renumbering: aligning the write-verb reject from 1 to 3 was **declined** — a behavior change on a public surface a driver may already key on, days before the 1.0 call. **The one-way door here is the statement, not the codes.**

| Exit | Meaning | Scope qualifier |
|---|---|---|
| **0** | the run did what was asked | includes a store-scope `jigc validate` **carrying content findings** — report-only by design, detected drift is not a gate ([validation.md](validation.md) → Exit semantics) — and clap's `--help` / `--version` |
| **1** | **operational error, and every reject that is not a task-scope gate** | not-a-project · an absent task id · a git/IO failure · a **blocked write** (`write.*`, which carries a real findings envelope and still exits 1) · a **hook-rejected finalize** · the store-scope **exit flips** the `render::STORE_EXIT_FLIPS` table enumerates — an operational statement about the **sweep**, explicitly **not** the task gate. Neither the count nor a single class is restated here: the hand-count this row carried went stale against that table repeatedly, and the members share no one class — each row carries its own `sweep_untrustworthy` verdict, some being sweeps that **worked** and are reporting what they found rather than sweeps that could not adjudicate at all (M49 Increment 8 / T6) ([validation.md](validation.md) → Exit semantics; `cli.rs` → `run_validate_store`) |
| **2** | usage error | clap's own convention, emitted **before** jigc reads `--format` (above) |
| **3** | **blocking findings at a task-scope gate** | the transaction gates only — `jigc task validate`, `jigc task finalize`, `jigc milestone finalize`. **Never** the store sweep, **never** a rejected write |
| **4** | migration review hold | a migration `finalize` without `--approve`: the fidelity diff rendered, nothing committed, `migrate.review-pending` named in the invocation log ([corpus-migration.md](corpus-migration.md); [finalize.md](finalize.md)) |

**The second clause, and it is not a rounding error: store-scope `validate` is deliberately blind to task-scope checks.** The live case is row **0** above — `jigc validate` sweeps the committed store and exits **0** carrying its content findings by design, and some of those very findings *do* block at **3** once a task's scope contains them (the sweep's trailer says which, per finding; [validation.md](validation.md) → Store-scope re-validation). That is a **scope** statement and it is sound: the store sweep and the task gate run different check sets over different surfaces ([validation.md](validation.md) → Scope = effective state), so *"validate previews what finalize blocks on"* is a claim about **task**-scope `validate` — never a promise that a green store sweep predicts a green finalize. It is stated because a driver that CI-gates on `jigc validate` alone is not gating on the finalize verdict, and no document said so.

**The third clause, and it is position, not scope: `jigc task validate` previews the gate up to the commit, not through it.** Same scope, same engine, one transaction — every check `task validate` runs (this task's content findings, the carryover gate, the six staging-independent `owner-artifact` causes, and the granted-but-unused changelog gate) is the same check `finalize` runs, at the same severity — so a blocking finding is exit **3** at both doors, and an advisory one stops neither. What it cannot show is what does not exist yet when it runs: four items are **unpreviewable in principle** — `finalize.stage-failed` · the commit hook's rejection · `empty-commit` / `nothing-staged` · the **untracked** `owner-artifact` cause (its six siblings *do* preview; [finalize.md](finalize.md) → 2. Validate) — and a handful more (the preflight's base pin, promotion, the migration review hold) are decided at other phases of the transaction and deliberately left out of the preview ([DECISIONS.md](../DECISIONS.md) → the 2026-07-26 M47 Settle, Decision 1). None of that is a scope difference: it is a **later position in the same transaction**, which is why the earlier framing — *the owner-artifact gate divergence follows from scope* — was wrong on both halves (it read a position change as a scope change, and cited a task-scope case to carry a store-scope claim). So a driver reads exit **3** from `jigc task validate` as *this will not commit as it stands*, and exit **0** as *nothing this side of the commit blocks it*.

**One table, one constant — and the constant does not exist yet.** The table above is the design of record for a **single code-side constant** the M45 exit-code suite asserts against, and which the AGENT.md one-liner is asserted against in the same motion (*statement == constant* — a stated fact with no fence is a fact that drifts). At HEAD there is no such constant: **0/1/2 are bare literals across ~8 decision sites**, and the two named ones — `EXIT_VALIDATION_BLOCKED` (3) and `EXIT_REVIEW_PENDING` (4) — are `pub(crate)` in the **binary** crate, unreachable from `crates/cli/tests/*.rs`. So minting the table and promoting it through the same lib re-export the golden and purity suites already need ([pinning.md](../implementation/pinning.md) → Sizing) is build scope, not a follow-up.

## Evolution posture (declared)

This doc owns **command-output contract v1** (the composed, write-ack, and findings shapes above). It follows the **`doc show` posture**, not an inline per-message version integer (which would be noise on outputs emitted every call): **additive keys are permitted pre-1.0 only; from the 1.0 pin the shape evolves solely by an explicitly versioned extension — never a silent additive key.** The version home is this declaration (named `vN`) plus the golden tests that pin each shape at ship — the same mechanism `doc show` uses. A post-1.0 breaking change ships as **command-output contract v2**, a declared named extension, exactly as the read side.

This wave pins the whole driver contract (task id, decomposed target, findings-as-data, the stable key) inside the still-open pre-1.0 window — so what would otherwise be a post-pin versioned-extension chore lands additively now, on the surface the vision names as jigc's reason to exist.

**M48 spends the window down, under one rule, and fences it.** The rule ([DECISIONS.md](../DECISIONS.md) → 2026-08-13 the Settle, *the pre-1.0 additive-key window*): **a value the human/agent text already prints, but the `--format json` envelope withholds, is a gap.** Its axis is the clap leaf-verb tree — *every machine-output surface* enumerates as *every leaf verb that speaks `--format json`* — and it ships as a **standing fence, not a census** (`crates/cli/tests/text_json_parity_axis.rs`): the registry bijects that tree and classifies each verb **fenced** (its text renders from a structured Rust value, so field-vs-key is mechanical — the check destructures the value exhaustively, making the compiler the field enumerator) or **judgment** (its text is composed prose, censused once instead). The keys the fence found and closed: **`copied_in`** on every `doc` write ack (above), **`committed_identity`** on the `doc rename` ack (`reslugged: false` alone cannot tell a committed identity's frozen slug from a never-committed doc that simply kept its id — a distinction the text makes), and **`milestone`** + **`no_docs_from`** on `jigc milestone join` (its text echoes the milestone id and names every sub-task that staged no doc; the envelope carried the merge outcome alone). **Deliberately excluded, and not gaps:** keys for values nothing computes, and values the envelope withholds *by a recorded routing decision* — `task diff`'s staged **bodies** (echoing them would mint a second, unversioned content-read path beside `doc show`) and `task discard`'s `transient` bit (a schema fact a driver reads from `jigc doc schema`). Each such exclusion is named at its own call site in the fence, so it stays a decision rather than an oversight.

**The M42 corrections, and what kind of change each one is.** The rc.6 wave touches this contract three ways, and the posture above authorizes only one of them as written — so each is named:

- **The `write.*` `target` normalization is a *value* change under an existing pin, not an additive key.** `target` was pinned at M41 to the URI normal form; the `write.*` family shipped emitting `null` (and one bare fragment) *against* that pin. So this is not an evolution of the contract — it is the contract **being made true**. The posture paragraph above governs *additive keys* and does not, as written, authorize a value change to a pinned key; it is authorized here, explicitly: **a normalization correction to a pinned value lands inside the pre-1.0 window.** The bound is narrow, and it is exactly why the window is the right place — a driver written against `(write.wrong-shape, null)` today cannot be *relying* on that null, because it is a **degenerate** key (every failed write of that code in the corpus collides in it), while after the 1.0 pin the same repair would cost a versioned extension of the one key every other family already honours. A correction does not get cheaper by waiting; it gets frozen.
- **The task-state acks are a new surface declaring its posture at ship** (§2) — not an addition to an existing shape, and exactly the move "Why this is a contract" prescribes. They ride this doc's posture (no in-band version integer; additive keys pre-1.0 only).
- **The `create.*`, `pack-probe-integrity`, `finalize.*`, parse-`conformance.*`, `override-default.*` and `workflow-refs.*` `target`s are the *same* value correction, not a third kind.** M42's first pass wrote the `create.*` one up as a *declaration* — "the value it emits today is the value the contract now states, and a driver may rely on it" — and drew a scope line that left the others out. Both moves were the same error: a driver **cannot** rely on a key that collides with itself, and a contract that *claims* unique keys while dozens of codes break the claim is **false at the pin**, not partially true. Every one of these families is a correction of a pinned value, authorized on exactly the grounds above. That the M41 sweep and a same-model review both blessed the `write.*` version of this defect, that the M42 design pass then re-introduced it one wave later *inside the fix for it*, and that the **sweep's own closure claim was still false twice over** when Increment 9 went to build it (`override-default.*` un-formed; `setup.*`/`uninstall.*` mis-filed as key-less) is why the general rule is now stated as a **rule** — scoped by a predicate, with named exceptions and an owed test — and not as a row.

**The M47 correction, and it is the *other* half of the key: a `code` change, authorized explicitly.** The clause above authorizes a correction to a pinned **`target` value**, and only that — a `code` change is a different kind, and the paragraph it would otherwise be read into exists *precisely because* M42 caught itself reasoning by analogy from one authorized kind to an unauthorized one. So this one is authorized in its own words, with its own bound. M47 flips the code an **item-id miss** emits from `write.wrong-shape` (and, on one cell, `write.unknown-field`) to **`write.not-present`** across every write verb that can address an item ([validation.md](validation.md) → the `write.*` route split; [DECISIONS.md](../DECISIONS.md) → 2026-07-26 M47 Settle, Decision 8). **A correction to a code that names the wrong *kind* of miss lands inside the pre-1.0 window**, on these grounds and no wider:

- **The old code was a false statement, not a naming preference.** `write.wrong-shape` routes `jigc doc schema <doctype>`, and a schema names the declared *shape* — never the corpus's live item ids. Emitting it for "the item you addressed was never minted" tells the agent to consult a surface that cannot contain the answer: a law-1 lie on the reject path ([surface-contract.md](surface-contract.md) → law 1). The contract cannot pin a code whose meaning is wrong and call the pin sound, for the same reason M42 could not pin a `target` that collided with itself.
- **The bound is the *absent addressed item*, and nothing wider.** A **section** miss keeps `write.unknown-section`; a genuine declared-shape defect — an `add-item` into a non-repeatable section, a non-conformant source, the malformed-title rejects — keeps `write.wrong-shape`. The flip is keyed on one predicate, swept over the whole verb axis as data (`crates/cli/tests/write_miss_shape_axis.rs`), so the code's meaning is now uniform rather than per-call-site.
- **No driver can be relying on the discrimination this moves, because there was none.** Before the flip, `write.wrong-shape` covered *both* an item-id miss and a genuine shape defect with no way to tell them apart from the `code`; the discrimination lived only in the `target` (which already names the addressed item) and the message prose. The flip therefore **adds** a distinction the key never carried and removes none. Nothing in the tree consumed the old distinction: no golden carries either code, neither is an `AMBUSH_CLASS_CODES` member or a severity-knob subject, and the only consumers were the route-selection guard and the two tests that pinned it — both moved in the same commit as a **basis-has-changed rebuttal**, not an override.
- **Waiting makes it permanent, not cheaper.** After the 1.0 pin the same repair costs a versioned extension of the one key every driver reads, to correct a code that was wrong the day it was minted. This is the identical shape as the `target` clause above, applied to the key's other component — and it is stated rather than inferred so the next reader does not have to re-derive the analogy the last one got wrong.

**The M49 code flip, on the same authorization and the same bound: the nested-section hop.** M47's clause directly above authorizes a `code` correction that names the wrong *kind* of miss, keyed on one predicate and swept over the verb axis. M49 spends it once more, on the sibling predicate M47 did not reach — and it is declared here in its own words rather than read into that paragraph, because that is the discipline the paragraph itself exists to enforce. The grounds are M47's, restated where they differ:

- **Three of the four old codes were false statements.** `write.not-present` routes `jigc doc show <doc>#<top-section>`, which exits 0 and lists the item ids of a section the address got *right* — a recovery that answers a question nobody asked; `write.unknown-field` asserts a field question about an item in a nested section that does not exist; `write.wrong-shape` is the one that was merely imprecise. - **No new contract member is minted, and that is the point.** A fifth code would itself be a spend on the key every driver reads. The shipped `write.unknown-section` already means exactly this miss and already carries the route that answers it — the `jigc doc schema <doctype>` read — so the flip **converges** the family rather than widening it.
- **The bound is the segment declared nowhere, and nothing wider.** A segment the item block declares as something else (a field, a slot) stays `write.wrong-shape` — the genuine declared-shape defect — exactly as a declared-but-non-repeatable *section* does one level up. A trailing **leaf** name (`#releases/1-3-0/bogus` at `set-slot` / `set-field`) is not a section hop at all and keeps its correct `write.unknown-field`. The flip is keyed on one predicate (`engine::write::nested_section_undeclared`, the ranked sibling of `section_undeclared`) and swept over the verb axis as data (`crates/cli/tests/write_miss_shape_axis.rs`), so the meaning stays uniform rather than per-call-site.
- **Nothing consumed the discrimination this removes, because it was noise.** The four codes did not partition anything: the same address shape produced a different one per door, so a driver keying on `code` could only have been keying on *which verb it called*, which it already knows. No golden carries these cells, none is an `AMBUSH_CLASS_CODES` member or a severity-knob subject, and the `target` — unchanged, the full write address — carried whatever discrimination there was.
- **Waiting makes it permanent, not cheaper**, for M47's reason exactly: after the pin, converging four keys onto one costs a versioned extension of the key every driver reads.
