Run: `jigc doc create jigc-feedback --title <TITLE> --task your-task-id`

This task files exactly one NEW finding. A title whose slug a doc on disk already
holds is refused `create.already-exists`, with nothing staged — choose a distinct
title, or keep it and pass `--slug <slug>` to the same create.

The `jigc-feedback` schema is the authority on what you write into it — its required
slots and fields, each field's enum members, the convention each string field
follows, and every address a write can take:

jigc doc schema jigc-feedback

Every `--from-file -` below reads its payload from stdin — attach it as a heredoc
directly to the `jigc` command, never as a `cat payload | jigc …` pipeline, which
jigc itself accepts but an agent harness that statically analyses shell commands
can refuse to run:

jigc doc set-slot jigc-feedback:<slug>#description --from-file - --task your-task-id <<'EOF'
<what jigc did, and what you expected instead>
EOF
