Plan the increment. Cut it into ordered, single-concern tasks straight from the
roadmap increment — its Deliverable, Grouped scope, and Proves — and the design
docs it names. Each task carries an observable done-criterion: a named test that
passes, or a command that exits clean with asserted output, so every task has a
real red step.

Keep the cut minimal — the smallest set of tasks that delivers the increment's
Deliverable, with no creep into later increments. Each task is one focused
concern that ends in one commit.

Checkpoint: new-fork-at-plan
If planning surfaced a genuinely new fork not covered by the settled gates and
not resolvable from the locked docs, stop and surface it to the human before
cutting tasks. A clarifying decision costs less than tasks cut against the wrong
shape.

Execute each task through the dev-workflow verbatim — scope, red, green,
refactor, gate, commit. Run the tasks strictly serially: they share one working
tree, each builds on the last, and each ends in exactly one conventional commit.
One task is one focused concern is one commit.

Checkpoint: blocked-task
Halt on a blocked task — a real ambiguity, a new fork, or a green gate
unreachable without overstepping the task's scope. Surface it to the human
rather than guessing past it or widening scope to force a pass.

Validate the increment independently against the roadmap — a read-only check
that does not edit or commit. Verify, with concrete evidence: the gate is green
from a clean state; the deliverable holds end-to-end by running the real binary
and observing output, not by trusting the tests alone; the increment proves what
the roadmap says it proves; the invariants are honored; and the scope is honest
— no inert feature, no stub presented as done, no creep into a later increment.

Return findings, each blocking (the deliverable, proves, invariants, or scope
are not genuinely met) or advisory (real but non-blocking).

Checkpoint: fix-rounds-exhausted
For each blocking finding, run a dev-workflow fix task — a red that fails because
of the defect, a minimal green, the gate, one commit — then re-validate. This is
bounded to three rounds. If blocking findings remain after the fix-round cap,
stop and surface it: thrash is a signal for a human, not for another round.
Advisories are surfaced, not gated.
