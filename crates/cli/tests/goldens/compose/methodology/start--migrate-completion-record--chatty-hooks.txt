FIRST, the refusal rung: a completion record RECORDS A CLOSE, so it needs a
derivable verdict. When the foreign document states NO outcome at all — nothing
done/shipped/passed-shaped and nothing failed/blocked-shaped — it is NOT a
completion record: author nothing, run `jigc task discard sweep-the-compose-surface`, and either
leave the file unmanaged or re-run `jigc migrate <path> --as <doctype>` with the
doctype it actually is. There is NO rung that fabricates a verdict.

Otherwise the target schema and its batch payload, both generated from the resolved
`completion-record` schema, follow — the CLI creates the per-milestone record (the
slug is minted from the title: the milestone this record closes) and places its
header fields and findings over a single staged buffer:

The `completion-record` schema — each instance a managed file at `docs/completions/<slug>.md`, its `<slug>` minted from `title`.

- `meta` (front-matter fields):
    - `verdict`: enum, one of: green | red — author-required
    - `owner-artifact`: owned-location — author-required
    - `schema-version`: int — CLI-stamped (schema-version) unless authored
- `findings`: repeatable items, one per `title`:
    - `title`: string — the item's id-source (authored as the item's `title:` payload key)
    - `severity`: enum, one of: blocking | advisory — author-required
    - `disposition`: enum, one of: fixed | deferred | contested — author-required
    - `evidence`: string — author-required

Author the whole document in ONE `jigc doc author` batch payload — fill each `<…>` value. The `<<…>>` wrapping on slot prose is REQUIRED literal syntax: keep the `<<`/`>>` markers and replace only the text between them (an inline field takes a bare value — wrapping one is rejected). An entry marked `# optional` may be omitted entirely. A repeatable's demonstrated item entry is a template — repeat one `- title:` entry per item. Pipe the payload on stdin:

jigc doc author completion-record --from-file - --task sweep-the-compose-surface <<'EOF'
title: "<the title>" # the id-source — slugged lowercase-kebab into the doc id, capped at the first 5 words / 50 chars
sections:
  - id: meta
    set:
      verdict: "<green | red>"
      owner-artifact: "<the owner-artifact>"
  - id: findings
    items:
      - title: "<the title>"
        set:
          severity: "<blocking | advisory>"
          disposition: "<fixed | deferred | contested>"
          evidence: "<the evidence>"
EOF

Each foreign finding maps onto one `findings` item: `severity` is `blocking` when
the foreign record treated it as must-fix, `advisory` otherwise; `disposition` is

When the foreign record states its outcome but records NO findings, author no

Finalizing a migration adds a review hold: a plain finalize commits NOTHING —
it renders the foreign source against the canonical rewrite and holds (exit 4),
because the CLI guarantees structure, never content-faithfulness. Review that
fidelity diff, then re-run the same finalize with `--approve` to write the
canonical doc, RETIRE the foreign original, and commit — approval is the one
destructive gate. Retired means removed: the foreign file is deleted from the
worktree and the deletion staged, so the removal lands in the same commit as
the canonical doc (a `git rm` in effect). A source already sitting at its
canonical destination is
rewritten in place on approval — the committed file is modified, nothing is
retired. A destination already committed when the doc was authored was copied
in as the edit base (the create said so), so approval updates that committed
file in place — review the fidelity diff before approving. Finalize blocks
(finalize.promote-clobber) only when a file appeared at the destination after
the doc was created: resolve that collision, or retitle the doc so it slugs
differently, then finalize again.
Land the change as exactly one logical commit. finalize commits the git index —
only what you have staged (`git add`), plus the docs it manages. Unstaged edits
and untracked files are left out of the commit; with nothing staged over a dirty
tree, finalize refuses. Anything still staged from BEFORE this task was minted
makes finalize refuse too (one blocking finding per carried path): unstage it, or
pass `--carry-staged` to declare the carryover deliberate.
