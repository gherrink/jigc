Develop the idea into a product direction. The idea is:
sweep the compose surface

Reason about the vision, the requirements it implies, and the context that
shapes it — audience, constraints, and what is out of scope — before authoring
the prd below.

Author every managed document through `jigc` — it owns placement, structure, and
cross-references. Files you write straight to disk are unmanaged: outside `jigc`'s
tracking, validation, and commit — this is a convention, not a sandbox, so a
hand-placed doc is simply invisible to the project.

Create the prd, then author its `vision` and `context` slots on the address
`create` prints — the created doc is a `prd`, so the write address is
`prd:<slug>#<slot>`:

<<author: prd:<slug>#vision>>
<<author: prd:<slug>#context>>

jigc doc set-slot prd:<slug>#vision --from-file - --task sweep-the-compose-surface
jigc doc set-slot prd:<slug>#context --from-file - --task sweep-the-compose-surface

jigc doc add-item prd:<slug>#requirements --title "<requirement>" --task sweep-the-compose-surface
jigc doc set-slot prd:<slug>#requirements/<id>/statement --from-file - --task sweep-the-compose-surface
